## Proposed rule text

Conventions used below: `(Operator fact)` = a required-facts outcome as defined in 04 § 1.2 (blocking `missing-element`, owner `operator`, never `notConfigured`); every new ruleset file ships with `source` and `retrieved` fields (WP-104); every new per-locale list follows 04 § 15 *Page locale*.

### Gap 1 — UX-025 (Must)
Pack ux, policy block adds:
```jsonc
"trackingIds": []       // UX-025: [{ host: <hosts[] entry host with purpose analytics|advertising>, ids: [string] }]; no default
```
`analytics-vendors` entries (UX-010 § 3) gain optional `idParam` (a query/form parameter name, or an RFC 9535 JSONPath into a JSON body, naming the property ID in a hit: GA4 `tid`, Meta `id`, Matomo `idsite`, TikTok `sdkid`, Plausible `domain`), `libraryIdParam` (parameter naming the ID in tag-library loads: `id` on `/gtag/js` and `/gtm.js`) and `idPattern` (regex of the vendor's ID shape for the static scan: `G-[A-Z0-9]{6,12}`, `GTM-[A-Z0-9]{5,8}`, `AW-[0-9]{8,11}`, `UA-[0-9]{4,10}-[0-9]{1,3}`, `[0-9]{15,16}` only when preceded by `fbq('init',`). New ruleset `placeholder-tracking-ids.json`: `string[]` of regexes (`^G-X+$`, `^GTM-X+$`, `^UA-0+-\d+$`, `^0+$`, `^1234567890?$`, `(?i)your.?(id|property)`, `(?i)^(test|demo|example)`).

- **UX-025** · P0 · browser, html, cfg — Tracking identifiers are the Operator's. Part `declared` (cfg): every `hosts[]` entry with purpose `analytics` or `advertising` that was requested in G6 on a sampled page or in a flow, or whose `idPattern` matched in part `static`, is covered by a `ux.trackingIds` entry; otherwise a blocking `missing-element` owned by `operator` naming `ux.trackingIds` and the host (Operator fact, 04 § 1.2). Part `match` (browser): every request recorded in G6 that the ruleset recognises as a hit or a tag-library load for such a host (`analytics-vendors` plus `google-tags.json`) carries, in its `idParam`/`libraryIdParam`, an ID equal (case-sensitive) to an `ids` value of the covering entry (`value-mismatch` showing the request URL, the parameter and the actual ID; owner builder). Part `static` (html): in the raw HTML of each sampled public page and in the same-origin JS files it references, every token matching an `idPattern` of the ruleset is in some `ids` list (`forbidden-value` showing the token, the file and the matched vendor), so tags that do not fire before consent are judged too. Part `placeholder` (html, browser): no ID found by `match` or `static` matches `placeholder-tracking-ids.json` (`forbidden-value`). Pre-consent behaviour stays PRV-001. Missing inputs: no analytics/advertising host requested and no token matched → `notApplicable`; `ux.trackingIds` absent with either present → the `declared` Operator-fact finding (builder cannot clear it by deleting the tag when `hosts[]` declares the host). Failure classes `value-mismatch`, `forbidden-value`, `missing-element`. Pack ux § 2; add UX-025 to the 04 § 1.2 required-facts list (part `declared`). Owner: WP-609 (browser side), ruleset data WP-104; `trace/ownership.tsv` row UX-025 → WP-609.
