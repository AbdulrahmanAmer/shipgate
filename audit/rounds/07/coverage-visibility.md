## Proposed rule text

**1 — web-delivery · RTE-016 (Must)** — insert after RTE-015.

- **RTE-016** · P0 · html, browser — Head integrity on indexable pages (Google ignores every head element after an invalid one and treats the head as ended there). **Head region:** in the raw HTML response (Googlebot smartphone user agent), the token stream from the first `<head>` start tag (or, when absent, the first token after the doctype and `<html>`) up to the first `</head>` or `<body>` start tag, tokenised with `html5ever`'s tokenizer without tree construction; content of `<script>`, `<style>`, `<template>` and `<noscript>` elements is not inspected. **Allowed head elements:** `title`, `meta`, `link`, `script`, `style`, `base`, `noscript`, `template`. **Signal elements:** `title`; `meta` with `name` in `robots`, `googlebot`, `bingbot`, `description`, `viewport` or `http-equiv="refresh"`; `link` with `rel` `canonical`, or `rel="alternate"` with `hreflang`; `script[type="application/ld+json"]`; `meta[charset]`.
  - Part `invalid-element` (P1 · html): a start tag in the head region that is not an allowed head element is a finding (`pattern-match`: element, byte offset, URL). 
  - Part `signals-after` (P0 · html): an `invalid-element` finding on a page with ≥ 1 signal element after the invalid element (before `</head>`) is escalated: this part reports each signal element that Google would ignore (`forbidden-value`: signal element, the invalid element that precedes it, URL). `invalid-element` is then not reported for that page.
  - Part `body-signal` (P0 · html, browser): in the DOM parsed from the raw HTML (html) and in the rendered DOM 2 s after `load` (browser; sampled pages, 04 § 10), no signal element other than `script[type="application/ld+json"]` and `meta[name=viewport]` is a descendant of `<body>` (`forbidden-value`: element, location `raw` or `rendered`). Rendered-only findings name the script that inserted the element when the browser records it.
  - Part `noscript-body` (W · html): a `<noscript>` in the head region whose children include an element other than `link`, `style` or `meta` (the HTML spec allows only those in a head `noscript`; browsers with scripting disabled then move the rest into the body and end the head).
  - Missing-input outcomes: none (no policy keys). Pages not served as HTML → `notApplicable`. Failure classes: `pattern-match`, `forbidden-value`.
  - Sources: Google Search Central *Valid HTML*; WHATWG HTML § 13.2.6.4.4 (in head noscript).
  - Ownership: `trace/ownership.tsv` rows `RTE-016 * WP-410 explicit`, `RTE-016 channel:browser WP-608 explicit`. Add to the *Cloaking* neighbours of the 02 coverage map under "Canonicals & duplicates".

**2 — web-delivery · RTE-017 (Should)** — insert after RTE-016.

- **RTE-017** · P1 · browser, html — No content that exists only after a click. On browser-sampled public pages (04 § 10), for every control whose disclosure exemption (04 § 15 *Disclosure exemption* items 1–5; the activation step is the one that section already performs) was verified, let C be the content it reveals (the element referenced by `aria-controls`, the `<details>` body, the dialog or popover). Part `empty` (P1 · browser): C had 0 UAX #29 words before activation and ≥ 20 after it (content is fetched or created on click). Part `absent-in-raw` (P1 · html, browser): C has ≥ 20 UAX #29 words after activation and fewer than 90 % of its normalised words (NFKC, case-folded) occur in the raw-HTML `<main>` text (RTE-001 token overlap, 04 § 12; reference = the activated C). Exempt: C inside `<dialog>`/`[popover]` items 4, controls on `app` surfaces, and carousel slides (item 5, which TPL/CNT rules and RTE-001 `links` already judge). A control whose activation changes the URL to an indexable page (a tab with its own `<a href>`) is judged as navigation by LNK-001. Failure class `missing-element` (control accessible name, C's selector, words before/after, URL). Part `button` (W · browser): a control matching ruleset `load-more-labels.json` (per locale: "load more", "show more", "read more"…) that appends ≥ 5 `<a href>` to indexable pages not present in raw HTML and is not paired with a plain `<a href>` to the next page of a series (URL-006 part `links` already owns series; this part reports the unpaired remainder).
  - Missing-input outcomes: no browser → `skipped(no-browser)`; no verified disclosure on the page → `notApplicable`.
  - New ruleset file: `load-more-labels.json` (WP-104).

**3 — programmatic · CRW-004 (Should)** — insert after CRW-003, section 4d.

- **CRW-004** · P1 · site — Closed link space (Google: calendars and parameter combinations create "infinite spaces"; block them or `nofollow` the links). During the G4 crawl (04 § 10), a **trap hit** is a URL that the crawler dropped because of a § 10 trap limit and that was discovered from an `a[href]` on an indexable 200 page, unless the link carries `rel~=nofollow` or the URL is disallowed for Googlebot by the robots.txt evaluation (04 § 15). Parts: `params` (> 3 query parameters on one URL), `values` (> 50 distinct values of one parameter under one path pattern), `depth` (path depth > 20) and `loop` (a path in which the same sequence of 1–3 segments repeats ≥ 3 times consecutively, e.g. `/a/b/a/b/a/b`), each P1; part `maxurls` (P1): `crawl.maxUrls` reached while ≥ 50 % of the crawled 200 HTML URLs are neither in a sitemap nor in the inventory (remote crawls use `crawl.remoteMaxUrls` and skip this part: `skipped(remote)`). One finding per path pattern: the pattern, the parameter or segment sequence, the first 3 dropped URLs and the first page linking to them (`budget-exceeded` for `maxurls`, `pattern-match` otherwise). The fix is robots.txt (parameter wildcard), `nofollow`, a bounded date range or removing the link.
  - Missing-input outcomes: none. Runs only when the crawl ran (`skipped(no-crawl)` otherwise); counts toward `incomplete-crawl` as today.
  - Ownership: `CRW-004 * WP-506 explicit`, crawler hook (record dropped URLs with discovery source) in WP-407.

**4 — web-delivery · URL-014 (Should)** — insert after URL-013.

- **URL-014** · P1 · http, edge — Canonical-variant probes (the variants URL-002 and RTE-004 leave undefined). For each service, on `/` and the first 3 indexable paths of the HTTP sample (04 § 10), request: (a) default-document variants — the path with `index.html`, `index.htm`, `index.php`, `default.aspx`, `default.asp` appended (ruleset `default-documents.json`; for a path that is a directory, i.e. ends in `/` or has no file extension); (b) the path with a doubled slash (`//` for the first `/` after the host); (c) when the path contains percent-encoded octets, the same path with lowercase hex digits; (d) the path with `;jsessionid=sg` appended to the last segment. Each answers **either** 404 / 410, **or** one hop with `redirectStatus` to the canonical, **or** (only for (b)–(d)) 200 whose `<link rel="canonical">` equals the canonical of the unmodified URL. A 200 with a different or missing canonical is a finding (`value-mismatch`: variant URL, expected, actual). Edge pass: the same probes on production for `/` only (`edge.production: true`).
  - Missing-input outcomes: static hosts whose emulation does not support the variant → `skipped(host-emulation)`.
  - New ruleset file: `default-documents.json` (WP-104).

**5 — search-engines · SE-128 (Should)** — insert after SE-127, section 3.2.

- **SE-128** · P1 · html — Sitewide third-party links (Google spam policies, link spam: "Widely distributed links in the footers or templates of various sites"). On the HTTP sample (04 § 10, ≥ 5 indexable pages required), an `a[href]` to a host that is no service origin, not in `business.json` `socialProfiles` or `answer-engines.organization.sameAs`, and not a `hosts` entry with purpose `payments`, `legal` or `assets`, which appears (same host and path) on ≥ 50 % of the sampled pages, carries `rel` containing `nofollow` or `sponsored`, unless its host is in `web-delivery.sitewideLinkAllow` (array of hostnames, default `[]`; the Operator's explicit choice, e.g. the agency credit). Failure class `forbidden-value` (href, anchor text, number of pages). Part `anchor` (W): even for an allowed host, the anchor text (NFKC, case-folded) is not a keyword phrase: it equals the host's registrable-domain label or a `sitewideLinkAllow` entry's `anchor` (when the array element is an object `{ host, anchor }`).
  - Policy: `web-delivery.sitewideLinkAllow` (default `[]`). Fewer than 5 sampled indexable pages → `skipped(sample-too-small)`.
  - Ownership: `SE-128 * WP-411 explicit`. Add `sitewideLinkAllow` to the 03 § 3 `web-delivery` default block and to the `WCF-007` host-format check.

**6 — search-engines · LOC-004 (Should)** — insert after LOC-003.

- **LOC-004** · W · review — Local listings on the other engines: for each location of `business.json` `locations` (applies where LOC-001 does) and each engine in `engines`, the Auditor confirms a claimed, verified listing exists whose name, address, phone and hours equal the file — Bing Places for Business (`bing`), Apple Business Connect (`apple`), Naver Smart Place (`naver`, Korean-market locations), Yandex Business (`yandex`, RU/CIS locations), Baidu Maps listing (`baidu`, `zh-CN` locations), Seznam Firmy (`seznam`, CZ locations). Review items are generated one per (location, engine) with the engine's listing-management URL from ruleset `local-listing-sources.json` (`{ engine, name, url, regions[] }`); answered in `quality/audit/review.json` (04 § 1.7) with `confirmed` and a date on or after the lock's `createdAt`; an unanswered item stays a W.
  - Missing-input outcomes: no `locations` → `notApplicable`. New ruleset file: `local-listing-sources.json` (WP-104).

**7 — programmatic · DAT-018 (Should)** — insert after DAT-017, section 4b; extend § 1 `sources` shape.

- Policy `programmatic.sources.<id>` gains `rights` (required for every source used by a family field, no default; one of `"owned"`, `"licensed"`, `"public-domain"`, `"open:<SPDX id>"`, `"facts-only"` (only facts, no creative text, copied from a third party)), `attribution` (string, required for `licensed` and for `open:` licences whose SPDX id is in ruleset `attribution-licences.json`, e.g. `CC-BY-4.0`, `ODbL-1.0`) and `attributionFragment` (a `staticFragments` key, default `attribution-<id>`).
- **DAT-018** · P1 · cfg, html, review — Dataset rights. Part `rights` (P1 · cfg): every source referenced by a `source` attribute of a family field has a `rights` value; a missing value is a blocking `missing-element` finding owned by `operator` naming `programmatic.sources.<id>.rights` (04 § 1.2 required-facts rules; agents cannot invent rights). Part `attribution` (P1 · html): every family page that renders a field whose source requires attribution shows the source's `attributionFragment` text (a `staticFragments` entry, so TPL-001 keeps it policy-owned) in `<main>` or `<footer>`, with a visible `<a href>` to the source's `url` when the licence requires a link. Part `licensed` (W · review): the Auditor confirms for each `licensed` and `facts-only` source that the supplier's terms allow republishing on a public website and programmatic use (one review item per source, answered in `quality/audit/review.json`).
  - Missing-input outcomes: no `families` → `notApplicable`; a source with `rights: "owned"` or `"public-domain"` → parts `attribution` and `licensed` are `notApplicable` for it.
  - Ownership: `DAT-018 * WP-502`, `DAT-018 channel:html WP-504`. Add `rights`/`attribution` to the programmatic sources schema in 03 § 3.5 and to PCF-004 (`source` must exist) so a missing `rights` is not also reported there.
