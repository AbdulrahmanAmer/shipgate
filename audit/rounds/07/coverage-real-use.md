**1 — privacy · PRV-029 (Must)**
- **PRV-029** · P1 · cfg, html, site — Declared jurisdictions cover the observed markets (GDPR Art. 3(2); consumer-law targeting). Observed signals, from ruleset `market-signals.json` (`[{ signal, value, implies: [jurisdiction], when? }]`): (a) region subtags of `<html lang>`, hreflang values and sitemap alternates of indexable pages (EU-27 member, IS, LI, NO → `eu-gdpr`; with `ecommerce` in `project.kinds` or `security.payments` also `eu-consumer`; GB → `uk-gdpr` (+ `uk-consumer` with ecommerce/payments); BR → `br-lgpd` (+ `br-consumer`); CA → `ca-pipeda`; CA-QC / fr-CA → `ca-qc`; JP → `jp-appi`; KR → `kr-pipa`; CN → `cn-pipl`; IN → `in-dpdp`; AU → `au-privacy`); (b) currencies of JSON-LD `Offer.priceCurrency` and `business.json` `prices[].currency` (EUR, GBP, BRL, INR, AUD, CAD, JPY, KRW, CNY → the same ecommerce-conditional jurisdictions); (c) `business.json` `locations[].address.country` and the country prefix of `legal.vatId`; (d) `OfferShippingDetails.shippingDestination.addressCountry`, `areaServed` country codes and the countries of the merchant-feed shipping columns; (e) the ccTLD of each service origin and `production.origins`. Every implied jurisdiction must be in `privacy.jurisdictions` or in `privacy.jurisdictionsNotTargeted: [{ jurisdiction, reason }]` (Operator-signed, `reason` non-empty; listed in the report). Otherwise a blocking `missing-element` finding owned by `operator` naming the signal, its value and the implied jurisdiction (required-facts rule, 04 § 1.2): the agent cannot clear it by removing the signal unless it is a builder-written signal (hreflang/JSON-LD), in which case the finding is `forbidden-value` owned by the builder when the signal is absent from `business.json`/policy. US state laws are not inferred from locale (no signal); `us-ca-ccpa` and `us-state-privacy` stay Operator-declared.
  Inputs: policy `privacy.jurisdictionsNotTargeted` (default `[]`); ruleset `market-signals.json`. Missing inputs: privacy pack off → `notApplicable`; no ruleset entry matches → `applied` with no findings. Sampling: indexable pages of the HTTP sample (04 § 10). `brief --stage start` lists the observed markets (TR-112).

**2 — privacy · PRV-030 (Must)**

Applies with `eu-consumer`, `uk-consumer`, `de` or `at` (for `de`/`at`, PRV-022 `imprint` already checks the imprint page; PRV-030 additionally requires the footer link below) and to `eu-gdpr`/`uk-gdpr` sites with `ecommerce`, `saas` or `local-business` in `project.kinds`. Its `<main>` (or the footer itself when it holds the data) contains: `legalName` (or `name`), `postalAddress` (else the first `locations[].address`; LOC-001 containment), an `emails[]` address, `legal.registerNumber` when declared, `legal.vatId` when declared. Country-specific required keys from ruleset `provider-id-by-country.json` (`{ "<ISO country of legal.registerCountry, else the first location country>": { requires: [legal key], pageMustShow: [...] } }`): GB → `registerNumber`, `registeredOffice` and `registerCountry` shown (company number, registered office, place of registration); FR → `registerNumber` (SIREN/RCS), `host` (name, address, phone), `publicationDirector`; IT → `registerNumber` (REA) and `vatId`; ES → `vatId`; NL → `registerNumber` (KvK) and `vatId`; default → name, address, email. A required `business.json` value that is absent is a blocking `missing-element` owned by `operator` (required-facts rule, 04 § 1.2); a value that is present but not shown is `missing-element` owned by the builder; a footer without the link is `missing-element`.
  Inputs: ruleset `provider-id-by-country.json`; `legal` keys per the cross-cutting edits. Missing inputs: no `business.json` → required-facts finding naming `business.json`. Owner WP-606(c).

**3 — ux · UX-023 (Must)**
- **UX-023** · P0 · html, cfg — Commercial terms oracle (no invented return, delivery, warranty, trial or service-level promises). `business.json` `terms`: `{ returns?: { windowDays, free? }, refunds?: { processingDays }, warranty?: { months }, guarantee?: { days }, shipping?: [{ id, region, minDays, maxDays, free?, freeOver?: { amount, currency } }], trial?: { days, cardRequired }, cancellation?: { noticeDays, anytime? }, support?: { responseHours }, sla?: { uptimePercent } }`. Part `claims` (P0 · html): on public pages (raw-HTML visible text outside programmatic family pages and `factsIgnore` regions, policy pages `legalPages.returns|shipping|terms` included), each match of ruleset per-locale `term-patterns.json` (`[{ id, kind, regex }]`; named groups `n` and optional `amount`; kinds `returnWindow`, `refundDays`, `warrantyMonths`, `guaranteeDays`, `shippingDays` (range `n`-`m`), `freeShippingOver`, `trialDays`, `noticeDays`, `responseHours`, `uptimePercent`, and boolean kinds `freeReturns`, `freeShipping`, `noCardRequired`, `cancelAnytime`) is compared by value (CLDR number parsing as UX-003; weeks/months converted by the pattern's `unit`) with the matching `terms` entry; a mismatch is a `value-mismatch` finding naming both values; a boolean kind needs the matching `true` flag. A match whose kind's `terms` key is absent is a blocking `forbidden-value` finding (facts-oracle rule, 04 § 1.2). A price inside a `freeShippingOver` match is judged by this rule, not UX-003 `prices`. Part `minimum` (P1 · cfg, `eu-consumer` or `uk-consumer`, `ecommerce` in kinds): `terms.returns.windowDays` is declared and ≥ 14 (CRD Art. 9; CCR 2013 reg. 29), else operator-owned `missing-element`. Policy: none. Missing inputs: no `terms` key and nothing detected → `notApplicable`. Owner WP-609(a).

**4 — security · SEC-074 (Must)**
- **SEC-074** · P0 · http — Property-level exposure (OWASP API3:2023). Judged over every JSON response recorded for `api`-surface routes, `auth: required` routes and flow-recorded requests, for each probed account. Part `sensitive` (P0): no object, at any depth, has a property whose name (case-folded, `_`/`-` removed) is in ruleset `sensitive-properties.json` (`password`, `passwordhash`, `passwd`, `hash`, `salt`, `secret`, `apikey`, `privatekey`, `resettoken`, `verificationtoken`, `refreshtoken`, `sessiontoken`, `totpsecret`, `otpsecret`, `ssn`, `taxid`, `cardnumber`, `cvv`, `stripesecret`, `webhooksecret`, ...) with a non-empty value, unless the response schema in the signed contract declares that property for that operation and the route policy is `owner` (the requesting account's own object). Part `other-account-pii` (P0): for each pair of accounts A, B in different tenants, no response to B contains A's seeded e-mail (`SHIPGATE_ACCT_<A>_EMAIL`, raw, JSON-escaped or percent-encoded), phone, or `account` id inside a string value, except where the route's `roles` include B's role. Part `undeclared` (W): a response property missing from a contract schema that allows additional properties. Findings `leak`, showing the route, JSON path and (masked) value. Missing inputs: no contract → part `sensitive` runs without the exemption; fewer than two tenants in `verifyEnv.auth.accounts` → part `other-account-pii` is `notConfigured(verifyEnv.auth.accounts: second tenant)`, owner `operator`. Read-only stage (it reuses recorded responses). Owner WP-607(a).
