# Decisions

Decisions taken during the spec audit and the build. Settled product decisions are in the `SPEC.md` decision log; these are the orchestrator's calls within it. Newest last.

## 2026-10-21 — round 06

- **D-001 Budget exhaustion (04 § 8).** Adopt the auditor's default (concreteness-algorithms #3): unfinished gates are `BLOCKED(budget)` owned by `operator` only when no earlier run on the same lock finished those gates within budget; otherwise they're owned by `builder` (the app got slower). Why: an operator-owned budget block gives a handoff, so a slow app would let an agent stop with G4–G9 unrun. Consistent with the decision-log principle that agents can't self-grant reduced verification.
- **D-002 Cache keys and the definition-of-done run (04 § 15–16).** Adopt the auditor's default (concreteness-algorithms #32): environment hash = SHA-256 of JCS of OS, arch, verify-env hash, resolved service env (secrets hashed), browser and database engine versions and CI detection; the definition-of-done run is any `verify` without a partial cause; a sealed PASS is never built from cached gate results of a different environment hash.
- **D-003 CSRF and SameSite (SEC-024).** Adopt the auditor's default (concreteness-security #16): requests whose session cookie is `SameSite=Strict`, or `Lax` for non-GET requests, are judged by the browser's cookie withholding, plus the Origin/`Sec-Fetch-Site` replay; header-auth sessions are excluded. Source: OWASP CSRF Prevention Cheat Sheet.
- **D-004 Session lifetime maxima (SEC-064).** Adopt the auditor's default (concreteness-security #31): ruleset `session-lifetimes.json` per project kind, defaults from NIST SP 800-63B-4; strictest over `project.kinds`; the Operator may set stricter values in `security.session`.
- **D-005 Operator questions.** None of D-001…D-004 contradicts the decision log, so per ORCHESTRATOR_PROMPT's decision policy they are the orchestrator's to take, not the Operator's.

## 2026-10-22 — round 09 and the start of the build

- **D-006 Stage 0 closed without a GO round (Operator).** The Operator asked for one solo pass over the current contradictions, then the build. Why: three whole-spec rounds cut vagueness slowly (404 → 274 → 245) and didn't cut contradictions (135 → 113, Blockers 4 → 11) because parallel fixers created new seams. The remaining gaps are found where they matter, by each WP's fixture author (an undecidable fixture is a spec gap, fixed before the WP continues), plus one Opus escape-path audit per phase.
- **D-007 Orchestration, not a solo build.** The orchestrator (Opus) builds WP-000 itself (machinery only, no rule fixtures) and drives every later WP through card → fixture author (Opus, high) → builder (Sonnet 5.5, high, own worktree) → reviewer holdouts (Opus, high) → gates → merge. Why: BUILD_MAP § 4.1 item 3 needs the test writer to differ from the builder, and ~100 WPs don't fit one context; the orchestrator keeps the plan, the contract files and the verification.
- **D-008 Licence allow-list detail.** `deny.toml` allows the spec 05 § 8 licences plus `Apache-2.0 WITH LLVM-exception`, which only adds permissions to Apache-2.0 (common in the Rust ecosystem). Workspace crates are `publish = false` and are not judged.
- **D-009 WP-000 `shipgate` binary.** WP-000 ships `version` and `rule --list [--json]` only, because trace-check reads the registry from the binary for every WP; with no rule implemented the honest registry is empty (`{"formatVersion":1,"ruleset":null,"rules":[]}`). Every other command exits 3 as unknown. WP-208 replaces this with the full command tree.
- **D-010 First ruleset locale set.** Every per-locale ruleset file covers 20 locales: ar, cs, da, de, en, es, fi, fr, it, ja, ko, nb, nl, pl, pt, ro, ru, sv, tr, zh (the largest web languages plus the EU languages covering most of the EU population). A page in another locale gets the 04 § 15 *No entry* outcome (operator-owned, blocking); later rulesets add locales. Gazetteers cover 34 countries, popular-package lists 8 ecosystems (SEC-053), foundation recipes the 19 framework adapters of 02 § 5 (`xtask/tests/wp_104.rs`).
- **D-011 Phase 1 outputs and where they live.** WP-101 records host payloads under `crates/sg-hooks/tests/host-payloads/<host>/` (`manifest.json` when observed live, else `unverified.json` with a reason; WP-306/803 conformance tests reuse them). WP-102 writes `toolchain/manifest.json` (03 § 19) and `toolchain/unavailable.json` (component × platform with no build, with the spec fallback). WP-103 adds the hidden `shipgate dev grammar-probe` (05 § 1) and `rules/grammar-tiers.json`. WP-104 writes `rules/**` and `rules/provenance.json`. Shape validation of every ruleset file is WP-206's typed loaders.
- **D-012 WP-102 open points.** Decided in `wp/WP-102/decisions.md`: npm tools install from pinned lockfiles (WP-401); per-package registry fetch replaces the nonexistent bulk deprecation/publish-time snapshots; `CDLA-Permissive-2.0` (webpki-roots) added to `deny.toml`; the WordPress vulnerability feed is BLOCKED on an Operator API key.
