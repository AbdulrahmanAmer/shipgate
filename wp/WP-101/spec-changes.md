Observed on the build machine, Windows 11 x64, 2026-10-22. Evidence lives in `crates/sg-hooks/tests/host-payloads/<host>/` (file names below are relative to that directory). The fenced blocks carry the exact replacement rows. Each block's first line says which table it replaces rows in; a row is replaced where its first cell matches.

Hosts: Claude Code 2.1.296, Codex 0.162.1 and OpenCode 1.19.3 were observed live. Cursor was not installed (`cursor/unverified.json`). ## 1. 03 § 16 *Host mappings*

Intro line: change "(to be confirmed by WP-101, which updates this table and 05 § 3.3 statuses)" to "(confirmed by WP-101 on 2026-10-22 for `claude-code`, `codex` and `opencode` against recorded payloads in `crates/sg-hooks/tests/host-payloads/`; `cursor` and `antigravity` rows are docs-derived and unconfirmed, 05 § 3.3)".

```md target=03:mapping
| `claude-code` | `hook_event_name`: SessionStart → session-start; UserPromptSubmit → prompt; PreToolUse → pre-tool; PostToolUse → post-tool; Stop → stop | `tool_name`: `Edit`, `MultiEdit`, `NotebookEdit` → edit; `Write` → write; `Bash`, `PowerShell` → shell; `Read`, `Grep`, `Glob` → read; `WebFetch`, `WebSearch` → fetch; `mcp__*` → fetch when listed in ruleset `fetch-tools.json`, else mcp; else other | `paths` from `tool_input.file_path`, `tool_input.notebook_path`, `tool_input.edits[].file_path`, and for `Grep`/`Glob` `tool_input.path` when present; on Windows these are absolute (backslashes from `Read`/`Write`/`Edit`, forward slashes from `Grep`/`Glob`) and normalised per § 1; `command` = `tool_input.command` (`Bash` and `PowerShell`); `prompt` = `prompt`; `fetched`: WebFetch `{ url: tool_input.url, kind: "web-fetch", text: tool_response.result }`, WebSearch `{ url: "search:" + tool_input.query, kind: "web-search", text: the string items of tool_response.results, then one "title — url" line per item of the content arrays in tool_response.results }`, `fetch-tools.json` tools `kind: "browser"` | `session_id`; `stop_hook_active` |

| `opencode` | `tool.execute.before` → pre-tool; `tool.execute.after` → post-tool; `session.idle` → stop (the plugin's `event` hook receives `{ type: "session.idle", properties: { sessionID } }`) | `tool`: `edit`, `patch` → edit; `write` → write; `bash` → shell; `read`, `grep`, `glob`, `list` → read (observed tools: `read`, `write`, `edit`, `bash`, `grep`, `glob`, `webfetch`; a directory is listed with `read`; `patch` and `list` were not seen); `webfetch` → fetch; else other | the generated plugin builds `{ event, tool, args, output, sessionID }` and writes it to stdin: `args` = the `output.args` object of `tool.execute.before` and the `input.args` object of `tool.execute.after`; `output` = the `output.output` string of `tool.execute.after`; `sessionID` = `input.sessionID`; `paths` from `args.filePath` (and `args.path` of `grep`/`glob` when present); `command` = `args.command`; `fetched`: `{ url: args.url, kind: "web-fetch", text: output }` | `sessionID`; `false` |
```

Evidence: `claude-code/` (21 payload files), `codex/` (6), `opencode/` (14). Differences from the old rows, each with its evidence file:

- **Claude Code `WebFetch` text.** Old row: `text: tool_response`. Observed `tool_response` is an object `{ bytes, code, codeText, result, durationMs, url }`; the text is `tool_response.result` (`claude-code/PostToolUse__WebFetch.json`).
- **Claude Code `WebSearch` text.** Observed `tool_response` is `{ query, results: [ { tool_use_id, content: [ { title, url } ] }, "<answer text>" ], durationSeconds }`; there is no single text field (`claude-code/PostToolUse__WebSearch.json`).
- **Claude Code `PowerShell` tool (NEW).** On Windows Claude Code has a second shell tool, `tool_name: "PowerShell"`, with `tool_input.command` and the same `tool_response` shape as `Bash`. The old table maps only `Bash`, and the old 05 § 3.3 matchers list only `Bash`, so a PowerShell command would be neither gated nor seen (`claude-code/PreToolUse__PowerShell.json`, `claude-code/PostToolUse__PowerShell.json`). Fixed above and in the 05 § 3.3 Events cell.
- **Claude Code `Write`/`Edit`/`Read` paths** arrive as absolute Windows paths with backslashes; `Grep`/`Glob` `tool_input.path` is whatever the model wrote (forward slashes seen) and is optional.
- **Codex shell tool name.** The Windows shell tool is PowerShell, yet the hook payload says `tool_name: "Bash"` (`codex/PreToolUse__Bash.json`, `command` = `Get-Content -LiteralPath .\sample.txt`). A single `apply_patch` call carried both an `*** Add File:` and an `*** Update File:` header (`codex/PreToolUse__apply_patch.json`). `PostToolUse` `tool_response` is a plain string (`Exit code: 0 …` for `apply_patch`, the raw stdout for `Bash`).
- **OpenCode.** `args` arrives as `output.args` in `tool.execute.before` and as `input.args` in `tool.execute.after`; the idle event comes through the `event` hook, not a hook named `session.idle`. Only the tools listed above were seen (`opencode/*.json`).
- **Not observed (UNPROVEN):** Claude Code `MultiEdit`, `NotebookEdit`, `mcp__*`; Codex `apply_patch` `*** Delete File:` / `*** Move to:` headers, and any web/MCP tool; OpenCode `patch`, `list` and any MCP tool.

## 2. 03 § 16 *Hook output*

Observed (all `took-effect`): Claude Code and Codex answered the pre-tool event with the `permissionDecision: "deny"` JSON below, the shell command was not run, and the model was shown the reason (`claude-code/deny-evidence.json`, `codex/deny-evidence.json`). Both answered the first Stop with the `decision: "block"` JSON; the agent started another turn (second Stop has `stop_hook_active: true`) and created the file the reason asked for (`claude-code/block-evidence.json`, `codex/block-evidence.json`). `{}` was accepted as the allow output on `PreToolUse` and `Stop`, and `additionalContext` from SessionStart, UserPromptSubmit and PostToolUse reached the model on both hosts (`claude-code/context-evidence.json`, `codex/context-evidence.json`). OpenCode: a throw in `tool.execute.before` stopped the command and the model was shown the thrown text (`opencode/deny-evidence.json`); a message sent from the idle handler started a new turn only in a long-lived OpenCode process (see the next paragraph).

```md target=03:output
| `codex` | exit 0, stdout `{}` | pre-tool: exit 0, stdout `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"<text>"}}`; stop: exit 0, stdout `{"decision":"block","reason":"<text>"}` (Codex continues with `reason` as a new user prompt) | exit 0, stdout `{"hookSpecificOutput":{"hookEventName":"<SessionStart\|UserPromptSubmit\|PostToolUse>","additionalContext":"<text>"}}` |
| `opencode` | the generated plugin returns normally | `tool.execute.before`: the plugin throws `Error("<text>")` (the model is shown `<text>`); `session.idle`: the plugin calls `client.session.promptAsync({ path: { id: sessionID }, body: { parts: [{ type: "text", text: "<text>" }] } })` and the host answers 204 | the same `promptAsync` message (only the idle path was observed; a `tool.execute.after` message was not tried) |
```

The `claude-code` row of this table is unchanged (every cell was observed as written). The `cursor` and `antigravity` rows are unchanged and unconfirmed.

**OpenCode idle follow-up (differs from the old assumption).** `opencode run` (one-shot) exits at the first `session.idle`; the follow-up message is created (HTTP 204) but no model turn follows (`opencode/block-evidence.json`, `headlessRun`). The same plugin against `opencode serve` plus `opencode run --attach` (a process that outlives the client) ran the follow-up turn and wrote the requested file (`persistentHost`). So the stop block holds in the OpenCode TUI/server and not in `opencode run`.

Other spec text to change with the matrix:

- 05 § 3.3 Invariants: "shipgate converts its own crashes/timeouts into the host's explicit deny where possible" cannot rely on the host: a hook that exceeds the host timeout is killed and the call proceeds on Claude Code and Codex (`claude-code/timeout-evidence.json`: hook with `timeout: 2` slept 8 s, was killed, the command ran; `codex/timeout-evidence.json`: same). The shipgate hook must time itself out (the 5 s `pre` budget already does) and answer deny before the host's timeout.
- 05 § 3 "Host detection": CLI names `claude`, `codex`, `opencode` exist on PATH here. `cursor-agent` and `antigravity` were not on PATH (Antigravity installs `%LOCALAPPDATA%\Programs\Antigravity\Antigravity.exe` without adding it to PATH), so the project-directory test (`.agents/`) is the only detection for it on Windows.
- 05 § 3.3 Claude Code: the old "default timeout 60 s" is wrong against the current docs and the installed version (docs: 600 s; 30 s for UserPromptSubmit). Source: https://code.claude.com/docs/en/hooks. Not observed live (a default-length timeout was not waited out); an explicit `timeout: 2` was observed to kill the hook.
- 05 § 3.3 Codex: the old "`features.hooks`" prerequisite is not needed (docs: hooks are on by default; `features.hooks = false` disables them). Hook trust is what gates execution (`codex/trust-evidence.json`). Source: https://developers.openai.com/codex/hooks (redirects to https://learn.chatgpt.com/docs/hooks).

## 4. Not delivered

- `cursor`: not observed. Needs the Cursor CLI/app installed and signed in.
- `antigravity`: not observed, BLOCKED (no headless entry point). Needs a headless CLI/SDK, or GUI automation of the signed-in IDE.
- OpenCode 2.x: no hook API to observe; the spec must decide whether to support only the 1.x line or to wait for a 2.x hook API.
- Not exercised on any host: exit-code-2 fallback (Claude Code), `additionalContext` on `PreToolUse`, hook payloads for MCP tools, the `failClosed`/error behaviour of a hook that exits non-zero without JSON.
