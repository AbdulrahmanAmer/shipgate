# WP-104 part b: spec problems and proposals

Each item: the spec line, what I observed, what I wrote in `rules/`, and the change I propose. Nothing here was worked around silently; the file contents follow the proposal where the spec is silent.

1. **`secret-patterns.json` has `formatVersion`; 03 § 1 says `rules/**` has none.** 04 § 13 (SEC-050 secret scan) gives the shape `{ formatVersion, patterns: [{ id, provider, regex }] }`; 03 § 1 exempts `rules/**` from `formatVersion`. I wrote `formatVersion: 1` in this one file (04 § 13 is the file's own definition). Proposal: drop `formatVersion` from the 04 § 13 shape, or list `secret-patterns.json` as the one ruleset with it.
2. **`live-key-prefixes.json` has no shape.** BUILD_MAP WP-104 and `trace/ownership.tsv` name it; CFG-004 and SEC-042 describe the patterns but no file shape. I wrote `[{ provider, kind: "literal"|"regex", pattern }]` (same as `payment-test-markers.json`): Stripe `sk_live_`, `rk_live_`, `pk_live_`, AWS regex `AKIA[0-9A-Z]{16}`, Paddle `pdl_live_apikey_`. PayPal live client ids are not included: PayPal's documentation shows no distinguishing prefix. Proposal: state this shape in CFG-004.
3. **`a11y-overlays.json` has no shape.** A11-018 says "no host in ruleset `a11y-overlays.json`". I wrote `[{ vendor, host }]`, `host` per 03 § 3.3. Proposal: state it in A11-018.
4. **`write-apis.json` cannot express two shipped entries.** 05 § 3.2: `host` is a 03 § 3.3 host pattern (DNS name or `*.name`), but the WordPress REST entry (any host, `/wp-json/`) and "any URL whose path is `/ping` with a `sitemap=` query parameter" have no fixed host, and the shape has no query field. I wrote `host: "*"` for both and added `queryPattern` (Rust regex over the query string) to the sitemap-ping entry. Proposal: allow `host: "*"` and `queryPattern?` in the 05 § 3.2 shape.
5. **`auth-bypass-headers.json` `rewrite` entries need a path placeholder.** SEC-021 says `X-Original-URL` / `X-Rewrite-URL` are "set to the protected path". I wrote `value: "{path}"`. Proposal: state the `{path}` placeholder in SEC-021.
6. **`weak-hash-apis.json` `ecosystem` values are undefined.** SEC-027 gives `{ ecosystem, call }` without the id set. I used the package-ecosystem ids of 03 § 15 (`npm`, `pypi`, `composer`, `rubygems`, `maven`, `go`, `nuget`, `cargo`), with `call` the callee text. Proposal: state the id set in SEC-027.
7. **`runtime-pins.json` covers runtimes only.** OPS-009 also requires the package manager pinned exactly (`packageManager` field, lockfile version) and OPS-015 judges "runtime and package-manager versions", but the file shape is `{ <runtime>: { identity, sources } }` with `identity` only defined for node, python, ruby, go, php. I shipped those five. `.nvmrc` aliases (`lts/*`, `node`) do not parse to a version (the `extract` capture is the alias text). Proposal: define package-manager keys (`pnpm`, `yarn`, `bun`, `npm`) and an `identity` for them, and say what a non-numeric capture means. The `file` globs use `{a,b}` alternation (`*.{yml,yaml}`); the spec does not define the glob grammar for this field.
8. **Cargo.lock names crates.io by its git index URL.** SEC-053 `registry` compares the resolved URL host to `registries.json`. For crates.io, Cargo.lock records `registry+https://github.com/rust-lang/crates.io-index` even when the sparse protocol is used (cargo reference, registry-index). Putting `github.com` in the cargo list would let any GitHub-hosted registry through, so `registries.json` has `index.crates.io`, `crates.io`, `static.crates.io` only. Proposal: SEC-053 says the loader maps that exact source string to crates.io. Also: composer.lock `dist.url` for GitHub-hosted packages points at `api.github.com` (redirects to `codeload.github.com`), so both are listed under `composer`; the `git` source type is still a finding by type.
9. **`takeover-fingerprints.json`: the spec's Heroku example is not an upstream fingerprint.** SEC-059 lists `herokucdn.com/error-pages/no-such-app`; can-i-take-over-xyz has `No such app` for Heroku. I confirmed the spec string against a live unclaimed `*.herokuapp.com` response (`<iframe src="https://www.herokucdn.com/error-pages/no-such-app.html">`) and shipped it. Upstream entries that are generic 404 text, NXDOMAIN-only or HTTP-status-only are not shipped (no body substring to match).
10. **`object-storage-hosts.json` path-style regional S3.** SEC-079 lists `s3.amazonaws.com` as the path-style pattern; `s3.<region>.amazonaws.com/<bucket>` is also a real path-style form and matches neither listed pattern. Not added (spec lists the shipped entries). Proposal: add `s3.*.amazonaws.com` as path-style.
11. **`mass-assignment-fields.json` `permissions`.** The type set is `string|bool|id|role|number`; `permissions` is normally an array. I typed it `string` (value `sg-ma-{n}`). Proposal: add an `array` type or accept this.
12. **`ci-hardening.json` check ids.** SEC-066 gives the shape `{ provider, fileGlob, check, pattern }` without the id vocabulary. I used `provider` ∈ `gitlab-ci`, `circleci`, `bitbucket-pipelines` and `check` ids `unpinned-include-ref`, `untrusted-variable-in-script`, `volatile-orb`, `unpinned-pipe`. No Azure Pipelines or Jenkins entries (no source fetched). Proposal: name the provider and check ids in SEC-066.
13. **`install-script-flags.json` `jsonPath` for YAML.** SEC-053 gives `jsonPath`, but `pnpm-lock.yaml` is YAML (JSON path applies after YAML parse). Whether lockfile v9 keeps `requiresBuild` under `packages` or `snapshots` was not confirmed (the v8 types have it on package entries; the v9 key-order table still lists it), so both paths are shipped.
