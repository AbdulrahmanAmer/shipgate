# Pack: ux

> Whether the site actually works for the person using it: every form reaches someone, every control does something, every fact matches the business, error pages look like the site, and measurement fires. Applies to `public` and `app` surfaces. Business facts come from the Operator-owned `quality/data/business.json` (03 § 14); this pack never decides which facts are true, only that pages match the file.

---

## 1. Policy section

```jsonc
"ux": {
  "formsNotCritical": [],          // [{ route: pattern, selector }] forms/controls exempt from UX-001 (e.g. site search, filters)
  "egressStubs": {},               // { host: { status, body } } stub reply for every request to that host, server-side and in the browser, for the whole run (04 § 4.6; also model-provider hosts); a host named only in an expectEgress step, or a model host without an entry, answers 200 {}; status integer 100–599, body string (sent verbatim) or JSON value (serialised)
  "contactPath": null,             // e.g. "web:/contact"; no default (UX-004 contact part is notConfigured without it)
  "factsIgnore": [],               // [{ route: pattern, selector? }] regions UX-003/013/014/023/027 don't read (e.g. third-party listings, product grids); without `selector` the whole matching route
  "chromeVariants": [],            // route patterns whose header/footer may differ from the rest of their service (UX-016), e.g. "web:/checkout/**"
  "socialProofSources": [],        // UX-020: [{ widget: <`social-proof-widgets` entry id>, route?: pattern, source: { hosts: [host] } | { db, query } }]; no default
  "stockSources": [],              // UX-020 `stock`: [{ route: pattern, dataset: { family, field } | feed: { field } | db: { db, query } }]; no default; `feed` reads search-engines `merchantFeed`
  "baseline": "widely",            // UX-008 target: "widely" | "newly" | Baseline year (integer 2015–current year, e.g. 2024)
  "nightlyBrowsers": ["firefox", "webkit"],   // UX-007; subset of chromium, firefox, webkit
  "analyticsMatchers": {},         // { host: { pageView: { pathMatches?, bodyContains? }, eventParam, idParam?, libraryIdParam?, idPattern? } } replaces the `analytics-vendors` entry for that host (UX-010, UX-025, § 3)
  "creditsPath": null,             // UX-024 `attribution`: route pattern (no wildcards) of an image-credits page linked from the page-level footer; null = attribution must be on the page itself
  "trackingIds": [],               // UX-025: [{ host: <host typed: a hosts[] entry with purpose analytics or advertising>, ids: [string] (≥ 1) }]; no default
  "searchProbe": { "maxForms": 3 } // UX-026: search forms probed per service (integer 1–20)
}
```

Validation (CFG-006 (b)): a `stockSources` entry with `feed` while the search-engines pack is off or `search-engines.merchantFeed` is unset is a `schema-violation` finding naming the entry; an `analyticsMatchers[host].pageView` with neither `pathMatches` nor `bodyContains` is a `schema-violation`; every `pathMatches` and `idPattern` compiles as a Rust regex; a `socialProofSources` entry with `source.hosts` whose `widget` ruleset entry has neither `hosts` nor `selectors` is a `schema-violation`; an out-of-range `baseline`, a `nightlyBrowsers` name outside the three, an `egressStubs` `status` outside 100–599, a `searchProbe.maxForms` outside 1–20, or a `trackingIds` entry whose `host` has neither purpose `analytics` nor `advertising` or whose `ids` is empty is a `schema-violation`.

Business facts: `quality/data/business.json` (03 § 14), signed with the lock. Visual comparison settings (`viewports`, `masks`, `maxDiffRatio`) are the refactor pack's `visual` section, with its defaults when that pack is off. UX-002 and UX-011 are unassigned: placeholder residue is owned by MET-011 and external links by LNK-006 (web-delivery).

## 2. Rules — `UX-*`

- **UX-001** · P0 · cfg, browser — Every form is proven to reach its destination. **Forms** = each `<form>` in a same-origin document of a sampled public page or an `app` page reached by a flow that has a submit control (`button` without `type` or with `type=submit`, `input[type=submit|image]`, or a control whose `form` attribute names it) or a `method` other than `get`, except a `<form>` whose `method` is absent or `get` and whose `action` is non-empty and not `#` or `javascript:` (a plain navigation form; UX-026 judges search and filter forms). A `<form>` without `action` that has a submit control is therefore a form whatever its `method`; site search and filters are exempted through `formsNotCritical`. Forms also include each visible (§ 3 *Visible element*), enabled `button` or `role=button` element outside any `<form>`, anywhere in the document, whose activation in the control click probe (UX-006) issues a non-GET request with a body (submit-driven fetch). Each form is either matched by an entry in `formsNotCritical` (route pattern + CSS selector matching the form or button), or submitted by ≥ 1 flow (a `click`/`press` step on a control inside the form, or on the button) followed, before the flow's next `goto`, by an outcome step: `expectEmail` (SMTP sink), `expectEgress` to a host in `hosts[]` with `server: true` or `browser: true` (CRM/form provider), or `expectDb`. Forms submitted only by the `verifyEnv.auth` login flow are covered by the auth strategy. A form neither exempt nor submitted is a `missing-element` finding (part `main`) showing the route and the form selector. Part `cfg` (P0 · cfg): every `formsNotCritical` selector parses, every `expectEgress` host is in `hosts[]`, every `expectDb` database is declared. Remote services: only with `nonProduction: true`, where `expectApi` or a browser-recorded `expectEgress` also count as outcomes (sink, egress proxy and database aren't observable); otherwise part `main` is `notConfigured(nonProduction)` and the forms are listed. `remote: write`. Form coverage of the testing pack points here (TST-010). Part `mobile` (P1 · cfg, browser; evaluated after the G6 form discovery of part `main`, and `blocked(prerequisite: G6)` when G6 did not run or is `BLOCKED`, as UX-022): each *form identity* found by part `main` is submitted by ≥ 1 flow whose `viewport` (03 § 10) is `mobile` or `tablet`, and for every flow with `journey` `checkout` or `signup` and `viewport` `desktop` another flow with the same `journey` and `viewport: "mobile"` exists; each gap is a blocking `missing-element` finding owned by `operator` (flows are Operator-owned, 01 § 5.2) naming the form identity or flow id. A *form identity* is the route group id (04 § 10) of the page the form is on, the uppercase request method and the path of the `<form>` `action` (empty or absent `action` → the page path), or, for a button outside a form, the method and path of its observed submit request; a flow submits a form identity when its submitting step (above) resolves to it. Findings name the form identity and a gap flow id.
- **UX-003** · P0 · html — Business facts oracle: on public pages (raw HTML visible text plus `tel:`/`mailto:` hrefs, outside programmatic family pages and `factsIgnore` regions), every detected fact of a kind whose key is present in `business.json` matches the file. Part `phones`: a phone candidate's E.164 form equals a `phones[].e164`, `locations[].phone`, `legal.host.phone` or `legal.grievanceOfficer.phone` value (PRV-030 and PRV-033 require the last two on pages). Email candidates (case-folded) equal an `emails` value or a `manufacturers[].contact`, `manufacturers[].euResponsible.contact`, `legal.dpo.email` or `legal.grievanceOfficer.email` value (PRV-025, PRV-033 and PRV-035 require those on pages); price candidates equal a `prices[]` entry; a rating candidate (ruleset `ratingPatterns`, § 3) with `value` v, `best` b (default 5) and optional `count` c equals a `ratings[]` entry when v/b = the entry's `value`/`best` (default 5) as decimals and, when c is present, c = the entry's `count`; a candidate with only a count equals the `count` of any entry; numeric claims (ruleset `claimPatterns`, § 3) equal a `claims[].value` or `founded`. A detected fact not in the file is a `forbidden-value` finding showing the candidate text and the nearest file values. A present but empty array allows none. **Candidates:** phone — spans found in visible text (§ 3) by libphonenumber `PhoneNumberMatcher` (leniency `VALID`, default region of 04 § 15 *E.164 normalisation*) plus every `tel:` href; an unbroken digit run (no space, `-`, `.`, `(`, `)`, `/` or `+`) of 8, 12, 13 or 14 digits whose last digit is a valid GS1 check digit is a product code, not a phone candidate, unless it is a `tel:` href; likewise a span that lies inside an occurrence (privacy § 1 *Fact containment*) of a `business.json` `legal.registerNumber`, `legal.vatId`, `legal.mailOrderNumber`, `legal.icpNumber`, `legal.psbNumber`, `legal.cnpj` or `legal.abn` value, or that equals, digits only, the `id` or `gtin` of a `search-engines.merchantFeed` item when that feed is an Operator-owned source (03 § 8), is not a phone candidate unless it is a `tel:` href (JSON-LD `gtin*`, `mpn` and `sku` never exempt a span: the agent writes them, 03 § 8); e-mail — matches of `[A-Za-z0-9._%+-]+@[A-Za-z0-9-]+(\.[A-Za-z0-9-]+)*\.[A-Za-z]{2,}` in visible text plus every `mailto:` address (query string dropped); price — a number in the CLDR decimal pattern of the page locale (04 § 15 page locale; digits of any numbering system), separated by at most one space or NBSP from a currency symbol, narrow symbol or ISO 4217 code of the CLDR currency data; a symbol stands for every currency CLDR assigns it (`$` → USD, CAD, AUD, …), and the candidate equals a `prices[]` entry when the amounts are equal as decimals and the entry's `currency` is in that set. Spans inside a UX-023 term match are judged by UX-023 only. A detected fact of a kind whose key is absent, or any detected fact without a `business.json`, is a blocking finding (04 § 1.2 facts-oracle rules): numbers on a page must come from the Operator's facts, never from the agent. **Ownership:** when LOC-001 applies (search-engines pack enabled and `business.json` `locations` non-empty), phone numbers, addresses and hours on indexable pages (04 § 15 indexable) belong to LOC-001 (rule metadata: LOC-001 `owns` UX-003 part `phones` there), so part `phones` is not evaluated on indexable pages and is evaluated on every other public page; otherwise UX-003 checks phone numbers and never addresses or hours. Placeholder residue: MET-011; facts on programmatic pages: the programmatic oracle; qualitative claims: UX-013.
- **UX-004** · P1 · html — Contact paths work on mobile: every visible occurrence on a public page of a phone number or email from `business.json` sits inside `<a href="tel:<e164>">` (the exact E.164 value) or `<a href="mailto:<address>">`. A *visible occurrence* is a UX-003 phone or e-mail candidate in visible text (§ 3) whose E.164 form (or case-folded address) equals a `phones[].e164`, `locations[].phone` or `emails` value; one not inside such a link is a `missing-element` finding showing the text and the expected href. Part `links`: the `tel:`/`mailto:` check above. Part `contact-path`: with `contactPath`, every public page links to it from inside `<header>` or `<footer>` (or `role="banner"`/`"contentinfo"`); without `contactPath` the part is `notConfigured(contactPath)`.
- **UX-005** · P1 · html — Error pages use the site: for each service with `public` or `app` surfaces, the 404 response to each RTE-004 Unknown-URL probe (`/sg-{n}` and `/{p}/sg-{n}`, web-delivery RTE-004), the 404 response to each RTE-006 probe URL (`sg-probe-404` params), and each 5xx HTML response produced by fault injection (04 § 4.5; requests with `Accept: text/html`) contain an `<a>` whose `href`, resolved against the response URL and normalised (04 § 10), has the path of the service mount root or, when the response URL's first path segment after the mount is a `web-delivery.locales` segment, the path of that locale root, a `<nav>` or `role="navigation"` landmark, and match no fingerprint in the adapter's `errorPageFingerprints` or the ruleset `error-pages` table (framework, server and host default pages). A fingerprint is `{ id, titleRegex?, bodyContains: [string] }`; a response matches when its `<title>` matches `titleRegex` (when set) and its entity-decoded body contains every `bodyContains` string (case-sensitive). Adapter `errorPageFingerprints[]` and the ruleset `error-pages` table share this shape. Failure classes: `missing-element` (link, landmark), `pattern-match` (fingerprint). Status codes themselves are owned by RTE-004/RTE-007.
- **UX-006** · P1 · browser — No dead controls. **Controls** = on sampled public pages and `app` pages reached by flows, every visible (§ 3 *Visible element*), enabled (no `disabled`, no `aria-disabled="true"`, not `inert`) element inside `<header>` or `<main>` that is a `button`, `summary`, `input[type=submit|button|reset|image]` or has `role` `button|link|menuitem|tab`, and is not an `<a>` element on a public page (`<a>` elements on `app` pages are controls here). The control click probe also clicks every other visible, enabled `button`/`role=button` element of the document (inside `<footer>`/`role=contentinfo`, `<aside>`, `<nav>`, dialogs open at load, or in no landmark); those clicks feed UX-001 form discovery and are judged by the dead test like any other control. **Control click probe** (mutating stage, 04 § 4.2 step 8). It runs whenever UX-001, UX-006, MET-011 `dead-anchor` or PRF-002 `probe` applies; PRF-002 measures INP during these clicks: each control is actually clicked once (trusted Playwright click; navigations are recorded, then aborted; the page is reloaded before the next click when the previous one changed it). Event listeners are never consulted — a control whose handler does nothing fails like one without a handler. A control fails when its click is **dead** (04 § 15 *dead control*: within 1 s, none of a navigation, a network request, a DOM mutation outside the element, a focus change, a dialog, or an `aria-expanded`/`aria-pressed`/`aria-selected` change). Controls with native activation behaviour are judged by that effect, never by listeners: `<summary>` passes when its `<details>` toggles `open`; a submit control (`button` without `type` or `type=submit`, `input[type=submit|image]`) or `input[type=reset]` passes when it has a form owner (submission outcome: UX-001), and one without a form owner is judged by the dead test; a control with `popovertarget` or `commandfor` passes when the id resolves and the target's popover or dialog open state changes (custom `--*` commands: the dead test); a control that is or is inside a `<label>` with a labelled control passes when that control gains focus or changes checkedness. `<a>` elements on public pages are owned by MET-011 `dead-anchor` (web-delivery). A dead control is a `missing-element` finding showing the selector and "no effect within 1 s". `remote: write`: on a remote service without `nonProduction: true` UX-006 does not run (`skipped(remote-read-only)`, and the report lists the controls not clicked), and the probe clicks only the `<a>` elements that MET-011 `dead-anchor` judges.
- **UX-007** · P1 · browser — Cross-browser public pages (profile `nightly`): sampled public pages (≥ 1 per route group) pass RTE-013 (no origin script errors, failed same-origin subresources or hydration errors) and A11-017 (no overflowing or covered interactive elements) in each of `nightlyBrowsers`. A11-017 is evaluated at the `accessibility.viewports` widths (default `[320, 768, 1280]`) even when the accessibility pack is off. Flows in other browsers are owned by TST-008.
- **UX-008** · W · build — Built CSS and JS use no web-platform feature beyond `baseline` (web-features data pinned with the ruleset; `"widely"` = Baseline widely available, `"newly"` = newly available, a year = Baseline that year or earlier) unless guarded. CSS: properties, values, at-rules and selectors whose BCD key belongs to a web-features feature; guarded inside a matching `@supports` block, or by a property declared twice with a supported fallback first. JS (oxc): syntax features listed in ruleset `baseline-js-syntax.json` (§ 3), and references to global identifiers and their static members (`structuredClone`, `Array.fromAsync`, `Intl.Segmenter`) whose BCD key belongs to a web-features feature; instance-member calls are not checked. CSS BCD keys are `css.properties.<name>`, `css.properties.<name>.<value>`, `css.at-rules.<name>`, `css.selectors.<name>`; global identifiers and static members map to `api.<Name>` or `javascript.builtins.<Name>[.<member>]` (the first that exists in the pinned BCD data). JS guards: the reference is inside `if ('x' in obj)` or `if (typeof X !== 'undefined')` testing that identifier, or is an optional call `?.()` on it. Excluded: code that the build's source maps (or the adapter `bundleManifest`) attribute to the packages `core-js`, `regenerator-runtime`, `@babel/runtime`, `tslib` or any package whose name contains `polyfill`; code without attribution is checked. Failure class `pattern-match`, showing the feature id, its Baseline status and the file:line.
- **UX-009** · P1 · browser — No unintended visual change: with screenshots in `quality/baselines/_main/visual/`, every route group outside the diff's blast radius matches its `_main` screenshot at each `refactor.visual.viewports` within `refactor.visual.maxDiffRatio`, with `refactor.visual.masks` applied (same comparison as REF-009). **Blast radius** = route groups whose route file (adapter `routes.fileMap`) is in the reverse-import closure of a changed file; a changed `config` or `style` file not reached through imports puts every route group in the radius. Without `_main` screenshots: `skipped(no-main)` with a warning (03 § 12). Services without `routes.fileMap` or an import graph (coverage `behaviour`): `noAdapterSupport`. Refactor runs are owned by REF-009: UX-009 is `notApplicable` when a signed `quality/refactor.json` exists or `--against` is given (REF-009 states the mirror). A differing route group is a `visual-diff` finding showing the viewport and the diff ratio.
- **UX-010** · P1 · browser — Measurement works: when `hosts[]` has an entry with purpose `analytics`, after accepting consent (`privacy.consent.banner.acceptLabel`; no consent step when the privacy pack is off or `consent.required` is false) every sampled public page load sends exactly one page-view hit to each such host (0 = broken, ≥ 2 = double counting; failure class `value-mismatch` showing the count). Observation: for each sampled page, open it in a fresh context, accept consent, then reload; count hits from the reload's navigation start until 2 s after the `load` event or until 500 ms with no network requests, whichever is later (cap 10 s). Without a consent step, count the same window from the first navigation. Conversions: every flow with `conversion: <event>` sends that event to at least one `analytics` host (browser-recorded, or server-side via the egress proxy) before the flow ends; otherwise a `missing-element` finding owned by the builder showing the flow id and event name. Hits and event names are recognised by the ruleset `analytics-vendors` table plus `analyticsMatchers` (shapes and matching: § 3); an analytics host matched by neither is `notConfigured(analyticsMatchers)`. A sampled page on which no control matches `acceptLabel` (privacy pack *Label match*) while the consent step applies is a `missing-element` finding of this rule, shown once per page, and its hits are not counted. Pre-consent behaviour is owned by PRV-001; identifiers in payloads by PRV-010; see also PRV-011.
- **UX-012** · W · html, browser — Finishing touches on public pages: part `manifest` — each sampled public page has `<link rel="manifest">` resolving 200 to JSON with non-empty `name`, `start_url`, `display` and `icons` containing an entry whose `sizes` includes `192x192` and one whose `sizes` includes `512x512`; part `theme-color` — each sampled public page has `<meta name="theme-color">` with a non-empty `content`; part `print` — on each sampled public page, under emulated `print` media, `<main>` has a non-zero `getBoundingClientRect().height` and computed `display` other than `none`.
- **UX-013** · P1 (parts `green` and `regulated` P0) · html — No invented qualitative claims: on public pages (visible text outside `factsIgnore` regions), each match of the ruleset per-locale `claimPhrases` (guaranteed, warranty, certified, licensed, insured, accredited, award-winning, #1, best, leading, 24/7, same-day, free estimate, …) (*Phrase-list matching*, § 3) lies in a sentence (ICU4X UAX #29 sentence segmentation) that contains a `business.json` `claims[].text` (normalised containment: NFKC, case-folded, whitespace collapsed); a match inside a UX-023 term match is judged by UX-023 only. Without `claims`: a found phrase is a blocking finding (04 § 1.2 facts-oracle rules), else `notApplicable`. Part `green` (applies when `privacy.jurisdictions` has an EU consumer jurisdiction — `eu-consumer`, `de` or `at`, as defined in the privacy pack — and the expiry clock (01 § 5.4) is on or after 2026-09-27 — Directive (EU) 2024/825; privacy pack off → `notConfigured(jurisdictions)`): each match of the ruleset per-locale `generic-green-claims.json` (eco-friendly, green, climate neutral, sustainable, …) fails unless its sentence contains the `text` of a claim that has an `evidence` URL. Part `regulated` (P0 · html; any jurisdiction; FTC Act § 5, 16 CFR Part 323, UCPD Annex I No. 17, Regulation (EC) 1924/2006 Art. 10, UK CAP Code s. 12): on the same pages and regions, each match of ruleset per-locale `regulated-claims.json` (§ 3) fails unless its sentence contains the `text` of a `claims[]` entry that has an `evidence` value (absolute URL or repo path, 03 § 14); without `claims` a match is a blocking `forbidden-value` finding (04 § 1.2 facts-oracle rules). A span matched both by `claimPhrases` and by `regulated-claims.json` is judged by part `regulated` only; a match inside a UX-023 term match is judged by UX-023 only.
- **UX-014** · P0 · html — No invented testimonials or people, on public pages outside `factsIgnore` regions. Part `testimonials`: every element matched by the ruleset `testimonial-markers.json` `testimonial` selectors (blockquote/figure, class and aria patterns) and every JSON-LD `Review` node has quote text (marker quote selector, else the element text minus its attribution; `reviewBody`) equal after normalisation (NFKC, case-folded, whitespace collapsed, quotation marks and trailing punctuation stripped) to the `text` of a `business.json` `testimonials[]` entry with `consentedOn` not in the future (01 § 5.4 expiry clock), and attribution (marker attribution selector, `<cite>`, `<figcaption>`; `author.name`, or `author` when it is a string) containing that entry's `author` as a whole-word normalised substring. Part `people`: each visible byline (text of the ruleset `byline.selectors` elements; a `byline.prefixes` entry of the page locale found at the start of the text after NFKC and case-folding is removed, then leading `:`, `-`, `–`, `—` and whitespace are trimmed), each JSON-LD `Person` `name`, and each element matched by the ruleset `team.name` selectors inside a `team` section (§ 3 `testimonial-markers.json`), plus each `h3`–`h6` there that is not matched by `team.name` and whose text does not match the per-locale `team.headings` (section titles such as "Our team", "Meet the team"), equals a `business.json` `people[].name` (normalised). A JSON-LD `Person` that is the `author` of a `Review` node (object with `name`, or a string) is judged by part `testimonials` only and is not read by part `people`. Per part: key absent from `business.json` → a blocking finding when anything is detected (04 § 1.2 facts-oracle rules), else `notApplicable`; a present but empty array allows none. Sources: FTC 16 CFR 465; Google E-E-A-T guidance. Author markup reachability: answer-engines.
- **UX-015** · P1 · browser — Shown price = charged price: in each flow with `journey: "checkout"`, every `markPrice { locator, priceId }` step's located text parses (ICU4X, 04 § 15 page locale) to the `amount` and `currency` of the `business.json` `prices[]` entry `priceId`, and the request later sent to a `hosts[]` entry with purpose `payments` (browser-recorded, or server-side via the egress proxy) carries a line item for it: amount and currency equal (`amount` converted to minor units with the ISO 4217 exponent of `currency`; provider values extracted per the ruleset `payment-amounts.json`, § 3), or a provider price id equal to that entry's `providerId`. A `markPrice` text that is not equal to the entry (or does not parse) is a blocking `value-mismatch` finding owned by the builder showing the step, the located text and the entry. A checkout flow without `markPrice` → `notConfigured(markPrice)`. A provider request that carries a provider price id while the `prices[]` entry has no `providerId` → a blocking `missing-element` finding owned by `operator` naming `prices[<priceId>].providerId` (04 § 1.2 required-facts rules). Otherwise a provider request with no line item that matches either way (including one with neither an extractable amount nor any price id), or no request to a `payments` host between the `markPrice` step and the end of the flow, is a blocking `value-mismatch` finding owned by the builder. No `hosts[]` entry with purpose `payments` while a checkout flow exists → `notConfigured(hosts.payments)`. Server-side tamper resistance: SEC-041. `remote: write`.
- **UX-016** · P1 · html — Consistent site chrome: per service and page locale (04 § 15 page locale), the page-level `<header>` and `<footer>` (the `banner`/`contentinfo` landmarks: not inside `article`, `aside`, `main`, `nav` or `section`, or `role="banner"`/`"contentinfo"`) of every public page have the same masked skeleton hash — 04 § 11 steps 1, 3 and 6 applied to the subtree, after removing `aria-current` attributes and class tokens in the ruleset `chrome-state-classes` list (`active`, `current`, `is-active`, …). The most common hash is the reference (tie → lexicographically smallest); each page that differs is a `skeleton-mismatch` finding, and each page lacking the `<header>` or `<footer>` the reference has is a `missing-element` finding, both showing the first differing node path. Pages matching `chromeVariants` are excluded.
- **UX-017** · W · html — AI-generated imagery in trust contexts is listed for review: same-origin images inside `testimonial-markers.json` `testimonial`, `team` or `byline.selectors` contexts, or referenced as `image` of a JSON-LD `Person`, whose XMP `Iptc4xmpExt:DigitalSourceType` or C2PA `c2pa.actions` `digitalSourceType` is the IPTC `trainedAlgorithmicMedia` or `compositeWithTrainedAlgorithmicMedia` code. Source: AI Act Art. 50(4).
- **UX-018** · W · html — Password reset is reachable: when the page at `verifyEnv.auth.loginPath` contains an `input[type=password]`, it contains an `<a>` whose accessible name matches the ruleset per-locale `password-reset-labels` ("Forgot password?", …) or whose `href` path matches its `password-reset-paths`, and that link answers 200. Login without a password field: `notApplicable`.
- **UX-019** · P0 · html — No invented trust marks or logo walls (UCPD Annex I item 2; uncertified sustainability labels banned in the EU from 2026-09-27; FTC endorsement rules). On public pages:
  - Part `marks`: every element matched by ruleset `trust-marks.json` (certification, review-platform, payment-security, award and sustainability badges, matched by image host, file name, `alt` or perceptual image hash; candidates (raw HTML, this rule's channel) are `img` (its `src` and every `srcset` URL), `input[type=image]` (`src`), `svg` elements containing an `image` child (its `href`), and the `url()` values of `background`/`background-image` declarations in inline `style` attributes, each URL resolved against the page URL and fetched for the hash; a candidate whose image can't be fetched or decoded is matched by host, file name and `alt` only) must be backed by `business.json` `certifications[] { name, issuer, evidence, validUntil? }`. A matched mark passes when a `certifications[]` entry has `name` equal (NFKC, case-folded, whitespace collapsed) to one of the `names` of the mark's ruleset entry, a non-empty `evidence` URL, and `validUntil` absent or not before the expiry clock (01 § 5.4). Entry shape in `trust-marks.json`: `{ id, kind, names: [string], imageHosts: [host], fileNamePatterns: [glob], altPatterns: [regex], dhash: [16-hex] }`; an element matches when its image host is in `imageHosts`, its file name matches a `fileNamePatterns` glob, its `alt` matches an `altPatterns` regex, or its decoded image's 64-bit dHash (9×8 greyscale, Lanczos3) is at Hamming distance ≤ 6 from a `dhash` value. Failure class `forbidden-value` (no backing entry) or `stale` (expired `validUntil`), showing the mark id, the element selector and the image URL.
  - Part `logo-wall`: the region is everything after a heading (`h1`–`h6` or `role=heading`) whose text matches the ruleset per-locale `logo-wall-headings` ("Trusted by", "As seen in", "Our clients", "Featured in", …), up to the next heading of the same or higher level or the end of its sectioning parent. Every `<img>` and inline `<svg>` in it passes when, after NFKC, case-folding and replacing `-`/`_` with spaces, its `alt` (svg: `<title>`) or file-name stem contains a `business.json` `clients[]` or `press[]` `name` (`{ name, url? }`, normalised the same way) as whole words; else `forbidden-value`, showing the image and the heading.

  If the key is absent and something is detected, that's a blocking `forbidden-value` finding (04 § 1.2 facts-oracle rules). The fix is to remove the content or have the Operator supply the facts; TR-112 tells agents this up front.
- **UX-020** · P0 · browser, html, db — No fake urgency or scarcity (UCPD Annex I No. 7, UK DMCC Act 2024, FTC Act § 5). Metadata `gates: [G4]`: the `db` queries of parts `stock` and `social-proof` run in G4's read-only stage (04 § 4.2 step 8) and their integers are compared with the G6 browser reads. *Valid db source* (both parts): every row the entry's `query` reads (tables found with the SQL parser, 02 § 4) is an Operator-owned source (03 § 8 *Operator-owned sources*, the single definition, including seeded rows). An entry whose source is not valid counts as absent (the page is unmapped). The query must return exactly one row with one column whose value is an SQL integer or an integer-valued numeric; anything else is a `value-mismatch` finding showing the returned rows.
  - Part `timer`: each element matched by ruleset `countdown-markers` on a public page is read in two fresh browser contexts with the real (uninstalled) clock: the second read starts ≥ 60 s of wall-clock time after the first (all first reads of the run, then all second reads, so a run waits once). Deadline = the wall-clock UTC time of the read + the remaining duration parsed from the element's visible text by the marker's `format` patterns (named groups `d`, `h`, `m`, `s`); resolution r = the smallest unit shown. `reset`: the two deadlines differ by > r + 2 s (the deadline restarts per visitor). `unbacked`: no `offers[].endsAt` lies within r + 2 s of the first deadline. Both are `value-mismatch` findings showing the selector, both texts and both deadlines. A matched element whose text no `format` pattern parses is a `parse-error` finding. `offers` absent while a countdown is detected → blocking `forbidden-value` (04 § 1.2 facts-oracle rules). The part reads the wall clock, so its outcomes are non-deterministic (TR-103).

JSON-LD `Offer.inventoryLevel` and any other page content are never a source, because the agent writes them. A match on a page that no `stockSources` entry with a valid source covers is a blocking `forbidden-value` finding (04 § 1.2 facts-oracle rules); a covered page whose source yields no integer, or a different number, is a `value-mismatch` finding.

## 3. Implementation notes
- UX-001, UX-006 and PRF-002 `probe` share one control inventory per page, built by the flows engine in G6, so a control is clicked once.
- Ruleset data used here: `error-pages` (UX-005), `ratingPatterns` and `claimPatterns` per language (UX-003), `claimPhrases` per locale, `generic-green-claims.json` and `regulated-claims.json` (UX-013), `testimonial-markers.json` with `testimonial`, `team` and `byline` sections (UX-014/017), `payment-amounts.json` (UX-015), `chrome-state-classes` (UX-016), `password-reset-labels`/`password-reset-paths` (UX-018), `analytics-vendors` (UX-010, UX-025), `placeholder-tracking-ids.json` (UX-025), `no-results-phrases.json` (UX-026), `incentive-disclosure-phrases.json` (UX-027), web-features and `baseline-js-syntax.json` (UX-008), `trust-marks.json` and `logo-wall-headings` (UX-019), `countdown-markers`, `stock-count-phrases` and `social-proof-widgets` (UX-020), `affiliate-disclosure-phrases` (UX-021), `term-patterns.json` (UX-023), `stock-preview-hosts.json` (UX-024).
- **Page locale and per-locale data.** Every "page locale" in this pack, and the entry used from every per-locale or per-language list it names (e.g. `claimPhrases`, `stock-count-phrases`, `term-patterns.json`, `ratingPatterns`, `claimPatterns`, `team.headings`), is as defined in 04 § 15 page locale (lookup and the outcome for a locale with no entry); this pack has no definition of its own. A locale with no entry is therefore never a skip, `notApplicable` or a `reduced-environment` handoff (04 § 15 page locale).
- **Visible text** (html channel): the text nodes of the raw HTML `<body>` outside `script`, `style`, `template` and `noscript`, joined with one space at element boundaries; (browser channel): the element's `innerText`. Regex lists are matched against visible text after NFKC.
- **Phrase-list matching** (literal lists: `claimPhrases`, `generic-green-claims`, `password-reset-labels`, `logo-wall-headings`, `affiliate-disclosure-phrases`, `no-results-phrases.json`, `incentive-disclosure-phrases.json`, `byline.prefixes`, `team.headings`, `claimPatterns` `nouns` and `sincePhrases`): both sides are NFKC-normalised, case-folded and whitespace-collapsed; a phrase matches a text when it occurs in it delimited by UAX #29 word boundaries (for page locales whose language is `ja`, `zh`, `th`, `km`, `lo` or `my`: as a substring). The text scanned is the visible text of the element or page; for a label or heading list it is the element's whole accessible name or text (containment, not equality).
- **Failure classes** (04 § 9.1) of rules whose text doesn't name one: UX-001 `missing-element` (route, form selector); UX-003, UX-013, UX-014, UX-017 `forbidden-value`; UX-004, UX-012, UX-018, UX-021 `missing-element`; UX-006 `missing-element` (selector, "no effect within 1 s"); UX-009 `visual-diff`; UX-016 `skeleton-mismatch` (differing hash) or `missing-element` (header or footer absent). Rules naming a class in their text keep it.
- `analytics-vendors` — `[{ id, hosts: [host], pageView?: { pathMatches?: regex, bodyContains?: string }, eventParam?: string, idParam?: string, libraryPaths?: regex, libraryIdParam?: string, idPattern?: regex }]` (analytics and advertising vendors; `pageView` and `eventParam` are required on entries for analytics vendors, UX-010; `idParam` names the property ID in a hit, e.g. GA4 `tid`, Meta Pixel `id`, Matomo `idsite`; `libraryPaths` (unanchored Rust regex on the path) and `libraryIdParam` name the ID in tag-library loads, e.g. `id` on `/gtag/js` and `/gtm.js`; `idPattern` is the vendor's ID shape for UX-025 `static`, e.g. `\bG-[A-Z0-9]{6,12}\b`, `\bGTM-[A-Z0-9]{5,8}\b`, `\bAW-[0-9]{8,11}\b`, `fbq\(\s*['"]init['"]\s*,\s*['"](?<id>[0-9]{15,16})`); `ux.analyticsMatchers[host]` has the same `pageView`, `eventParam`, `idParam`, `libraryPaths`, `libraryIdParam` and `idPattern` fields and replaces the ruleset entry whose `hosts` match that host. `pageView` needs at least one of its two members (else CFG-006). A request is a page-view hit for an `analytics` host entry when its host matches the entry's `hosts` (03 § 3.3 host matching), its URL path matches `pathMatches` (unanchored Rust regex, when set) and its decoded body contains `bodyContains` (when set). The event E is sent when a request to that host has a parameter named `eventParam` whose string value equals E (case-sensitive), searched in the query string, then a form-encoded body, then a top-level JSON body key.
- `testimonial-markers.json` — `{ testimonial: [{ selector: css, quote?: css, attribution?: css }], byline: { selectors: [css], prefixes: { <locale>: [string] } }, team: { section: [css], headings: { <locale>: [string] }, name: [css] } }`. `quote` and `attribution` are evaluated inside the element matched by `selector`. A `team` section is an element matching a `team.section` selector, or the region after a heading whose text matches `team.headings` (region rule of UX-019 `logo-wall`).
- `payment-amounts.json` — `[{ id, hosts: [host], requests: [{ pathMatches: regex, format: "json" | "form" | "query", items?: jsonPath, amount: field, currency: field, priceId?: field, total?: field, unit: "minor" | "major" }] }]`; a *field* is an RFC 9535 JSONPath (`json`) or a parameter name (`form`, `query`), evaluated relative to each element of `items` (`total`: relative to the body root); without `items` the request is one item. The first `requests` entry of an entry whose `hosts` match the request host and whose `pathMatches` matches the path (unanchored) is used; none matches → the request has no extractable amount. `unit: "minor"` is converted with the ISO 4217 exponent of `currency`.
- `ratingPatterns` — per language `[{ regex }]`, each with named groups among `value`, `best` (default 5 when the group is absent or doesn't participate) and `count`, at least one of `value` and `count` present, matched against visible text (NFKC). `claimPatterns` — per language `{ nouns: [string], sincePhrases: [string] }`: a claim candidate is a number (CLDR number pattern of the page locale, suffixes `k` and `+` as in the UX-003 parsing note at the end of this section) followed by at most one intervening word and a `nouns` entry, or a `sincePhrases` entry followed by a 4-digit year; nouns and phrases match as in *Phrase-list matching*.
- `term-patterns.json` — per locale `[{ id, kind, regex, unit? }]`; `kind` is one of the UX-023 kinds; each regex has named group `n` (and `m` for a `shippingDays` range; a `freeShippingOver` regex has group `amount`, read as a UX-003 price candidate); numbers parse with the page locale's CLDR number pattern; `unit` (`hour`, `day`, `week`, `month`, `year`, `percent`) converts to the kind's unit by exact rational arithmetic without rounding (a non-integer result equals no integer `terms` value): hour = 1/24 day, day = 24 hours, week = 7 days or 168 hours, month = 30 days or 1 month, year = 365 days or 12 months; a `unit` with no conversion into the kind's unit makes the pattern invalid (CFG-006 against the pinned ruleset); boolean kinds have no groups.
- `password-reset-paths` — per locale `[string]`; an entry matches an `href` when its percent-decoded, lower-cased path contains the entry as a whole run of path segments (`reset-password` matches `/account/reset-password/` and not `/reset-passwords`). `chrome-state-classes` — `[string]` of class tokens; a token is removed when it equals an entry (case-sensitive).

- **Visible element** (browser channel; UX-001, UX-006, UX-024): an element with a non-empty bounding rect to which, on it or an ancestor, none of items 1, 2, 3 and 5 of 04 § 15 *Hidden content* applies (applied whether or not the element has text); off-screen elements are visible (the probe scrolls them into view).

- UX-017 reads XMP packets (JPEG, PNG, WebP, AVIF) and C2PA manifests (JUMBF) with a pinned C2PA reader in the Rust core.
