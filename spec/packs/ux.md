# Pack: ux

> Whether the site actually works for the person using it: every form reaches someone, every control does something, every fact matches the business, error pages look like the site, and measurement fires. Applies to `public` and `app` surfaces. Business facts come from the Operator-owned `quality/data/business.json` (03 § 14); this pack never decides which facts are true, only that pages match the file.

---

## 1. Policy section

```jsonc
"ux": {
  "formsNotCritical": [],          // [{ route: pattern, selector }] forms/controls exempt from UX-001 (e.g. site search, filters)
  "egressStubs": {},               // { host: { status, body } } replies the egress proxy gives to expectEgress traffic (03 § 10); unlisted host → 200 {}
  "contactPath": null,             // e.g. "web:/contact"; no default (UX-004 contact part is notConfigured without it)
  "factsIgnore": [],               // [{ route: pattern, selector? }] regions UX-003/013/014 don't read (e.g. third-party listings, product grids)
  "chromeVariants": [],            // route patterns whose header/footer may differ from the rest of their service (UX-016), e.g. "web:/checkout/**"
  "socialProofSources": [],        // UX-020: [{ widget: <`social-proof-widgets` entry id>, route?: pattern, source: { hosts: [host] } | { db, query } }]; no default
  "stockSources": [],              // UX-020 `stock`: [{ route: pattern, dataset: { family, field } | feed: { field } | db: { db, query } }]; no default
  "baseline": "widely",            // UX-008 target: "widely" | "newly" | Baseline year (integer, e.g. 2024)
  "nightlyBrowsers": ["firefox", "webkit"],   // UX-007
  "analyticsMatchers": {}          // { host: { pageView: { pathMatches?, bodyContains? }, eventParam } } extends the ruleset table (UX-010)
}
```

Business facts: `quality/data/business.json` (03 § 14), signed with the lock. Visual comparison settings (`viewports`, `masks`, `maxDiffRatio`) are the refactor pack's `visual` section, with its defaults when that pack is off. UX-002 and UX-011 are unassigned: placeholder residue is owned by MET-011 and external links by LNK-006 (web-delivery).

## 2. Rules — `UX-*`

- **UX-001** · P0 · cfg, browser — Every form is proven to reach its destination. **Forms** = each `<form>` with `method` other than `get` in a same-origin document of a sampled public page or an `app` page reached by a flow, plus each visible, enabled `button` or `role=button` element outside any `<form>`, anywhere in the document (including `<footer>`, `<aside>` and dialogs open at load), whose activation in the control click probe (UX-006) issues a non-GET request with a body (submit-driven fetch). Each form is either matched by an entry in `formsNotCritical` (route pattern + CSS selector matching the form or button), or submitted by ≥ 1 flow (a `click`/`press` step on a control inside the form, or on the button) followed, before the flow's next `goto`, by an outcome step: `expectEmail` (SMTP sink), `expectEgress` to a host in `hosts[]` with `server: true` or `browser: true` (CRM/form provider), or `expectDb`. Forms submitted only by the `verifyEnv.auth` login flow are covered by the auth strategy. Cfg part: every `formsNotCritical` selector parses, every `expectEgress` host is in `hosts[]`, every `expectDb` database is declared. Remote services: only with `nonProduction: true`, where `expectApi` or a browser-recorded `expectEgress` also count as outcomes (sink, egress proxy and database aren't observable); otherwise the outcome part is `notConfigured(nonProduction)` and the forms are listed. `remote: write`. Form coverage of the testing pack points here (TST-010).
- **UX-003** · P0 · html — Business facts oracle: on public pages (raw HTML visible text plus `tel:`/`mailto:` hrefs, outside programmatic family pages and `factsIgnore` regions), every detected fact of a kind whose key is present in `business.json` matches the file. Part `phones`: a phone number is a candidate that libphonenumber parses with the default region of 04 § 15 *E.164 normalisation* and for which `isValidNumber` is true; its E.164 form equals a `phones[].e164` or `locations[].phone`. Email addresses ∈ `emails`; prices (locale currency patterns, parsed with ICU4X) equal a `prices[]` amount and currency; star ratings and review counts (ruleset `ratingPatterns`) equal a `ratings[]` value and count; numeric claims (ruleset `claimPatterns`: a number followed by a listed noun such as "customers", "projects", "years", or "since/founded/est. <year>") equal a `claims[].value` or `founded`. A detected fact not in the file is a finding. A present but empty array allows none. A detected fact of a kind whose key is absent, or any detected fact without a `business.json`, is a blocking finding (04 § 1.2 facts-oracle rules): numbers on a page must come from the Operator's facts, never from the agent. **Ownership:** when LOC-001 applies (search-engines pack enabled and `business.json` `locations` non-empty), phone numbers, addresses and hours belong to LOC-001 (rule metadata: LOC-001 `owns` UX-003 part `phones`) and part `phones` is not evaluated; otherwise UX-003 checks phone numbers and never addresses or hours. Placeholder residue: MET-011; facts on programmatic pages: the programmatic oracle; qualitative claims: UX-013.
- **UX-004** · P1 · html — Contact paths work on mobile: every visible occurrence on a public page of a phone number or email from `business.json` sits inside `<a href="tel:<e164>">` (the exact E.164 value) or `<a href="mailto:<address>">`. Part `links`: the `tel:`/`mailto:` check above. Part `contact-path`: with `contactPath`, every public page links to it from inside `<header>` or `<footer>` (or `role="banner"`/`"contentinfo"`); without `contactPath` the part is `notConfigured(contactPath)`.
- **UX-005** · P1 · html — Error pages use the site: for each service with `public` or `app` surfaces, the 404 response to the RTE-004 unknown-URL case (a GET to the service mount root joined with `sg-probe-404/sg-probe-404`, a path no route pattern matches), the 404 response to each RTE-006 probe URL, and each 5xx HTML response produced by fault injection (04 § 4.5; requests with `Accept: text/html`) contain an `<a>` resolving to the service mount root, a `<nav>` or `role="navigation"` landmark, and match no fingerprint in the adapter's `errorPageFingerprints` or the ruleset `error-pages` table (framework, server and host default pages). A fingerprint is `{ id, titleRegex?, bodyContains: [string] }`; a response matches when its `<title>` matches `titleRegex` (when set) and its entity-decoded body contains every `bodyContains` string (case-sensitive). Adapter `errorPageFingerprints[]` and the ruleset `error-pages` table share this shape. Failure classes: `missing-element` (link, landmark), `pattern-match` (fingerprint). Status codes themselves are owned by RTE-004/RTE-007.
- **UX-006** · P1 · browser — No dead controls. **Controls** = on sampled public pages and `app` pages reached by flows, every visible, enabled (no `disabled`, no `aria-disabled="true"`, not `inert`) element inside `<header>` or `<main>` that is a `button`, `summary`, `input[type=submit|button|reset|image]` or has `role` `button|link|menuitem|tab`, and is not an `<a>` element on a public page (`<a>` elements on `app` pages are controls here). The control click probe also clicks every visible, enabled `button`/`role=button` element inside `<footer>`/`role=contentinfo`, `<aside>` and dialogs open at load; those clicks feed UX-001 form discovery and are judged by the dead test like any other control. **Control click probe** (mutating stage, 04 § 4.2 step 8). It runs whenever UX-001, UX-006, MET-011 `dead-anchor` or PRF-002 `probe` applies; PRF-002 measures INP during these clicks: each control is actually clicked once (trusted Playwright click; navigations are recorded, then aborted; the page is reloaded before the next click when the previous one changed it). Event listeners are never consulted — a control whose handler does nothing fails like one without a handler. A control fails when its click is **dead** (04 § 15 *dead control*: within 1 s, none of a navigation, a network request, a DOM mutation outside the element, a focus change, a dialog, or an `aria-expanded`/`aria-pressed`/`aria-selected` change). Controls with native activation behaviour are judged by that effect, never by listeners: `<summary>` passes when its `<details>` toggles `open`; a submit control (`button` without `type` or `type=submit`, `input[type=submit|image]`) or `input[type=reset]` passes when it has a form owner (submission outcome: UX-001), and one without a form owner is judged by the dead test; a control with `popovertarget` or `commandfor` passes when the id resolves and the target's popover or dialog open state changes (custom `--*` commands: the dead test); a control that is or is inside a `<label>` with a labelled control passes when that control gains focus or changes checkedness. `<a>` elements on public pages are owned by MET-011 `dead-anchor` (web-delivery).
- **UX-007** · P1 · browser — Cross-browser public pages (profile `nightly`): sampled public pages (≥ 1 per route group) pass RTE-013 (no origin script errors, failed same-origin subresources or hydration errors) and A11-017 (no overflowing or covered interactive elements) in each of `nightlyBrowsers`. Flows in other browsers are owned by TST-008.
- **UX-008** · W · build — Built CSS and JS use no web-platform feature beyond `baseline` (web-features data pinned with the ruleset; `"widely"` = Baseline widely available, `"newly"` = newly available, a year = Baseline that year or earlier) unless guarded. CSS: properties, values, at-rules and selectors whose BCD key belongs to a web-features feature; guarded inside a matching `@supports` block, or by a property declared twice with a supported fallback first. JS (oxc): syntax features whose AST node kinds map to BCD keys `javascript.operators|statements|grammar.*`, and references to global identifiers and their static members (`structuredClone`, `Array.fromAsync`, `Intl.Segmenter`) whose BCD key belongs to a web-features feature; instance-member calls are not checked. JS guards: the reference is inside `if ('x' in obj)` or `if (typeof X !== 'undefined')` testing that identifier, or is an optional call `?.()` on it. Excluded: code that the build's source maps (or the adapter `bundleManifest`) attribute to the packages `core-js`, `regenerator-runtime`, `@babel/runtime`, `tslib` or any package whose name contains `polyfill`; code without attribution is checked. Failure class `pattern-match`, showing the feature id, its Baseline status and the file:line.
- **UX-009** · P1 · browser — No unintended visual change: with screenshots in `quality/baselines/_main/visual/`, every route group outside the diff's blast radius matches its `_main` screenshot at each `refactor.visual.viewports` within `refactor.visual.maxDiffRatio`, with `refactor.visual.masks` applied (same comparison as REF-009). **Blast radius** = route groups whose route file (adapter `routes.fileMap`) is in the reverse-import closure of a changed file; a changed `config` or `style` file not reached through imports puts every route group in the radius. Without `_main` screenshots: `skipped(no-main)` with a warning (03 § 12). Services without `routes.fileMap` or an import graph (coverage `behaviour`): `noAdapterSupport`. Refactor tasks are owned by REF-009.
- **UX-010** · P1 · browser — Measurement works: when `hosts[]` has an entry with purpose `analytics`, after accepting consent (`privacy.consent.banner.acceptLabel`; no consent step when the privacy pack is off or `consent.required` is false) every sampled public page load sends exactly one page-view hit to each such host (0 = broken, ≥ 2 = double counting; failure class `value-mismatch` showing the count). Observation: for each sampled page, open it in a fresh context, accept consent, then reload; count hits from the reload's navigation start until 2 s after the `load` event or until 500 ms with no network requests, whichever is later (cap 10 s). Without a consent step, count the same window from the first navigation. Conversions: every flow with `conversion: <event>` sends that event to an analytics host (browser-recorded, or server-side via the egress proxy) before the flow ends. Hits and event names are recognised by the ruleset `analytics-vendors` table plus `analyticsMatchers`; an analytics host matched by neither is `notConfigured`. Pre-consent behaviour is owned by PRV-001; identifiers in payloads by PRV-010; see also PRV-011.
- **UX-012** · W · html, browser — Finishing touches on public pages: part `manifest` — `<link rel="manifest">` resolves 200 with JSON containing `name`, `start_url`, `display` and icons of 192 and 512 px; part `theme-color` — `<meta name="theme-color">` present; part `print` — under emulated `print` media, `<main>` is displayed with non-zero height.
- **UX-013** · P1 (part `green` P0) · html — No invented qualitative claims: on public pages (visible text outside `factsIgnore` regions), each match of the ruleset per-locale `claimPhrases` (guaranteed, warranty, certified, licensed, insured, accredited, award-winning, #1, best, leading, 24/7, same-day, free estimate, …) lies in a sentence (ICU4X UAX #29 sentence segmentation) that contains a `business.json` `claims[].text` (normalised containment: NFKC, case-folded, whitespace collapsed). Without `claims`: a found phrase is a blocking finding (04 § 1.2 facts-oracle rules), else `notApplicable`. Part `green` (applies when `privacy.jurisdictions` has an EU consumer jurisdiction — `eu-consumer`, `de` or `at`, as defined in the privacy pack — and the expiry clock (01 § 5.4) is on or after 2026-09-27 — Directive (EU) 2024/825; privacy pack off → `notConfigured(jurisdictions)`): each match of the ruleset per-locale `generic-green-claims.json` (eco-friendly, green, climate neutral, sustainable, …) fails unless its sentence contains the `text` of a claim that has an `evidence` URL.
- **UX-014** · P0 · html — No invented testimonials or people, on public pages outside `factsIgnore` regions. Part `testimonials`: every element matched by the ruleset `testimonial-markers.json` `testimonial` selectors (blockquote/figure, class and aria patterns) and every JSON-LD `Review` node has quote text (marker quote selector, else the element text minus its attribution; `reviewBody`) equal after normalisation (NFKC, case-folded, whitespace collapsed, quotation marks and trailing punctuation stripped) to the `text` of a `business.json` `testimonials[]` entry with `consentedOn` not in the future (01 § 5.4 expiry clock), and attribution (marker attribution selector, `<cite>`, `<figcaption>`; `author.name`) containing that entry's `author` as a whole-word normalised substring. Part `people`: each visible byline (ruleset `byline` selectors, locale prefix such as "By" stripped), each JSON-LD `Person` `name`, and each `h2`–`h6` or ruleset `team.name` element inside a `team` section (ruleset `team` selectors and per-locale headings) equals a `business.json` `people[].name` (normalised). Per part: key absent from `business.json` → a blocking finding when anything is detected (04 § 1.2 facts-oracle rules), else `notApplicable`; a present but empty array allows none. Sources: FTC 16 CFR 465; Google E-E-A-T guidance. Author markup reachability: answer-engines.
- **UX-015** · P1 · browser — Shown price = charged price: in each flow with `journey: "checkout"`, every `markPrice { locator, priceId }` step's located text parses (ICU4X, page locale) to the `amount` and `currency` of the `business.json` `prices[]` entry `priceId`, and the request later sent to a `hosts[]` entry with purpose `payments` (browser-recorded, or server-side via the egress proxy) carries a line item for it: amount and currency equal (`amount` converted to minor units with the ISO 4217 exponent of `currency`; provider values extracted per the ruleset `payment-amounts.json`), or a provider price id equal to that entry's `providerId`. A checkout flow without `markPrice` → `notConfigured(markPrice)`. A provider request that carries a provider price id while the `prices[]` entry has no `providerId` → a blocking `missing-element` finding owned by `operator` naming `prices[<priceId>].providerId` (04 § 1.2 required-facts rules). Otherwise a provider request with no line item that matches either way (including one with neither an extractable amount nor any price id), or no request to a `payments` host between the `markPrice` step and the end of the flow, is a blocking `value-mismatch` finding owned by the builder. No `hosts[]` entry with purpose `payments` while a checkout flow exists → `notConfigured(hosts.payments)`. Server-side tamper resistance: SEC-041. `remote: write`.
- **UX-016** · P1 · html — Consistent site chrome: per service and locale, the page-level `<header>` and `<footer>` (the `banner`/`contentinfo` landmarks: not inside `article`, `aside`, `main`, `nav` or `section`, or `role="banner"`/`"contentinfo"`) of every public page have the same masked skeleton hash — 04 § 11 steps 1, 3 and 6 applied to the subtree, after removing `aria-current` attributes and class tokens in the ruleset `chrome-state-classes` list (`active`, `current`, `is-active`, …). The most common hash is the reference (tie → lexicographically smallest); each page that differs, or lacks an element the reference has, is a finding showing the first differing node path. Pages matching `chromeVariants` are excluded.
- **UX-017** · W · html — AI-generated imagery in trust contexts is listed for review: same-origin images inside `testimonial-markers.json` `testimonial`, `team` or `byline` contexts, or referenced as `image` of a JSON-LD `Person`, whose XMP `Iptc4xmpExt:DigitalSourceType` or C2PA `c2pa.actions` `digitalSourceType` is the IPTC `trainedAlgorithmicMedia` or `compositeWithTrainedAlgorithmicMedia` code. Source: AI Act Art. 50(4).
- **UX-018** · W · html — Password reset is reachable: when the page at `verifyEnv.auth.loginPath` contains an `input[type=password]`, it contains an `<a>` whose accessible name matches the ruleset per-locale `password-reset-labels` ("Forgot password?", …) or whose `href` path matches its `password-reset-paths`, and that link answers 200. Login without a password field: `notApplicable`.
- **UX-019** · P0 · html — No invented trust marks or logo walls (UCPD Annex I item 2; uncertified sustainability labels banned in the EU from 2026-09-27; FTC endorsement rules). On public pages:
  - Part `marks`: every element matched by ruleset `trust-marks.json` (certification, review-platform, payment-security, award and sustainability badges, matched by image host, file name, `alt` or perceptual image hash) must be backed by `business.json` `certifications[] { name, issuer, evidence, validUntil? }`. A matched mark passes when a `certifications[]` entry has `name` equal (NFKC, case-folded, whitespace collapsed) to one of the `names` of the mark's ruleset entry, a non-empty `evidence` URL, and `validUntil` absent or not before the expiry clock (01 § 5.4). Entry shape in `trust-marks.json`: `{ id, kind, names: [string], imageHosts: [host], fileNamePatterns: [glob], altPatterns: [regex], dhash: [16-hex] }`; an element matches when its image host is in `imageHosts`, its file name matches a `fileNamePatterns` glob, its `alt` matches an `altPatterns` regex, or its decoded image's 64-bit dHash (9×8 greyscale, Lanczos3) is at Hamming distance ≤ 6 from a `dhash` value. Failure class `forbidden-value` (no backing entry) or `stale` (expired `validUntil`), showing the mark id, the element selector and the image URL.
  - Part `logo-wall`: the region is everything after a heading (`h1`–`h6` or `role=heading`) whose text matches the ruleset per-locale `logo-wall-headings` ("Trusted by", "As seen in", "Our clients", "Featured in", …), up to the next heading of the same or higher level or the end of its sectioning parent. Every `<img>` and inline `<svg>` in it passes when, after NFKC, case-folding and replacing `-`/`_` with spaces, its `alt` (svg: `<title>`) or file-name stem contains a `business.json` `clients[]` or `press[]` `name` (`{ name, url? }`, normalised the same way) as whole words; else `forbidden-value`, showing the image and the heading.

  If the key is absent and something is detected, that's a blocking `forbidden-value` finding (04 § 1.2 facts-oracle rules). The fix is to remove the content or have the Operator supply the facts; TR-112 tells agents this up front.
- **UX-020** · P0 · browser, html — No fake urgency or scarcity (UCPD Annex I No. 7, UK DMCC Act 2024, FTC Act § 5).
  - Part `timer`: each element matched by ruleset `countdown-markers` on a public page is read in two fresh browser contexts with the real (uninstalled) clock: the second read starts ≥ 60 s of wall-clock time after the first (all first reads of the run, then all second reads, so a run waits once). Deadline = the wall-clock UTC time of the read + the remaining duration parsed from the element's visible text by the marker's `format` patterns (named groups `d`, `h`, `m`, `s`); resolution r = the smallest unit shown. `reset`: the two deadlines differ by > r + 2 s (the deadline restarts per visitor). `unbacked`: no `offers[].endsAt` lies within r + 2 s of the first deadline. Both are `value-mismatch` findings showing the selector, both texts and both deadlines. A matched element whose text no `format` pattern parses is a `parse-error` finding. `offers` absent while a countdown is detected → blocking `forbidden-value` (04 § 1.2 facts-oracle rules). The part reads the wall clock, so its outcomes are non-deterministic (TR-103).
  - Part `stock`: each per-locale ruleset `stock-count-phrases` match ("only 3 left", "2 in stock", …) on a public page, with or without an `Offer`, must state the number read from the Operator-owned source that `ux.stockSources` maps to that page (first entry whose `route` matches): `dataset` — the field value of the programmatic row rendered on the page (programmatic oracle, 04 § 11); `feed` — the named column (TSV) or element (XML) of the merchant feed item whose `link` equals the page canonical; `db` — the single integer returned by the entry's SQL `query` (`:path` bound to the page path) run against the seeded database `db` in the read-only stage (seed inputs are lock-protected, 03 § 3). JSON-LD `Offer.inventoryLevel` and any other page content are never a source, because the agent writes them. A match on a page that no `stockSources` entry covers is a blocking `forbidden-value` finding (04 § 1.2 facts-oracle rules); a covered page whose source yields no integer, or a different number, is a `value-mismatch` finding.
  - Part `social-proof`: widgets matched by ruleset `social-proof-widgets` (vendor hosts or markers such as "X just bought", "N people viewing") are a blocking `forbidden-value` finding (04 § 1.2 facts-oracle rules) unless a `ux.socialProofSources` entry has the widget's ruleset entry `id` as `widget` (and a matching `route`, when set). With `source.hosts`, every request the widget's elements or scripts make during the page load goes to a listed host, and each listed host is in `hosts[]`; with `source.db`, the number the widget shows (the ruleset entry's `numberRegex`, named group `n`) equals the single integer the entry's `query` returns against the seeded database `db` in the read-only stage (`:path` bound to the page path). A request to an unlisted host, or a different or missing number, is a `value-mismatch` finding.
- **UX-021** · P1 · html — Affiliate and sponsored disclosure for readers (FTC 16 CFR 255.5, UK CAP Code, UCPD Annex I No. 11). On an indexable page with affiliate or sponsored links (the SE-120 detection), `<main>` contains a per-locale ruleset `affiliate-disclosure-phrases` match before the first such link. `rel="sponsored"` (SE-120) informs search engines; this rule informs people. With the search-engines pack off, detection uses `hosts[]` purpose `affiliate` only.
- **UX-022** · P1 · edge — Production conversion check at launch (with `project.stage: "live"` and `edge.production: true`). Each UX-001 form proven by a flow has a **form key** = `<flow id>#<index of the submitting step>→<outcome>`, where `<outcome>` is `email:<expectEmail.to>`, `egress:<expectEgress.host>` or `db:<expectDb.db>` (flows are Operator-owned, so the key never comes from agent-written files). Every form key must have an entry in `quality/approvals/launch-forms.json` (Operator-owned, covered by the lock, 03 § 8): `{ "formatVersion": 1, "forms": [{ "key": string, "result": "arrived" | "failed"\| "failed", "confirmedOn": date, "note"?: string }] }`, written after the Operator submitted that form once on production and checked that the outcome arrived. A key without an entry, an entry with `result: "failed"`, or a `confirmedOn` in the future (01 § 5.4 expiry clock) is a blocking `missing-element` finding owned by `operator` that shows the route, the form selector, the outcome and the key; a changed flow or outcome changes the key and asks again. Entries whose key matches no current form are listed as W. shipgate never submits forms on production (decision log: remote targets are read-only); `remote: none`. Forms matched by `formsNotCritical` are excluded.

## 3. Implementation notes
- UX-001, UX-006 and PRF-002 `probe` share one control inventory per page, built by the flows engine in G6, so a control is clicked once.
- Ruleset data used here: `error-pages` (UX-005), `ratingPatterns` and `claimPatterns` per language (UX-003), `claimPhrases` per locale and `generic-green-claims.json` (UX-013), `testimonial-markers.json` with `testimonial`, `team` and `byline` sections (UX-014/017), `payment-amounts.json` (UX-015), `chrome-state-classes` (UX-016), `password-reset-labels`/`password-reset-paths` (UX-018), `analytics-vendors` (UX-010), web-features (UX-008), `trust-marks.json` and `logo-wall-headings` (UX-019), `countdown-markers`, `stock-count-phrases` and `social-proof-widgets` (UX-020), `affiliate-disclosure-phrases` (UX-021).
- Ruleset data shapes: `stock-count-phrases` — per locale, `[{ id, regex }]`, each regex with exactly one named group `n` matched against visible text (NFKC); `n` is parsed with the locale's CLDR number pattern and compared as an integer. `countdown-markers` — `[{ id, selector?, textRegex?, format: [regex] }]`: an element matches by `selector` or by its visible text matching `textRegex`; each `format` regex has named groups among `d`, `h`, `m`, `s`, and the first that matches the element's visible text gives the remaining duration. `social-proof-widgets` — `[{ id, hosts: [host], selectors: [css], textRegex?, numberRegex? }]`: a widget matches when a request goes to one of `hosts` or an element matches `selectors` or its visible text matches `textRegex`; `numberRegex` has one named group `n`.
- UX-017 reads XMP packets (JPEG, PNG, WebP, AVIF) and C2PA manifests (JUMBF) with a pinned C2PA reader in the Rust core.
- UX-003 compares parsed values, not strings: "10,000+", "10k" and "10 000" all equal 10000; a claim matches when its value equals a `claims[].value` and the matched `claimPatterns` noun occurs as a whole word in the claim's `text` (NFKC, case-folded).
