# Pack: data-api

> API contracts proven against real responses, and database changes proven safe on a disposable database. Applies to `api` surfaces and any service with a database.

---

## 1. Policy section

```jsonc
"data-api": {
  "contracts": [
    { "service": "api", "type": "openapi", "path": "quality/contracts/api.openapi.yaml" },
    { "service": "web", "type": "openapi", "path": "quality/contracts/web-routes.openapi.yaml" }
    // also: "graphql" (SDL; optional "endpoint": path served, default "/graphql", SEC-060), "trpc"/"rpc" (generated schema), "jsonschema"
    // optional per entry (no default): "clientTypes": { "command": "pnpm gen:api-types", "output": "packages/api-client/types.ts" } (API-008)
  ],
  "examples": "quality/contracts/examples/",        // request/expectation files (03 § 14), Operator-owned
  "errorShape": { "$ref": "quality/contracts/error.schema.json" },
  "pagination": { "maxLimit": 100 },
  "maxBodyBytes": 1048576,                            // integer bytes; API-007 sends 2 × this
  "idempotentPosts": ["/api/payments", "/api/orders"],
  "raceSensitive": [],                                // [{ example: "<examples id>", effect: { db, sql } | { egress: host } | { email: to } }] (API-009)
  "released": "quality/contracts/released/",          // layout and CHANGES.md: 03 § 14 (API-004)
  "db": {
    "database": "main",                                // id in verifyEnv.databases (engine, version, provider live there)
    "migrations": { "format": "sql-dir", "dir": "supabase/migrations" },   // or prisma|drizzle|django|rails|laravel|knex via the service's migrate command
    "exposedSchemas": ["public"],                      // e.g. Supabase PostgREST-exposed schemas

    "rpcPublic": [],                                   // SECURITY DEFINER functions intentionally executable by apiRoles
    "edgeFunctionsPublic": [],                         // Supabase Edge Functions deployed without JWT verification on purpose
    "approvedDestructive": [ { "file": "supabase/migrations/20261001_drop_legacy.sql", "sha256": "…" } ]
  },
  "firebase": {                                        // DB-011; rules files are read from firebase.json (else firestore.rules, storage.rules, database.rules.json at the repo root)
    "publicRead": [],                                  // match paths (as written in the rules file, e.g. "/products/{id}") whose read may be unconditional
    "seed": null,                                      // emulator export directory with seeded docs (no default; emulator part notConfigured without it)
    "owned": []                                        // [{ path: "invoices/{id}", ownerField: "uid" }] seeded collections and the field holding the owner's uid
  },
  "jobs": [ { "service": "worker", "name": "send-invoices", "schedule": "0 * * * *", "run": "pnpm job:send-invoices", "writes": ["invoice_emails"] } ]
```

Migrations are applied by the database lifecycle in 04 § 4 (never by vendor CLIs that need Docker).

## 2. API contracts — `API-*`

- **API-001** · P0 · contract, http, build — Every endpoint the service exposes is declared in a contract; every declared endpoint exists. Discovery = adapter routes ∪ contract ∪ requests observed during flows and sampled pages (network log). Part `bundle-only` (W · build): a same-origin path string in a built client asset (G3) that matches no contract operation and no discovered endpoint is listed (`orphan`), never blocking. A declared operation exists when adapter route discovery (`routes.discover`) lists its method and path, or, for adapters without `routes.discover`, when its contract-generated request (04 § 15) answers with a status other than 404, 405 or 501. Undeclared = an adapter route, or a flow/page network-log request (method + path normalised to the contract's path templates), that matches no contract operation. Generated requests other than GET/HEAD/OPTIONS run in a mutating stage (04 § 4.2 step 8).
- **API-002** · P0 · contract, http — Responses to declared example requests and to contract-derived generated requests match the contract (status, headers, body schema), including error responses. Part `deprecation` (W): operations marked `deprecated` in the contract respond with a `Deprecation` header (RFC 9745) and, when the contract gives a sunset date (`x-sunset`), a matching `Sunset` header (RFC 8594). Example and generated requests other than GET/HEAD/OPTIONS run in a mutating stage (04 § 4.2 step 8).
- **API-003** · P0 · http — Status semantics, judged over every response to API-002 example and generated requests and to SEC-030 fuzz requests: (a) fuzz requests, and generated requests that violate the request schema, answer 400 or 422 with a body valid against `errorShape`; (b) requests for a probe id answer 404; (c) anonymous requests (04 § 15 contract request generation) answer 401 or 403, and other-tenant requests answer 403 or 404 (whether access is refused at all: SEC-021/SEC-023); (d) no 2xx response has a body valid against `errorShape` or a top-level `error`/`errors` key; (e) no request of kind (a)–(c) answers 5xx. 409 is judged only where the contract documents a 409 response (API-002). Kinds (a) and (e) on SEC-030 fuzz requests are reported by SEC-030 `behaviour` only; this rule judges them on API-002 requests. Requests other than GET/HEAD/OPTIONS run in a mutating stage (04 § 4.2 step 8). Part `retry-after` (W): every 429 observed (including SEC-025 rate-limit probes) carries `Retry-After` (503s: RES-007).
- **API-004** · P0 · contract — No breaking changes against the latest contract in `released/` (removed endpoints/fields, narrowed types, new required inputs, changed status codes) unless the contract's major version is bumped and the change is declared. Declared = (a) an `api-field-removed` entry in `refactor.json` naming the `endpoint` and `jsonPath`; (b) an `api-status` entry whose `from` equals the status the latest released contract documents for that operation; or (c) a `- removed:`/`- changed:` line naming the path under a `## <semver>` heading of `quality/contracts/released/<service>/CHANGES.md` (03 § 14) whose major equals the current contract's major. Removals, narrowed types and new required inputs also need the current contract's major > the latest released major; an `api-field-added` entry is never needed here (additions are not breaking). No released contract for the service: `notApplicable` (listed in the report).
- **API-005** · P1 · contract, http — Pagination. List endpoints = contract `GET` operations whose 200 response schema is an array or has a top-level array property. Each declares a query parameter named `limit`, `per_page`, `perPage`, `pageSize`, `page_size`, `first` or `take` (none → finding `missing-element`). Probes: the operation called with that parameter = `pagination.maxLimit` + 1 answers 400/422, or 2xx with ≤ `maxLimit` items in that array; called without it, the response has ≤ `maxLimit` items.
- **API-006** · P1 · http — Idempotency. For each `idempotentPosts` entry, the first `examples` request (03 § 14) whose `request.method` is `POST` and whose `request.path` equals the entry after 04 § 10 normalisation of the path (query stripped, a trailing slash removed), or, when the entry contains `{name}` segments, matches it as a path template (03 § 2.1), is sent twice with the same `Idempotency-Key: sg-{lockDigest[0..16]}-{exampleId}` header and session (mutating stage, 04 § 4.2 step 8). Part `replay`: after the second request, compared with the state after the first, there is no side effect (04 § 15 "No side effect": table rows, captured emails, egress requests), and the second response has the first one's status and a body that is equal after `refactor.normalize.json` masking. Part `key-required` (W): a finding when the same request sent twice without the header produces two side effects and neither response is 400/422. No matching example → `notConfigured(examples)`; `idempotentPosts` empty → `notApplicable`. `remote: write`.
- **API-007** · P1 · http — Body size limit: for each contract operation with a request body, one request whose body is valid JSON padded with one extra string field to 2 × `maxBodyBytes` answers 413 (mutating stage, 04 § 4.2 step 8). Operations whose request media type is not `application/json` are excluded (multipart and other upload limits: SEC-032 `size`). `remote: write`.
- **API-008** · P1 · contract, cmd, ast — Client types are generated from the contract. Part `stale` (cmd, G1): for each `contracts[]` entry with `clientTypes`, `command` runs in a temporary copy of the working tree (tracked and untracked non-ignored files, as `treeHash`, 04 § 15) and the `output` file it writes there equals the committed `output` byte for byte; without `clientTypes`: `notConfigured(clientTypes)`. Part `hand-copied` (ast): in changed files outside every `clientTypes.output`, no exported type, interface or class has the name of a contract schema (OpenAPI `components.schemas` keys, GraphQL type names, JSON Schema `$defs` keys).
- **API-009** · P1 · http — Race safety: for each `raceSensitive` entry, its example request (03 § 14) is sent 10 times concurrently with identical inputs and session (mutating stage, 04 § 4.2 step 8); the side effect happens exactly once: `effect.sql` (a scalar) increases by exactly 1, or exactly one request to `effect.egress` passes the egress proxy, or exactly one email to `effect.email` reaches the SMTP sink. Responses other than the winner are 2xx replays of the same result or 409/422/429. `raceSensitive` empty → `notApplicable`; an `example` id not in `examples` → `notConfigured(examples)`. `remote: write`.

## 3. Database — `DB-*`

- **DB-001** · P0 · db — Migrations are the only path to schema changes. Part `apply`: applying all migrations to an empty disposable database (04 § 4.2 step 4) exits 0; a finding makes the service's later G4–G7 checks `blocked(prerequisite: DB-001)`, owner `builder` (04 § 1.5). Part `drift`: the adapter's `schemaDriftCommand` (e.g. `prisma migrate diff --from-url {db.url} --to-schema-datamodel … --exit-code`, `drizzle-kit check`), run against the migrated database, exits 0, and committed generated DB types (adapter `codegen[]` outputs for the database) equal a fresh regeneration byte for byte. Adapters without `schemaDriftCommand`: part `drift` is `noAdapterSupport`.
- **DB-002** · P0† · diff, lock — Applied migrations are immutable: files already in the base branch never change; fixes are new migrations.
- **DB-003** · P1 · db — Safe-migration rules, on migration files added in the diff. Parts `concurrent-index`, `expand-contract`, `not-null`, `rewrite` and `backfill` (all P1): `concurrent-index`: indexes on `largeTables` created `CONCURRENTLY` (Postgres) / `ALGORITHM=INPLACE, LOCK=NONE` (MySQL); `expand-contract`: no column rename or drop in the same diff as code still referencing it (04 § 13); `not-null`: no `SET NOT NULL` or `ADD COLUMN … NOT NULL` without `DEFAULT`, unless an earlier migration in the diff runs `UPDATE` on that column; `rewrite`: on `largeTables`, no column type change (Postgres `ALTER COLUMN … TYPE`, MySQL `MODIFY COLUMN`/`CHANGE COLUMN` with a different type) that isn't in ruleset `safe-type-changes` (Postgres only: `varchar(n)`→`varchar(m>n)`, `varchar`→`text`, `numeric(p,s)`→`numeric(p'>p,s)`); MySQL is judged by probe instead: a change is safe when, in 04 § 4.2 step 4 before its migration file is applied, the same `ALTER TABLE` run against an empty structural copy of the table (`CREATE TABLE sg_probe LIKE <table>`, dropped afterwards) succeeds with `, ALGORITHM=INSTANT` appended, or else with `, ALGORITHM=INPLACE, LOCK=NONE` appended; both refused → finding; `backfill`: no migration file contains both DDL and `INSERT`/`UPDATE`/`DELETE` on a table that existed before it. Non-`sql-dir` formats: the statements attributed to each migration file as in DB-006.
- **DB-004** · P0† · db — Row Level Security: every table in `exposedSchemas` has RLS enabled and at least one policy; write policies with `using (true)`/`with check (true)` are findings; every view in `exposedSchemas` that selects from a table with RLS enabled has `security_invoker=true` in `reloptions` (PostgreSQL ≥ 15) or is not selectable by any of `apiRoles` (`has_table_privilege`). Non-Postgres databases: `notApplicable`.
- **DB-005** · deprecated — tombstone; owned by CFG-004 (production targets) and the command policy (05 § 3.2).
- **DB-006** · P0 · db, lock — Destructive statements in migrations (`DROP TABLE`, `DROP COLUMN`, `TRUNCATE`, `DELETE`/`UPDATE` without `WHERE`) require an entry in `db.approvedDestructive` with the file's SHA-256 (signed policy), never a marker inside the file. `sql-dir`: the statements are parsed from the file. Other formats: the statements PostgreSQL/MySQL log while 04 § 4.2 step 4 applies each pending migration file on its own (adapter `migrations.applyCommand`, one invocation per file, statement logging on) are attributed to that file. Adapters whose `applyCommand` can't apply a single file: adapter `destructiveMigrationApis[]` calls (e.g. Django `RemoveField`, `DeleteModel`; Rails `drop_table`, `remove_column`; knex `dropTable`, `dropColumn`) in the migration file, matched with ast; neither available → `noAdapterSupport`.
- **DB-007** · P1 · db — Part `fk-index`: every foreign key on a table created or altered in the diff has an index whose leading columns equal the FK columns in order. Part `pk`: every table created in a migration added in the diff has a primary key.
- **DB-008** · P1 · ast — No N+1 patterns, in changed code (04 § 13 DB-008): a finding is a `queryApis` call whose nearest enclosing loop in the same function — `for`, `for…of`, `for…in`, `while`, `do…while`, a Python/Ruby/Rust loop or comprehension, or a callback passed to `map`, `forEach`, `flatMap`, `reduce` or `each` (including `Promise.all(x.map(…))`) — iterates a value whose data-flow origin (same function, as AGT-003 in 04 § 13) is the result of another `queryApis` call. Calls reached only through a callee are not followed. Failure class `pattern-match` (file and line of both calls). Adapters without `queryApis` → `noAdapterSupport`.
- **DB-009** · P0 · db, cfg — Postgres API exposure (after migrations, from the catalog): in `exposedSchemas`, every `SECURITY DEFINER` function sets `search_path` (`proconfig`), and `EXECUTE` on it is not held by any of `apiRoles` or `PUBLIC` unless the function is in `rpcPublic`; no view (or materialized view) references `auth.users`; materialized views and foreign tables (which can't carry RLS) aren't selectable by `apiRoles` (tables are owned by DB-004). Part `edge-functions` (cfg): Supabase Edge Functions verify JWTs — `supabase/config.toml` `[functions.<name>] verify_jwt = false` and `--no-verify-jwt` in deploy scripts or CI files are findings unless `<name>` is in `edgeFunctionsPublic`. Non-Postgres databases: `notApplicable`.
- **DB-010** · W · browser, db — Query plans on large tables: queries logged during G6 on the embedded instance (04 § 4.2: PostgreSQL `log_min_duration_statement = 0`; MySQL general log) that read a `largeTables` table holding ≥ `planRows` rows after seeding are re-run as `EXPLAIN` (after `ANALYZE`) with their logged parameters; a `Seq Scan` (MySQL `type: ALL`) on that table is a finding. Tables below `planRows`: `skipped(small-table)`.
- **DB-011** · P0† · cfg, db — Firebase security rules (Firestore, Storage, Realtime Database; files from `firebase.json`). Part `rules` (cfg), on the parsed rules after inlining functions defined in the file and constant-folding `&&`/`||`/`!`: (a) no `allow` of `write`, `create`, `update` or `delete` that is unconditional or whose condition is `true`; (b) no such `read`, `get` or `list` except on a match path in `firebase.publicRead`; (c) no `match /{x=**}` directly under `match /databases/{database}/documents` (Storage: `match /b/{bucket}/o`) with an `allow` whose condition isn't `false`; (d) no write `allow` satisfied by every signed-in user — its atoms are only `true`, `request.auth != null` and `request.auth.uid != null`, with no comparison of `request.auth.uid` or `request.auth.token.*` against a path variable, `resource.data.*`, `request.resource.data.*` or a `get()`/`exists()` result. `database.rules.json`: the same on `.read`/`.write` values (`true`, `"true"`, `"auth != null"`, `"auth.uid != null"`); a root-level value other than `false` counts as (c). Part `emulator` (db; Firebase emulator from the managed toolchain where a build exists for the OS, else `skipped(no-emulator)` and listed; without `firebase.seed`/`owned`: `notConfigured`): with `seed` imported and every `verifyEnv.auth.accounts` id signed in to the Auth emulator as uid = id, through the rules-unit-testing library — for each seeded doc under an `owned` path, an unauthenticated context and every account whose uid ≠ the doc's `ownerField` are refused get, update and delete, and an unauthenticated create in that collection is refused; the owner's own get must succeed. An owner's get that is refused is a finding `access-denied-wrongly`; an unauthenticated or other-uid get, update, delete or create that is not refused is a finding `access-allowed`; both owner `builder`. Only when the seeded doc has no `ownerField` value, or the value is no `verifyEnv.auth.accounts` id, is the outcome `notConfigured(owned)`. Other client-direct backends (dependencies `appwrite`, `pocketbase`, `convex`) → `noAdapterSupport`, listed in the report. Postgres/Supabase: DB-004, DB-009.
- **DB-012** · P0 · db, ast — No seeded credentials in production migrations: the migration files the deploy applies (`db.migrations.dir`, else the adapter's `migrations.dir`; never seed files such as `supabase/seed.sql` or adapter seed paths) insert no row into a ruleset `user-tables` table (`auth.users`, `users`, `user`, `accounts`, `auth_user`, `admin_users`, …; names matched case-insensitively against unquoted identifiers, schema-qualified or not) whose values include a string literal in a ruleset `password-columns` column (same matching), a literal matching a ruleset `password-hash-patterns` regex (`^\$2[aby]\$\d\d\$`, `^\$argon2(id|i|d)\$`, `^\$scrypt\$`, `^pbkdf2_sha(1|256|512)\$`, `^\$[156]\$`, `^\{SSHA\}`), a literal argument to `crypt()`, or an email literal matching a ruleset `default-emails` glob over the lower-cased address (`admin@example.com`, `test@*`, `*@example.{com,org,net}`, …). SQL (`INSERT`, `COPY`, `MERGE`) is parsed for `sql-dir`; for ORM formats, create/insert calls (adapter `queryApis`) in migration files are read with ast.

## 4. Background jobs — `JOB-*`

- **JOB-001** · P1 · cfg, ast — Every scheduled or queued job is declared in `jobs`. Discovered jobs = adapter `jobDiscovery` matches ∪ `vercel.json` `crons[]`, `netlify.toml` scheduled functions, `wrangler.toml` `[triggers] crons`, `supabase/config.toml` and migration `cron.schedule(...)` calls, and CI workflow `on.schedule` jobs that run a service command. A discovered job is declared when a `jobs` entry of the same service has its `name` equal to the job's registered name, or its `run`/`schedule` equal to the job's command/cron expression. Undeclared → finding (`orphan`).
- **JOB-002** · P1 · db — (Runtime part of `db`, evaluated in G4, 04 § 1.1.) Jobs are idempotent: in its own mutating stage (04 § 4.2 step 8), `run` executes twice in sequence on one fresh instance. The first run exits 0. After the second, compared with the state after the first, there is no side effect on the `writes` tables (03 § 14), captured emails or egress requests (04 § 15 "No side effect", tables restricted to `writes`). Part `vacuous` (W): the first run changes no `writes` row and produces no email or egress (the seed gives the job nothing to do).
- **JOB-003** · P1 · ast — Bounded retries. Failure swallowing in job handlers is owned by AGT-010. Every queue/job registration matched by adapter `jobDiscovery` sets the adapter-declared retry argument (adapter `jobRetryArgs` entry `arg`, 03 § 6; e.g. BullMQ `attempts`, Celery `max_retries`, Sidekiq `retry`) to an integer literal 0–25, or omits it where `unboundedDefault` is false. Adapters without `jobRetryArgs`: `noAdapterSupport`.
