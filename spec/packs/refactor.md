# Pack: refactor

> Lets agents restructure a live site or platform safely. Before the refactor, shipgate records what the system actually does; afterwards it proves nothing observable changed except what the Operator declared. The baseline is the oracle.

---

## 1. Policy section and change declaration

```jsonc
"refactor": {
  "normalize": {                                   // differences that are never meaningful
    "html": ["asset-hashes", "nonces", "csrf-tokens", "build-ids"],
    "json": { "ignorePaths": ["$..createdAt", "$..updatedAt", "$..requestId"] },
    "headers": ["date", "etag", "x-request-id", "set-cookie:value"]
  },
  "tolerance": { "lcpMs": 100, "cls": 0.02, "tbtMs": 50, "inpMs": 50, "scriptBytesPct": 3, "cssBytesPct": 3, "apiP95Pct": 10 },
  "visual": { "maxDiffRatio": 0.001, "masks": [], "viewports": ["mobile", "desktop"] }
}
```

**Normalisation tokens** (applied at baseline capture and before every comparison):
- `asset-hashes`: in a path segment ending in an asset extension (`.js`, `.mjs`, `.css`, `.woff2`, `.woff`, image extensions), the leftmost match of `[.-]([A-Za-z0-9_-]{8,})\.<ext>$` whose captured run contains at least one ASCII digit → the run is replaced by `⟦hash⟧` (`main.3f9a2c1b.js`, `index-D-3xQ1aB.js` normalise; `-component.js`, `-vendors.css` don't);
- `nonces`: `nonce` attribute values and CSP `'nonce-…'` sources → `⟦nonce⟧`;
- `csrf-tokens`: the `value` of an `<input type=hidden>` whose `name` contains `csrf`, `xsrf` or `authenticity_token`, and `<meta name=csrf-token>` `content` → `⟦csrf⟧`;
- `build-ids`: `__NEXT_DATA__.buildId`, `data-build-id` attribute values and `/_next/static/<id>/` path segments → `⟦build⟧`;
- `json.ignorePaths`: JSONPath matches are removed before comparison;
- `headers`: the named response headers are removed before comparison; `set-cookie:value` keeps cookie names and attributes but replaces each value with `⟦v⟧`.

**Flow normalisation** (REF-006, REF-012, and at baseline capture): every generator output of the run (`{uniqueEmail}`, `{strongPassword}`, `{uuid}`, `{account.*}`; 03 § 10) is replaced by `⟦gen:<name>⟧`; then visible dates (04 § 15), UUIDs, runs matching `[A-Za-z0-9_-]{20,}` and the `normalize` maskings above are replaced by placeholders before comparison or hashing.

`quality/refactor.json` (Operator-owned, signed, per refactor) declares intended changes; format and `kind` enum: `03-formats.md` § 11.

## 2. Baseline contents (`shipgate baseline`)

Recorded from the running system in the verify environment, then locked:
- **Routes:** discovered (adapter + crawl + sitemap + declared) with status, redirect target, robots, canonical, title, description, h1, normalised main-text hash and extracted text, JSON-LD, internal links.
- **APIs:** contract snapshot; responses to declared and generated requests (normalised).
- **Database:** schema dump after migrations; RLS policies.
- **Flows:** outcome of every declared flow (URLs, visible texts, API states); emails captured by the SMTP sink (subject, link paths, SHA-256 of the normalised text part); third-party requests (host, and event name where the ruleset `analytics-vendors` table or `ux.analyticsMatchers` recognises one).
- **Redirects:** every redirect source declared in host config files for `services[].host` (`vercel.json`, `_redirects`/`netlify.toml`, nginx/apache configs, Cloudflare `_redirects`), web-delivery `retired` entries and adapter-discovered redirect tables (adapter `redirectSources`, e.g. Next `redirects()`), each with its status and `Location`.
- **Remote baselines** (`baseline --from-remote <origin>`, 03 § 12): for re-platforming or rebuilding a live site; routes only, from sitemaps ∪ a capped read-only crawl ∪ `quality/data/legacy-urls.txt` ∪ declared redirect sources. Each route also records `mainWords` (UAX #29 word count of `<main>`, else of `<body>` minus `header`, `footer`, `nav`; REF-010 `depth`), and the capture loads `/` and the browser sample in Chromium (read-only) to record every service worker registration (`scriptURL`, `scope`; REF-013). Each route also records `images[]`: the absolute URLs of `<img src>`, `srcset` candidates and `<picture><source srcset>` candidates in `<main>`, `og:image`, and the image-sitemap `<image:loc>` entries of that `<loc>` (REF-014).
- **Budgets:** performance metrics per route group, bundle sizes, accessibility findings.
- **Security observations:** headers, cookie flags, auth/authorization probe results.

## 3. Rules — `REF-*`

- **REF-001** · P0 · cfg — When a signed `quality/refactor.json` exists or `verify --against` is given, the run requires an existing, signed baseline whose manifest `commit` is the diff base (04 § 5), captured before any change (for a rebuild of a live site, a signed remote baseline of its origin; the `commit` condition does not apply to a remote baseline); without one, G7 is `BLOCKED(no-baseline)` through its prerequisite (04 § 1.5), so the run is `BLOCKED` with owner `operator`.
- **REF-002** · P0 · baseline — Every `routes.jsonl` field, `db/schema.sql` and `db/policies.json` is equal after normalisation (§ 1), unless covered by an `allowedChanges` entry (what each `kind` covers: 03 § 11). Owned elsewhere: `api.jsonl` by REF-004, `flows.jsonl` outcomes by REF-006, emails and third-party requests by REF-012, `redirects.jsonl` by REF-011, `budgets.json`/`a11y.json`/`security.json` by REF-005, `visual/` by REF-009, `url-move` routes by REF-003. With a remote baseline (re-platforming), only REF-001, REF-010, REF-013 and REF-014 apply; the other REF rules are `notApplicable`. REF-011 is `notApplicable` because a remote baseline has no `redirects.jsonl` (03 § 12); old-site redirect sources become recorded routes, judged by REF-010.
- **REF-003** · P0 · baseline, http — `url-move` changes: old URLs redirect in one hop to the new ones; new URLs answer the old URL's recorded status with `mainTextHash`, `title`, `description`, `h1`, `robots` and JSON-LD `@type` set equal to the old URL's baseline record (canonical: the new URL itself). Part `links`: no sitemap `<loc>` and no internal `a[href]` on crawled pages points to a `from` URL.
- **REF-004** · P0 · baseline, contract — API responses are unchanged except as declared. For each `api.jsonl` record, the same request is re-sent and its response has (a) the recorded `status`, or the `to` of an `api-status` entry for the endpoint whose `from` is the recorded status; and (b) a JSON body equal to the recorded body after 03 § 12 body normalisation and `refactor.normalize.json.ignorePaths`, once every path selected by an `api-field-added` entry for the endpoint is removed from the current body. A recorded path missing from the current body is a removal: a finding `schema-violation` unless an `api-field-removed` entry for the endpoint and path exists and the current contract's major is ≥ the major of its `contractVersion` (03 § 11). Any other difference, including a current path not covered by `api-field-added`, is a finding `value-mismatch` (endpoint, JSON path, recorded and current values). Non-JSON bodies: the `sha256:` values (03 § 12, after the 04 § 15 fallback-body masking) are equal (`value-mismatch` otherwise). A status difference is `status-mismatch`.
- **REF-005** · P2 · baseline — No regressions. Parts `budget`, `a11y` and `security` (all P2): `budget`: no route-group metric in `budgets.json` exceeds baseline + `tolerance` (`*Ms` and `cls` absolute, `*Pct` relative; API p95 per endpoint by `apiP95Pct`); `a11y`: no (url, `axeRule`, impact) triple absent from `a11y.json` (selectors not compared); `security`: for each URL in `security.json`, no header present in the baseline is missing, HSTS `max-age` is not lower, `includeSubDomains`/`preload` are not dropped, no CSP directive gains a source, `'unsafe-inline'`, `'unsafe-eval'` or `*`, no cookie loses `Secure`/`HttpOnly`, and `SameSite` doesn't weaken (Strict > Lax > None). A `budget` or `header` allowedChanges entry covers its routes (03 § 11). `budget` measurement for the current run: on the URLs of the baseline's `budgets.json` route groups, each Lighthouse metric is the median of `performance.lighthouse.runs` runs per URL (performance-pack lab protocol), then the maximum across the route group's URLs; `scriptBytes`/`cssBytes` are the transferred bytes summed per URL, then the maximum; API `p95` per endpoint is measured as PRF-011 does. Timing metrics (`lcp`, `tbt`, `inp`, `p95`) are `skipped(slow-host)` when TR-111 says so; `cls`, `scriptBytes` and `cssBytes` are not.
- **REF-006** · P0 · baseline — Every baseline flow still passes with the same observable outcomes: per step, `ok`, `url`, `texts[]`, `api` and `db` equal the `flows.jsonl` record after flow normalisation (§ 1), unless covered by a `flow` allowedChanges entry.
- **REF-007** · W · baseline — Changed files the baseline can't see are listed, so the Planner can add flows or examples before relying on equivalence. A changed file is touched when it is a route file (adapter `routes.fileMap`) of a URL in `routes.jsonl` or `flows.jsonl`, the handler of an endpoint in `api.jsonl`, a file those import transitively (import graph), or a migration (`db/`). Every other changed file outside tests is listed.
- **REF-008** · W · review — Refactors whose diff against the baseline commit changes > 50 files or > 2,000 lines run in steps; each step is verified against the same baseline before the next begins (bounded blast radius, easy rollback).
- **REF-009** · P1 · baseline, browser — Visual equivalence: screenshots of every route group at each baseline viewport (mobile and desktop by default) match the baseline within `visual.maxDiffRatio` (share of differing pixels, pixelmatch semantics: YIQ threshold 0.1, anti-aliased pixels not counted), with dynamic regions masked (`visual.masks`: selectors for dates, carousels, ads). Each route group is captured at the URL recorded in the baseline manifest `visual[{ routeGroup, url }]`, full page, viewports `mobile` and `desktop` as defined in 03 § 10 (390×844 DPR 3, 1366×768 DPR 1), after fonts load and with animations disabled. Larger differences need a `visual` entry in `refactor.json`. Catches CSS/Tailwind refactors that change layout without changing HTML. Owner of visual equivalence in refactor runs: UX-009 does not run when a signed `quality/refactor.json` exists or `--against` is given.

- **REF-010** · P0 · baseline, edge — Rebuilds keep every live URL: with a remote baseline, every recorded URL whose recorded `status` is 200 — a URL recorded with a 3xx status passes when it redirects in one hop (301/308) to its recorded `location` mapped onto the service origin, or to that URL's `url-move` target; URLs recorded with 404/410 are `notApplicable` and listed in the report — (mapped onto the service origin; URLs on other hosts are listed and ignored) on the new build either (a) returns 200 with equivalent metadata — same indexability, self canonical, `<title>` and `<h1>` equal after whitespace and case normalisation, JSON-LD `@type` set ⊇ the recorded one — unless covered by a `metadata`/`text` allowedChanges entry; or (b) redirects in one hop with a permanent status (301/308; `web-delivery.redirectStatus` when that pack is on) to the target of the matching `url-move` entry in `refactor.json`, which returns an indexable 200 and is not `/` unless the source was `/`; or (c) returns 410 when it matches a `url-remove` entry or a web-delivery `retired` entry without successor. Part `depth` (P1; W when a `text` allowedChanges entry covers the URL): each URL passing under (a) has a `<main>` word count (same counting as `mainWords`) ≥ 0.7 × its recorded `mainWords`. **Where it runs:** always in G7 against the local build; additionally in the edge pass (G8) against `previewUrl` when set; and, once `project.stage` is `"live"` and `edge.production` is `true`, also against `production.origins` in the edge pass (read-only, 04 § 2 item 5). At the edge it checks the IDX-011 sample of 20 recorded URLs plus every recorded URL with a `url-move` entry, at most 200 per origin.
  - **Part `old-origin`** (P0; edge; stage `live`): when the remote baseline's origin host differs from the service origin host (a domain move), each sampled recorded URL on the old origin, under each of https, http, apex and www, answers with one 301/308 hop to its mapped (or `url-move`) target on the new origin. It never lands on `/` unless the source was `/`. The old host's `robots.txt` doesn't disallow Googlebot or Bingbot, since a blocked old domain hides its redirects. Review item (W): Search Console Change of Address and Bing Site Move were submitted.
- **REF-011** · P0 · baseline — Redirects survive: the baseline's redirect sources (§ 2) include every source declared on the base branch (a missing one is a finding: re-capture the baseline), and on the new build each source answers with the same status and a `Location` that, resolved against the request URL, mapped onto the service origin and normalised per 04 § 10, equals the baseline's, unless covered by a `url-move` or `url-remove` entry.
- **REF-012** · P1 · baseline — Side channels unchanged: for each baseline flow, the captured emails (count, subject, link paths, text-part hash after flow normalisation, § 1) and the third-party request set (host + event name) equal the baseline, unless covered by a `flow` allowedChanges entry for that flow.
- **REF-013** · P0 (part `sw-cache` P1) · baseline, http, browser — Old service workers are retired: for each service worker registration in the remote baseline (mapped onto the service origin), the new build either answers its `scriptURL` with 200, a JavaScript MIME type and a script that calls `self.registration.unregister()`, or sends `Clear-Site-Data` containing `"storage"` or `"cache"` (or `"*"`) on every HTML response of the service. A 404 there leaves the old worker controlling returning visitors. Baselines without `serviceworkers.jsonl`: main part `notApplicable`. Part `sw-cache` (browser channel; applies whenever the new build registers a service worker on a sampled page, with or without a baseline): (mutating stage, 04 § 4.2 step 8) after logging out (SEC-028's logout), revisiting each `app` page a flow saw while logged in yields no 200 response with CDP `serviceWorkerResponseSource: "cache-storage"`, and an RTE-006 probe URL loaded under the worker's control answers 404.
- **REF-014** · P1 · baseline, http — Re-platforming keeps image URLs (Google Search Central: image SEO — keep image URLs stable or redirect them): with a remote baseline, every image URL in the recorded routes' `images[]` (§ 2) whose host is the baseline origin's host, mapped onto the service origin, answers 200 with an `image/*` content type, or redirects in one hop (301/308) to a URL that does. A 404/410, a redirect chain or a redirect to a non-image response is a finding (`status-mismatch` / `redirect-chain` / `redirect-target`) listing the image URL and the baseline pages that used it. Exempt: images recorded only on routes that REF-010 doesn't keep (routes covered by a `url-remove` entry or a web-delivery `retired` entry without successor), and image URLs matched by a `url-remove` entry (which may answer 410). Images on other hosts are listed and ignored. Runs in G7 against the local build; above 2,000 image URLs per origin, 2,000 are drawn with the lock-digest PRNG.

Formats: `refactor.json` and the baseline layout are specified in `03-formats.md` §§ 11–12; normalisation and visual settings live in the policy section above.
