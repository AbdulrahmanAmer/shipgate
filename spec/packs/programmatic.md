# Pack: programmatic

> Page **families**: many pages generated from a dataset (city × service, products, locations, glossaries, integrations). Adds data contracts, quarantine, templates-as-data, an independent oracle, and anti-doorway checks on top of `web-delivery`.

Google treats pages that differ only by a swapped name as doorway pages / scaled content abuse. **Valid row ≠ eligible page ≠ indexable page** — three separate decisions, all computed by the Verifier.

### 1.1 Field types

| Type | Value | Rules |
|---|---|---|
| `id` | `^[A-Za-z0-9_-]{1,128}$` | unique per (family, locale); the same `id` in different locales marks alternates (PCF-006) |
| `slug` | `^[a-z0-9]+(?:-[a-z0-9]+)*$`, ≤ 80 | URL-007 |
| `slugList` | array of slugs | URL-008 |
| `text` | 1–500 Unicode code points after NFC, trimmed, no double spaces, no `<` `>` | `max`, `pattern` |
| `sourcedText` | ≥ `min` (default 80) code points, no `<` `>` | after removing (NFKC, case-folded) every occurrence of (a) the row's `primaryEntityField` value, (b) the value of every other field of the row except this one, as its stored string for `text`/`enum`/`id`/`slug` and as its TPL-003 `attr` and `text` for the other types (values shorter than 3 code points are not removed), and (c) every literal segment (text outside `{…}`) of the family's and its hubs' title/description/H1 templates, `staticFragments` values, breadcrumb names and field `label`s for the row's locale, ≥ `min` code points and ≥ 12 UAX #29 words not in ruleset `stop-words.json` for the row's locale remain |
| `int` / `number` | finite | `min`, `max` |
| `money` | `{ amountMinor: int ≥ 0, currency: ISO-4217 }` | DAT-010 |
| `geo` | `{ lat: -90..90, lng: -180..180 }` | DAT-011 |
| `url` | absolute `https:` | SEC-002 |
| `date` / `datetime` | ISO-8601 (datetime with offset) | |
| `enum` / `bool` | declared values / boolean | |
| `aiText` | text generated by a model into the dataset, 1–2,000 chars | DAT-013..016; never counts toward eligibility |

Field attributes: `required`, `source`, `observedAtField` + `maxAgeDays`, `regional` (context figure, never local), `label`; `max` ≤ 500; `pattern` is a Rust `regex`-crate expression that must match the whole value. A field is **rendered** when it has a `label`, or its type is `sourcedText` or `aiText`; a rendered field with a value for the row is a fact slot (inventory `facts`, TPL-003/007/008). Fields without a `label` (other than `sourcedText`/`aiText`) are rendered only through `{tokens}`. PCF-005 applies `format` to rendered fields.

**Per-locale word lists:** `stop-words.json` is `{ "<BCP 47 tag>": [word…] }`, words NFKC and case-folded, compared by equality with the NFKC, case-folded word. Lookup by locale (a family page's page locale is its row's locale) and the outcome for a locale with no entry: 04 § 15 *Page locale* (no silent `en` fallback; the check runs with `en` and raises the blocking `missing-element` finding owned by `operator`).

### 1.2 Validation — `PCF-*` (G0)
- **PCF-001** · P0 · cfg — Template tokens reference only required fields of the family, whitelisted constants (`{brand}`, `{siteName}`), `{self}`, or `{page}` in paginated hub templates. Part `hub-constant` (P0 · data): hub template fields are constant within each group.
- **PCF-002** · P0 · cfg — `localFacts` ⊆ declared fields (required or optional), none `regional`, includes `primaryEntityField`, and `|localFacts| ≥ minLocalFacts ≥ 3`; `measurement` needs a numeric/money/geo local fact; `sourcedText` needs `sourcedTextField` ∈ `localFacts` of type `sourcedText`. Every `localFacts` member other than `primaryEntityField` and fields of type `geo` is rendered (§ 1.1: has a `label`, or is `sourcedText`).
- **PCF-003** · P0 · cfg — `schemaTypes` ⊆ the public-page types of web-delivery § 6 *Allowed types by surface*, minus `Review`, `AggregateRating`, `FAQPage`, `HowTo`, `ClaimReview`, `SpecialAnnouncement`; `LocalBusiness` only with a `localBusiness` block (§ 1.3) whose mapped fields are required; `Offer` needs a required `money` field. Family JSON-LD values come from policy and data only: `Service.name` = oracle `h1`; `Service.areaServed` = `{ "@type": "Place", "name": <text of primaryEntityField> }`. With `Offer` in `schemaTypes`: `Offer.price` = the field named by family key `offerField` (default `null`: the family's only `money` field with `required: true`; `offerField` null with zero or several such fields, or naming a field that is not a required `money` field, is a PCF-003 finding) as a decimal string in major units with the ISO 4217 minor digits (`"285.00"`), `priceCurrency` = its currency, `url` = canonical, `availability` = `https://schema.org/InStock`. Inventory `schema.values` = `{ "<@type>": { "<property>": <value> } }` holding exactly these values; G4 compares the page's JSON-LD with it (`value-mismatch`).
- **PCF-004** · P0 · cfg, data — `rendering: isr` ⇔ `revalidateSeconds` set (an integer ≥ 1); every `source` exists (its `rights`: DAT-018); `ymyl: true` ⇒ required `reviewedBy` (text) and `sourceUrl` (url); `demand.field`, `lastmodField` and `priorityField` name declared fields, and `demand.field` has a registered `source`. Ranges: `maxQuarantineRate` ∈ [0, 1]; `localCardinalityRatio`, `maxSimilarity` and `rollout.minIndexRate` ∈ (0, 1]; `maxGeneratedUrls`, `links.count`, `links.maxClickDepth`, `rollout.pilot` and `rollout.waveSize` are integers ≥ 1; `minLocalFacts` is an integer ≥ 3 (PCF-002); `demand.min` and `rollout.minWaveAgeDays` are integers ≥ 0. `observedAtField` and `maxAgeDays` are declared together, `observedAtField` names a declared `date`/`datetime` field and `maxAgeDays` is an integer ≥ 1. `aiTextDisclosure`, when set, is a key of `staticFragments`. `priorityField` is a declared field of type `int`, `number`, `date`, `datetime` or `money` (compared by `amountMinor`); a row with the value missing sorts after every row that has one; when `priorityField` is `null` (the default, § 1.3) all rows compare equal and slug ascending decides. A violation is a PCF-004 finding naming the key. Part `priority-currency` (P0 · data): a `money` `priorityField` whose rows carry more than one currency. `rendering: ssg` and `ssr` are informational (only `isr` has checks).
- **PCF-005** · P0 · cfg — Every field rendered as text has a `format` (defaults per type, 04 § 15); `links.relation` is one of `nearest-by-geo`, `same-group:<field>`, `field-similarity:<fields>`, `declared:<field>`. **Related candidates** for a row: the other released eligible rows (§ 4-0) of the same family and locale, excluding rows served `noindex` by DAT-017 `onLow: "noindex"`. `nearest-by-geo` needs exactly one required `geo` field in the family (else a PCF-005 finding) and orders candidates by haversine distance between the two rows' values of that field (R = 6,371.0088 km, `f64`), nearest first; a candidate without a valid value is skipped. `same-group:<field>` and `field-similarity:<fields>` (comma-separated) name declared fields (else a PCF-005 finding); `same-group` candidates have a value equal to the current row's in `<field>`, `field-similarity` candidates need a value in every named field; their orders are 04 § 11 *Relations*. `declared:<field>` names a declared `slugList` field (else a PCF-005 finding); its slugs are the candidates in listed order (slugs of rows that are not candidates are skipped; this relation ignores the slug tie-break). Every relation then applies the 04 § 11 tie-break (slug ascending) except `declared`, excludes the row itself, and the first `links.count` candidates in the relation's order are the oracle `related` set.
- **PCF-006** · P0 · cfg — Multi-locale families declare `locales`, a `localeField` (or one dataset per locale) and templates keyed by locale (`"titleTemplates": { "en-US": [...], "es-US": [...] }`); rows of different locales with the same `id` are alternates. Every copy key (`titleTemplates`, `descriptionTemplates`, `h1Template`, `staticFragments` values, `breadcrumbs[].name`, field `label`, hub `titleTemplate`, `descriptionTemplate`, `h1Template`, `paginatedTitleTemplate`, `paginatedDescriptionTemplate`, `targetQueryTemplate`) is a bare value (used for every locale) or an object keyed by locale; a locale of `locales` with neither a keyed entry nor a bare value is a PCF-006 finding. `aiTextDisclosure` must name a `staticFragments` key that exists for every locale in which the family renders `aiText`.
- **PCF-007** · P0 · cfg — Hubs declare `service`, `minMembers` (default 2), `descriptionTemplate`, `paginatedTitleTemplate` and `paginatedDescriptionTemplate` (both containing `{page}`, so MET-001/002 uniqueness holds), and an optional `parent` hub; a hub with fewer released eligible members than `minMembers` is not generated (404). For an ungenerated hub the oracle sets each member's `hub` to the nearest generated ancestor via `parent`, else `null` (no hub link required), and drops every breadcrumb entry whose resolved `path` equals the ungenerated hub's pathname; the inventory, breadcrumbs and PLK-001 use these values. Part `members` (P0 · data): hub-member counting is evaluated at G2 over released eligible rows (§ 4-0). When a family sets `hub`, exactly one hub has `groupBy.family` = this family and a `routePattern` equal to the family's `hub` pattern; `groupBy.field` is a required field of the family and is the only family-field token of that `routePattern`; a mismatch is a PCF-007 finding naming both keys. The oracle `hub` of a row is that hub's pathname for the row's `groupBy.field` value (an ungenerated hub: as above).

### 1.3 Family keys

- `dataset` and `retired` paths (every per-locale dataset too) lie under `quality/data/`, so they are lock inputs and Operator-owned sources (03 § 8 *Operator-owned sources*); the policy JSON Schema enforces the prefix, and a path elsewhere is a CFG-001 finding.
- `retired`: path of a JSONL file of `{ id, slug, successor? }` (`successor` = the `id` of a live row of the family). Each retired slug's pathname returns 410, or 301 in one hop to the successor's pathname (URL-008).
- `indexation` (families and hubs): `"index"` | `"noindex"`; `noindex` serves every eligible page (hub page) with `noindex` and excludes it from sitemaps.
- `contentParams`: same shape and meaning as web-delivery `contentParams`, scoped to the family's `routePattern`; on a conflict for the same `param`, the family entry wins.
- `links.maxClickDepth`: overrides web-delivery `maxClickDepth` for LNK-003 on this family's pages.
- `priorityField`: a declared field name or `null`, default `null` (the § 1 example value is a placeholder, 03 § 3.5); `null` = all rows compare equal and slug ascending decides (PCF-004, CNT-006, ROL-002).
- `prebuild`: `"all"` | `{ top: int ≥ 1 }`; build-time routing only (adapter notes, § 8). Verification covers every released eligible row either way.
- `localBusiness`: `null` | `{ fields: { streetAddress, addressLocality, postalCode, addressCountry, telephone? } }`, each value naming a required family field (PCF-003) whose value fills that `LocalBusiness.address`/`telephone` property.

## 2. Data — `DAT-*`

- **DAT-001** · P0 · data — Dataset format: UTF-8 JSON Lines, one object per line, blank lines ignored. A missing `dataset` file, invalid UTF-8, or a line that is not a JSON object is a blocking `parse-error` finding owned by `operator` (file, line) and the family produces no inventory; a `retired` path whose file is missing is the same finding; an absent `retired` key means no retired rows. Every row is validated by the Verifier against the field types. A row with an unknown key is quarantined with rule DAT-001 (the implicit `aiText` sibling fields, 04 § 15 *aiText provenance*, are not unknown keys).
  - Part `types` (P0 · data): `shipgate codegen` (adapter codegen `types-from-policy`, 02-adapters) writes `quality/generated/types/<family>.<ext>` in the adapter's language; G2 regenerates them into `quality/out/generated/types/`, and a committed file that differs is a `stale` finding owned by `operator` (as the inventory, 03 § 13). Adapters without `types-from-policy`: `noAdapterSupport`.
  - Part `types-import` (W · ast): a family route file that declares a type, interface or struct with ≥ 3 of the family's field names instead of importing it from `quality/generated/types/`.
- **DAT-002** · P0 · data — Blank, whitespace-only and `null` = missing; reject `NaN`/`Infinity`, invalid dates, malformed slugs, out-of-range numbers, unknown enums, `<`/`>` in text, and text-like values (`text`, `sourcedText`, `aiText`, `enum`) that contain `{`, `}` or `${`, or that equal, after trim and case-fold, `undefined`, `null`, `nan` or `[object object]` (leak markers, MET-008).
- **DAT-003** · P0 · data — Required field missing/invalid/stale → row **quarantined** with rule IDs (no page, no links, no sitemap entry). Optional field missing, invalid or stale → its fact slot, sentence, meta claim and JSON-LD property are all omitted; an invalid optional value is listed in `quarantine.jsonl` with its rule and `"fields"`, without quarantining the row or counting toward DAT-004.
- **DAT-004** · P0† · data — Quarantined/total (per family and locale, § 4-0 *DAT-004 rate*) > `maxQuarantineRate` → build fails. Agents never edit data to change the rate.
- **DAT-005** · P0 · data — Duplicate `(family, locale, id)`, `(family, locale, slug)`, pathname or canonical → build failure (never first-row-wins). Finding: `duplicate-element`, showing the family, locale, the duplicated `id`, slug, pathname or canonical and the row `id`s (line numbers for a duplicated `id`).
- **DAT-006** · P0 · data, site, http — Generated set = inventory. Part `size` (P0 · data): inventory lines of type `page` and `hub` number ≤ `maxGeneratedUrls`; each `page` line comes from exactly one dataset row and each `hub` line from one group (no cartesian expansion). Part `served` (P0 · site): every crawled URL answering 200 whose pathname matches a family or hub `routePattern` (03 § 2.1) is the `pathname` of an inventory `page`/`hub` line, a pagination page of a hub (URL-006) or a declared static path; any other is `inconsistent-set` (URL). Part `omitted` (P0 · http): for each family and each row state `quarantined` (rows with a valid value for every `routePattern` token), `thin` with `onThin: omit`, `nearDuplicateOmitted`, `demandWithheld` and `unreleased` (§ 4-0), up to 20 rows drawn with the lock-digest PRNG (04 § 15; stream id `DAT-006:<family>:<state>`, candidate key the row `id`) are requested at the pathname the family `routePattern` gives for the row's token values (locale prefixed as the inventory does), skipping rows whose pathname is also an inventory line's pathname or a `previousSlugs`/`retired` pathname: the status must be 404; for `thin` with `onThin: noindex` it must be 200 with `noindex` and the URL absent from every sitemap; otherwise `status-mismatch` (URL, state, expected, actual). Part `fixtures` (P1 · data): a family without a fixture file (§ 7), or whose fixture file lacks one of the § 7 cases, is a blocking `missing-element` finding owned by `operator` naming the file and the missing cases (04 § 1.2 required-facts rules).
- **DAT-007** · P0† · data, html — No fallback chains (proven on output: every fact slot's `data-value` equals the row's own field; a regional field never fills a local slot). Part `source-hint` (W · ast): `??`/`||` around fact fields in family route files. Regional/national figures are their own `regional` fields with their own labels ("Texas average"), never in a local slot and never counted as local. (Filler text: MET-011.)
- **DAT-008** · P0 · cfg, data — Every field listed in `localFacts`, every `regional` field and every field rendered with `data-fact` (TPL-003), other than fields of type `id`, `slug`, `slugList` or `url` and the fields named by `observedAtField` or `lastmodField`, declares a registered `source`. Conflicts between suppliers are resolved upstream; the snapshot carries one value per field.
- **DAT-009** · P0 · data — Freshness via `observedAtField` vs `dataAsOf` (never the wall clock). Stale required → quarantine; stale optional → omitted. A missing `observedAtField` value counts as stale. A value is stale when `dataAsOf` − `observedAt` > `maxAgeDays` × 86,400 s; an `observedAt` later than `dataAsOf` is not stale. `observedAtField` and `maxAgeDays` are declared together (PCF-004).
- **DAT-010** · P0 · data, html — Money is `{amountMinor, currency}`; one formatter produces the visible text and `Offer.price`.
- **DAT-011** · P0 · data — Geo: both coordinates, finite, in range, not `(0, 0)`.
- **DAT-012** · P0 · data — YMYL rows without `reviewedBy` and https `sourceUrl` are quarantined. Part `advice` (P0 · cfg; owner `operator`, the text is policy): in YMYL families, `staticFragments`, field `label`s, breadcrumb names and title/description/H1 templates contain no sentence matching ruleset `advice-patterns.json` for each locale of the family's `locales` (imperative or modal recommendation patterns, e.g. "you should", "we recommend", "consult … before"); each match is a finding naming the policy key and the pattern index. `advice-patterns.json`: `{ "<BCP 47 tag>": [regex…] }` (Rust `regex` syntax), each matched case-insensitively against each UAX #29 sentence of the NFKC text (the copy keyed by that locale, else the bare value); lookup and no-entry outcome: 04 § 15 *Page locale*, with that locale as the page locale.

## 3. Templates as data — `TPL-*`

- **TPL-001** · P0 · cfg, ast — All user-visible copy on family and hub pages comes from policy (templates, labels, breadcrumbs, `staticFragments`). String literals > 80 characters rendered in family or hub route files fail (04 § 13 TPL-001). Agents write markup and structure, not copy.
- **TPL-002** · P0 · data — `applyTemplate` replaces `{token}` with formatted values (row field → constant → `{self}` → `{page}`). Unknown token, leftover brace, `${` or empty substitution is an error. No expressions or conditionals. The first title/description template whose result fits `web-delivery.titleLength.hardMax` / `descriptionLength.hardMax` is used; none fits → quarantine.
- **TPL-003** · P0 · html — Every rendered fact is an element with `data-fact="<field>"` and `data-value="<canonical machine value>"`, text = formatted value. Other template-token text (e.g. `{city}` in the H1, breadcrumb names, labels) is wrapped in `data-token="<name>"`. Optional sections are wrapped in `data-section="<field>"`; variable-length lists (related links, hub items) in a `data-list` container. The Verifier checks `data-value` exactly and the text against the oracle (inventory mode) or by parse-back (live mode).
  **Canonical machine value** (`data-value`, by field type): `int`/`number` → shortest round-trip ASCII decimal, `-` sign, `.` decimal point, no grouping, no exponent, no leading `+` or trailing zeros (`974447`, `-1.5`); `money` → `<amountMinor> <CURRENCY>` (`28500 USD`); `geo` → `<lat>,<lng>`, each a shortest round-trip decimal; `date` → `YYYY-MM-DD`; `datetime` → RFC 3339 in UTC with `Z`, seconds always present, fraction only when non-zero and without trailing zeros (`2026-09-30T00:00:00Z`); `bool` → `true`/`false`; `id`, `slug`, `text`, `enum`, `url` → the stored string after NFC; `sourcedText`/`aiText` → the TPL-007 hash. Inventory `page` lines carry it as `facts.<field>.attr` (03 § 13), and the app renders `attr` verbatim. Equality is byte equality of these strings.
- **TPL-004** · P0 · content — **Skeleton identity** (algorithm: 04 § 11): after masking token/fact text and variable attributes, collapsing `data-list` containers and hashing `data-section` subtrees separately (unreviewed `aiText` counts as absent), the canonical `<main>` serialisation is identical across a family's pages (per locale) and across the pages of each hub (per hub id and locale, paginated pages included; `data-list` items collapse by step 4), and every instance of a given section is identical too. Per-row prose and hidden doorway branches become impossible.
- **TPL-005** · P0 · content — Conditionals exist only around declared optional fields: a `data-section` whose name is neither a declared optional field of the family nor a `sourcedText`/`aiText` field (TPL-007), or a section present for a row whose field is absent (or absent while the field is present), is a TPL-005 finding (`skeleton-mismatch`), emitted from TPL-004 step 6a (04 § 11); TPL-004 does not report it again.
- **TPL-006** · P0† · content — No per-row generated prose in templates: emitted when the TPL-004 main hash or a section hash differs on a page and the first differing node path (04 § 11 step 8) is a text node (per-row prose); TPL-004 then does not report that page. Non-text differences stay TPL-004. Part `source-hint` (W · ast): string concatenation or template literals combining a family field with literal text in family route files. Long-form text per row is allowed only as a `sourcedText` field or a **reviewed** `aiText` field in the data (Operator-owned pipeline, DAT-013..016).
- **TPL-007** · P0 · html — `sourcedText` and `aiText` fields render as an element with `data-fact="<field>"` inside a `data-section="<field>"` wrapper; their `data-value` is the lowercase hex SHA-256 of the field's UTF-8 bytes after NFC, and the element's text, with whitespace runs collapsed to U+0020 and trimmed, equals the field value normalised the same way. This keeps TPL-003/TPL-004 decidable for long text.
- **TPL-008** · P0 · html — Page equals oracle (§ 6), in inventory mode, in the fixture pass (§ 7) and in live mode (against the snapshot-derived oracle). On every released eligible family page and every generated hub page (PCF-007) answering 200, in the raw HTML: part `facts` (family pages) — `<main>` contains exactly one `[data-fact=F]` element for each key F of the inventory line's `facts` and none for any other F (`missing-element` / `duplicate-element` / `forbidden-value`: URL, field); part `h1` — the text (NFC, whitespace collapsed, trimmed) of the page's `<h1>` equals the oracle `h1` (`value-mismatch`: URL, expected, actual; one `<h1>`: MET-003); part `robots` — on a page whose oracle `robots` contains `noindex`, the MET-006 directives that apply to every agent contain `noindex` (`missing-element`: URL); on the other pages MET-006 (1) owns the absence of `noindex`; part `tokens` (family pages) — for each token T of the family's `h1Template` that is a row field, the `<h1>` contains a `[data-token=T]` element whose text (normalised as for `h1`) equals the inventory `tokens.T` (`missing-element` / `value-mismatch`: URL, token, expected, actual). Values of fact slots: TPL-003/007; title and description: MET-001/002; canonical: URL-004; `lastmod`: IDX-003; alternates: I18-002; breadcrumbs, hub link and related links: PLK-001; JSON-LD: PCF-003.

## 4. Eligibility & scaled-content safety — `CNT-*`

- **CNT-001** · P0 · data — Eligible = not quarantined (row states, § 4-0) + ≥ `minLocalFacts` local facts **present and fresh in this row** + local evidence (CNT-002). The eligible set is the inventory.
- **CNT-002** · P0 · data — Local evidence matches `localEvidence` (`measurement`: a numeric/money/geo local fact present and fresh; `sourcedText`: the `sourcedTextField` passes the § 1.1 `sourcedText` rule for this row).
- **CNT-003** · P0 · data — Local cardinality: with n ≥ 2 eligible rows, each local fact has ≥ `max(2, ⌈localCardinalityRatio · n⌉)` distinct values. Distinct values are counted among the eligible rows in which the fact is present, with n the number of eligible rows; `geo` compares `(lat, lng)`, `money` compares `(amountMinor, currency)`, text compares NFC strings, other types their TPL-003 canonical machine value. Failure fails the build (a family design problem). Agents never relabel facts or drop rows to pass. Finding: `similarity`, showing the fact, family, locale, distinct count and required count.
- **CNT-004** · P0 · data — No two eligible rows share the full tuple of local-fact values apart from the entity name. Fails the build. Finding: `similarity`, showing the family, locale and the first 5 `id` pairs sharing the tuple.
- **CNT-005** · P0 · content — Exact duplicate `<main>` text (UAX #29 words, NFKC, lowercase, joined by U+0020) across indexable URLs fails when at least one of the two is a family or hub page (other pairs: CQ-002).
- **CNT-006** · P1 · data — Near-duplicates measured over **row-specific text only** (fact texts, `sourcedText`, list items; template text excluded, since TPL-004 makes it identical by design): MinHash/LSH as in 04 § 11; pairs above `maxSimilarity` get `onNearDuplicate`; top 20 pairs reported. Domain: rows that are neither quarantined nor `thin`, before DAT-017, CNT-006 and ROL-001 filtering. A row's text is its fact texts, `sourcedText` and reviewed-`aiText` texts and the link texts of its `data-list` containers computed from the pre-omission oracle, joined by U+0020 in page order; a row with fewer than 5 words is compared as one shingle of all its words and a row with no words is skipped. Pairs are resolved in descending Jaccard order, ties by (lower row's slug, higher row's slug) ascending; under `omit` a pair is skipped when either row is already `nearDuplicateOmitted`, otherwise the lower-`priorityField` row (ties → later slug) becomes `nearDuplicateOmitted`; under `fail` every pair above `maxSimilarity` is a finding.
- **CNT-007** · P0 · data — Ineligible rows follow `onThin` (`omit` default → 404 (row state `thin`, § 4-0; probed by DAT-006 `omitted`); `noindex` → served noindex, excluded from sitemap and related links). Agents never choose this.
- **CNT-008** · P0† · content — On family and hub pages, visible text matching `bannedClaims` (an entry matches when its NFKC, case-folded form occurs in the NFKC, case-folded text and is neither preceded nor followed by a letter or digit, so `#1` matches in `the #1 choice` but not in `#10`; the list applies to every locale of the family) fails unless inside a fact slot whose data value contains it.
- **CNT-009** · P0† · browser, html — On family and hub pages, in the rendered DOM at the mobile and desktop viewports, no element carrying `data-fact`, `data-token` or `data-section` is hidden, and no other `<main>` text is hidden. **Hidden** and its exemptions: 04 § 15 *Hidden content* and *Disclosure exemption*, the only definitions, shared with AEO-014, SE-109 and SE-123. Not findings: text with no letter or digit (icon glyphs), and text of < 30 UAX #29 words hidden only by the clip/size or off-screen conditions of that definition (still exposed to assistive technology) that contains no `<a href>` and no `data-fact` element (screen-reader labels; the AEO-014 `hidden-text` allowance), provided the page's non-exempt hidden elements in `<main>` hold < 100 UAX #29 words in total (each text node counted once; the AEO-014 `hidden-text` page total) — at or above that total every such element is a finding. Part `raw` (P0† · html): the same elements carry no `hidden` attribute, no `aria-hidden="true"` and no inline `style` with `display:none` or `visibility:hidden` (on themselves or an ancestor) in raw HTML, except an element inside a closed `<details>` (not its `<summary>`), the target of `aria-controls` of a control with `aria-expanded="false"`, a `role="tabpanel"` controlled by a `role="tab"`, a `<dialog>` or `[popover]`, or `<template>`/`<noscript>` (*Disclosure exemption* items 1–4 and 6, judged structurally in the raw DOM without activation; item 5 is judged by the main part only). Bot-only content (served to crawlers, not to users) is owned by RTE-010 and AEO-014 `agent-parity`. **Ownership:** inside `<main>` of family and hub pages, CNT-009 `owns` `AEO-014#hidden-text` and the hidden-link condition of SE-123.
- **CNT-010** · P1 · html — On family and hub pages, every visible date (04 § 15 *Visible dates*) is inside a `data-fact` element whose field is of type `date`/`datetime` (family pages) or equals the hub inventory line's `lastmod` (hub pages; § 6 *Hub `lastmod`*); any other visible date is a `forbidden-value` finding (build time is never a source).

## 4-0. Which rows each rule sees

- **All eligible rows** (released or not): eligibility (CNT-001/002), cardinality (CNT-003), tuple uniqueness (CNT-004), similarity (CNT-006/012), cannibalisation (KW-003).
- **Released eligible rows only:** inventory, sitemap, hubs and `minMembers`, related links (PLK-001), breadcrumbs, internal-link graph.
- **Row states** (each row has exactly one, first match wins):
  - `quarantined` — fails DAT-001, DAT-002, DAT-003, DAT-009, DAT-011 or DAT-012, or TPL-002 (no fitting title/description template): invalid data; no page, no links, no sitemap entry; listed in `quarantine.jsonl`; counts toward DAT-004.
  - `thin` — valid but fails CNT-001's local-fact clause or CNT-002; follows `onThin`: `omit` → 404, `noindex` → served noindex. Not quarantined, not counted.
  - `nearDuplicateOmitted` (CNT-006 with `onNearDuplicate: "omit"`), `demandWithheld` (DAT-017 `onLow: "omit"`), `unreleased` (ROL-001) → 404; not quarantined, not counted. Every 404 / noindex outcome of this list is probed on the served site by DAT-006 `omitted`. Rows served noindex by DAT-017 `onLow: "noindex"` keep state `eligible`.
  - `eligible` — otherwise.
- **DAT-004 rate** = `quarantined` rows ÷ all dataset rows, per family and locale.

## 4a. AI-written text — `DAT-013..016`

Evidence basis: Google's generative-AI guidance (updated 2026-10-01) says AI content must be fact-checked and reviewed before publishing, and that generating many pages without added value is scaled content abuse; quality raters flag automated main content as potentially lowest quality; case studies show unique data, not prose, separates programmatic winners from deindexed sites, and schema-constrained generation grounded in data outperforms freeform text. So AI text is allowed only as reviewed, grounded enrichment of real data.

- **DAT-013** · P0 · data — Every `aiText` field has provenance sibling fields: `<field>Model`, `<field>GeneratedAt`, `<field>PromptVersion`, and, once reviewed, `<field>ReviewedBy`, `<field>ReviewedAt`. Generation happens upstream in the Operator's pipeline (one schema field per prompt, never whole pages); agents never write it. Types: `<f>Model`, `<f>PromptVersion`, `<f>ReviewedBy` are `text`; `<f>GeneratedAt`, `<f>ReviewedAt` are `datetime`. An `aiText` value is *reviewed* when `ReviewedBy` and `ReviewedAt` are present and valid and `ReviewedAt` ≥ `GeneratedAt` (YMYL families also need `ReviewedBy` ∈ `ymylReviewers`, DAT-015). A value with `Model`, `GeneratedAt` or `PromptVersion` missing or invalid is unreviewed and is listed in `quarantine.jsonl` with `"rules": ["DAT-013"]` and `"fields": ["<field>"]`, without quarantining the row or counting toward DAT-004.
- **DAT-014** · P0 · data — Grounding: every number, percentage, currency amount and date in `aiText` (number detection: 04 § 15) equals a value of a field in the same row; otherwise the field is treated as absent for that row (as unreviewed `aiText`, 04 § 11 step 5) and listed in `quarantine.jsonl` with `"rules": ["DAT-014"]` and `"fields": ["<field>"]`, without quarantining the row or counting toward DAT-004. A percentage `n%` is grounded when an `int`/`number` field equals `n`, or equals `n/100` and has `format.style: percent`. Part `proper-nouns` (W · data): a word that starts with an uppercase letter, is not sentence-initial, is not in ruleset `stop-words.json` for the row's locale, and equals no word of the row's field values or of `allowedTerms` (NFKC, case-folded).
- **DAT-015** · P0† · data, html — Unreviewed `aiText` (not *reviewed* per DAT-013: no valid `ReviewedBy`/`ReviewedAt`, or `ReviewedAt` < `GeneratedAt`) is never rendered on indexable pages; the page still publishes from its data if otherwise eligible. YMYL families additionally require `<field>ReviewedBy` to be one of the family's `ymylReviewers`.
- **DAT-016** · P0 · data — `aiText` never counts toward `minLocalFacts`, local evidence, cardinality or tuple checks: eligibility comes from data only. It does count in similarity checks (CNT-006) as row-specific text.
- **CNT-011** · W · html — Pages rendering reviewed AI text show the family's `aiTextDisclosure` fragment: its text for the page locale (NFKC, whitespace collapsed) occurs in the visible text of the page's `<main>` (Google suggests telling readers how automated content was made). `aiTextDisclosure` unset while `aiText` fields render → `notConfigured(aiTextDisclosure)` (W).

## 4b. Demand, cannibalisation, cross-family duplicates

- **DAT-017** · P1 · data — With `demand` set, rows whose `demand.field` value is < `demand.min` or missing follow `onLow`: `"omit"` (default; 404, row state `demandWithheld`, § 4-0) or `"noindex"` (served noindex, excluded from sitemap and related links). The demand data is Operator-provided (e.g. a keyword tool export) with a declared `source`.
- **DAT-018** · P1 · cfg, html, review — Dataset rights (Google spam policies, scraped content: republishing other sites' content without adding value or citing the source; ODbL, CC-BY and similar licences require attribution on the page). Policy `programmatic.sources.<id>` keys: `rights` — one of `"owned"`, `"licensed"`, `"public-domain"`, `"open:<SPDX id>"`, `"facts-only"` (only facts, no creative text, copied from a third party), no default; `attribution` — string or `null`, a required key for `licensed` sources (`null` = the supplier requires none; the Auditor confirms it in part `licensed`) and a required non-null string for `open:` licences whose SPDX id is in ruleset `attribution-licences.json` (`[SPDX id…]`, e.g. `CC-BY-4.0`, `ODbL-1.0`); `attributionFragment` — a `staticFragments` key of every family with a rendered field (§ 1.1) whose `source` is that source (default `attribution-<id>`). Part `rights` (P1 · cfg): every source referenced by a `source` attribute of a family field has a valid `rights` value and the `attribution` key its `rights` requires, and, when `attribution` is non-null, its `attributionFragment` is a `staticFragments` key of every family with a rendered field (§ 1.1) whose `source` is that source; a missing or invalid value is a blocking `missing-element` finding owned by `operator` naming the key (`programmatic.sources.<id>.rights`, `.attribution`, or the family's `staticFragments.<key>`) (04 § 1.2 required-facts rules; agents cannot invent rights). Part `attribution` (P1 · html): every family page that renders a field (fact slot, `data-token` or `sourcedText`) whose source has a non-null `attribution` shows the source's `attributionFragment` text for the page locale (NFKC, whitespace collapsed) in the visible text of `<main>` or `<footer>`, and, when the source has a `url`, a visible `<a href>` to that `url` in the same element (`missing-element`: source id, URL). Part `licensed` (W · review): for each `licensed` and `facts-only` source the Auditor confirms that the supplier's terms allow republishing on a public website and programmatic use, and that `attribution` is what they require (one review item per source, target `source:<id>`, answered in `quality/audit/review.json`, 03 § 15, 04 § 1.7).
  - Missing-input outcomes: no `families` → `notApplicable`; a source with `rights: "owned"` or `"public-domain"` → parts `attribution` and `licensed` are `notApplicable` for it; `open:` licences not in `attribution-licences.json` with `attribution: null` → part `attribution` `notApplicable` for that source.
- **KW-003** · P1 · data, site — Each family's `targetQueryTemplate` (the copy for the row's locale, PCF-006) yields one target query per row through `applyTemplate` (TPL-002). **KW-003 normalisation** of a query, with the page locale (04 § 15 *Page locale*; for a family row, its locale; for a `web-delivery.targets` entry, the page locale of its `url`): UAX #29 words, NFKC, lowercase, words of ruleset `stop-words.json` for that locale removed, each word stemmed by the pinned Snowball stemmer of the locale's primary language (WP-104; a language with no Snowball stemmer: words are not stemmed), tokens sorted, joined by U+0020. Target pages: every eligible row (§ 4-0, released or not) of a family with `indexation: "index"` that is not served `noindex` by DAT-017 `onLow: "noindex"`, and every `web-delivery.targets` entry. No two target pages of the same page locale, across all families and `targets`, share a normalised query; rows with the same `id` in different locales (alternates, PCF-006) never conflict, and two `targets` entries with the same `url` are one target page. A shared query is a `duplicate-element` finding (normalised query, both URLs or row `id`s).
- **CNT-012** · P1 · content — Across families and non-programmatic pages, two indexable pages whose full `<main>` text has Jaccard similarity > 0.9 and < 1.0 (MinHash/LSH, 04 § 11; exact duplicates: CNT-005) are a finding (e.g. a neighbourhood page that duplicates its city page). Pairs of pages of the same family and locale, and pairs of pages of the same hub (paginated pages), are not compared (TPL-004 and CNT-006 own them).

## 4c. Staged rollout — `ROL-*`

Evidence basis: practitioner case studies consistently show pilot batches indexing well and bulk launches indexing poorly, with "scale only when the previous batch indexes ≥ 70 %" as a common gate. Not an official Google rule; it is low-regret risk control.

- **ROL-001** · P0 · data, site — With `rollout` set, only rows in released waves (`quality/rollout/<family>.json`, Operator-signed) are published: inventory, sitemap, hubs and related links include released pages only; unreleased rows return 404 (omission, not `noindex`: Google still crawls noindex pages; probed by DAT-006 `omitted`). With `rollout` set and no rollout file, zero waves are released (every row is `unreleased`) and the report states `0 released`.
- **ROL-002** · P0 · data — Wave 1 has ≤ `pilot` rows; later waves ≤ `waveSize`; rows are assigned to waves by `priorityField` (highest first), deterministically. Ties → slug ascending; released waves are fixed lists of `rowIds`; rows not yet in a wave are ranked for the next wave.
- **ROL-003** · P0 · cfg, data — `shipgate rollout release <family>` (Operator, 05 § 1) releases the next wave only if the previous wave is at least `minWaveAgeDays` old and its index rate ≥ `minIndexRate`, computed from an Operator-provided Search Console indexing export (`quality/data/indexing/<family>.csv`, 03 § 18). The rollout file records the evidence used. Part `evidence` (P0 · data): for each wave k ≥ 2, `waves[k].releasedAt` − `waves[k-1].releasedAt` ≥ `minWaveAgeDays` × 86,400 s (the wall clock is used only by `rollout release` to write `releasedAt`); the file at `waves[k].evidence.exportFile` has SHA-256 `exportSha256`; and the index rate of wave k-1 recomputed from it (04 § 15 *Index rate*) equals `evidence.indexRate` to within 0.0001 and is ≥ `minIndexRate`. A violation is a finding naming the wave (`value-mismatch`).
- **ROL-004** · W · data — With `rollout` set: the *latest aged wave* is the highest-index wave of `quality/rollout/<family>.json` whose `releasedAt` is at least `minWaveAgeDays` × 86,400 s before the reference time (04 § 15 *Reference time*). Its index rate (04 § 15 *Index rate*, from `quality/data/indexing/<family>.csv`) below 0.4 is a warning recommending a pause and a quality review of the family (`value-mismatch`: wave, rate). No `rollout`, no rollout file, or no aged wave → `notApplicable`; no export file → `skipped(no-indexing-export)`.

## 4d. Crawl efficiency — `CRW-*`

Evidence basis: Google's crawl-budget documentation (crawl capacity rises with stable, fast responses including TTFB and falls with slowdowns, 5xx and 429; support `304 Not Modified`; use 404/410 for removed pages; noindex still consumes crawling).

- **CRW-001** · P2 · http, edge — Family and hub pages: per family and per hub, one discarded warm-up request, then one GET per URL of a 100-URL sample drawn with the lock-digest PRNG (all pages when fewer), sent sequentially; the p75 of TTFB (request sent to first response byte; nearest rank: the value at position ⌈0.75·n⌉ of the n TTFBs sorted ascending) ≤ `crawl.ttfbMs` (default 500 ms). Edge pass: the family and hub pages among the 04 § 2 item 5 edge sample (none among them → the edge pass is `notApplicable` for this rule). The verify-environment measurement is a timing rule of TR-111: `skipped(slow-host)` below `performance.minBenchmarkIndex`, which defaults to 1000 even when the performance pack is not enabled (calibration: 04 § 6.3).
- **CRW-002** · P1 · http — Family and hub pages send `ETag` or `Last-Modified` (from the inventory `lastmod`: the row's `lastmodField` for family pages, the hub line's `lastmod` for hubs, § 6 *Hub `lastmod`*), and a repeat request with `If-None-Match` / `If-Modified-Since` returns `304` when unchanged. A sent `Last-Modified` equals the inventory `lastmod` as an HTTP-date (UTC, whole seconds); an `ETag` is equal across two identical requests; a page without an inventory `lastmod` must send `ETag`.
- **CRW-003** · W · cfg — Families using `onThin: "noindex"` get a reminder that omission (404) saves crawl capacity; use noindex only for pages users need.
- **CRW-004** · P1 · site — Closed link space (Google: calendars and parameter combinations create "infinite spaces"; block them or `nofollow` the links). Applies to the whole G4 crawl (04 § 10), not only family pages. A **trap hit** is a URL that the crawler dropped because of a 04 § 10 trap limit and that was discovered from an `a[href]` on an indexable 200 page, unless the link carries `rel~=nofollow` or the URL is disallowed for Googlebot by the robots.txt evaluation (04 § 15). Parts `params`, `values`, `depth`, `loop` and `maxurls` (each P1): `params` (> 3 query parameters on one URL), `values` (> 50 distinct values of one parameter under one path pattern), `depth` (path depth > 20), `loop` (a path in which the same sequence of 1–3 segments repeats ≥ 3 times consecutively, e.g. `/a/b/a/b/a/b`), and `maxurls` (`crawl.maxUrls` reached while ≥ 50 % of the crawled 200 HTML URLs are neither in a sitemap nor in the inventory; remote crawls stop at `crawl.remoteMaxUrls` by design, so this part is `skipped(remote)` there). One finding per path pattern and part: the pattern, the parameter or segment sequence, the first 3 dropped URLs and the first page linking to them (`budget-exceeded` for `maxurls`, `pattern-match` otherwise). The fix is robots.txt (parameter wildcard), `nofollow`, a bounded date range or removing the link.
  - Missing-input outcomes: none (no policy keys). Runs only when the crawl ran (`skipped(no-crawl)` otherwise); a URL dropped by a trap limit counts toward `incomplete-crawl` (04 § 10 *Complete crawl*, *Graph rules*) unless it was discovered only through `a[href]` with `rel~=nofollow` or is disallowed for Googlebot (04 § 15 *robots.txt evaluation*), so the fix this rule names never leaves the run PARTIAL.

## 5. Family links — `PLK-*`

- **PLK-001** · P1 · html — Family pages link every breadcrumb, the hub, and exactly the oracle's related set (`links.relation`, computed by the Verifier, relative to the current row, tie-break by slug, no self; candidate set and orders: PCF-005 *Related candidates*). Links are `a[href]`, compared as normalised pathnames (04 § 10; order not compared): each breadcrumb path (other than a `{self}` entry) and the hub path anywhere in `<body>`, each related path inside `<main>` (`missing-element`: URL, path). Part `short` (W): the oracle's related set has fewer than `links.count` paths (the page links all of them). Never invented targets. "First N alphabetically" is not a relation.
- **PLK-002** · P1 · html — On family pages, links inside `<main>` ⊆ breadcrumb ∪ hub ∪ related set (∪ DAT-018 `attribution` source links). `staticFragments` are plain text and contain no links.

## 6. The oracle and inventory

For every eligible row the Verifier computes from policy + data only: `pathname`, `canonical`, `locale`, `robots`, `title`, `description`, `h1`, `facts` (`{value, text, attr}`; `attr` = canonical machine value, TPL-003), `breadcrumbs`, `hub`, `related`, `alternates`, schema values (PCF-003), `lastmod`. G4 compares each served page's raw HTML with it through TPL-003, TPL-007, TPL-008, MET-001/002, URL-004, PLK-001 and PCF-003.

**Hub `lastmod`:** the greatest `lastmod` (as an instant) among the inventory `page` lines listed in that hub page's `items`; a hub page with no items has no `lastmod`, and then CNT-010 allows no visible date and CRW-002 requires `ETag`.

**Hub items:** per locale, a hub's items are the `page` lines of its group (the released eligible rows of `groupBy.family` in that locale whose `groupBy.field` value gives the hub's pathname), ordered by the family's `priorityField` descending (PCF-004 ordering), ties by slug ascending. With `pagination`, page k (1-based) holds the items at positions (k−1)·`pageSize` to k·`pageSize`−1 (0-based), and `pages` = max(1, ⌈n ÷ `pageSize`⌉) for n items; without `pagination` there is one page holding all items. Each hub inventory line is one hub page: `page` = k, `pages`, `items` = that page's pathnames in order, `lastmod` as above. A hub with a `parent` lists no child hub as an item; child-to-parent navigation is the breadcrumb.

**Data modes:**
- **`inventory` (default, every stack):** `shipgate inventory` (licence-free, so deploy pipelines can run it) writes `quality/generated/inventory/<family>.jsonl` before the build (03 § 13); the app's route generation, sitemap, links and breadcrumbs read only this file (from the directory in `SHIPGATE_INVENTORY_DIR` when that variable is set, § 7), and render `facts.*.text` and `facts.*.attr` verbatim. shipgate is the only formatter (ICU4X, pinned CLDR version recorded in the report), so there is nothing to keep in sync. Any language reads JSON lines, so this works for every stack.
- **`live`:** for data that changes between builds. The app reads its own source and formats with its own runtime; the oracle uses a snapshot produced at verify time by `family.snapshot: { db, sql }` (JSONL, same field schema), run in the read-only stage against the seeded database. A live-mode family without `family.snapshot` is a CFG-001 finding; a service `commands.snapshot` is never an oracle source (the Builder can write it). The snapshot is an Operator-owned source only when every returned row is one under 03 § 8 *Operator-owned sources* (seeded rows: inserted by a lock-input seed file and written by no other statement, 04 § 4.2 step 5 write attribution); otherwise the family has no oracle: one blocking `missing-element` finding per family, owned by `operator`, naming `family.snapshot` and the first 5 non-Operator-owned rows (04 § 1.2 required-facts rules), and its pages get no oracle comparison.

**Formatting across stacks (live mode).** Runtimes ship different Unicode CLDR versions, and CLDR changes visible output between versions (CLDR 42 replaced the space before AM/PM with U+202F, which changed Node 18.13+ and JDK 20+ output). No bridge between programs can make two runtimes with different locale data print identical strings, so live mode never compares formatted strings for equality. Instead:
1. `data-value` must be byte-equal to the canonical machine value (TPL-003) of the snapshot row's field.
2. The visible text is **parsed back into a value** (locale-aware: grouping and decimal separators, currency symbol or code, digits in any numbering system, date fields) and must equal `data-value`. All space variants (U+0020, U+00A0, U+202F, U+2009) are treated as one.
3. Text that can't be parsed back as the declared type fails with the exact characters shown, so the cause is visible.

## 7. Fixtures (Operator-owned)
Fixtures live in `quality/fixtures/programmatic/<family>.jsonl` (the family's row schema plus a required `fixture` key naming the case; the key is not an unknown key for DAT-001). Cases (each `fixture` value at least once): `longest-name` and `shortest-name` (longest/shortest entity names); `diacritics` (apostrophes/diacritics: `Coeur d'Alene`, `São Paulo`); `same-name` (same name in two regions); `optional-missing` (every optional field missing); `zero` (a numeric value `0`); `stale` (a stale fact); `script` (`</script><script>alert(1)</script>` in a text field); `javascript-url` (`javascript:alert(1)` in a `url` field); `literal-token` (literal `{city}` in a text field); `literal-undefined` (`undefined` as a text value); `previous-slugs` (a row with `previousSlugs`); `retired` (appended to the temporary `retired` file as `{ id, slug, successor? }` instead of the dataset); `thin` (fails CNT-001's local-fact clause); `multi-page-hub` (rows that give some hub ≥ 2 pages; satisfied without rows when the fixture inventory already has such a hub).

**Fixture pass:** `shipgate verify` with the programmatic pack generates the inventory from a temporary copy of the dataset (and `retired` file) with the fixture rows appended, into `quality/out/fixtures/inventory/<family>.jsonl`, and builds and starts the service a second time with `SHIPGATE_INVENTORY_DIR` pointing there (an extra G4 stage after the read-only stage on a freshly restored database, like the preview pass, 04 § 2); the production inventory is never touched. Each fixture row gets its § 4-0 state by the same rules as any row (the values of `script`, `javascript-url`, `literal-token` and `literal-undefined` fail DAT-002 / SEC-002 `data`: the row is quarantined when the field is required, else the value is omitted, DAT-003; `thin` is `thin`). In the fixture build every fixture row is checked without sampling: eligible rows by the G4 oracle comparison (§ 6, including TPL-008), TPL-004, TPL-006, MET-008, SCH-002 and SEC-002 `html`; every other state by DAT-006 `omitted`; `previous-slugs` and `retired` by URL-008. Findings name the case (`fixture: <case>`). Live-mode families: fixture rows join the snapshot for G2 row states only, and the fixture build is `skipped(live-mode)` for them (shipgate does not write the app's data source).

**Missing fixtures:** a family without a fixture file, or whose fixture file lacks one of the cases above, is a DAT-006 `fixtures` finding.
