# Pack: ops

> Logs, health, error reporting, email, configuration and process lifecycle, checked inside the verify environment. Production monitoring (uptime, real-user metrics) is a separate later product.

---

## 1. Policy section

```jsonc
"ops": {                                       // health endpoints = verifyEnv.health entries with endpoint: true
  "errorReporting": { "provider": "sentry", "dsnVar": "SENTRY_DSN" },    // or null
  "email": {
    "fromDomains": ["example.com"],
    "bulkSenders": ["newsletter@example.com"],
    "dnsCheck": true,                                                 // SPF/DKIM/DMARC checked in the edge pass
    "dkimSelectors": []                                               // DKIM selectors per sending setup (OPS-006 `dkim`); default []
  },
  "env": {
    "example": ".env.example",                                        // one file name applied to every service, relative to services[].path (default ".env.example"); a service without that file: a blocking OPS-010 finding `missing-element` owned by `builder` naming the file (the start probe still runs), and ARC-015's env mention fails
    "optional": []                                                    // vars in the example file the service may start without
  },
  "domain": { "minDaysValid": 60 },                                   // OPS-016: integer days; default 60
  "shutdownSec": 10                                                   // OPS-012
}
```
`errorReporting.provider` is a key of ruleset `error-reporting-providers.json` (`{ "<provider>": { hosts: [hostPattern], sdkPackages: [] } }`: sentry, bugsnag, rollbar, honeybadger, datadog, newrelic, posthog); unknown values are a CFG-006 `schema-violation` (a value that is no key of the pinned `error-reporting-providers.json`). Provider hosts = that entry's `hosts` ∪ `hosts[]` entries with purpose `monitoring`. With `errorReporting: null`: OPS-003 and OPS-011 are `notApplicable`.

## 2. Rules — `OPS-*`

- **OPS-001** · P0 · http, browser — Service logs captured during G4/G6 contain no secrets (classification of SEC-005), test-account passwords, session tokens, card numbers or full email addresses of test accounts. Card numbers: a run of 13–19 digits (groups of 4 may be separated by one space or hyphen) bounded by non-alphanumeric characters on both sides, Luhn-valid, whose first digits are an issuer prefix (`4`; `34`, `37`; `51`–`55`, `2221`–`2720`; `6011`, `65`; `3528`–`3589`; `62`). Failure class `leak` (log line, matched kind, masked value).
- **OPS-002** · P1 · http — Health endpoints (`verifyEnv.health` with `endpoint: true`) return 200 when dependencies are up and a non-200 status when the database is down (shares fault injection with RES-001). The health response body contains no SEC-005 secret value, no JSON key (any depth) named `version`, `versions`, `commit`, `gitSha` or `build` except at the top level, and no match of `(?i)\b(<name>)\b.{0,20}?\d+\.\d+`, where `<name>` is an `engine` of `verifyEnv.databases` (with `postgres`, `postgresql` and `pg` equivalent) or the name of a direct dependency (ARC-007 manifest sections) of the service with ≥ 3 characters; the finding (`leak`) shows the matched text.
- **OPS-003** · W · ast, cfg, http — An error-reporting integration is configured for each service (a provider `sdkPackages` entry is a dependency of the service) and reads its DSN (`dsnVar`) from the env module. In the verify environment its traffic is captured by the egress proxy and never sent. Part `event` (http): during the database-down fault stage (04 § 4.5), over the API-002 example and generated requests (04 § 15) and the `fault-20` sample, every request that answers 5xx is followed within 10 s by a request to a provider host recorded by the egress proxy (one provider request may cover several 5xx answered within 1 s of each other); a 5xx with none is a finding (`missing-element`, showing the request and its time). No 5xx observed: `skipped(no-5xx)`.
- **OPS-004** · P1 · browser — Emails captured by the SMTP sink during flows: every `<a href>` and plain-text URL is absolute (`http`/`https`, or `mailto:`/`tel:`). A link is a finding (`forbidden-value`) when its host is `localhost`, a loopback or private address, a `*.shipgate.test` name, a `web-delivery.aliasHosts` entry or a resolved adapter `defaultAliasHosts` entry (URL-011), or when it is on a service host but not on that service's origin (wrong scheme or port); links to other hosts, `mailto:` and `tel:` are not judged. A relative link or an unrendered placeholder (`{{…}}`, `%…%`, `${…}`) is a finding (`value-mismatch`). Every HTML email has a plain-text part (`missing-element`); sender domain ∈ `fromDomains` (`forbidden-value`).
- **OPS-005** · P1 · browser — Bulk/marketing emails (from `bulkSenders`) include `List-Unsubscribe` and `List-Unsubscribe-Post: List-Unsubscribe=One-Click` headers, the HTML part has an `<a href>` whose text, after NFKC, case-fold and whitespace collapse, contains an entry of ruleset `unsubscribe-labels.json` for the page locale (04 § 15) of the page where the flow's submitting step ran (the last URL before the step that triggered the email; an email no flow step triggered, e.g. from a job run, uses the page locale of the service's `/`; the email's `lang`, `Content-Language` and subject are never used; a locale with no entry: the 04 § 15 *No entry* outcome), and the text part contains a URL. Failure classes `missing-header` (the header) and `missing-element` (link or URL). Part `postal` (P1): their text part contains `business.json` `postalAddress` (or `locations[0].address`), as CAN-SPAM requires, compared with LOC-001's normalised containment (`missing-element`). No `postalAddress` and no `locations[0].address` while a bulk email was captured: one blocking `missing-element` finding owned by `operator` naming `business.json` `postalAddress` (04 § 1.2 required-facts rules), never `notConfigured`.
- **OPS-006** · P1 · edge — With `dnsCheck`, for each `fromDomains` entry (read-only DNS lookups in G8): part `spf`: exactly one TXT record at the domain starting `v=spf1`; part `dkim`: for each selector in `email.dkimSelectors`, a TXT record at `<selector>._domainkey.<domain>` containing `p=` with a non-empty value (no selectors declared → part `dkim` is `notConfigured(email.dkimSelectors)`, owner `operator`; DKIM can't be checked without a selector); part `dmarc`: a TXT record at `_dmarc.<domain>` starting `v=DMARC1` with a `p=` tag.
- **OPS-007** · P1 · http — Every response of a service process to a request shipgate sends in G4 (crawl, contract, security and preview-pass requests; not host-emulation static files, 04 § 3) carries a request id in `x-request-id`, `request-id` or `traceparent` (the id is its trace-id field), and the same id appears in the service log line for that request.
- **OPS-008** · W · http — Denied probes are visible: each security probe answered 401, 403 or 429 (SEC-* authentication, authorization, CSRF and rate-limit probes) produces a service log line at level warn or higher (structured `level`/`severity` field, else a level token per adapter `loggerApis`) that contains the response's request id (OPS-007).
- **OPS-009** · P1 · cfg — Toolchain versions are pinned and agree: each service pins its runtime (e.g. `package.json` `engines.node` within one major, `.nvmrc`/`.node-version`, `.python-version` or `requires-python`, `.ruby-version`, `.tool-versions`/`mise.toml`) and its package manager exactly (`packageManager` field, or the lockfile's declared version); every runtime version found in those files, in the host config for `services[].host` (e.g. `netlify.toml` `NODE_VERSION`, Cloudflare Pages `NODE_VERSION`; Vercel reads `engines.node`) and in CI workflow files (e.g. `actions/setup-node` `node-version`, `setup-python` `python-version`; `*-version-file` inputs follow the file) resolves to the same major; when any source pins an exact version, every other source is that exact version or a range containing it. Version sources per runtime: ruleset `runtime-pins` = `{ "<runtime>": { "identity": "major" | "major.minor", "sources": [{ "file": "<glob>", "kind": "manifest" | "ci" | "host", "extract": "<Rust regex, one capture group = the version spec>" }] } }`; `identity` is `major` for `node` and `major.minor` for `python`, `ruby`, `go` and `php`. "Same major" above means the same identity: two sources agree when their versions have the same identity components. Failure class `inconsistent-set` (each source with its version).
- **OPS-010** · P1 · cfg, http — Environment contract: every variable read by the service (the `architecture.<service>.envModule` when set, else adapter `envReadApis` call sites with literal names) appears in `env.example` (`missing-element`, the variable); shipgate-injected variables (SEC-005 list) are exempt. A service without the `env.example` file is one blocking `missing-element` finding owned by `builder` naming the file (the file is in the Builder's write scope, so its absence is never `notConfigured`). Start probe (04 § 4.1, after BLD-005): the service started with its verify environment minus one variable, chosen by the PRNG seeded with the lock digest among the env-module variables (the variables read by the service, as above) that are not in `env.optional` and not shipgate-injected, exits non-zero within `verifyEnv.health.<service>.timeoutSec` and its output names the variable. Exit 0, health 200, or no exit within the timeout is a finding (`runtime-error`). No eligible variable: the start probe is `notApplicable`.
- **OPS-011** · P1 · http, browser — Error-reporting payloads are clean: events sent to the `errorReporting` provider's hosts during G4/G6 (server-side via the egress proxy, client-side as recorded browser requests), including those from injected errors (OPS-003), contain no secrets (SEC-005 classification), test-account passwords, session token values or test-account email addresses. Log contents are owned by OPS-001.
- **OPS-012** · W · http — Graceful shutdown, in its own mutating stage (04 § 4.2 step 8): after `SIGTERM` the service exits within `shutdownSec` with code 0 or 143 (`runtime-error` otherwise), and a request in flight when the signal was sent completes. The request in flight is the first contract operation (path byte order, then method) with a JSON request body and a documented 2xx response, built by 04 § 15 contract request generation and sent with its body in 4 chunks 250 ms apart; `SIGTERM` is sent after the second chunk; the request must complete with its documented 2xx status (a reset, timeout or 5xx is `runtime-error`). No such operation: that clause is `notApplicable` (the exit clause still applies). On Windows (no `SIGTERM` for console processes): `skipped(platform)`.
- **OPS-013** · W · db — Scheduled jobs don't overlap: after a `data-api.jobs` entry's `run` executes twice concurrently on one fresh instance (mutating stage, 04 § 4.2 step 8), its `writes` table contents equal those after a single run on another fresh instance (04 § 15 "No side effect" row hashing, restricted to `writes`), and the concurrent pair produces no more captured emails or egress requests than the single run (a lock, `SKIP LOCKED` or platform concurrency limit). Sequential idempotency is owned by JOB-002.
- **OPS-014** · W · browser — HTML emails captured by the SMTP sink during flows render for everyone: part `lang` — the root `<html>` has a non-empty `lang`; part `alt` — every `<img>` has an `alt` attribute (empty allowed); part `dark-logo` — the logo (first `<img>` whose `src`, `alt`, `class` or `id` contains `logo`, case-insensitive, else the first `<img>`; none → `notApplicable`), screenshotted alone in Chromium with `omitBackground`, fails when ≥ 10 % of its pixels have alpha < 0.5, the mean colour of its pixels with alpha ≥ 0.5 has a contrast ratio < 3:1 against `#121212`, and the `<img>`'s computed `background-color` is transparent (a dark transparent logo vanishes in dark-mode clients).
- **OPS-015** · P1 (parts `soon`, `eol-unknown` W) · cfg, deps — Supported versions (OWASP Top 10 A06; PCI DSS 4.0.1 req. 6.3.3: vulnerability scanning finds nothing once a version is out of support). Versions judged: every runtime and package-manager version OPS-009 finds (manifest, host config, CI; a range counts as the lowest version it admits); the resolved lockfile version of each direct dependency (ARC-007 manifest sections) whose package name is a key of ruleset `eol-products.json`; each `verifyEnv.databases[].version`; and the WordPress core version SEC-073 determines. Ruleset `eol-products.json` = `{ "<runtime id, verifyEnv.databases engine or package name>": "<product>" }` (e.g. `node` → `nodejs`, `postgres` → `postgresql`, `next` → `nextjs`, `django` → `django`, `laravel/framework` → `laravel`). Each version maps to the cycle of the `eol-dates` data snapshot (03 § 19 `purpose: "data"`, `refresh: "fetch"`; built from endoflife.date; `{ "<product>": [{ "cycle": "<string>", "eol": "YYYY-MM-DD" | false }] }`) whose `cycle` equals the version's first k dot-separated components, k = the number of components of `cycle`. Main part: a version whose cycle has an `eol` date earlier than the expiry clock (01 § 5.4; a wall-clock read, non-deterministic per TR-103) is a finding `stale` showing the product, cycle, EOL date and source file. Part `soon` (W): `eol` within 90 days after that time (`stale`). Part `eol-unknown` (W): a version whose product or cycle the snapshot lacks (listed). Waivers use scope kind `package` (03 § 3.4); the waiver's `expires` is the re-evaluation date.
- **OPS-016** · P1 · edge — Domain registration, with `edge.production: true` (otherwise `notApplicable`). For the registrable domain (Public Suffix List) of each `production.origins` host, an RDAP lookup in the edge pass (IANA bootstrap file `https://data.iana.org/rdap/dns.json`, then the registry's RDAP service; RFC 9082/9083; read-only GETs) reports an `events` entry with `eventAction: "expiration"` whose date is ≥ `ops.domain.minDaysValid` days after the edge pass's wall clock, and no `status` among `pending delete`, `redemption period`, `client hold`, `server hold` (`stale`, showing the domain, the date or status). A TLD with no RDAP service in the bootstrap file, or an RDAP answer without an `expiration` event (some registries don't publish it), or a lookup that fails after one retry: the expiry clause is `skipped(no-rdap)`, listed, with one W review item "confirm the registration term" (the `status` clause still applies to any answer received). Wall-clock observation of a live system, non-deterministic as SEC-056 (TR-103).
