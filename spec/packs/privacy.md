# Pack: privacy

> Consent, tracking, third parties and legal pages, proven by what the browser actually loads and stores. Not legal advice: shipgate checks declared obligations mechanically; the Operator (with counsel) decides which jurisdictions and processors apply.

`legalPages` accepts exactly the keys shown; each value is `{ path, index: bool }`; `path` is a URL pattern without wildcards, or `{ "<locale tag>": pattern }` (a string applies to every locale; a map is read for the page locale by the 04 § 15 *Page locale* lookup, and a locale without an entry uses the entry for `web-delivery.defaultLocale`, else the first key in byte order). The legal page of a page is the one for that page's locale; PRV-006 requires the footer link of a page to point to it; every distinct pattern must answer 200 and counts as an exact-path `indexRules` entry.

**Validation** (CFG-006): `consent.required: false` is accepted only when ruleset `consent-models.json` (`{ "<jurisdiction>": "opt-in" | "opt-out" }`) gives every declared jurisdiction `opt-out` (a jurisdiction absent from the file counts as `opt-in`); each `jurisdictionsNotTargeted[].reason` is non-empty and its `jurisdiction` is not also in `jurisdictions`; each `smsForms` entry is a form key of a declared flow; each `art27Exempt` key is `eu-gdpr` or `uk-gdpr`, is in `jurisdictions`, and has a non-empty reason; each `marketingForms[].formKey` is a form key of a declared flow, and an entry with `confirmation: "provider"` has a non-empty `reason`. Each failure is a `schema-violation` naming the key path.

**Definitions:** *footer* = the `<footer>` element or `contentinfo` landmark; *page-level footer* = the page-level `contentinfo` landmark as defined in UX-016. *Google tag hosts* and *Google measurement requests* = ruleset `google-tags.json` (hosts, tag-library paths such as `/gtag/js` and `/gtm.js`, and measurement paths such as `/g/collect`, `/pagead/`, `/ccm/`). `google-tags.json` shape: `{ "hosts": [host pattern], "libraryPaths": [path], "measurementPaths": [path], "gcd": [{ "pattern": "<regex over the whole gcd value>", "default": { "ad_storage": "granted"|"denied", "analytics_storage": …, "ad_user_data": …, "ad_personalization": … }, "update": { same keys } }] }`. A `gcd` value is decoded by the first row whose regex matches it; none matches: `value-mismatch` (PRV-011). "Denied-by-default for all four types" = every `default` value of the decoding row is `denied`. Rows are generated by WP-104 from Google's Consent Mode documentation. *Typed values* = `value`s of `fill` steps in flows (after generator expansion). *EU consumer jurisdiction* = any of `eu-consumer`, `de`, `at`. *GDPR-family jurisdiction* = `eu-gdpr`, `uk-gdpr` or one listed as GDPR-family in the `jurisdictions` comment above. *Page locale*, the per-locale ruleset lookup and the outcome when a locale has no entry: 04 § 15 *Page locale* (never `<html lang>`); *indexable*: 04 § 15 *Indexable page*. *Price* = text matching the page locale's CLDR currency pattern.

*Sampled page*: for a rule whose channels include `browser`, a browser-sampled page; for every other rule, a page of the HTTP sample (both 04 § 10). *Sampled public page* = a sampled page on a `public` surface. Rules on *product pages* (PRV-025, PRV-026, PRV-033, PRV-040) examine every product page of the HTTP sample and every page a flow visits.

*Third-party host* = a host other than the project's origins (04 § 6.1); one matching no `hosts[]` entry has `essential: false`. A request to a host matching no `hosts[]` entry is reported by PRV-005 only; PRV-001 and PRV-002 judge the hosts present in `hosts[]`.

*Phrase match*: a text has a phrase match in a phrase list (the file the rule names) when, with both NFKC-normalised, case-folded and whitespace-collapsed, a phrase of the list for the page locale (lookup and no-entry outcome: 04 § 15 *Page locale*) occurs in the text as a substring. Wherever a rule of this pack says text or an accessible name "matches" or is "matching" a list of a ruleset data file, it means a phrase match; only `banner.*Label` (*Label match*) and `ccpa.linkLabels` (PRV-013) use equality.

*Encodings of a value* (PRV-010, PRV-019): the value; its percent-encoding (RFC 3986, uppercase hex, and again with `+` for spaces); its JSON string escape (RFC 8259, both with `\uXXXX` escapes and with raw non-ASCII); its base64 of the UTF-8 bytes in the standard and the URL-safe alphabet, each with and without `=` padding, at each of the three byte alignments (the value's bytes preceded by 0, 1 or 2 arbitrary bytes, the output characters that depend on those bytes, and on the unknown following bytes, dropped). A request *contains* the value when an encoding occurs as a substring of its URL, a header value, its body decoded as UTF-8 (lossy), or a WebSocket text frame.

*Page state*: of a sampled page, its state at the end of its PRV-001 observation window; of a flow page, the DOM of each view of the flow (A11-030 definition of view), read when the step that produced the view has settled (no request in flight for 500 ms, cap 5 s) and before the next step runs.

*Fact containment*: text and value are NFKC-normalised, case-folded and whitespace-collapsed, and the value occurs in the text as a substring. For `legal.registerNumber`, `vatId`, `mailOrderNumber`, `icpNumber`, `cnpj` and `abn`, spaces, hyphens, dots and slashes are also removed from both sides. An `emails[]` value may instead be the target of a `mailto:` link in the element. A `phones[]` value is contained when a phone-like text of the element, parsed with libphonenumber and the 04 § 15 default region, equals its `e164`, or a `tel:` link in the element equals it. `postalAddress` and every other address-shaped value: LOC-001 normalised containment. "Contains" in this pack means fact containment unless a rule states another test.

*Product page* = a public page that has `Product` + `Offer` JSON-LD, or whose `<main>` contains a *Price* and a control whose accessible name has a phrase match in ruleset `add-to-cart-labels.json` or `order-button-labels.json`. Removing the markup does not remove a page from scope.

*Identification page* (PRV-030, PRV-033, PRV-034, PRV-037, PRV-042) = `legalPages.imprint`, else web-delivery `trustPages.contact`, else `trustPages.about`. When none of these is declared, PRV-033 part `in-ecommerce`, PRV-037 part `contact` and PRV-042 part `dmca-agent` (when it has no `legalPages.terms` either) each emit one blocking `missing-element` finding owned by `operator` naming `privacy.legalPages.imprint`, as PRV-030 does (04 § 1.2 required-facts rules).

*Observation window* (PRV-001, PRV-002, PRV-003, PRV-004, PRV-014): a fresh browser context with Playwright's clock installed at context creation; after navigation, wait until no request has been in flight for 500 ms (cap 15 s after `load`), then `clock.fastForward` 60 s, then wait again for 500 ms network idle (cap 5 s). Requests, cookies (all domains) and storage entries are read at the end of the window. Each navigation of PRV-002/003/004/014 gets its own window. The fresh context is created once per scenario: per sampled page for PRV-001; once per context a rule names (accept context, reject context, pre-consent context, PRV-004 GPC context). Later navigations in it reuse it and repeat the wait, `fastForward`, wait cycle.

*Pre-consent context* (PRV-003 `server-side`): one fresh browser context that loads the three consent pages in order with no consent interaction, one observation window each.

*Consent not required*: `consent.required: false` asserts that every declared jurisdiction allows non-essential cookies and third-party requests without prior consent (Validation above). With `false`: PRV-001, PRV-002, PRV-003 (all parts), PRV-011 and PRV-014 are `notApplicable`; PRV-004 runs its windows without the accept step; PRV-007 and PRV-015 use a fresh context with no consent interaction (PRV-015 reads its cookies at the end of the third consent page's window); PRV-013 and every other rule run unchanged.

*Essential cookie / storage entry*: a cookie name, `localStorage`/`sessionStorage` key or IndexedDB database name that equals an `essentialCookies` entry or a `verifyEnv.auth.sessionCookies` entry, or starts with an entry's text before a trailing `*` (e.g. `__Host-csrf*`). Every other cookie or storage entry is non-essential.

*Consent pages* (PRV-002, PRV-003, PRV-004, PRV-014): the first sampled public page by URL (lexicographic), then the next two sampled public pages in that order. With fewer than 3 sampled public pages the list is completed by repeating the last page (a fresh navigation to the same URL), so each of these rules always observes 3 windows. With no sampled public page they are `notApplicable`. With `consent.required: true` and no `consent.banner`, or no control with a Label match for `acceptLabel` or for `rejectLabel` in the first layer of the first consent page, the accept or reject context cannot be built: PRV-003, PRV-004 (main part), PRV-007, PRV-011 (its after-accept and after-reject checks), PRV-014 (other than its own `consent.banner` finding, PRV-002), PRV-015 and PRV-036 part `string` are `blocked(prerequisite: PRV-002)`, and PRV-002 carries the blocking finding; PRV-001, PRV-011's default-command and first-request checks and PRV-036 part `cmp` still run. *Label match*: a control matches a `banner.*Label` when its accessible name, trimmed and case-folded, equals the label for the page locale (a string label applies to every locale; a locale map falls back to `en`). *First layer* = the elements visible at the end of the observation window with no prior interaction. *Reachable* = focused within 50 Tab presses from page start.

## 2. Rules — `PRV-*`

- **PRV-001** · P0 · browser — Before any consent interaction, at the end of the observation window of each sampled page, no non-essential cookie or storage entry is present and no request has gone to a third-party host without `essential: true` (requests are recorded even when stubbed, 04 § 6.1). Only exception: with `consent.googleConsentMode: "advanced"`, requests to Google tag hosts are allowed when they are tag-library loads or measurement requests carrying `gcs=G100`, carry no `Cookie` header, and set no cookie (first- or third-party). With `"off"` or `"basic"`, no Google tag host request occurs before consent. Findings: `forbidden-value` showing the cookie, storage key or request URL.
- **PRV-002** · P0 · browser — Reject is as easy as accept: on the first consent page, a control that matches `rejectLabel` is in the first layer and is reachable; after activating it, the observation windows of the next two consent pages contain no non-essential cookie or storage entry and no request to a third-party host without `essential: true` (PRV-001's advanced-mode exception applies). Missing or unreachable control: `missing-element`; a forbidden cookie or request: `forbidden-value`. No control in the first layer of the first consent page has a Label match for `acceptLabel`: builder-owned `missing-element` naming `privacy.consent.banner.acceptLabel`. With `consent.required: true` and no `consent.banner`, PRV-002 and PRV-014 each emit one blocking `missing-element` finding owned by `operator` naming `privacy.consent.banner`.
- **PRV-003** · P1 · browser, http — Consent withdrawal: in a context where the `acceptLabel` control was activated on the first consent page (the *PRV-003 accept context*), activate the control matching `banner.reopenLabel`, then the control matching `rejectLabel` in the reopened layer (either absent: `missing-element`); the observation window of the next consent page has no request to a third-party host without `essential: true` and no non-essential cookie or storage entry that was not present before withdrawal (`forbidden-value`). Hosts absent from `hosts[]` are owned by PRV-005; PRV-003 `main` judges only hosts present in `hosts[]`. Part `server-side` (P0; exclusive stage, 04 § 4.2 step 8): server-side requests seen by the egress proxy to `hosts[]` entries with purpose `analytics` or `advertising` (server-side tagging, Meta CAPI, …) happen only for sessions that have accepted. None occur before consent or after rejection. Attribution: the pre-consent context (§ 1) and the PRV-002 reject context each run alone, with no other browser, crawler or flow activity against the verify environment. Any such egress seen from the first navigation of the pre-consent context, or of the reject context, until 5 s after the end of that context's last observation window is a `forbidden-value` finding showing host, method and path.
- **PRV-004** · P1 · browser, cfg — With `honourGpc`: in a fresh context that sends `Sec-GPC: 1` on every request and exposes `navigator.globalPrivacyControl === true` (init script), after activating the `acceptLabel` control on the first consent page, the observation windows of the next two consent pages contain no request to a host whose purposes include `advertising` or `affiliate` (finding `forbidden-value`, showing the request URL). Part `required` (cfg) — with a `privacy.jurisdictions` entry listed in ruleset `us-opt-out-states.json` (state laws requiring universal opt-out signals; shape `{ "jurisdictions": ["us-ca-ccpa", "us-state-privacy"] }`), `consent.honourGpc` is `true` (`value-mismatch` naming `privacy.consent.honourGpc`).
- **PRV-005** · P0 · browser — Every third-party host requested by the browser in G6 is in the `hosts` registry with a declared purpose; unknown hosts are `forbidden-value` findings showing the host and the first request URL. (Server-side egress is owned by SEC-004.)
- **PRV-006** · P1 · html, site — Each page in `legalPages` exists (200) and is linked from the footer of every public page. Its `index` value counts as an exact-path `indexRules` entry (04 § 15 *Indexable page* item 3), so whether it is served with or without `noindex` is judged by web-delivery MET-006 (1)–(2), not by this rule. Findings: `status-mismatch` (not 200), `missing-element` (no footer link, showing the page URL).
- **PRV-007** · P0 · browser — No personal data in URLs sent to third parties: in a context where consent was accepted (the PRV-003 accept context), each sampled page is also loaded once with `email=sg-probe%40example.com` appended to its query (`?`, or `&` when it has one). In every request to a third-party host without `essential: true`, during both loads, the URL query (each parameter, and each parameter value that parses as an absolute URL, one level deep) and the `Referer` header contain no parameter named in `piiQueryParams` (case-insensitive) and no value matching `[^@\s/?#&=]+@[^@\s/?#&=]+\.[A-Za-z]{2,}` after one percent-decoding. Finding class `leak`, showing the request URL and parameter.
- **PRV-008** · P1 · browser — No pre-ticked marketing opt-ins: on sampled pages and every flow page, no `input[type=checkbox]` or `[role=checkbox]` whose accessible name has a phrase match in ruleset `marketing-optin-labels.json` is checked (`checked` property or `aria-checked="true"`) in its page state (§ 1). Finding `forbidden-value` with the selector.
- **PRV-009** · W · review — Cancellation and account deletion are as easy as signup (dark-pattern review: no more steps or channels than signup). (Behaviour of deletion and export: PRV-016; processors named in the privacy notice: PRV-031.)
- **PRV-010** · P1 · browser — No account identifiers in tracking: identifier values = each test account's `SHIPGATE_ACCT_<ID>_EMAIL` and the `value` of `fill` steps into fields with `autocomplete` `name`, `given-name`, `family-name` or `nickname` (typed email/tel/password values: PRV-019). In every request recorded during flows and sampled-page loads, no request to a host whose purposes include `analytics`, `advertising` or `affiliate` contains them (*Encodings of a value*, § 1); the SHA-256 hex of the lowercased, trimmed value is allowed only to hosts with purpose `advertising`. Finding class `leak`, showing the request URL and the matched encoding. A (request, value) pair whose value was typed into a field judged by PRV-019 (`type` password, email or tel; `autocomplete` `cc-*`, `one-time-code`, `email`, `tel*`, `current-password`, `new-password`) is reported by PRV-019 only; PRV-010 judges the other identifier values (name-field fills, and an account email that reaches a request in a flow that never typed it). Log contents are owned by OPS-001.
- **PRV-011** · P0 · browser — Google Consent Mode v2, when a jurisdiction is `eu-gdpr` or `uk-gdpr`, a Google tag host is requested on any sampled page or flow, and `googleConsentMode` is `"basic"` or `"advanced"`: an init-script hook on `window.dataLayer` records a `consent`/`default` command setting `ad_storage`, `analytics_storage`, `ad_user_data` and `ad_personalization` to `denied` before the first Google tag host request (a `region` list, if present, must contain every country of the declared jurisdictions: EU-27, IS, LI, NO for `eu-gdpr`; GB for `uk-gdpr`); with `"advanced"`, the first measurement request of the PRV-001 window carries `gcs=G100` and a `gcd` value that decodes (the `gcd` table of ruleset `google-tags.json`) to denied-by-default for all four types; with `"basic"` no measurement request exists before consent and this check is not run. After accept: a `consent`/`update` granting all four precedes the next measurement request, which carries `gcs=G111`. After reject (fresh context): no update granting any type, and measurement requests (advanced) carry `gcs=G100`. With `"off"` and a Google tag host requested: finding. Contexts: default and first request — the PRV-001 window; accept — the PRV-003 accept context; reject — the PRV-002 reject context. Classes: `missing-element` (no `consent`/`default` command), `value-mismatch` (value, order, `region`, `gcs` or `gcd`), `forbidden-value` (`"off"` with a Google tag host).
- **PRV-012** · P0 · html, browser — Sensitive values stay out of first-party URLs: part `form-method` — every `<form>` containing `input[type=password]` or a field whose `name` is in `piiQueryParams` has `method="post"` (missing method = GET); part `flow-urls` — no request URL to a service origin recorded during flows carries a query parameter named in `piiQueryParams` or a typed password value, excluding navigations started by `openEmailLink` and the redirects that follow them. Findings `forbidden-value` showing the form selector or request URL.
- **PRV-013** · P1 · browser, site — With `us-ca-ccpa` and any `hosts` entry with purpose `advertising`: part `link` — the footer of every public page contains a link whose accessible name equals one of `ccpa.linkLabels` after NFKC, case-folding and whitespace collapse (both sides); part `gpc-indicator` — under `Sec-GPC: 1`, the element matching `ccpa.gpcIndicator` is visible on sampled public pages (no selector → this part `notConfigured`). Findings `missing-element` showing the page URL.
- **PRV-014** · P1 · browser — Consent persistence: after accept (and, in a fresh context, after reject) on the first consent page, navigating to the next two consent pages and reloading the last shows no banner (its accept and reject controls are absent or hidden) and, after reject, each of those windows satisfies PRV-002's cookie and request test (after accept there is no request test). In the accept context, after the reload, each sampled public page is loaded once (one window) and has a control whose accessible name has a Label match for `banner.reopenLabel`; activating it makes controls with a Label match for `acceptLabel` and `rejectLabel` visible within 1 s. Findings: `forbidden-value` (banner shown again, or a request or cookie contradicting the choice), `missing-element` (no reopen control, or accept/reject not visible after it).
- **PRV-015** · P1 · browser, html — Every cookie name present (all domains) in the PRV-014 accept context after its three consent-page windows and the reload appears in the `<main>` text of `legalPages.cookies`, verbatim or as a listed prefix ending in `*` (e.g. `_ga_*`) that matches it (`missing-element` naming the cookie); essential cookies are listed too. Without `legalPages.cookies`: `forbidden-value` naming each non-essential cookie (§ 1) present.
- **PRV-016** · P1 · browser, db — Account data rights. Part `deletion` — after `accountData.deletionFlow` completes as its account, each `personalDataTables` entry has no row where `column` = the account id (`accountIdSql`, resolved before the flow, `{account.email}` = the flow account's email), and the account's stored session is refused on an `auth: required` endpoint (SEC-021 semantics). Part `export` — for each `exportFields` entry, the stored value is `select <column> from <table> where <keyColumn> = <account id>` read before the flow (no row: blocking `missing-element` owned by `operator`). Export text = the file captured by the flow's `expectDownload` step, or by an `expectEmail` step with `attachment: true` (03 § 10; first attachment captured like a download): UTF-8 content; `application/zip` → concatenation of every entry's UTF-8 content in entry order; `application/pdf` → extracted text. Each stored value is contained in the export text (`value-mismatch` otherwise). (mutating stage, 04 § 4.2 step 8) Without `accountData`, or without a key a part reads (`deletion`: `deletionFlow`, `accountIdSql`, `personalDataTables`; `export`: `exportFlow`, `exportFields`): when any flow has `journey: "signup"`, one blocking `missing-element` finding owned by `operator` naming the key (04 § 1.2 required-facts rules); otherwise `notApplicable`.
