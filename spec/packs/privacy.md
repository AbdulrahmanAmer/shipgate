# Pack: privacy

> Consent, tracking, third parties and legal pages, proven by what the browser actually loads and stores. Not legal advice: shipgate checks declared obligations mechanically; the Operator (with counsel) decides which jurisdictions and processors apply.

---

## 1. Policy section

```jsonc
"privacy": {
  "jurisdictions": ["eu-gdpr", "uk-gdpr", "us-ca-ccpa"],   // also "eu-eaa" (European Accessibility Act, PRV-017), "eu-consumer" (EU consumer law: CRD, Omnibus; PRV-021/023/024),
                                                           // "de", "at" (national rules, e.g. imprint; imply eu-consumer), "us-state-privacy" (states with universal opt-out laws, PRV-004),
                                                           // "kr-pipa", "cn-pipl", "br-lgpd", "ca-pipeda", "jp-appi" (GDPR-family: privacy page, controller identity, consent per ruleset `required-legal-pages.json` / `consent-models.json`)
                                                           // "kr-ecommerce" (Korea E-Commerce Act Art. 10/13), "jp-sct" (Japan Act on Specified Commercial Transactions Art. 11), "cn-icp" (China ICP filing): seller identity notices, PRV-022
                                                           // "uk-consumer" (UK consumer law: Consumer Contracts Regulations 2013, Price Marking Order 2004, DMCC Act 2024 Part 4; PRV-023, PRV-026)
  "consent": {
    "required": true,                               // consent before non-essential cookies/requests
    "banner": { "acceptLabel": "Accept all", "rejectLabel": "Reject all", "settingsLabel": "Settings",
                "reopenLabel": "Cookie settings" },   // reopenLabel: persistent control that reopens the choice (PRV-014); each label: string or { "<locale>": string }
    "honourGpc": true,                              // Global Privacy Control
    "googleConsentMode": "basic"                    // "off" | "basic" | "advanced" (advanced: cookieless Google pings before consent, PRV-001/011)
  },
  "ccpa": { "linkLabels": ["Do Not Sell or Share My Personal Information", "Your Privacy Choices"],
            "gpcIndicator": ".gpc-honoured" },      // gpcIndicator: selector shown under Sec-GPC: 1 (no default)
  "essentialCookies": ["session", "csrf", "consent"],
  // processors = hosts[] registry entries (03 § 3.3) with purposes and the essential flag
  "legalPages": { "privacy": { "path": "web:/privacy", "index": true }, "terms": { "path": "web:/terms", "index": true },
                  "imprint": { "path": "web:/imprint", "index": false }, "cookies": { "path": "web:/cookies", "index": false },
                  "accessibility": { "path": "web:/accessibility", "index": true },
                  "returns": { "path": "web:/returns", "index": true }, "shipping": { "path": "web:/shipping", "index": true },
                  "commercialTransactions": { "path": "web:/tokushoho", "index": true } },  // required keys: PRV-022
  "piiQueryParams": ["email", "phone", "name", "token"],
  "accountData": {                                  // PRV-016 (no default; absent → notConfigured)
    "deletionFlow": "quality/flows/delete-account.json",
    "exportFlow": "quality/flows/export-data.json",
    "accountIdSql": "select id from auth.users where email = {account.email}",
    "personalDataTables": [ { "db": "main", "table": "profiles", "column": "user_id" } ],
    "exportFields": [ { "db": "main", "table": "profiles", "column": "display_name", "keyColumn": "user_id" } ]
  },
  "digitalProductPaths": ["web:/downloads/**"],     // PRV-025: URL patterns of digital goods/services pages (no default)
  "ai": { "assistants": [] },                       // PRV-018: [{ page, open?: Locator, input: Locator, message, disclosure }]
  "audience": { "children": false, "ageGate": null } // ageGate: { paths: [pattern], contentSelector, flow } (no default)
}
```
`legalPages` accepts exactly the keys shown; each value is `{ path: URL pattern without wildcards, index: bool }`.

**Definitions:** *footer* = the `<footer>` element or `contentinfo` landmark. *Google tag hosts* and *Google measurement requests* = ruleset `google-tags.json` (hosts, tag-library paths such as `/gtag/js` and `/gtm.js`, and measurement paths such as `/g/collect`, `/pagead/`, `/ccm/`). *Typed values* = `value`s of `fill` steps in flows (after generator expansion). *EU consumer jurisdiction* = any of `eu-consumer`, `de`, `at`. *Page locale* = the primary subtag of `<html lang>`, else of web-delivery `defaultLocale`, else `en`; locale-keyed rulesets fall back to `en`. *Price* = text matching the page locale's CLDR currency pattern.

*Observation window* (PRV-001, PRV-002, PRV-003, PRV-004, PRV-014): a fresh browser context with Playwright's clock installed at context creation; after navigation, wait until no request has been in flight for 500 ms (cap 15 s after `load`), then `clock.fastForward` 60 s, then wait again for 500 ms network idle (cap 5 s). Requests, cookies (all domains) and storage entries are read at the end of the window. Each navigation of PRV-002/003/004/014 gets its own window.

*Essential cookie / storage entry*: a cookie name, `localStorage`/`sessionStorage` key or IndexedDB database name that equals an `essentialCookies` entry or a `verifyEnv.auth.sessionCookies` entry, or starts with an entry's text before a trailing `*` (e.g. `__Host-csrf*`). Every other cookie or storage entry is non-essential.

*Consent pages* (PRV-002, PRV-003, PRV-004, PRV-014): the first sampled public page by URL (lexicographic), then the next two sampled public pages in that order. *Label match*: a control matches a `banner.*Label` when its accessible name, trimmed and case-folded, equals the label for the page locale (a string label applies to every locale; a locale map falls back to `en`). *First layer* = the elements visible at the end of the observation window with no prior interaction. *Reachable* = focused within 50 Tab presses from page start.

## 2. Rules — `PRV-*`

- **PRV-001** · P0 · browser — Before any consent interaction, at the end of the observation window of each sampled page, no non-essential cookie or storage entry is present and no request has gone to a host without `essential: true` (requests are recorded even when stubbed, 04 § 6.1). Only exception: with `consent.googleConsentMode: "advanced"`, requests to Google tag hosts are allowed when they are tag-library loads or measurement requests carrying `gcs=G100`, carry no `Cookie` header, and set no cookie (first- or third-party). With `"off"` or `"basic"`, no Google tag host request occurs before consent. Findings: `forbidden-value` showing the cookie, storage key or request URL.
- **PRV-002** · P0 · browser — Reject is as easy as accept: on the first consent page, a control that matches `rejectLabel` is in the first layer and is reachable; after activating it, the observation windows of the next two consent pages contain no non-essential cookie or storage entry and no request to a host without `essential: true` (PRV-001's advanced-mode exception applies). Missing or unreachable control: `missing-element`; a forbidden cookie or request: `forbidden-value`. With `consent.required: true` and no `consent.banner`, PRV-002 and PRV-014 each emit one blocking `missing-element` finding owned by `operator` naming `privacy.consent.banner`.
- **PRV-003** · P1 · browser, http — Consent withdrawal: in a context where the `acceptLabel` control was activated on the first consent page, activate the control matching `banner.reopenLabel`, then the control matching `rejectLabel` in the reopened layer (either absent: `missing-element`); the observation window of the next consent page has no request to a host without `essential: true` and no non-essential cookie or storage entry that was not present before withdrawal (`forbidden-value`). Hosts absent from `hosts[]` are owned by PRV-005; PRV-003 `main` judges only hosts present in `hosts[]`. Part `server-side` (P0): server-side requests seen by the egress proxy to `hosts[]` entries with purpose `analytics` or `advertising` (server-side tagging, Meta CAPI, …) happen only for sessions that have accepted. None occur before consent or after rejection. Attribution: the pre-consent context and the reject context each run alone, with no other browser, crawler or flow activity against the verify environment. Any such egress during that window is a finding.
- **PRV-004** · P1 · browser, cfg — With `honourGpc`: in a fresh context that sends `Sec-GPC: 1` on every request and exposes `navigator.globalPrivacyControl === true` (init script), after activating the `acceptLabel` control on the first consent page, the observation windows of the next two consent pages contain no request to a host whose purposes include `advertising` or `affiliate` (finding `forbidden-value`, showing the request URL). Part `required` (cfg) — with `us-state-privacy` or `us-ca-ccpa` (state laws requiring universal opt-out signals: ruleset `us-opt-out-states.json`), `consent.honourGpc` is `true`.
- **PRV-005** · P0 · browser — Every third-party host requested by the browser in G6 is in the `hosts` registry with a declared purpose; unknown hosts are findings. (Server-side egress is owned by SEC-004.)
- **PRV-006** · P1 · html, site — Each page in `legalPages` exists (200, indexable or noindex as declared) and is linked from the footer of every public page.
- **PRV-007** · P0 · browser — No personal data in URLs sent to third parties: in a context where consent was accepted (PRV-003), each sampled page is also loaded once with `email=sg-probe%40example.com` appended to its query (`?`, or `&` when it has one). In every request to a host without `essential: true`, during both loads, the URL query (each parameter, and each parameter value that parses as an absolute URL, one level deep) and the `Referer` header contain no parameter named in `piiQueryParams` (case-insensitive) and no value matching `[^@\s/?#&=]+@[^@\s/?#&=]+\.[A-Za-z]{2,}` after one percent-decoding. Finding class `leak`, showing the request URL and parameter.
- **PRV-008** · P1 · browser — No pre-ticked marketing opt-ins: on sampled pages and every flow page, no `input[type=checkbox]` or `[role=checkbox]` whose accessible name matches ruleset `marketing-optin-labels.json` for the page locale is checked (`checked` property or `aria-checked="true"`) at the end of the observation window before any interaction. Finding `forbidden-value` with the selector.
- **PRV-009** · W · review — Cancellation and account deletion are as easy as signup (dark-pattern review: no more steps or channels than signup), and the privacy notice lists every processor in the `hosts` registry. (Behaviour of deletion and export: PRV-016.)
- **PRV-010** · P1 · browser — No account identifiers in tracking: identifier values = each test account's `SHIPGATE_ACCT_<ID>_EMAIL` and the `value` of `fill` steps into fields with `autocomplete` `name`, `given-name`, `family-name` or `nickname` (typed email/tel/password values: PRV-019). In every request recorded during flows and sampled-page loads, they never appear in the URL, headers or body of requests to hosts whose purposes include `analytics`, `advertising` or `affiliate`, matched raw, percent-encoded, JSON-escaped and base64; the SHA-256 hex of the lowercased, trimmed value is allowed only to hosts with purpose `advertising`. Finding class `leak`, showing the request URL and the matched encoding. Log contents are owned by OPS-001.
- **PRV-011** · P0 · browser — Google Consent Mode v2, when a jurisdiction is `eu-gdpr` or `uk-gdpr`, a Google tag host is requested on any sampled page or flow, and `googleConsentMode` is `"basic"` or `"advanced"`: an init-script hook on `window.dataLayer` records a `consent`/`default` command setting `ad_storage`, `analytics_storage`, `ad_user_data` and `ad_personalization` to `denied` before the first Google tag host request (a `region` list, if present, must contain every country of the declared jurisdictions: EU-27, IS, LI, NO for `eu-gdpr`; GB for `uk-gdpr`); the first measurement request carries `gcs=G100` and a `gcd` value that decodes (the `gcd` table of ruleset `google-tags.json`) to denied-by-default for all four types. After accept: a `consent`/`update` granting all four precedes the next measurement request, which carries `gcs=G111`. After reject (fresh context): no update granting any type, and measurement requests (advanced) carry `gcs=G100`. With `"off"` and a Google tag host requested: finding.
- **PRV-012** · P0 · html, browser — Sensitive values stay out of first-party URLs: part `form-method` — every `<form>` containing `input[type=password]` or a field whose `name` is in `piiQueryParams` has `method="post"` (missing method = GET); part `flow-urls` — no request URL to a service origin recorded during flows carries a query parameter named in `piiQueryParams` or a typed password value, excluding navigations started by `openEmailLink` and the redirects that follow them.
- **PRV-013** · P1 · browser, site — With `us-ca-ccpa` and any `hosts` entry with purpose `advertising`: part `link` — the footer of every public page contains a link whose accessible name equals one of `ccpa.linkLabels`; part `gpc-indicator` — under `Sec-GPC: 1`, the element matching `ccpa.gpcIndicator` is visible on sampled public pages (no selector → this part `notConfigured`).
- **PRV-014** · P1 · browser — Consent persistence: after accept (and, in a fresh context, after reject) on the first consent page, navigating to the next two consent pages and reloading the last shows no banner (its accept and reject controls are absent or hidden) and the request pattern of each observation window matches the choice (PRV-001/003). Every sampled public page has a control whose accessible name matches `banner.reopenLabel`; activating it makes the accept and reject controls visible.
- **PRV-015** · P1 · browser, html — Every cookie name present in the browser context (all domains) after accept in G6 appears in the `<main>` text of `legalPages.cookies`, verbatim or as a listed prefix ending in `*` (e.g. `_ga_*`) that matches it. Without `legalPages.cookies`: finding when any non-essential cookie (§ 1) is set.
- **PRV-016** · P1 · browser, db — Account data rights. Part `deletion` — after `accountData.deletionFlow` completes as its account, each `personalDataTables` entry has no row where `column` = the account id (`accountIdSql`, resolved before the flow, `{account.email}` = the flow account's email), and the account's stored session is refused on an `auth: required` endpoint (SEC-021 semantics). Part `export` — for each `exportFields` entry, the stored value is `select <column> from <table> where <keyColumn> = <account id>` read before the flow (no row: blocking `missing-element` owned by `operator`). Export text = the file captured by the flow's `expectDownload` step, or by an `expectEmail` step with `attachment: true` (03 § 10; first attachment captured like a download): UTF-8 content; `application/zip` → concatenation of every entry's UTF-8 content in entry order; `application/pdf` → extracted text. Each stored value is contained in the export text (`value-mismatch` otherwise). (mutating stage, 04 § 4.2 step 8) Without `accountData`: `notConfigured`.
- **PRV-017** · P1 · cfg, site — With `eu-eaa`: `legalPages.accessibility` is declared, returns 200 and is linked from the footer of every public page (PRV-006 checks apply). Part `pack` (cfg) — `packs` contains `accessibility` and no `ruleOverrides` entry sets an accessibility rule of severity P0 or P1 to `off` or `warn`.
- **PRV-018** · P1 · browser — AI interaction disclosure (EU AI Act Art. 50(1), applicable since 2026-08-02): for each `ai.assistants` entry, on `page` (after activating `open`, if set), text containing `disclosure` is visible inside the viewport before `message` is sent through `input`, and is still visible when the first reply renders. Sending = `fill` `message` into `input`, then press Enter. First reply = the first element added to the DOM after sending, outside `input` and not containing `message`, with non-whitespace text, within 15 s (hosts with purpose `ai` answer with their `ux.egressStubs` stub); none → `flow-step-failed`. *Contains `disclosure`* = the element's visible text, whitespace-collapsed and case-folded, contains `disclosure` processed the same way. Disclosure not visible at either moment: `missing-element`.
- **PRV-019** · P0 · browser — Typed values entered into fields with `type` `password`, `email` or `tel`, or `autocomplete` `cc-*`, `one-time-code`, `email`, `tel*`, `current-password`, `new-password`, never appear in any request to a third-party host (URL, headers, body, WebSocket frames), matched raw, percent-encoded, JSON-escaped and base64-encoded (part `hashed`, W: SHA-256 hex of the lowercased, trimmed value). Hosts with purposes `auth` or `payments` are exempt. (Session-replay and form-capture scripts; account identifiers in analytics: PRV-010.)
- **PRV-020** · P1 · browser, html — Audience. Part `children` — with `audience.children: true`, no host with purpose `advertising` is requested on any sampled page or flow, before or after accept. Part `age-gate` — with `audience.ageGate`, the raw HTML of each sampled URL matching `paths` contains no element matching `contentSelector` with non-empty text; after `ageGate.flow` passes, the element is visible in the browser.
- **PRV-021** · P1 · html, browser, cfg — EU withdrawal function (Consumer Rights Directive Art. 11a, applicable since 19 June 2026), with `eu-consumer` and (`ecommerce` in `project.kinds` or `security.payments` set). Part `link` — every sampled public page contains a link or button whose accessible name matches ruleset `withdrawal-labels.json` for the page locale, and following it without a session reaches a 200 page that is not a redirect to `auth.loginPath`. Part `flow` — ≥ 1 flow has `journey: "withdrawal"` (cfg); it activates (`click` or `press`) a control whose accessible name matches ruleset `withdrawal-confirm-labels.json` for the page locale, a later step is `expectEmail`, and the flow passes (G6 mutating flow; mutating stage, 04 § 4.2 step 8).
- **PRV-022** · P1 · cfg, html — Required legal pages: every `legalPages` key that ruleset `required-legal-pages.json` requires for the declared `jurisdictions` and `project.kinds` is declared (e.g. `eu-gdpr`/`uk-gdpr`/`us-ca-ccpa` → `privacy`; `de`/`at` → `imprint`; `ecommerce` → `terms`, `returns`, `shipping`; `eu-eaa` → `accessibility`; any `hosts[]` entry with `browser: true` and without `essential: true` → `cookies`). Existence and footer links: PRV-006. Part `imprint` (P1 · html; `de`/`at`, DDG § 5 / ECG § 5): the `<main>` of `legalPages.imprint` contains `business.json` `legalName` (or `name`), `postalAddress` (else the first `locations[].address`; LOC-001 normalised containment), an `emails[]` address, and `legal.registerNumber` or `legal.vatId` when declared. Part `controller` (P1 · html; GDPR-family jurisdictions): the `<main>` of `legalPages.privacy` contains `business.json` `legalName` (or `name`) and an `emails[]` address, so the data controller is the real business, not boilerplate.
  - Part `kr-ecommerce` (P1 · html; `kr-ecommerce`): the page-level footer (`contentinfo` landmark as in UX-016) of every public page contains `business.json` `legalName` (or `name`), `legal.representative`, the `postalAddress` (LOC-001 normalised containment), a `phones[]` number, an `emails[]` address and `legal.registerNumber` (사업자등록번호), plus `legal.mailOrderNumber` (통신판매업 신고번호) when `project.kinds` contains `ecommerce`.
  - Part `jp-sct` (P1 · html; `jp-sct`): `legalPages.commercialTransactions` (特定商取引法に基づく表記; required by ruleset `required-legal-pages.json` for `jp-sct` with `ecommerce`, linked per PRV-006) has a `<main>` containing `legalName` (or `name`), `legal.representative`, the `postalAddress`, a `phones[]` number and an `emails[]` address, and a ruleset per-locale `sct-labels` match for each of price, shipping cost, payment timing and method, delivery time, and returns/cancellation. `sct-labels` shape: `{ "<locale>": { "price": [phrase], "shippingCost": [...], "payment": [...], "delivery": [...], "returns": [...] } }`; a category passes when any of its phrases occurs in the `<main>` text (NFKC, case-folded).
  - Part `cn-icp` (P1 · html; `cn-icp`): the page-level footer of each service's home page contains `legal.icpNumber` (e.g. "京ICP备12345678号") as the start of the text of an `<a>` (both NFKC-normalised, whitespace removed; a trailing `-<digits>` suffix is allowed) whose `href` host is `beian.miit.gov.cn`; when `legal.psbNumber` is declared, also as the start of the text of an `<a>` (same normalisation and suffix rule) whose `href` host is `beian.mps.gov.cn`.

  For parts `imprint`, `controller`, `kr-ecommerce`, `jp-sct` and `cn-icp`, a `business.json` value the part needs that is absent is a blocking `missing-element` finding owned by `operator` (04 § 1.2 required-facts rules), never `notConfigured`.
- **PRV-023** · P1 · browser — Order button (EU: CRD Art. 8(2); UK: Consumer Contracts Regulations 2013 reg. 14(3)): with an EU consumer jurisdiction or `uk-consumer`, in each `journey: "checkout"` flow, the order control — the element activated by the step during which the request carrying the `markAmount` field, or else the first request to a `hosts[]` entry with purpose `payments` (browser or egress), is sent — has an accessible name matching ruleset `order-button-labels.json` for the page locale ("Buy now", "Order with obligation to pay", "Zahlungspflichtig bestellen", …), in any frame. Neither request observed: `notConfigured` for that flow.
- **PRV-024** · P1 · html — EU consumer information, with an EU consumer jurisdiction, on sampled public pages. Part `prior-price` — each `<del>` or `<s>` whose text is a price and whose parent element contains another price has, within that parent's text or 200 characters of the element, a phrase from ruleset `prior-price-phrases.json` for the page locale (Omnibus 30-day prior price). Part `reviews` (W) — pages with `Review` or `AggregateRating` markup (JSON-LD or microdata) or a rating widget (ruleset `rating-widget-markers.json`) contain, or link same-origin to a page whose `<main>` contains, a phrase from ruleset `review-verification-phrases.json` for the page locale.
- **PRV-025** · P1 · html, data — EU product safety information (GPSR, Regulation (EU) 2023/988 Art. 19, applies since 2024-12-13), with an EU consumer jurisdiction and `ecommerce` in `project.kinds`. Each page with a `Product` + `Offer` for a physical product shows the following in visible text, with values equal to the matching `business.json` `manufacturers[]` entry. That entry is the one whose `name` equals the JSON-LD `manufacturer.name`, else `brand.name`, after NFKC, case-folding, whitespace collapse and removal of punctuation. No match (including a page with neither name, or no `manufacturers` key) is a blocking `missing-element` finding owned by `operator` that names the product page and the unmatched name (04 § 1.2 required-facts rules), never `notConfigured`:
  - the manufacturer's name;
  - the manufacturer's postal address and email or contact URL;
  - when the manufacturer's `country` is outside the EU, the EU responsible person (`euResponsible`);
  - a product identifier: a JSON-LD `gtin`, `gtin8`, `gtin12`, `gtin13`, `gtin14`, `mpn` or `sku` value of the `Product` appears in visible text; a `Product` with none of these properties is a builder-owned `missing-element`;
  - a link to, or section with, warnings and safety information (ruleset `safety-info-labels` per locale).

  `manufacturers[].address` and `euResponsible.address` have the shape of `locations[].address` (LOC-001 normalised containment); `contact` is an email address or absolute URL, matched in visible text or as an `href` (`mailto:` or the URL). A shown value that differs, or is absent, is `missing-element` (builder-owned) naming the field. Part `facts` (P1 · data): every `manufacturers[]` entry has `address`, `contact` and `country` (ISO 3166-1 alpha-2), plus `euResponsible` when `country` is not in EU-27 (operator-owned `missing-element` naming the entry and key).

  Digital goods and services are `notApplicable` only when the page URL matches a `privacy.digitalProductPaths` pattern (Operator-owned list of URL patterns, no default). A page whose `Product` has an `additionalType` in ruleset `digital-product-types` but matches no such pattern is a blocking `missing-element` finding owned by `operator` naming `privacy.digitalProductPaths`.
- **PRV-026** · P1 · html, browser — Price transparency.
  - Part `indication` (with an EU consumer jurisdiction or `uk-consumer`; UK: Price Marking Order 2004): on each page with `Product` + `Offer` markup, every visible text matching *Price* inside an element whose text contains the `Offer` `price` value has, in its parent element's text or in the text of the element targeted by a same-page fragment link (`<a href="#id">`) inside that parent, a ruleset `vat-phrases` match for the page locale ("incl. VAT", "inkl. MwSt.", …), and that parent contains a link to `legalPages.shipping` or a ruleset `shipping-cost-phrases.json` match for the page locale. Finding `missing-element` showing the price text and selector.
  - Part `total` (any jurisdiction; `journey: "checkout"` flows): the total amount sent to the `hosts[]` entry with purpose `payments` (amount extraction and units as UX-015: ruleset `payment-amounts.json`, minor units per ISO 4217) equals the sum of the `amount`s of the `prices[]` entries selected by the flow's `markPrice` steps (each step counted once) plus the amounts of some subset of the `business.json` `prices[]` entries with `kind: "fee"` in the same currency. More than 16 fee entries in one currency: blocking `missing-element` owned by `operator` naming `business.json prices[]`. No matching subset (undeclared fees added at checkout: drip pricing; FTC fees rule, CA SB 478) → `value-mismatch` showing both amounts. No `markPrice` → `notConfigured(markPrice)`; no extractable amount → `notConfigured(providerId)` (as UX-015). Per-item equality is owned by UX-015; this part judges only the total.
  - Part `drip` (P1 · browser; `uk-consumer`, DMCC Act 2024 Part 4, in force 2025-04-06: mandatory charges belong in the headline price): part `total`'s subset match is repeated using only fee entries whose `feeType` (03 § 14) is `delivery` or `optional`; a total that matches only when an entry with `feeType: "mandatory"` (the default) is included is a `value-mismatch` of this part showing the fee `id`.
- **PRV-027** · P1 · browser — Auto-renewal disclosure (ROSCA, California ARL as amended 2025-07-01, EU CRD), with `security.payments.recurring: true`. In `journey: "checkout"` flows, before the step that activates the order control (PRV-023's definition; not observed: `notConfigured` for that flow), the page shows the renewal price, the renewal frequency and how to cancel (ruleset `renewal-terms-phrases` frequency and cancellation phrases for the page locale, and the `amount` of each `prices[]` entry with `recurring` set that the flow selects by `markPrice`, parsed per UX-015). Any consent checkbox for renewal is not pre-checked.
- **PRV-028** · P1 · html — Privacy notice at the point of collection (GDPR Art. 13; CCPA notice at collection). Every form with a field for personal data (`autocomplete` tokens for name, email, tel, address, or `type=email|tel`) has a link to `legalPages.privacy` inside the `<form>` or inside its closest ancestor that is a `<section>`, `<article>`, `<aside>`, `<dialog>` or `<main>` element (`missing-element` showing the form selector). Such a form with no `legalPages.privacy` declared: blocking `missing-element` owned by `operator` naming `privacy.legalPages.privacy`.
