# Pack: privacy

> Consent, tracking, third parties and legal pages, proven by what the browser actually loads and stores. Not legal advice: shipgate checks declared obligations mechanically; the Operator (with counsel) decides which jurisdictions and processors apply.

---

## 1. Policy section

```jsonc
"privacy": {
  "jurisdictions": ["eu-gdpr", "uk-gdpr", "us-ca-ccpa"],   // also "eu-eaa" (European Accessibility Act, PRV-017), "eu-consumer" (EU consumer law: CRD, Omnibus; PRV-021/023/024),
                                                           // "de", "at" (national rules, e.g. imprint; imply eu-consumer), "us-state-privacy" (states with universal opt-out laws, PRV-004),
                                                           // "kr-pipa", "cn-pipl", "br-lgpd", "ca-pipeda", "jp-appi" (GDPR-family: privacy page, controller identity, consent per ruleset required-legal-pages.json / consent-models.json)
                                                           // "kr-ecommerce" (Korea E-Commerce Act Art. 10/13), "jp-sct" (Japan Act on Specified Commercial Transactions Art. 11), "cn-icp" (China ICP filing): seller identity notices, PRV-022
  "consent": {
    "required": true,                               // consent before non-essential cookies/requests
    "banner": { "acceptLabel": "Accept all", "rejectLabel": "Reject all", "settingsLabel": "Settings",
                "reopenLabel": "Cookie settings" },   // reopenLabel: persistent control that reopens the choice (PRV-014)
    "honourGpc": true,                              // Global Privacy Control
    "googleConsentMode": "basic"                    // "off" | "basic" | "advanced" (advanced: cookieless Google pings before consent, PRV-001/011)
  },
  "ccpa": { "linkLabels": ["Do Not Sell or Share My Personal Information", "Your Privacy Choices"],
            "gpcIndicator": ".gpc-honoured" },      // gpcIndicator: selector shown under Sec-GPC: 1 (no default)
  "essentialCookies": ["session", "csrf", "consent"],
  // processors = hosts[] registry entries (03 § 3.3) with purposes and the essential flag
  "legalPages": { "privacy": { "path": "web:/privacy", "index": true }, "terms": { "path": "web:/terms", "index": true },
                  "imprint": { "path": "web:/imprint", "index": false }, "cookies": { "path": "web:/cookies", "index": false },
                  "accessibility": { "path": "web:/accessibility", "index": true },
                  "returns": { "path": "web:/returns", "index": true }, "shipping": { "path": "web:/shipping", "index": true } },  // required keys: PRV-022
  "piiQueryParams": ["email", "phone", "name", "token"],
  "accountData": {                                  // PRV-016 (no default; absent → notConfigured)
    "deletionFlow": "quality/flows/delete-account.json",
    "exportFlow": "quality/flows/export-data.json",
    "accountIdSql": "select id from auth.users where email = {account.email}",
    "personalDataTables": [ { "db": "main", "table": "profiles", "column": "user_id" } ],
    "exportFields": [ { "db": "main", "table": "profiles", "column": "display_name" } ]
  },
  "ai": { "assistants": [] },                       // PRV-018: [{ page, open?: Locator, input: Locator, message, disclosure }]
  "audience": { "children": false, "ageGate": null } // ageGate: { paths: [pattern], contentSelector, flow } (no default)
}
```

**Definitions:** *footer* = the `<footer>` element or `contentinfo` landmark. *Google tag hosts* and *Google measurement requests* = ruleset `google-tags.json` (hosts, tag-library paths such as `/gtag/js` and `/gtm.js`, and measurement paths such as `/g/collect`, `/pagead/`, `/ccm/`). *Typed values* = `value`s of `fill` steps in flows (after generator expansion). *EU consumer jurisdiction* = any of `eu-consumer`, `de`, `at`. *Page locale* = the primary subtag of `<html lang>`, else of web-delivery `defaultLocale`, else `en`; locale-keyed rulesets fall back to `en`. *Price* = text matching the page locale's CLDR currency pattern.

## 2. Rules — `PRV-*`

- **PRV-001** · P0 · browser — Before any consent interaction, sampled pages set no cookies outside `essentialCookies`, no non-essential storage entries, and send no requests to hosts without `essential: true` (requests are recorded even when stubbed, 04 § 6.1). Only exception: with `consent.googleConsentMode: "advanced"`, requests to Google tag hosts are allowed when they are tag-library loads or measurement requests carrying `gcs=G100`, carry no `Cookie` header, and set no cookie (first- or third-party). With `"off"` or `"basic"`, no Google tag host request occurs before consent.
- **PRV-002** · P0 · browser — Reject is as easy as accept: a reject control with `rejectLabel` exists on the first layer of the banner, reachable by keyboard; after rejecting, no non-essential cookies or requests appear on subsequent navigations (PRV-001's advanced-mode exception applies).
- **PRV-003** · P1 · browser, http — After accepting, only declared processors are contacted; withdrawing consent (settings) stops non-essential requests on the next navigation. Part `server-side` (P0): server-side requests seen by the egress proxy to `hosts[]` entries with purpose `analytics` or `advertising` (server-side tagging, Meta CAPI, …) happen only for sessions that have accepted. None occur before consent or after rejection. Attribution: the pre-consent context and the reject context each run alone, with no other browser, crawler or flow activity against the verify environment. Any such egress during that window is a finding.
- **PRV-004** · P1 · browser, cfg — With `honourGpc`, a browser sending `Sec-GPC: 1` is treated as having opted out of sale/sharing (no non-essential processor requests). Part `required` (cfg) — with `us-state-privacy` or `us-ca-ccpa` (state laws requiring universal opt-out signals: ruleset `us-opt-out-states.json`), `consent.honourGpc` is `true`.
- **PRV-005** · P0 · browser — Every third-party host requested by the browser in G6 is in the `hosts` registry with a declared purpose; unknown hosts are findings. (Server-side egress is owned by SEC-004.)
- **PRV-006** · P1 · html, site — Each page in `legalPages` exists (200, indexable or noindex as declared) and is linked from the footer of every public page.
- **PRV-007** · P0 · browser — No personal data in URLs sent to third parties: query parameters named in `piiQueryParams` or containing email-shaped values never appear in requests to non-essential processors.
- **PRV-008** · P1 · browser — No pre-ticked marketing-consent checkboxes in forms; newsletter/marketing opt-ins are unchecked by default.
- **PRV-009** · W · review — Cancellation and account deletion are as easy as signup (dark-pattern review: no more steps or channels than signup), and the privacy notice lists every processor in the `hosts` registry. (Behaviour of deletion and export: PRV-016.)
- **PRV-010** · P1 · browser — Analytics/tracking requests (to non-essential processors) carry no user identifiers beyond what the declared processor purpose needs (no email, phone or name values in payloads). Log contents are owned by OPS-001. (Values typed into sensitive fields: PRV-019.)
- **PRV-011** · P0 · browser — Google Consent Mode v2, when a jurisdiction is `eu-gdpr` or `uk-gdpr`, a Google tag host is requested on any sampled page or flow, and `googleConsentMode` is `"basic"` or `"advanced"`: an init-script hook on `window.dataLayer` records a `consent`/`default` command setting `ad_storage`, `analytics_storage`, `ad_user_data` and `ad_personalization` to `denied` before the first Google tag host request (a `region` list, if present, must contain every country of the declared jurisdictions: EU-27, IS, LI, NO for `eu-gdpr`; GB for `uk-gdpr`); the first measurement request carries `gcs=G100` and a `gcd` decoding (ruleset gcd table) to denied-by-default for all four types. After accept: a `consent`/`update` granting all four precedes the next measurement request, which carries `gcs=G111`. After reject (fresh context): no update granting any type, and measurement requests (advanced) carry `gcs=G100`. With `"off"` and a Google tag host requested: finding.
- **PRV-012** · P0 · html, browser — Sensitive values stay out of first-party URLs: part `form-method` — every `<form>` containing `input[type=password]` or a field whose `name` is in `piiQueryParams` has `method="post"` (missing method = GET); part `flow-urls` — no request URL to a service origin recorded during flows carries a query parameter named in `piiQueryParams` or a typed password value, excluding navigations started by `openEmailLink` and the redirects that follow them.
- **PRV-013** · P1 · browser, site — With `us-ca-ccpa` and any `hosts` entry with purpose `advertising`: part `link` — the footer of every public page contains a link whose accessible name equals one of `ccpa.linkLabels`; part `gpc-indicator` — under `Sec-GPC: 1`, the element matching `ccpa.gpcIndicator` is visible on sampled public pages (no selector → this part `notConfigured`).
- **PRV-014** · P1 · browser — Consent persistence: after accept (and, in a fresh context, after reject) on one sampled page, navigating to two other sampled pages and reloading shows no banner (its accept and reject controls are absent or hidden) and the request pattern matches the choice (PRV-001/003). Every sampled public page has a control whose accessible name equals `banner.reopenLabel`; activating it makes the accept and reject controls visible.
- **PRV-015** · P1 · browser, html — Every cookie name present in the browser context (all domains) after accept in G6 appears in the `<main>` text of `legalPages.cookies`, verbatim or as a listed prefix ending in `*` (e.g. `_ga_*`) that matches it. Without `legalPages.cookies`: finding when any cookie outside `essentialCookies` is set.
- **PRV-016** · P1 · browser, db — Account data rights. Part `deletion` — after `accountData.deletionFlow` completes as its account, each `personalDataTables` entry has no row where `column` = the account id (`accountIdSql`, resolved before the flow, `{account.email}` = the flow account's email), and the account's stored session is refused on an `auth: required` endpoint (SEC-021 semantics). Part `export` — `accountData.exportFlow` produces a download (or an `expectEmail` attachment) whose text contains, for each `exportFields` entry, the value stored for the account before the flow. (mutating stage, 04 § 4.2 step 8) Without `accountData`: `notConfigured`.
- **PRV-017** · P1 · cfg, site — With `eu-eaa`: `legalPages.accessibility` is declared, returns 200 and is linked from the footer of every public page (PRV-006 checks apply). Part `pack` (cfg) — `packs` contains `accessibility` and no `ruleOverrides` entry sets an accessibility rule of severity P0 or P1 to `off` or `warn`.
- **PRV-018** · P1 · browser — AI interaction disclosure (EU AI Act Art. 50(1), applicable since 2026-08-02): for each `ai.assistants` entry, on `page` (after activating `open`, if set), text containing `disclosure` is visible inside the viewport before `message` is sent through `input`, and is still visible when the first reply renders.
- **PRV-019** · P0 · browser — Typed values entered into fields with `type` `password`, `email` or `tel`, or `autocomplete` `cc-*`, `one-time-code`, `email`, `tel*`, `current-password`, `new-password`, never appear in any request to a third-party host (URL, headers, body, WebSocket frames), matched raw, percent-encoded, JSON-escaped and base64-encoded (part `hashed`, W: SHA-256 hex of the lowercased, trimmed value). Hosts with purposes `auth` or `payments` are exempt. (Session-replay and form-capture scripts; account identifiers in analytics: PRV-010.)
- **PRV-020** · P1 · browser, html — Audience. Part `children` — with `audience.children: true`, no host with purpose `advertising` is requested on any sampled page or flow, before or after accept. Part `age-gate` — with `audience.ageGate`, the raw HTML of each sampled URL matching `paths` contains no element matching `contentSelector` with non-empty text; after `ageGate.flow` passes, the element is visible in the browser.
- **PRV-021** · P1 · html, browser, cfg — EU withdrawal function (Consumer Rights Directive Art. 11a, applicable since 19 June 2026), with `eu-consumer` and (`ecommerce` in `project.kinds` or `security.payments` set). Part `link` — every sampled public page contains a link or button whose accessible name matches ruleset `withdrawal-labels.json` for the page locale, and following it without a session reaches a 200 page that is not a redirect to `auth.loginPath`. Part `flow` — ≥ 1 flow has `journey: "withdrawal"` (cfg); it activates (`click` or `press`) a control whose accessible name matches ruleset `withdrawal-confirm-labels.json` for the page locale, a later step is `expectEmail`, and the flow passes (G6 mutating flow; mutating stage, 04 § 4.2 step 8).
- **PRV-022** · P1 · cfg, html — Required legal pages: every `legalPages` key that ruleset `required-legal-pages.json` requires for the declared `jurisdictions` and `project.kinds` is declared (e.g. `eu-gdpr`/`uk-gdpr`/`us-ca-ccpa` → `privacy`; `de`/`at` → `imprint`; `ecommerce` → `terms`, `returns`, `shipping`; `eu-eaa` → `accessibility`; any `hosts[]` entry with `browser: true` and without `essential: true` → `cookies`). Existence and footer links: PRV-006. Part `imprint` (P1 · html; `de`/`at`, DDG § 5 / ECG § 5): the `<main>` of `legalPages.imprint` contains `business.json` `legalName` (or `name`), the postal address, an email address, and `legal.registerNumber` or `legal.vatId` when declared. Part `controller` (P1 · html; GDPR-family jurisdictions): the `<main>` of `legalPages.privacy` contains `business.json` `legalName` (or `name`) and an email address, so the data controller is the real business, not boilerplate.
  - Part `kr-ecommerce` (P1 · html; `kr-ecommerce`): the page-level footer (`contentinfo` landmark as in UX-016) of every public page contains `business.json` `legalName` (or `name`), `legal.representative`, the `postalAddress` (LOC-001 normalised containment), a `phones[]` number, an `emails[]` address and `legal.registerNumber` (사업자등록번호), plus `legal.mailOrderNumber` (통신판매업 신고번호) when `project.kinds` contains `ecommerce`.
  - Part `jp-sct` (P1 · html; `jp-sct`): `legalPages.commercialTransactions` (特定商取引法に基づく表記; required by ruleset `required-legal-pages.json` for `jp-sct` with `ecommerce`, linked per PRV-006) has a `<main>` containing `legalName` (or `name`), `legal.representative`, the `postalAddress`, a `phones[]` number and an `emails[]` address, and a ruleset per-locale `sct-labels` match for each of price, shipping cost, payment timing and method, delivery time, and returns/cancellation.
  - Part `cn-icp` (P1 · html; `cn-icp`): the page-level footer of each service's home page contains `legal.icpNumber` (e.g. "京ICP备12345678号") as the text of an `<a>` whose `href` host is `beian.miit.gov.cn`; when `legal.psbNumber` is declared, also as the text of an `<a>` whose `href` host is `beian.mps.gov.cn`.

  For these three parts, a `business.json` value the part needs that is absent is a blocking `missing-element` finding owned by `operator` (04 § 1.2 required-facts rules), never `notConfigured`.
- **PRV-023** · P1 · browser — EU order button (CRD Art. 8(2)): with an EU consumer jurisdiction, in each `journey: "checkout"` flow, the order control — the element activated by the step during which the request carrying the `markAmount` field, or else the first request to a `hosts[]` entry with purpose `payments` (browser or egress), is sent — has an accessible name matching ruleset `order-button-labels.json` for the page locale ("Buy now", "Order with obligation to pay", "Zahlungspflichtig bestellen", …), in any frame. Neither request observed: `notConfigured` for that flow.
- **PRV-024** · P1 · html — EU consumer information, with an EU consumer jurisdiction, on sampled public pages. Part `prior-price` — each `<del>` or `<s>` whose text is a price and whose parent element contains another price has, within that parent's text or 200 characters of the element, a phrase from ruleset `prior-price-phrases.json` for the page locale (Omnibus 30-day prior price). Part `reviews` (W) — pages with `Review` or `AggregateRating` markup (JSON-LD or microdata) or a rating widget (ruleset `rating-widget-markers.json`) contain, or link same-origin to a page whose `<main>` contains, a phrase from ruleset `review-verification-phrases.json` for the page locale.
- **PRV-025** · P1 · html, data — EU product safety information (GPSR, Regulation (EU) 2023/988 Art. 19, applies since 2024-12-13), with an EU consumer jurisdiction and `ecommerce` in `project.kinds`. Each page with a `Product` + `Offer` for a physical product shows the following in visible text, with values equal to the matching `business.json` `manufacturers[]` entry. That entry is the one whose `name` equals the JSON-LD `manufacturer.name`, else `brand.name`, after normalisation. No match (including a page with neither name, or no `manufacturers` key) is a blocking `missing-element` finding owned by `operator` that names the product page and the unmatched name (04 § 1.2 required-facts rules), never `notConfigured`:
  - the manufacturer's name;
  - the manufacturer's postal address and email or contact URL;
  - when the manufacturer's `country` is outside the EU, the EU responsible person (`euResponsible`);
  - a product identifier (`gtin`, `mpn` or `sku`);
  - a link to, or section with, warnings and safety information (ruleset `safety-info-labels` per locale).

  Digital goods and services (`Product` with `additionalType` in ruleset `digital-product-types`, or `security.payments` without physical items) are `notApplicable`.
- **PRV-026** · P1 · html, browser — Price transparency.
  - Part `indication` (with an EU consumer jurisdiction): every visible product price is accompanied, within its parent element or a linked footnote, by a ruleset `vat-phrases` match for the locale ("incl. VAT", "inkl. MwSt.", …), and by shipping information or a link to `legalPages.shipping`.
  - Part `total` (any jurisdiction; `journey: "checkout"` flows): the amount sent to the payment provider equals the sum of the selected items' prices (selected items = the `priceId`s of the flow's `markPrice` steps) plus fees declared in `business.json` `prices[]` with `kind: "fee"`. Undeclared fees added at checkout (drip pricing; FTC fees rule, CA SB 478) are findings.
- **PRV-027** · P1 · browser — Auto-renewal disclosure (ROSCA, California ARL as amended 2025-07-01, EU CRD), with `security.payments.recurring: true`. In `journey: "checkout"` flows, before the step that activates the order control, the page shows the renewal price, the renewal frequency and how to cancel (ruleset `renewal-terms-phrases`, plus the `prices[]` amount). Any consent checkbox for renewal is not pre-checked.
- **PRV-028** · P1 · html — Privacy notice at the point of collection (GDPR Art. 13; CCPA notice at collection). Every form with a field for personal data (`autocomplete` tokens for name, email, tel, address, or `type=email|tel`) contains, or has within the same `<form>` or its nearest section, a link to `legalPages.privacy`.
