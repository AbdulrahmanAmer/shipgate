# Pack: search-engines

> Engine-specific requirements beyond the shared fundamentals in web-delivery: Google search features and spam policies, Bing (and the engines and AI products built on its index: Copilot, DuckDuckGo, Yahoo), Yandex, Baidu, Naver, Seznam and Apple, plus local search (business facts, location pages). Every rule cites the engine's own documentation in its metadata (`sources`). Engine behaviour changes often, so feature-level requirements live in **feature tables** shipped with the ruleset (`rules/features/<engine>.json`, § 4), updated with each ruleset release rather than hard-coded.

---

  "sponsoredLinkSelectors": [".sponsored a", "[data-affiliate]"],
  "ugcSelectors": [".comment a", ".forum-post a"],

  "products": { "variantParams": [], "discontinued": [] },   // variantParams: query params selecting a variant; discontinued: [{ pattern, successor? }]

## 2. Shared crawl and index plumbing — `SE-0xx`

- **SE-001** · P0 · http — robots.txt health (Google treats server errors on robots.txt as a full disallow for a period; Naver treats 5xx as "disallow everything"): `/robots.txt` on each service origin host and on its apex/`www` counterpart answers 200 with the complete body within 5 s, never 5xx or 429, as `text/plain`, ≤ 512,000 bytes, valid UTF-8; a redirect is allowed only to `/robots.txt` on the service's canonical origin host. Part `missing` (W): a 404 (allow-all) answer; IDX-004 owns the 200 requirement for production.
- **SE-002** · P0 · http, browser — robots.txt groups for the crawler token of every engine in `engines` ∪ {`google`, `bing`} (`google` Googlebot, `bing` Bingbot, `yandex` YandexBot, `naver` Yeti, `baidu` Baiduspider, `seznam` SeznamBot, `apple` Applebot) allow (a) every indexable URL of the HTTP crawl (04 § 10) and (b) every same-origin resource URL referenced in the raw HTML of the HTTP-sampled indexable pages by `<script src>`, `<link rel="stylesheet|preload|modulepreload" href>`, `<img src|srcset>`, `<source srcset>` or `<video poster>`; failure class `access-denied-wrongly` (URL, token, matching line). Part `rendered-resources` (P0 · browser): the same for every same-origin request made by the browser-sampled indexable pages (04 § 10). Each engine's group is evaluated on its own (04 § 15 *robots.txt evaluation*; named groups don't inherit from `*`).
- **SE-003** · P1 · html, http — Engine verification. Value grammar of each `verification` entry: `"dns"` | `"meta:<name>:<content>"` | `"file:<path>[:<content>]"`; a legacy `<name>:<content>` value is `meta`. `meta`: the homepage of every public service origin has `<meta name="<name>" content="<content>">` in its raw-HTML `<head>` (outside frames); `file`: `<path>` on every public service origin returns 200 (and its body contains `<content>` when given). `"dns"` is not checkable here: `skipped(dns-verification)`. `null` → `notApplicable` for that engine (SE-009 owns null `google`/`bing`).
- **SE-004** · P1 · site — (Owner of lastmod format; IDX-003 owns lastmod source.) Sitemap `<lastmod>` uses W3C datetime **with time and timezone** (`YYYY-MM-DDThh:mm:ss` followed by `Z` or `±hh:mm`; a date-only value fails; Bing prioritises recrawls with it) (movement only with content: AEO-012; value source: IDX-003); with `baidu` in `engines`, robots.txt carries one `Sitemap:` line for every child sitemap file of the index in addition to the index itself (Baidu doesn't support sitemap index files).
- **SE-005** · P1 · http — All indexable HTML responses support conditional requests (`ETag` or `Last-Modified` with `If-None-Match`/`If-Modified-Since` → `304`): Google, Bing and Yandex all use them to save crawl. SE-005 does not evaluate family and hub pages of programmatic families (CRW-002 owns them).
- **SE-006** · P0 · http — Non-HTML documents: same-origin responses of content type `application/pdf`, `application/msword`, `application/vnd.openxmlformats-officedocument.*` or `application/vnd.oasis.opendocument.*` linked from indexable pages. A document has an HTML equivalent when an indexable page links it with `<link rel="alternate" type="<its content type>" href>`; such a document's response carries `Link: <url>; rel="canonical"` equal to that page's canonical, or `X-Robots-Tag: noindex`. Part `unpaired` (W): a linked document with no HTML equivalent (no `rel=alternate`) and no `X-Robots-Tag` is listed for the Operator to confirm it is meant to be indexed on its own; this part reports only that case (AEO-009 `pdf` owns title equality between a PDF and its HTML page).
- **SE-007** · P1 · html, ast — Part `uri` (P1 · html): each internal `<a href>`, after percent-encoding non-ASCII characters, is an RFC 3986 URI-reference; a raw space, any of `<>"{}|\^` or a backtick, a `%` not followed by two hex digits, or a query containing `;` as parameter separator is a finding (`pattern-match`: URL, character); and no internal `<a href>` to an indexable page has a fragment starting with `#/` or `#!` (hash routing). Part `hash-router` (P1 · ast): the adapter reports hash-based routers as findings. (Slug format: URL-007.)
- **SE-008** · W · edge, review — Bot reach. Part `ua-reach` (W · edge): in the edge pass (G8), requests with the `userAgent` of the `search-agents.json` entry of each engine token of SE-002 (`engines` ∪ {`google`, `bing`}; variant `desktop`, else the only variant) to the homepage and 5 sampled indexable URLs (04 § 2) that get 403/429 or a challenge page (`cf-mitigated: challenge` header, or a body matching ruleset `error-pages` fingerprints; shared with AEO-008) are reported (a 403 to a spoofed user agent from a non-engine IP can be correct, hence W). Part `allowlist` (W · review): the Auditor confirms the firewall/CDN allows each engine's published crawler IP ranges or reverse-DNS verification.
- **SE-009** · P1 · cfg, html, review — Webmaster tools are connected: `verification.google` and `verification.bing` are non-null (a value checked by SE-003, or `"dns"`). Part `submitted` (W, review): the Auditor confirms the sitemap index is submitted in Google Search Console and Bing Webmaster Tools for each production origin.

## 3. Google — `SE-1xx`

### 3.1 Search features and appearance
- **SE-101** · P1 · html — Structured-data features, against the feature table of the pinned ruleset (`rules/features/google.json`, § 4). For each feature in `features` and each indexable page whose JSON-LD has a node of one of the feature's `schemaTypes`: part `required` (P1) — every `required` entry resolves on that node; part `recommended` (W) — every `recommended` entry resolves; part `deprecated` (W) — a node of a feature with `status: deprecated` in the feature table is present on an indexable page, whether or not the feature is in `features` ("no longer shown"; e.g. FAQ rich results (removed May 2026), practice problems, Sitelinks Search Box, HowTo, course info, estimated salary, learning video, special announcement, vehicle listing). Part `unused` (W): a feature in `features` that no indexable page carries.
- **SE-102** · P1 · html — Site name: the homepage `WebSite` node carries `name` equal to `web-delivery.siteName` and to `og:site_name`, and, when `web-delivery.siteAlternateName` (string, default `null`) is set, `alternateName` equal to it.
- **SE-103** · P1 · html — Discover. With `discover.enabled`, on indexable pages whose JSON-LD has an `Article`/`BlogPosting`/`NewsArticle` node: part `preview` (P1) — meta robots carries `max-image-preview:large` (on these pages SE-103 `preview` `owns` `AEO-001#large-preview`); part `image` (P1) — the image of `og:image` (else the first `Article.image`) is fetched, its decoded width is ≥ 1,200 px and width × height > 300,000, and its URL differs from `Organization.logo` and from `web-delivery.defaultOgImage` (16:9 preferred, not checked); part `clickbait` (W) — the NFKC `<title>` or `<h1>` matches ruleset `clickbait-patterns.json` (`{ "<BCP 47 tag>": [regex…] }`, Rust `regex` syntax, matched case-insensitively; locale lookup `ll-CC` → `ll` → `en`, 04 § 14); the finding names the pattern index.
- **SE-104** · P1 · html, site — With `news.enabled`: every `NewsArticle` node on an indexable page has `datePublished` and `dateModified`, and each `author` with a `url` that returns 200 and is indexable. Part `unused` (W): no indexable page has a `NewsArticle` node. Part `sitemap` (P1 · site), with `news.sitemap`: a sitemap declaring the `news:` namespace is listed in robots.txt or the sitemap index; each of its `<loc>` is an indexable 200 page; each `<news:publication_date>` is ≥ 0 and ≤ 2 days (172,800 s) before the reference time (04 § 15) and equals the page's `NewsArticle.datePublished` as an instant. `news.enabled` false → `notApplicable`.
- **SE-105** · P1 · html — Images: images referenced as `og:image` (except a URL equal to `web-delivery.defaultOgImage`), `Article.image` or `Product.image` are also present in `<main>` as an `<img>` whose `src` or any `srcset` candidate, or a `<picture><source srcset>` candidate, resolves to the same absolute URL ignoring the query string (not only CSS backgrounds); image license metadata (`license`, `acquireLicensePage`) is present when the `image-metadata` feature is enabled.
- **SE-106** · P1 · html, browser — Video watch pages (pages whose `{canonical}#primary` node (SCH-001) or `WebPage.mainEntity` is a `VideoObject`): a `<video>`, `<iframe>` embed or `<object>` is present in raw HTML, and at the mobile viewport its top edge is within the first viewport height.
- **SE-107** · P1 · html — Merchant listings (`merchant-listing`): `Product` + `Offer` with `price`, `priceCurrency`, `availability`, plus `shippingDetails` and `hasMerchantReturnPolicy` (or organization-level return policy) as the feature table requires; prices match visible values (SCH-006). (Required-property presence: SE-101; price visibility is SCH-006, availability visibility is SE-112; this rule owns the organisation-level return-policy fallback.)
- **SE-108** · P0 · http, html — Expiring content: a 200 page must not carry `JobPosting.validThrough` or `Event.endDate` earlier than the reference time (04 § 15); expired postings return 404/410 or drop the markup. A date-only value is the end of that day (23:59:59) and a value without an offset is UTC.
- **SE-109** · P0 · html, browser — Paywalled or gated content: on an indexable page whose raw-HTML `<main>` (Googlebot smartphone user agent) contains a *gated block* — an element whose text has ≥ 50 UAX #29 words, that is hidden (04 § 15 *Hidden content*) or absent in the rendered anonymous Chrome page, and whose parent is not itself such an element — JSON-LD has `isAccessibleForFree: false` and a `hasPart` with `isAccessibleForFree: false` whose `cssSelector` is a class selector matching that gated block (a single class on the block or on its closest ancestor with a class) (otherwise it looks like cloaking). RTE-010 owns user-agent-dependent differences; SE-109 owns the markup. **Ownership:** elements matched by the `hasPart.cssSelector` of an `isAccessibleForFree: false` declaration are judged here, not by AEO-014 `hidden-text` (SE-109 `owns` `AEO-014#hidden-text` for them).
- **SE-110** · W · html — Byline dates (owner of the "article shows a date" check; CQ-004 refers here): on pages with an `Article`/`BlogPosting`/`NewsArticle` node, at least one visible date (04 § 15 *Visible dates*) parses back to `datePublished` or `dateModified` (AEO-006 owns cross-source consistency).
- **SE-111** · P1 · html — Product variants. A page has variants when its JSON-LD contains a `ProductGroup` or a `Product` with `inProductGroupWithID`, or its URL carries a `products.variantParams` parameter. Then: the `ProductGroup` has `productGroupID`, `variesBy` (schema.org property URLs or names, e.g. `https://schema.org/color`) and `hasVariant` with ≥ 2 `Product`s, each with `inProductGroupWithID` = `productGroupID`, a `url` and its own `Offer`; variant `url`s are distinct; either every variant URL is self-canonical, or every variant URL is canonical to the group page (mixed fails; URL-004 admits this cross-path canonical and URL-001 the `variantParams` query); on a variant URL, a visible price in `<main>` parses back (SCH-006) to the `Offer.price` of the variant whose `url` equals the requested URL; on the group URL, every visible price in `<main>` outside related-product cards equals some variant's `Offer.price`. **Related-product cards** (also SE-112): `data-list` containers, elements with their own `Product` `itemscope`, and `<li>`/`<article>` elements containing an `<a href>` to a different URL of the page's route group (04 § 10).
- **SE-112** · P1 · html, http — Stock state. Part `availability`: let S be the set of stock states whose ruleset phrases (`stock-phrases.json` per locale: in stock, out of stock, sold out, pre-order, back-order, limited, discontinued) appear in `<main>` of a `Product` page outside related-product cards (SE-111); when S is non-empty, some `Offer.availability` maps to each state in S (with one `Offer`, its value maps to every state in S). State → schema.org value: in stock `InStock`; out of stock `OutOfStock` or `SoldOut`; sold out `SoldOut` or `OutOfStock`; pre-order `PreOrder`; back-order `BackOrder`; limited `LimitedAvailability`; discontinued `Discontinued`. `stock-phrases.json` shape: `{ "<locale>": { "<state>": [phrase…] } }`, matched whole-word, case-insensitive, after NFKC. Part `out-of-stock`: pages whose markup or merchant feed (SE-113) says `OutOfStock` return 200, stay indexable and keep `Product` + `Offer` markup. Part `discontinued`: URLs matching `products.discontinued` answer, when the entry has a `successor`, a 301 or 308 in one hop to it, else 410; no 200 page carries `availability` `https://schema.org/Discontinued` or has S = {discontinued} (owner of discontinued products; `retired` paths stay URL-008).
- **SE-113** · P1 · data, html — Merchant feed (with `merchantFeed` set; RSS 2.0/Atom with the `g:` namespace, or TSV with Merchant Center column names, 03 § 14): each item's `link` returns 200 with a canonical equal to `link` (or to the group page under SE-111's group-canonical choice, matched via `item_group_id` = `productGroupID`); the page's `Offer` equals the item: `price` and currency equal `g:sale_price` when present and the reference time (04 § 15) is inside `g:sale_price_effective_date` (or no date is given), else `g:price`; `availability` after replacing spaces with `_` (`in_stock`→`InStock`, `out_of_stock`→`OutOfStock`, `preorder`→`PreOrder`, `backorder`→`BackOrder`); and `gtin` equal to the page's `gtin`/`gtin8`/`gtin12`/`gtin13`/`gtin14` after left-padding to 14 digits. Prices compare as decimal numbers in major units (`15.00 USD` equals `Offer.price` `"15"` with `priceCurrency` `USD`). An item without a `gtin` is not checked for `gtin`; an item with a `gtin` and a page with no `gtin*` property is a `missing-element` finding. A `merchantFeed` path that is missing or unparsable is a blocking `parse-error` finding owned by `builder` (reassigned to `operator` only when the path lies outside the Builder's `writeScope`, 04 § 14). Items checked: all when ≤ 1,000, else 1,000 drawn with the lock-digest PRNG.
- **SE-114** · P1 · data, html — Agentic-commerce feeds (with `agenticFeeds` set): each entry's `path` exists and parses by extension (`.json`, `.jsonl`, `.csv`, `.tsv`, `.xml`); fields are read through the per-`kind` map in ruleset `agentic-feeds.json`, and for `kind: "other"` through the entry's `fields` object of the same shape (absent → `notConfigured(agenticFeeds.fields)`). `agentic-feeds.json` shape: `{ "<kind>": { "items": "<JSON Pointer (.json) | XPath 1.0 (.xml) | null (.jsonl/.csv/.tsv: one item per line/row)>", "fields": { "link", "price", "currency"?, "availability", "item_group_id"?: "<key, column or relative path>" }, "price": "major-number" | "minor-int" | "amount-space-currency", "availability": { "<feed value>": "<schema.org value>" } } }`. A path that is missing or unparsable is a blocking `parse-error` finding owned by `builder` (reassigned to `operator` only when the path lies outside the Builder's `writeScope`, 04 § 14). Each item is checked exactly as in SE-113: `link` returns 200 with a canonical equal to `link` (or to the group page under SE-111), and the page's `Offer` `price`, `priceCurrency` and `availability` equal the item. Items checked as in SE-113.

### 3.2 Spam-policy compliance (decidable parts)
- **SE-120** · P0 · html — Paid, affiliate and sponsored links (`sponsoredLinkSelectors`, and links to hosts in the `hosts` registry with purpose `affiliate`) carry `rel="sponsored"` (or `nofollow`); user-generated links (`ugcSelectors`) carry `rel="ugc"`.
- **SE-121** · P1 · html — Keyword stuffing signals, in `<main>` of indexable pages (words: UAX #29, NFKC, lowercase; ruleset `stop-words.json` (shape: programmatic § 1.1) and `verbs.json` for the page locale; `verbs.json` is `{ "<BCP 47 tag>": [form…] }` listing every inflected form, NFKC and case-folded, a word matching by equality; locale lookup `ll-CC` → `ll` → `en`, 04 § 14). Part `list` (P1): a text node or list with > 10 items separated by `,`, `|`, newline or list items, each ≤ 4 words, where no item contains a word from `verbs.json` and not every item is a link. Part `density` (P1 on pages with > 300 `<main>` words, W otherwise): one Snowball stem (WP-104) of a word not in `stop-words.json` accounts for > 5 % of `<main>` words. Part `phones` (P1): > 5 phone-number candidates (UX-003 part `phones` detection) with no other word between consecutive ones.
- **SE-122** · P0 · http, browser — No sneaky redirects: for every sampled page, the final URL (after HTTP and JavaScript redirects, 5 s after `load`) for Googlebot smartphone equals that for Chrome mobile, and for Googlebot desktop equals that for Chrome desktop (separate mobile URLs, SE-503 `mobile-agent`, stay possible); no JavaScript redirect to another host on indexable pages. This rule judges final URLs reached after JavaScript or meta redirects; UA-dependent HTTP redirects are owned by RTE-010 `behaviour`.
- **SE-123** · P0 · browser — No hidden links on indexable pages: `<a href>` elements that are hidden (04 § 15 *Hidden content*, which includes zero-size, clipped, same-colour and off-screen links), or whose text is a single non-alphanumeric character and which has no `aria-label` or sits inside a `<p>` (a one-character link in running text is reported even when labelled). Excepted: skip links (an `<a href="#id">` among the first 3 focusable elements whose target is on the page and which is visible when focused). **Ownership:** SE-123 `owns` the hidden-link condition of `AEO-014#hidden-text`; inside `<main>` of programmatic family and hub pages, CNT-009 owns it.
- **SE-124** · P1 · browser — No intrusive interstitials, at the mobile viewport 2 s after `load`: any element with computed `position: fixed` or `sticky`, not matching `interstitialAllowlist` (consent, age verification, legal notices), whose visible box intersected with the viewport covers > 30 % of the viewport area; or, on a document taller than the viewport, `window.scrollY` stays 0 after `window.scrollBy(0, innerHeight)`.
- **SE-125** · W · review — Site reputation abuse: the Auditor confirms that each third-party content section hosted on the domain (coupons, partner articles) has a named owner and editorial oversight.
- **SE-126** · W · html — Thin affiliate pages: on an indexable page, affiliate links (matching `sponsoredLinkSelectors` or pointing at hosts with purpose `affiliate`) number more than 1 per 100 `<main>` words (UAX #29), or `<main>` has < 300 words and ≥ 3 affiliate links.
- **SE-127** · W · review — Expired-domain abuse: with `domainHistory.previousUse: "unrelated"`, the Auditor confirms the site doesn't trade on the previous owner's reputation (content, retained URLs or backlinks from the old topic); a null `domainHistory` is itself the review item ("record the domain's history").
- **SE-128** · P1 · html — Sitewide third-party links (Google spam policies, link spam: "Widely distributed links in the footers or templates of various sites"). On the HTTP sample (04 § 10; ≥ 5 indexable pages required), an `a[href]` to a host that is no service origin, not in `business.json` `socialProfiles` or `answer-engines.organization.sameAs`, and not matched by a `hosts` entry (03 § 3.3) with purpose `payments` or `assets`, and that appears (same host and path) on ≥ 50 % of the sampled indexable pages, carries `rel` containing `nofollow` or `sponsored`, unless its host matches a `sitewideLinkAllow` entry (the Operator's explicit choice, e.g. an agency credit). Failure class `forbidden-value` (href, anchor text, number of pages). Part `anchor` (W): for an allowed link, the anchor text (NFKC, case-folded, whitespace collapsed) equals the host's registrable-domain label (Public Suffix List) or, when the entry is an object `{ host, anchor }`, its `anchor` normalised the same way; otherwise it is reported as a keyword anchor.
  - Missing-input outcomes: `sitewideLinkAllow` absent = `[]`; fewer than 5 sampled indexable pages → `skipped(sample-too-small)`. Entries follow the 03 § 3.3 host grammar (policy JSON Schema, CFG-001).

### 3.3 Faceted navigation (Google's 2024 guidance)
Facet probe bases: the first 3 URLs (crawl order, 04 § 10) matching each `facets.routes` pattern; without `facets.routes`, the first 3 crawled URLs carrying any `facets.params` parameter; neither → SE-130..132 are `notApplicable` when `facets.params` is unset or empty, else `notConfigured(facets.routes)`. `facets.indexable` is an array of parameter-name sets (`[["color"], ["color", "size"]]`); a combination is indexable when its set of non-default facet parameters equals one entry (URL-001 admits these queries).

- **SE-130** · P0 · http — Facet parameters (`facets.params`): combinations with no results return 404 (not an empty 200 page or a redirect to a generic page); probed with the value `shipgate-none` on each probe base (04 § 15 *Facet probes*).
- **SE-131** · P1 · http, html — Facet parameters appear in the order of `facets.params` with values equal to `facets.defaults` dropped; reordered or default-valued variants of each probe base redirect once to the normalised URL.
- **SE-132** · P0 · http, html — Facet combinations that are not indexable (above) are robots-disallowed (by parameter) or fragment-based, carry a canonical equal to the same URL with every `facets.params` parameter removed, and never `noindex` (URL-005, IDX-004).

## 4. Feature tables (`rules/features/<engine>.json`)

Each ruleset release ships `rules/features/google.json` (and `rules/features/bing.json`, `rules/features/naver.json`) generated from the engines' documentation at release time: `{ feature, schemaTypes[], required[], recommended[], status: active|deprecated, deprecatedOn?, docUrl, checkedOn }`. `required[]`/`recommended[]` entries are a property path (dot-separated from the feature's type; through an array, every element) or `{ "anyOf": [path…] }` (at least one resolves). SE-101 evaluates against the table of the pinned ruleset, so engine changes reach projects through new ruleset releases (05 § 6), never silently. The vendor's release process includes a documentation diff of every engine's structured-data and robots pages.

## 5. Bing and its index consumers (Copilot, DuckDuckGo, Yahoo) — `SE-2xx`

- **SE-201** · P1 · html, http — No `noarchive` or `nocache` on indexable pages unless declared in `answer-engines.snippetRules`: Bing documents that `noarchive` keeps content out of Copilot answers and grounding, and `nocache` limits citations to URL, title and snippet.
- **SE-202** · P1 · html — Bing minimum lengths: title ≥ 20 and meta description ≥ 50 Unicode code points (pages whose language is `zh`, `ja` or `ko`: title ≥ 10, description ≥ 25) (presence and uniqueness are owned by MET-001/002); Bing ties short titles/descriptions to lower indexing reliability and grounding eligibility.
- **SE-203** · deprecated — tombstone; owned by RTE-001 (raw-HTML main content, which Bing needs) and AEO-009 (main text not only inside images or video).
- **SE-204** · P1 · html — On every indexable page, when `web-delivery.locales` has ≥ 2 entries or `baidu` or `naver` is in `engines`, add `<meta http-equiv="content-language">` (or `Content-Language` header) whose first language tag equals `<html lang>` case-insensitively: Bing treats hreflang as a weak signal and relies on content-language.
- **SE-205** · deprecated — tombstone; IndexNow is owned by AEO-007 (accepted by Bing, Seznam, Naver and Yandex).

## 6. Yandex — `SE-3xx`

- **SE-301** · P1 · http — With `yandex` in `engines`, the YandexBot group contains `Clean-param` lines that together list every `web-delivery.trackingParams` entry without `*`, and, for an entry ending in `*`, the names ruleset `tracking-param-expansions.json` lists for it (`{ "<entry ending in *>": [param…] }`, e.g. `utm_*` → `utm_source utm_medium utm_campaign utm_term utm_content`; an entry ending in `*` that the file lacks is W `notConfigured(tracking-param-expansions:<entry>)`); and for every URL tested by SE-002, the YandexBot group decision (04 § 15 *robots.txt evaluation*) equals the `*` group decision (Yandex ignores `*` when a Yandex group exists).
- **SE-302** · P1 · http — Indexable HTML responses are ≤ 10,485,760 bytes after `Content-Encoding` is removed (304 handling: SE-005).

## 7. Naver — `SE-4xx`

- **SE-401** · P0 · http, browser — With `naver` in `engines`: in the browser check, the homepage's main frame has no navigation within 5 s after `load` that no HTTP redirect, meta refresh (RTE-009) or user input caused ( meta refresh is RTE-009, robots.txt health is SE-001, Yeti access is SE-002).

## 8. Baidu — `SE-5xx`

**Chinese-locale pages:** pages whose locale has language `zh` and region `CN` or script `Hans`. SE-501..504 apply with `baidu` in `engines`.

- **SE-501** · P0 · html, browser — Chinese-locale pages. Part `hosts` (P0 · html): no `<script src>`, stylesheet, `@font-face` source, `<iframe>`, or `<img>`/`<video>` inside `<main>` on those pages loads from a host in ruleset `china-blocked-hosts.json` (`[host…]` in the 03 § 3.3 host grammar, `*.` wildcard; e.g. Google Fonts, YouTube, reCAPTCHA hosts); `@font-face` sources are read from inline `<style>` and from same-origin stylesheets linked by the page. Part `parity` (P0 · browser): on browser-sampled Chinese-locale pages all main content and navigation are in raw HTML — RTE-001 parts `links` and `main` with the `<main>` token overlap required to be 1.0 instead of `parity.minOverlap`; RTE-001 `main` does not apply to those pages (SE-501 `owns` `RTE-001#main` there).
- **SE-502** · P1 · html — Chinese-locale pages: `<html lang>` is one of `zh-CN`, `zh-Hans`, `zh-Hans-CN` (equality of `<html lang>` with the page locale and the UTF-8 charset are MET-007's; the content-language declaration itself is owned by SE-204, which applies to Baidu targets too, since Baidu ignores hreflang).
- **SE-503** · P1 · html — Chinese-locale pages declare the mobile/desktop relationship with Baidu's `applicable-device` meta: `pc,mobile` unless the page has a `<link rel="alternate" media>` to a mobile URL, in which case it carries `<meta name="mobile-agent" content="format=html5; url=<that URL>">` (format any of `html5`, `xhtml`, `wml`; the URL compared canonicalised, 04 § 10 normalisation).
- **SE-504** · W · html — Meta keywords present on Chinese-locale pages (still read by Baidu; ignored by Google and Bing): 5–10 comma-separated terms, no term repeated (NFKC, case-folded).

## 10. Local search — `LOC-*`

Applies when the search-engines pack is enabled and `quality/data/business.json` (03 § 14) has a non-empty `locations` (the condition UX-003 uses to hand phones over). Otherwise phones are owned by UX-003, LOC-002 is `notApplicable`, and:
- LOC-001 is a facts-oracle rule (04 § 1.2): a page showing an address (part `address` detection, with the postal-code patterns of the regions of `web-delivery.locales`) that contains none of the `postalAddress`, `manufacturers[].address` or `euResponsible.address` values (part `address`), or opening hours (part `hours` detection) is a blocking `forbidden-value` finding owned by the builder; with no such content it is `notApplicable`.
- LOC-003 is a required-facts rule (04 § 1.2): with `project.kinds` including `local-business` and no `business.json` or an empty `locations`, it is a blocking `missing-element` finding owned by `operator` naming `business.json#/locations`; without `local-business` it is `notApplicable`.

Owner of name, phone, address and opening hours; prices, ratings and other business claims belong to the ux pack (UX-003). Phones compare as E.164 (default region: 04 § 15 *E.164 normalisation*); addresses by normalised containment (NFKC, case-folded, whitespace-collapsed) of `street`, `locality` and `postalCode`; hours as day + 24-hour times.

- **LOC-001** · P0 · html, site — NAP and hours match the facts file on every indexable page (text inside `data-fact` elements of programmatic family pages is excluded: the dataset oracle checks it, TPL-003). **Ownership:** LOC-001 `owns` `UX-003#phones` when this section applies. Candidates of parts `phones`, `address` and `hours` are taken outside `ux.factsIgnore` regions. Part `phones`: every phone number shown in raw-HTML visible text (libphonenumber `isValidNumber` with the default region of 04 § 15 *E.164 normalisation*) or in a `tel:` link equals a `business.json` `phones[].e164` or `locations[].phone`. Part `address`: candidates are `<address>` elements and every block element whose own text contains a match of a ruleset `postal-patterns.json` pattern (libaddressinput `zip` regular expressions; shape `{ "<ISO 3166-1 alpha-2>": "<regex>" }`, a country without an entry yields no candidates) for the `country` of some `locations[].address`, where the match is not part of a longer digit sequence, is not preceded by `#`, `$`, `€`, `£`, `¥`, `+`, `-` or `.`, and either is preceded, separated only by spaces and at most one comma, by a word of letters, or stands at the start of a comma- or newline-separated segment and is followed by a word of letters; each candidate contains the `street`, `locality` and `postalCode` of one `locations[].address`, of `business.json` `postalAddress`, of a `manufacturers[].address` or of a `euResponsible.address` (required-facts addresses of PRV-022 and PRV-025) (JSON-LD addresses: part `jsonld`). With an empty `locations`, the facts-oracle `forbidden-value` finding is raised only for a candidate matching none of these. Part `jsonld`: `Organization`/`LocalBusiness` `name` equals `business.json` `name` or a location `name`; `telephone`, `address` (`streetAddress`, `addressLocality`, `postalCode`, `addressCountry`) and `openingHoursSpecification` of a `LocalBusiness` equal the location whose `pagePath` is the page (or, on other pages, the location its `@id` names), and are visible per SCH-006. Part `hours`: in visible text of any indexable page, each match of `<days> <time-range>` (≤ 40 characters apart) is expanded into `(day, opens, closes)` triples; `<days>` is a CLDR abbreviated or wide day name of the page locale, a range of two day names joined by `-`, `–` or `—` (expanded in the locale's CLDR week order from `firstDay`), or a comma list of these; `<time-range>` is two CLDR times (12- or 24-hour) joined by `-`, `–` or `—`, normalised to `HH:MM` 24 h. Every triple must be in the expanded `hours` of the page's location (`pagePath`), else of some location; hours the page omits are not compared. Failure class `value-mismatch`.
- **LOC-002** · W · html, review — Business Profile: each location page's `LocalBusiness` lists the location's `gbpUrl` (or its Google Maps URL) in `sameAs` or `hasMap` (html); the Auditor confirms each Business Profile's website link points to the location's `pagePath` (review).
- **LOC-003** · P1 · site, html — Location pages: every `locations[]` entry has exactly one indexable 200 page at its `pagePath` carrying a `LocalBusiness` (or subtype) node with `@id` `{canonical}#localbusiness`, unique across the site, and that location's name, address and phone (LOC-001); with ≥ 2 locations, `local.locationsHub` is an indexable 200 page linking every location page with plain `<a href>`.
- **LOC-004** · W · review — Local listings on the other engines: for each location of `business.json` `locations` (applies where LOC-001 does) and each engine in `engines` whose ruleset `local-listing-sources.json` entry (`[{ engine, name, url, regions[] }]`, `regions` ISO 3166-1 alpha-2, empty = every country) covers the location's `country` — Bing Places for Business (`bing`), Apple Business Connect (`apple`), Naver Smart Place (`naver`), Yandex Business (`yandex`), Baidu Maps (`baidu`), Seznam Firmy (`seznam`) — the Auditor confirms that a claimed, verified listing exists whose name, address, phone and hours equal the file. One review item per (location, engine) with the entry's listing-management `url`, answered in `quality/audit/review.json` (04 § 1.7) with `confirmed` and a date on or after the lock's `createdAt`; an unanswered item stays a W. Google Business Profile: LOC-002.
  - Missing-input outcomes: no `locations` → `notApplicable`; no engine covering a location → `notApplicable` for it.
