**Shared probe definitions** (used by several rules below):
- **No side effect:** 04 § 15 "No side effect" (no status shortcut: a changed row behind a 500 is a side effect).
- **Refused:** as in SEC-021 (API 401/403, pages redirect to `auth.loginPath`, never 2xx with protected data).
- **Protected body match** (against a protected path P): a 2xx response whose `<title>` and first `<h1>` text (HTML), or sorted top-level JSON keys (JSON), equal those of P fetched with the session of an account P's policy allows.
- **Public form targets:** same-origin `action` URLs of `<form method="post">` on sampled `public` pages (raw HTML and rendered DOM) plus POST/PUT/PATCH requests recorded during flows with `account: null`, excluding `authEndpoints` and `auth: signature` routes.
- **Mail endpoints:** `authEndpoints` ∪ `mailEndpoints` ∪ public form targets whose flow-recorded request was followed by a message in the SMTP sink before the next flow step.
- **Nonce `{n}`:** 8 lowercase hex characters, unique per probe point, seeded by the lock digest.
- Probes that write, log out, lock out or otherwise mutate state run in a mutating stage (04 § 4.2 step 8); each such rule or part says "(mutating stage, 04 § 4.2 step 8)".

## 2. Output and data handling

- **SEC-001** · P0† · ast — Untrusted content is rendered only through framework escaping. Raw-HTML sinks (adapter list: `dangerouslySetInnerHTML`, `v-html`, `set:html`, `innerHTML`, `|safe`, `raw`, `{!! !!}`, `html_safe`, …) receive only `safeJsonLd()` output or the service's approved sanitizer output (detector: 04 § 13). (Behaviour: SEC-047.)
- **SEC-002** · P0† · data, html — Data-derived URLs are `https:` or same-origin relative; `javascript:`, `data:`, `vbscript:` rejected and absent from output.
- **SEC-003** · P0† · http, ast — No open redirects: probed with `next`, `redirect`, `returnTo`, `url`, `continue`, `dest` parameters set to an external host; `Location` must stay same-origin.
- **SEC-004** · P0 · ast, http — Server-side fetches only to `hosts` with `server: true` (source rule on adapter `httpClientApis`), and the egress proxy records no other destinations during G4 (behaviour; owner of "unexpected egress"; SEC-046 probe hosts excluded).
- **SEC-005** · P0† · build, html, http — No secret in client bundles, HTML or API responses. **Secrets** = values of env vars that are not public (adapter `publicEnvPrefixes`, `security.publicEnv`) **and** either have a secret-like name (`*KEY*`, `*SECRET*`, `*TOKEN*`, `*PASSWORD*`, `*PRIVATE*`, `*CREDENTIAL*`, `*_DSN`, URLs containing userinfo) or a value of ≥ 16 characters with Shannon entropy ≥ 3.5 bits/char. shipgate-injected variables (`SITE_URL`, `DEPLOY_ENV`, `SHIPGATE_*`, `PORT`, `NODE_ENV`) and service origins are never secrets. Service-role/admin keys never appear in client code. Part `provider-pattern` (P0†): built client assets and HTML are also scanned with the SEC-050 provider-key patterns (04 § 13) regardless of variable names or public prefixes. Any public-prefixed env var (`NEXT_PUBLIC_`, `VITE_`, `PUBLIC_`, `EXPO_PUBLIC_`, …) whose value matches a provider secret pattern is a finding, as is a Supabase JWT whose payload has `role: "service_role"`. Publishable keys listed in ruleset `publishable-keys.json` are exempt: Stripe `pk_`, the Supabase anon JWT, the Firebase web `apiKey`, Google Maps browser keys. Public prefixes don't make a secret public. (Owner; ARC-002 and adapter traps reference it; OPS-001 uses the same classification.)
- **SEC-006** · W · review — Cache keys include every dimension that changes output; user/tenant data never in shared caches. (Automated parts: SEC-013, SEC-016.)
- **SEC-007** · P0 · http — Production-mode errors never expose stack traces, SQL errors, file paths, debug pages or internal hostnames (detection patterns: 04 § 12), probed with malformed input, unknown ids, wrong content types and oversized bodies; non-GET probes (mutating stage, 04 § 4.2 step 8). (Debug tool paths: SEC-035.)
- **SEC-008** · P1 · build, http — No publicly served source maps (`*.map`) for production client bundles unless `sourceMaps: "public"`.
- **SEC-009** · P0 · html — No mixed content: https pages load no `http:` subresources.

## 3. Transport and headers

- **SEC-010** · P1 · http, edge — HTML responses send `Content-Security-Policy` (scripts without `unsafe-inline` unless nonce/hash; `frame-ancestors` set), `X-Content-Type-Options: nosniff`, `Referrer-Policy` (`strict-origin-when-cross-origin` or stricter), `Permissions-Policy`. `Strict-Transport-Security` (`max-age` ≥ 31536000) is an edge rule (G8) unless the app sets it. Part `isolation` (W): HTML responses lack `Cross-Origin-Opener-Policy: same-origin|same-origin-allow-popups`; pages whose same-origin scripts reference `SharedArrayBuffer` lack `Cross-Origin-Embedder-Policy: require-corp|credentialless`; authenticated API responses lack `Cross-Origin-Resource-Policy: same-origin|same-site`. Part `trusted-types` (W): the CSP lacks `require-trusted-types-for 'script'`.
- **SEC-011** · P0 · http — Cookies named in `auth.sessionCookies`: `HttpOnly`, `Secure`, `SameSite=Lax|Strict`, scoped path; no auth tokens in `localStorage` for apps whose framework supports cookie sessions (ast hint). Part `host-prefix` (W): session cookies not named `__Host-…` (with `Secure`, `Path=/`, no `Domain`).
- **SEC-012** · P0 · http — CORS: never `*` with credentials; allowed origins ⊆ `cors.allowedOrigins`; preflight from an unlisted origin refused.
- **SEC-013** · P0 · http — Authenticated responses are `Cache-Control: private` or `no-store`, with `Vary: Cookie`/`Authorization` where caching is allowed.
- **SEC-058** · P0 · http, edge — Web cache deception: for one `auth: required` page P per route group, requests with an allowed account's session to `<P>/sg{n}.css`, `<P>;sg{n}.css` and `<P>%2Fsg{n}.js` are not a protected body match against P unless the response has `Cache-Control: private` or `no-store`. Part `edge` — the edge pass has no sessions: on `previewUrl` (and `production.origins` with `edge.production`) each variant URL of the same pages is requested anonymously twice in a row, and the second response carries no cache-hit indicator from ruleset `cache-hit-headers.json` (`CF-Cache-Status: HIT`, `X-Vercel-Cache: HIT`, `X-Nf-Cache-Status: hit`, `X-Cache: Hit…`, `Age` > 0): an edge that caches the variant anonymously also caches it for sessions.
- **SEC-014** · W · html — Third-party scripts carry Subresource Integrity where the provider serves versioned files.
- **SEC-015** · P1 · edge — `/.well-known/security.txt` per `securityTxt` (contact and expiry present, not expired).
- **SEC-016** · P0 · http, edge — Shared-cacheable responses carry no `Set-Cookie`. Shared-cacheable = `Cache-Control` (or `CDN-Cache-Control`, `Surrogate-Control`, `Vercel-CDN-Cache-Control`) contains `public`, `s-maxage` > 0, or `max-age` > 0 without `private`/`no-store`. Checked on every probed response (anonymous and authenticated). (SEC-013 owns cache headers of authenticated responses; PRF-008 owns lifetimes.)
- **SEC-056** · P1 · edge — TLS on `previewUrl` and, with `edge.production`, `production.origins`: the leaf certificate is valid for ≥ `tls.minDaysValid` days at the time of the edge pass (the run records it); its SANs cover the apex and `www` host of each production origin; the server sends the full chain (validates against the bundled Mozilla root store without AIA fetching); TLS 1.0 and 1.1 handshakes are refused and TLS 1.2 or 1.3 succeeds.

## 4. Authentication, authorization, sessions (probe-proven)

- **SEC-017** · P1 · http — Session renewal: part `fixation` — a session cookie (each name in `auth.sessionCookies`) present before login, and one pre-set to `sg-fixation-{n}`, is not the value in force after the login flow; part `credential-change` — after each `passwordFlows` flow, the sessions of the flow's account captured before the snapshot (04 § 4.2 step 6) are refused (no `passwordFlows` → `notConfigured`). (mutating stage, 04 § 4.2 step 8)
- **SEC-018** · P1 · browser, html — Password policy (NIST SP 800-63B-4): the minimum is `passwords.minLength`, or `passwords.minLengthWithMfa` when `passwords.mfa: true`. Flows containing a `fill` into an element with `autocomplete="new-password"` are replayed with that value replaced by: (a) a random lowercase password one character shorter than the minimum → rejected; (b) the first entry of the bundled breached-password list (ruleset `breached-passwords.txt`) with length ≥ the minimum → rejected; (c) a random 64-character password → accepted; (d) a random lowercase-letters-only password of exactly the minimum length → accepted (no composition rules). Accepted = the flow completes with all expectations passing; rejected = it does not and logging in with the variant fails. Every `new-password` input has no `maxlength` below 64 (html part). Replays (mutating stage, 04 § 4.2 step 8).
- **SEC-019** · P1 · http — OAuth/OIDC: part `state` — each `oauth.callbacks` route requested with a syntactically valid `code` and (a) no `state`, (b) a `state` from a different initiation, sets no session cookie and doesn't return 2xx with protected data; part `client-redirect` — each `oauth.initiate` route requested with `redirect_uri`, `redirect_to`, `redirectTo`, `return_to` set to `https://evil.shipgate.test/cb` answers with no `Location` whose provider-bound `redirect_uri`/`redirect_to` parameter or own target is off the service's origins (SEC-003 owns plain redirect parameters); part `authorization-server` — each `oauth.authorize` route requested with a registered `client_id` and an unregistered `redirect_uri` answers with an error and never redirects to that URI. Without any `oauth` entries: `notApplicable`.
- **SEC-020** · P0† · cfg, http — Every route and endpoint resolves to an access policy (surface default or `security.routes`); undeclared → finding.
- **SEC-021** · P0† · http — `auth: required` routes refuse anonymous requests: API 401/403, pages redirect to `auth.loginPath`; never 200 with protected data. Every declared route and discovered endpoint is probed. Part `override-headers` (P0†) — each anonymous probe is repeated with each entry of ruleset `auth-bypass-headers.json` (`{ header, value, mode }`): mode `same-path` (`x-middleware-subrequest: middleware:middleware:middleware:middleware:middleware` and its `src/middleware` variant, `X-Forwarded-For: 127.0.0.1`, `X-Real-IP: 127.0.0.1`, `X-Forwarded-Host: localhost`, …) must still be refused; mode `rewrite` (`X-Original-URL`, `X-Rewrite-URL` set to the protected path, sent to the service's mount root) fails when the response is a protected body match against the protected path and differs (masked hash, 04 § 15 fallback body) from the mount root's response without the header. Probe headers pass the front proxy unchanged (as SEC-038).
- **SEC-022** · P0† · http — `roles` routes refuse authenticated accounts without those roles.
- **SEC-023** · P0† · http — Tenant/owner isolation: account B requesting A's resource ids (ownership fixtures or harvesting, 03 § 14) gets 403/404 for read **and** write methods; write probes (mutating stage, 04 § 4.2 step 8); without a write body the write part is `notConfigured`.
- **SEC-024** · P0 · http — CSRF: state-changing requests recorded during flows are replayed with valid cookies but without the CSRF token and with a foreign `Origin`/`Sec-Fetch-Site: cross-site`; they must be rejected and have no side effect (mutating stage, 04 § 4.2 step 8).
- **SEC-025** · P1 · http — Auth endpoints rate-limit (`rateLimit.attempts` rapid attempts → 429 or lockout) when `enforcedAt: "app"`; responses don't reveal whether an account exists (identical status/body shape for known and unknown emails). Both parts (mutating stage, 04 § 4.2 step 8). Edge-enforced limits (`enforcedAt: "edge"`) can't be probed by the read-only edge pass: that part is W plus a review item. (Owner for `authEndpoints` request limits; all other endpoints and mail volume: SEC-054.)
- **SEC-026** · P0 · http — Webhooks with `auth: signature` reject unsigned and wrongly signed payloads (mutating stage, 04 § 4.2 step 8). (Replay and timestamps: SEC-049.)
- **SEC-027** · P0 · ast — Passwords only through established hashing (bcrypt/scrypt/argon2/framework default); no custom crypto; no MD5/SHA-1 for credentials.
- **SEC-028** · P0 · http — Logout invalidates the session server-side: the old session cookie/token replayed after logout is refused (mutating stage, 04 § 4.2 step 8).
- **SEC-029** · P0 · http, browser — Password-reset and magic-link tokens are single-use: a used link replayed fails (via the SMTP sink; mutating stage, 04 § 4.2 step 8). Expiry is checked only when `auth.tokenTtlVar` lets the verify environment shorten token lifetimes; otherwise the expiry part is W.
- **SEC-030** · P0 · ast, http — API handlers validate input at the boundary; invalid input → 400/422 with the declared error shape, never 500. Fuzzing (04 § 15) uses the contract (mutating stage, 04 § 4.2 step 8); without a contract the behaviour part is `SKIPPED`.
- **SEC-031** · P0 · ast — Parameterised queries or the ORM's safe API; no string-built SQL with request data. (Other injection sinks: SEC-045.)
- **SEC-032** · P1 · http, review — Uploads: server-side size/type limits (oversized/wrong-type probes rejected); user uploads never served from the app origin with executable or HTML types. Upload probes (mutating stage, 04 § 4.2 step 8). Part `svg` (W, same stage): shipgate's SVG fixture containing `<script>`, uploaded in place of the file of each flow `upload` step, is served from the app origin as `image/svg+xml` without a CSP containing `script-src 'none'` or `default-src 'none'` and without `Content-Disposition: attachment`.
- **SEC-033** · P1 · cfg, http — Test-login backdoors (`auth.verifyBackdoor`) return 404 unless `SHIPGATE_VERIFY=1` (probed in the preview pass).
- **SEC-037** · P0 · http — Token tampering: for each account's session token (`auth.sessionCookies` values, or the `headerTemplate` token; JWT = three base64url segments, after adapter cookie decoding), one `auth: required` endpoint or page per route group is requested with each variant and must be refused: part `alg-none` — header `alg` set to `none`/`None`/`NONE`, empty signature; part `payload` — `sub` replaced by account B's `sub` (no `sub`: the first role/tenant claim changed), original signature; part `foreign-key` — payload unchanged, re-signed with a fresh key of the same algorithm family, plus, for asymmetric tokens whose public key is published (`/.well-known/jwks.json` on the service or issuer), HS256 signed with that public key; part `expired` — a genuine token past its lifetime (only with `auth.tokenTtlVar`; otherwise W); part `opaque` — non-JWT tokens with one character changed.
- **SEC-057** · P0† · ast, http — Server functions (enumerated by adapter `serverFunctions`: Next.js Server Actions — `'use server'` exports and the server-reference manifest; SvelteKit form actions; React Router/Remix actions; tRPC/oRPC procedures) that perform writes (a write operation of `queryApis`, or an `httpClientApis` call with a non-GET method, directly or via a function they call directly) call an adapter `authGuardApis` function before the first such write in source order, or are listed in `publicServerFunctions`. Part `behaviour` — each enumerated function not in `publicServerFunctions` is invoked per the adapter's invocation template (Next.js Server Actions: posted with their action id to a `public` page path, since ids are path-independent; others: to their own route) anonymously and as account B, with the arguments recorded when account A's flows called it (none recorded: empty arguments, anonymous only); each invocation has no side effect (mutating stage, 04 § 4.2 step 8).

## 5. Injection and request forgery

- **SEC-036** · P0 · http, db — Mass assignment: each write request (POST/PUT/PATCH) recorded during flows is replayed as the same account with extra body fields: properties marked `readOnly: true` in the operation's contract schemas, plus the ruleset list `mass-assignment-fields.json` (`role`, `roles`, `is_admin`, `isAdmin`, `admin`, `tenant_id`, `tenantId`, `org_id`, `owner_id`, `ownerId`, `user_id`, `userId`, `plan`, `verified`, `email_verified`, `emailVerified`, `price`, `amount`, `balance`, `credits`, `permissions`) and `massAssignment.extraFields`. Values: strings `sg-ma-{n}`; ids of account B's user/tenant for `*_id`/`*Id`; a role from `auth.accounts` the account doesn't have (preferring one named in a `roles` route policy) for `role`/`roles`; `true` for booleans; `0` for `price`/`amount`, `999999` for `balance`/`credits`. Fails when the injected value persists: part `readback` — a GET of the written resource (the `Location` header, the response's `$.id` with the contract's item path, or the same path for PUT/PATCH) as the same account returns the injected value; part `db` — in local databases, a row created or changed by the replay (diff against a pre-replay snapshot of tables having a column of that name) holds the injected value in that column. (mutating stage, 04 § 4.2 step 8)
- **SEC-038** · P0 · http — Host header poisoning: each mail endpoint is called with a valid body for a seeded account (flow-recorded or contract example) and, in separate requests, `Host: evil.shipgate.test` and `X-Forwarded-Host: evil.shipgate.test` (the front proxy passes probe-supplied values through). Every link in the captured mail uses the service's configured origin (`SITE_URL`); no response header or body contains an absolute URL with `evil.shipgate.test`. (mutating stage, 04 § 4.2 step 8)
- **SEC-039** · P0 · http — Email header injection: for each mail endpoint, each string field of the request is sent in turn as `sg{n}@example.com\r\nBcc: sg{n}@evil.shipgate.test`, its `%0d%0a`-encoded form, and `sg{n}\r\nCc: sg{n}@evil.shipgate.test`; the SMTP sink records no `RCPT TO` and no `Bcc`/`Cc`/`To` header containing `evil.shipgate.test`, and no message header added after a field value. (mutating stage, 04 § 4.2 step 8)
- **SEC-045** · P0† · ast, http — Injection beyond SQL. Source parts flag request-derived values (adapter sources, 04 § 13 data flow) reaching: part `exec` — adapter `execApis` (shell or process execution); part `fs` — the path argument of adapter `fsApis` unless it passed through an adapter `pathGuardApis` call or a `pathSanitizers` export; part `eval` — adapter `evalApis` (`eval`, `new Function`, `vm.run*`, template compilation from a string: `render_template_string`, `Handlebars.compile`, `ejs.render`, `Template(str)`, …); part `deserialize` — adapter `deserializeApis` (`pickle.loads`, `yaml.load` without a safe loader, `unserialize`, `Marshal.load`, `ObjectInputStream.readObject`, `BinaryFormatter`, `node-serialize`); part `nosql` — document-store filters in adapter `queryApis` whose values are request body/query properties not passed through a schema-validation call or a primitive coercion (`String()`, `Number()`, `str()`, `int()`). Probe parts: part `traversal` — parameters named in ruleset `file-params.json` (`file`, `path`, `filename`, `download`, `doc`, `template`, `page`, `include`) on flow-recorded requests and contract operations, and the last path segment of routes that answered with `Content-Disposition` or a non-HTML type, sent (non-GET requests: mutating stage, 04 § 4.2 step 8) with ruleset `traversal-payloads.json` (`../../../../etc/passwd`, `..%2f..%2f..%2f..%2fetc%2fpasswd`, `....//....//....//etc/passwd`, `..\..\..\..\windows\win.ini`): fails when the response is 2xx and its body matches `root:.*:0:0:` or `\[fonts\]`; part `ssti` — the same query parameters and flow fields as SEC-047 sent with `{{D*7}}`, `${D*7}`, `<%= D*7 %>`, `#{D*7}` (`D` = a 6-digit number derived from `{n}`): fails when the product appears in the response or a later-visited page and not in the unprobed response. (SQL: SEC-031; input validation: SEC-030.)
- **SEC-046** · P0 · http — SSRF: URL-accepting inputs — contract request fields with `format: uri|url|iri`, and query/body/form fields named in ruleset `ssrf-params.json` (`url`, `uri`, `src`, `source`, `callback`, `webhook`, `image`, `imageUrl`, `image_url`, `avatar`, `avatarUrl`, `feed`, `link`, `target`, `endpoint`, `proxy`) on flow-recorded requests and contract operations — are sent each probe target in turn: `http://127.0.0.1:{canary}/sg{n}`, `http://[::1]:{canary}/sg{n}`, `http://localhost:{canary}/sg{n}`, `http://2130706433:{canary}/sg{n}`, `http://169.254.169.254/latest/meta-data/`, `http://[fd00:ec2::254]/latest/meta-data/`, `http://10.0.0.1/sg{n}`, `http://172.16.0.1/sg{n}`, `http://192.168.0.1/sg{n}`, and `http://ssrf-redirect.shipgate.test/sg{n}` (answered by the egress proxy with a 302 to the loopback canary). `{canary}` = a shipgate listener on a free loopback port. Fails when the canary receives any request, or the egress proxy records a connection to a probe address or a request following the redirect. Replays of non-GET requests (mutating stage, 04 § 4.2 step 8). Processes that bypass the proxy variables leave the non-loopback targets unobservable; the report says so (04 § 4.6).
- **SEC-047** · P0† · http, browser — Behavioural XSS: payloads from ruleset `xss-payloads.json`, each containing `{n}` (e.g. `"'><sgx{n}></sgx{n}><img src=x onerror=__sg('{n}')>`, `'-__sg('{n}')-'`, `</script><sgx{n}>`), are injected into: query parameters seen in links and GET forms of sampled pages plus `q`, `s`, `search`, `query`, `ref`; each `{param}` segment of one sample URL per parameterised route; and `fill` values of text-like fields (`text`, `search`, `url`, `textarea`, `contenteditable`) in flows, replayed (mutating stage, 04 § 4.2 step 8). Fails when: the raw HTML (html5ever) of the response or of any page later visited contains an element named `sgx{n}` or an event-handler attribute containing `__sg('{n}')`; or, in the browser (pages visited by the flow and every account's sampled `app` pages), the init-script hook `window.__sg` is called with `{n}` or a `dialog` opens. Part `reflected` (query/path, `remote: read`, so it runs on Tier-3 and hosted services) and part `stored` (flows).

## 6. Exposure and abuse

- **SEC-034** · P0† · http, edge — Exposed files: each path in ruleset `exposed-paths.json` returns no 2xx whose body matches that entry's signature, including `/.git/HEAD` (`^ref: |^[0-9a-f]{40}`), `/.git/config` (`\[core\]`), `/.env`, `/.env.local`, `/.env.production`, `/.env.development`, `/.env.staging`, `/.env.backup` (a line `^[A-Z_][A-Z0-9_]*=`), `/.DS_Store` (magic `\x00\x00\x00\x01Bud1`), `/debug.log` and `/wp-content/debug.log` (`PHP (Notice|Warning|Fatal error)`), `/phpinfo.php` (`phpinfo\(\)|PHP Version`), `/server-status` (`Apache Server Status`). Backup copies: for up to 20 served same-origin files and route paths per service, the variants `<path>.bak`, `<path>.old`, `<path>.orig`, `<path>~`, `<dir>/.<name>.swp` return no 2xx with a non-empty body whose masked hash differs from the response to `/sg-{n}<ext>` (the fallback body). Auto-index: each directory prefix of served asset paths returns no body containing `<title>Index of /` or `Directory listing for`. (Source maps: SEC-008; committed secrets: SEC-050.)
- **SEC-035** · P0 · http — Debug and admin tools: each path in ruleset `debug-paths.json` (`/actuator`, `/actuator/env`, `/telescope`, `/_profiler`, `/graphiql`, `/swagger-ui`, `/swagger-ui.html`, `/api-docs`, `/phpmyadmin`, `/adminer.php`, `/__debug__`, `/rails/info`, `/_debugbar`, `/elmah.axd`, `/console`, …) returns 404 or is refused (401/403 or a redirect to `auth.loginPath`) in production mode, or returns 2xx without that entry's signature; paths matching a `security.routes` pattern are exempt. (Error pages: SEC-007.)
- **SEC-054** · P1 · http — Abuse rate limits beyond login: for each endpoint in `rateLimited.endpoints` ∪ public form targets ∪ AI endpoints (SEC-062), `rateLimit.attempts` valid requests sent back-to-back from one client produce at least one 429 (or the declared lockout response); for each mail endpoint (including `authEndpoints`), the SMTP sink captures ≤ `rateLimited.mailsPerAddress` messages to the probed address during the burst. `enforcedAt: "edge"` → the request part is W plus a review item (as SEC-025). (mutating stage, 04 § 4.2 step 8) (`authEndpoints` request limits: SEC-025.)
- **SEC-055** · P1 · http — Bot protection on public form targets: each target satisfies at least one of: (a) SEC-054's request part passes for it; (b) honeypot — the form contains a non-`hidden`-type field that is not visible in the browser (computed `display: none`, `visibility: hidden`, zero size, or off-screen), and a submission with that field filled has no side effect; (c) challenge — the submission carries a field from ruleset `challenge-fields.json` (`cf-turnstile-response`, `g-recaptcha-response`, `h-captcha-response`, `frc-captcha-solution`, `altcha`), and replays with it removed and with `sg-{n}` have no side effect. (mutating stage, 04 § 4.2 step 8)
- **SEC-059** · P1 · edge — Subdomain takeover: every non-wildcard host in `aliasHosts` (web-delivery), `production.hosts`, and `hosts[]` entries under the registrable domain (Public Suffix List) of a `production.origins` entry resolves (its CNAME chain ends in an A or AAAA record; NXDOMAIN or SERVFAIL anywhere in the chain is a finding), and the bodies of `GET https://<host>/` and `GET http://<host>/` match no entry of ruleset `takeover-fingerprints.json` (`NoSuchBucket`, `There isn't a GitHub Pages site here`, `herokucdn.com/error-pages/no-such-app`, …). Wall-clock observation, marked non-deterministic (as SEC-056).

## 7. Payments, webhooks, realtime, storage

- **SEC-040** · P0 · browser, ast — Card data is entered only in the provider's hosted fields/iframe or redirect (`payments.hostedFields`); no card-number inputs in the app's own DOM.
- **SEC-041** · P0 · http — Prices and amounts are computed server-side: the request carrying the field marked by a flow's `markAmount` step is replayed with the amount (or price id) altered; the server rejects it or the provider-bound amount stays unchanged (egress proxy observes the provider request) (mutating stage, 04 § 4.2 step 8). Without a `markAmount` step: `notConfigured`.
- **SEC-042** · P0 · build — No live payment keys in client bundles or built assets (verify-environment keys are owned by CFG-004).
- **SEC-043** · P0 · http — Realtime (`realtime.protocol` adapter: supabase, socket.io, raw-ws): anonymous subscriptions to protected channels are refused; account B cannot subscribe to channels matching A's `tenantChannelPattern`. Other protocols: `noAdapterSupport`.
- **SEC-044** · P0 · http, db — Storage: buckets with `private: true` refuse anonymous and cross-tenant reads; storage policies exist for every bucket (Supabase: `storage.objects` policies). Signed-URL expiry is checked only with `auth.tokenTtlVar`; otherwise W.
- **SEC-048** · P0 · http — Payment fulfilment: entitlements are granted only from a verified webhook or a server-side lookup of the provider session. Part `fabricated` — each account requests `payments.successPath` with `{id}` = a provider-shaped id (`cs_test_sg{n}` for Stripe; ruleset `payment-id-shapes.json` for others); part `foreign-session` — when a mutating flow completed a test-mode payment and reached `successPath`, account B requests the same URL. Afterwards the `payments.entitlement` value for the requesting account still equals `unpaidValue`. Without `successPath` or `entitlement`: `notConfigured`. (mutating stage, 04 § 4.2 step 8)
- **SEC-049** · P1 · http — Webhook replay, for `auth: signature` routes with `scheme`, `secretVar` and `fixture`: shipgate signs the fixture event with the secret per the scheme (ruleset `webhook-schemes.json`: Stripe, Standard Webhooks/Svix, GitHub, Shopify, Paddle, Lemon Squeezy). Part `stale` — a correctly signed event whose signed timestamp is `toleranceSec + 60` s in the past is rejected (non-2xx) and has no side effect (schemes without a signed timestamp: `notApplicable`); part `duplicate` — the same event id delivered twice with fresh signatures: both answered 2xx, and the second delivery has no side effect, measured from the state after the first. (mutating stage, 04 § 4.2 step 8)
- **SEC-063** · P1 · browser, http — Payment-page scripts (PCI DSS 4.0.1 req. 6.4.3). Payment pages = documents visited by `journey: "checkout"` flows that contain an input with `autocomplete` `cc-*` or an iframe from a `hosts[]` entry with purpose `payments`. On them, every script loaded by the browser (static, dynamic and in same-origin frames) comes from the service origin, from a `hosts[]` entry with purpose `payments` or `essential: true`, or matches an entry of the Operator-signed inventory `quality/data/payment-scripts.json`; part `csp` (http) — the CSP of those documents (`script-src`, else `default-src`) contains no `*`, no host source with a `*`, and no scheme-only `https:`/`http:`. No checkout flow: `notConfigured`.
- **SEC-064** · P1 · http, cfg — Session lifetime and admin MFA (ASVS V3/V2):
  - Part `lifetime` (mutating stage, 04 § 4.2 step 8): needs `security.session.idleVar` and/or `absoluteVar`, the env variables holding the service's idle and absolute session lifetimes. shipgate restarts the service with the variable under test set to 5 s and the other left as configured, logs in afresh, then checks:
    - idle: no request for 7 s → the next request is refused;
    - absolute: requests every 2 s for 7 s → refused after ~5 s.

    The declared `idleSec`/`absoluteSec` values (if any) must not exceed ruleset maximums for the project's kinds. Without the variables: `notConfigured`.
  - Part `admin-mfa` (cfg): accounts with role `admin` in `verifyEnv.auth.accounts` either use TOTP in their login flow or `security.adminMfa: "enforced-elsewhere"` is declared with a reason.
- **SEC-065** · P0 · edge — Production takes real payments: with `project.stage: "live"` and `security.payments` set, the edge pass loads the checkout routes recorded by `journey: "checkout"` flows on `production.origins` (GET only) and the same-origin scripts they reference. Neither may contain a test-mode marker from ruleset `payment-test-markers.json` (`pk_test_`, Stripe `livemode: false` config, PayPal sandbox SDK hosts or client ids, Paddle `sandbox-` hosts, Braintree sandbox, …), unless `security.payments.testModeInProduction: true` is declared with a reason. (Live keys in the verify environment: CFG-004.)
- **SEC-066** · W · review, cfg — CI workflow hardening (CI files are Operator-owned, so this is advice to the Operator). Third-party actions are pinned to a full commit SHA. No `pull_request_target` workflow checks out the PR head. No `${{ github.event.* }}` expression is interpolated inside `run:` steps. Equivalent checks for other CI providers come from the ruleset.

## 8. Secrets and dependencies

- **SEC-050** · P0† · diff — No secrets committed (provider patterns and verify-env values per 04 § 13; entropy-only hits are W; `.env` files with real values never committed). Part `history` (P0) — once, at `init` and `verify --adopt`, every commit reachable from `HEAD` is scanned with the same patterns; each hit becomes an Operator-owned debt entry (03 § 9) that clears only when the Operator signs a rotation attestation (`rotatedOn` date) on it; later runs re-evaluate those entries without rescanning.
- **SEC-051** · P0 · deps — No known vulnerabilities ≥ `vulnerabilities.blockAt` (OSV offline database), except waived packages.
- **SEC-052** · P1 · deps — New dependencies: licence in `licences.allow`; not archived/deprecated according to the offline registry snapshot fetched by `shipgate fetch` (unknown → W).
- **SEC-053** · P0 · deps, diff — Supply chain. Part `lockfile` — every dependency manifest has its committed lockfile (`package-lock.json`/`pnpm-lock.yaml`/`yarn.lock`/`bun.lock`, `poetry.lock`/`uv.lock`/hash-pinned `requirements*.txt`, `composer.lock`, `Gemfile.lock`, `go.sum`, `Cargo.lock`), and every direct dependency in the manifest has a lockfile entry whose version satisfies its declared range (frozen-install equivalence, checked offline). Part `registry` — every resolved URL is on a host in ruleset `registries.json` for its ecosystem or in `dependencies.registries`, and every entry carries an integrity hash where the lockfile format supports one; git, file and tarball-URL sources are findings unless the package is in `dependencies.allowNames`. Part `age` — each package version added or changed in the diff was published ≥ `dependencies.minReleaseAgeDays` days before the reference time (04 § 15), per the registry snapshot fetched by `shipgate fetch` (publish time unknown → W). Part `typosquat` — each new direct dependency name, unless in `dependencies.allowNames` or itself in the list, is not within Damerau-Levenshtein distance 2 (names ≥ 6 characters) or 1 (4–5 characters) of a name in the ecosystem's top-10,000 list (ruleset `popular-packages/<ecosystem>.txt`); names < 4 characters are exempt. Part `install-scripts` — each new package with install-time scripts (npm `hasInstallScript`, pnpm `requiresBuild`, ruleset equivalents) is listed in `quality/proposals/dependencies.json` with `installScripts: true`. (Declaration of dependencies: AGT-009.)
