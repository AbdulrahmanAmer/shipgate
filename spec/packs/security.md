**Validation** (pack validation, CFG-006 `schema-violation`): `payments.testModeInProduction: true` requires a non-empty `payments.testModeReason`; `adminMfa: "enforced-elsewhere"` requires a non-empty `adminMfaReason`; `csp.allowUnsafeEval: true` requires a non-empty `csp.unsafeEvalReason`; `session.idleSec`/`absoluteSec` are positive integers or `null`.

**Shared probe definitions** (used by several rules below):
- **No side effect:** 04 § 15 "No side effect" (no status shortcut: a changed row behind a 500 is a side effect).
- **Refused:** as in SEC-021 (API 401/403, pages redirect to `auth.loginPath`, never 2xx with protected data).
- **Protected body match** (against a protected path P): a 2xx response whose `<title>` and first `<h1>` text (HTML), or sorted top-level JSON keys (JSON), equal those of P fetched with the session of an account P's policy allows.
- **Default P** (when a rule uses a protected body match without naming P): the lexicographically first sampled URL (04 § 10) of the first `auth: required` route group in pattern order, fetched with the session of an account its policy allows; no such route group → `notConfigured(security.routes: an auth-required route)`.
- **Account X / account B:** X = the account of the flow that recorded the request or created the object under probe; else the account that owns the id per ownership fixtures or harvesting (03 § 14); else the lowest `verifyEnv.auth.accounts` id in byte order. Account B = the lowest account id in byte order whose `tenant` differs from X's; if every account shares one tenant, the lowest id ≠ X. "Account A" in the rules below means X. SEC-023 uses as B every account the route's `owner` excludes (`owner: "tenant"`: every account with a different `tenant`; `owner: "user"`: every account ≠ X); all other rules use the single B. No account ≠ X → `notConfigured(verifyEnv.auth.accounts: second account)`, owner `operator`.
- **Lifetime variables** (`security.session.idleVar`, `absoluteVar`, and `auth.tokenTtlVar` for SEC-029, SEC-037, SEC-044): values are the decimal integer text of the duration in seconds (5 s = `5`; 03 § 4 `tokenTtlVar`). shipgate sets them in that format and reads configured values in it. Any other format (milliseconds, `5m`) is unsupported; the Operator supplies a wrapper via the service `env` that converts the value.
- **Public form targets:** same-origin `action` URLs of `<form method="post">` on sampled `public` pages (raw HTML and rendered DOM) plus POST/PUT/PATCH requests recorded during flows with `account: null`, excluding `authEndpoints` and `auth: signature` routes.
- **Mail endpoints:** `authEndpoints` ∪ `mailEndpoints` ∪ public form targets whose flow-recorded request was followed by a message in the SMTP sink before the next flow step.
- **Nonce `{n}`:** 8 lowercase hex characters, unique per probe point, seeded by the lock digest.
- Probes that write, log out, lock out or otherwise mutate state run in a mutating stage (04 § 4.2 step 8); each such rule or part says "(mutating stage, 04 § 4.2 step 8)".

## 2. Output and data handling

- **SEC-001** · P0† · ast — Untrusted content is rendered only through framework escaping. Raw-HTML sinks (adapter list: `dangerouslySetInnerHTML`, `v-html`, `set:html`, `innerHTML`, `|safe`, `raw`, `{!! !!}`, `html_safe`, …) receive only `safeJsonLd()` output or the service's approved sanitizer output (detector: 04 § 13). (Behaviour: SEC-047.)
- **SEC-002** · P0† · data, html — Dangerous URL schemes. Part `data` (data): dataset fields of type `url` are absolute `https:` or same-origin relative. Part `html` (html): the values of attributes `href`, `src`, `action`, `formaction`, `xlink:href`, `poster`, `data` (on `object`), each `srcset` candidate URL and each `<meta http-equiv=refresh>` `url=` target, after trimming and removing ASCII tab/newline characters, never start (case-insensitive) with `javascript:` or `vbscript:`, nor with `data:` — except `data:image/(png|gif|jpeg|webp|avif)` on `img[src]`, `source[srcset]`, `img[srcset]` and `video[poster]`. The finding shows the URL, the element's selector and the attribute.
- **SEC-003** · P0† · http, browser, ast — No open redirects. Probed URLs: every route that answered 3xx during the crawl or flows, `auth.loginPath`, and every crawled URL that already carries one of the parameters. Each of `next`, `redirect`, `returnTo`, `url`, `continue`, `dest` is set in turn to `https://evil.shipgate.test/sg{n}`, `//evil.shipgate.test/sg{n}`, `/\evil.shipgate.test/sg{n}`, `https:evil.shipgate.test/sg{n}` and `/%2F%2Fevil.shipgate.test/sg{n}` (GET, read-only stage). Part `login-replay`: the login flow is replayed starting at `auth.loginPath?<param>=<value>` for each parameter and value (mutating stage, 04 § 4.2 step 8). Fails when any `Location` header, `<meta http-equiv=refresh>` target, or URL the browser navigates to after the replayed login, resolved per RFC 3986 against the request URL, has host `evil.shipgate.test`. Part `source` (W, ast): an argument of an adapter `redirectApis` call is request-derived (04 § 13 *Request-derived data flow*).
- **SEC-004** · P0 · ast, http — Server-side fetches only to `hosts` with `server: true`. Part `source` (ast): `httpClientApis` calls whose URL argument is a string literal, or a template/concatenation whose leading literal contains `scheme://host`, with a host matching no `hosts[]` entry with `server: true` and no service origin; non-literal URLs are judged only by the `egress` part. Part `egress` (http): the egress proxy records no other destinations during G4 (owner of "unexpected egress"; SEC-046 probe hosts and hosts answered by an `expectEgress`/`ux.egressStubs` stub, 04 § 4.6, are excluded).
- **SEC-005** · P0† · build, html, http — No secret in client bundles, HTML or API responses. **Secrets** = values of the variables in `verify.env` and the service `env` that are not public (adapter `publicEnvPrefixes`, `security.publicEnv`) **and** either have a secret-like name (`*KEY*`, `*SECRET*`, `*TOKEN*`, `*PASSWORD*`, `*PRIVATE*`, `*CREDENTIAL*`, `*_DSN`, URLs containing userinfo) and a value of ≥ 8 characters that is not purely decimal digits and is not `true`, `false` or `null` (case-insensitive), or have a value of ≥ 16 characters with Shannon entropy ≥ 3.5 bits/char. shipgate-injected variables (`SITE_URL`, `DEPLOY_ENV`, `SHIPGATE_*`, `PORT`, `NODE_ENV`) and service origins are never secrets. Service-role/admin keys never appear in client code. Part `provider-pattern` (P0†): built client assets and HTML are also scanned with the SEC-050 provider-key patterns (04 § 13) regardless of variable names or public prefixes. Any public-prefixed env var (`NEXT_PUBLIC_`, `VITE_`, `PUBLIC_`, `EXPO_PUBLIC_`, …) whose value matches a provider secret pattern is a finding, as is a Supabase JWT whose payload has `role: "service_role"`. Publishable keys listed in ruleset `publishable-keys.json` are exempt: Stripe `pk_`, the Supabase anon JWT, the Firebase web `apiKey`, Google Maps browser keys. Public prefixes don't make a secret public. (Owner, including `SEC-042#client-secret`; ARC-002 and adapter traps reference it; OPS-001 uses the same classification.)
- **SEC-006** · W · review — Cache keys include every dimension that changes output; user/tenant data never in shared caches. (Automated parts: SEC-013, SEC-016.)
- **SEC-007** · P0 · http — Production-mode errors never expose stack traces, SQL errors, file paths, debug pages or internal hostnames (detection patterns: 04 § 12). Probes, per route of the `api` surface and per one sampled URL (04 § 10) of each route group of `public` and `app` pages: (a) unknown id — each `{param}` set in turn to `sg-{n}`, `0`, `-1` and 4096 × `a`; (b) malformed input — on each write route (flow-recorded or contract operation) the body `{` as `application/json`, and on each GET route every crawled query parameter set in turn to `%`, `[]` and `%00`; (c) wrong content type — the recorded body of each write route sent as `text/plain` and as `application/xml`; (d) oversized — on one write route per service (the lexicographically first by pattern) a JSON body padded with one extra string field to 2 × `data-api.maxBodyBytes`. GET probes run in the read-only stage; non-GET probes (mutating stage, 04 § 4.2 step 8). Every probe response, whatever its status, is scanned with the 04 § 12 patterns. (Debug tool paths: SEC-035; the 413 status of oversized bodies: API-007.)
- **SEC-008** · P1 · build, http — No publicly served source maps (`*.map`) for production client bundles unless `sourceMaps: "public"`. Probed: `<asset>.map` for each JS/CSS asset of G3 output, plus every `sourceMappingURL` comment target and `SourceMap` header target; fails on a 2xx JSON body containing `"mappings"`.
- **SEC-009** · P0 · html — No mixed content: https pages load no `http:` subresources. Subresources: `script[src]`, `link[rel~=stylesheet|preload|modulepreload|icon][href]`, `img[src|srcset]`, `source[src|srcset]`, `video[src|poster]`, `audio[src]`, `iframe[src]`, `object[data]`, `embed[src]`, `track[src]`, and CSS `url()` in inline `style` attributes and `<style>` elements.

## 3. Transport and headers

- **SEC-010** · P1 · http, edge — Every 2xx `text/html` response of sampled pages (04 § 10) sends: `Content-Security-Policy` (when `csp.required`; otherwise that header check is `notApplicable`) whose `script-src` (else `default-src`) contains no `'unsafe-inline'` unless it also contains a `'nonce-…'` or `'sha256-…'`/`'sha384-…'`/`'sha512-…'` source or `csp.allowUnsafeInlineScripts: true`, and which contains a `frame-ancestors` directive (any value); `X-Content-Type-Options: nosniff`; `Referrer-Policy` whose last valid token ∈ {`no-referrer`, `same-origin`, `strict-origin`, `strict-origin-when-cross-origin`}; `Permissions-Policy` present and parsing as an RFC 8941 dictionary. The finding names the URL, the header and the actual value. Part `hsts` (P1; channels http, edge): when a G4 response of a sampled page carries `Strict-Transport-Security`, its `max-age` must be ≥ 31536000 (finding shows URL and value); absence is not judged in G4. In the edge pass the response to the HEAD of each checked origin (04 § 2 item 5) must carry it with `max-age` ≥ 31536000. No edge pass → the edge half is `skipped(no-edge)`. Part `isolation` (W): HTML responses lack `Cross-Origin-Opener-Policy: same-origin|same-origin-allow-popups`; pages whose same-origin scripts reference `SharedArrayBuffer` lack `Cross-Origin-Embedder-Policy: require-corp|credentialless`; authenticated API responses lack `Cross-Origin-Resource-Policy: same-origin|same-site`. Part `trusted-types` (W): the CSP lacks `require-trusted-types-for 'script'`. (CSP source strength: SEC-075.)
- **SEC-075** · P1 · http, edge — CSP strength (OWASP CSP Cheat Sheet; ASVS 5.0 V3), on the same responses whose `Content-Security-Policy` SEC-010 judges, when `csp.required`; otherwise `notApplicable`. `Content-Security-Policy-Report-Only` is ignored; with several enforced CSP headers a condition is met when any one of them meets it. Script sources = the `script-src` directive, else `default-src`. Main part (P1): (a) when the script sources contain `'strict-dynamic'` together with a `'nonce-…'` or hash source, host and scheme sources are ignored (CSP Level 3) and (b) is skipped; (b) otherwise the script sources contain no `*`, no scheme-only source (`https:`, `http:`, `data:`, `blob:`), no host source with `*` in its registrable-domain part (Public Suffix List), and no host source whose host is in ruleset `csp-bypass-hosts.json` (`[{ host, reason }]`: hosts serving JSONP endpoints or script gadgets such as AngularJS, e.g. `www.google.com`, `ajax.googleapis.com`, `cdnjs.cloudflare.com`, `cdn.jsdelivr.net`, `unpkg.com`; matched by exact host); (c) the script sources contain no `'unsafe-eval'` unless `csp.allowUnsafeEval: true` (`'wasm-unsafe-eval'` is allowed); (d) `object-src` is `'none'`, or there is no `object-src` and `default-src` is `'none'`; (e) `base-uri` is present with the value `'self'` or `'none'`. Part `form-action` (W): `form-action` is present. Findings `header-value` showing the URL, the directive and the offending source (or the missing directive). On payment pages (SEC-063) checks (b)'s `*`, scheme-only and wildcard-host conditions are reported by SEC-063 `csp` only. The edge half runs on the edge pass responses SEC-010 judges; no edge pass → `skipped(no-edge)`.
- **SEC-011** · P0 · http, browser — Session cookies. Part `attributes` (P0, http): each `Set-Cookie` for a name in `auth.sessionCookies` has `HttpOnly`, `Secure`, `SameSite=Lax` or `SameSite=Strict`, and a `Path` equal to the service `mount` or below it. Part `local-storage` (W, browser): for services whose adapter manifest declares `sessionCookies[]`, after the login flow no `localStorage`/`sessionStorage` value equals or contains the session token, `{account.token}`, or a JWT whose `sub` is the account's. Part `host-prefix` (W): session cookies not named `__Host-…` (with `Secure`, `Path=/`, no `Domain`).
- **SEC-012** · P0 · http — CORS. Probed: each route on the `api` surface and each route that sent any `Access-Control-*` header during the crawl, with a GET carrying `Origin: https://evil.shipgate.test`, and an `OPTIONS` preflight with that origin, `Access-Control-Request-Method: POST` and `Access-Control-Request-Headers: content-type,authorization`. Fails when `Access-Control-Allow-Origin` is `*` together with `Access-Control-Allow-Credentials: true`, equals the probe origin, or is `null`; or, on any crawled response, has a value that is neither `*` nor in the allowed origins, or is `*` on a response of a route whose resolved policy is not `auth: none` (surfaces `public`/`asset` count as `auth: none`). Allowed origins = `cors.allowedOrigins` ∪ service origins (absent key = `[]`).
- **SEC-013** · P0 · http — Responses to requests carrying an account's session, for routes whose resolved access policy is `auth: required`, has `roles`, or has `owner`, are `Cache-Control: no-store`, or `Cache-Control: private` together with a `Vary` header listing `Cookie` or `Authorization`.
- **SEC-058** · P0 · http, edge — Web cache deception: for P = the lexicographically first sampled URL of each `auth: required` route group, requests with an allowed account's session to `<P>/sg{n}.css`, `<P>;sg{n}.css` and `<P>%2Fsg{n}.js` are not a protected body match against P unless the response has `Cache-Control: private` or `no-store`. Part `edge` — the edge pass has no sessions: on `previewUrl` (and `production.origins` with `edge.production`) each variant URL of the same pages, for the first 5 `auth: required` route groups in lexicographic order of pattern, is requested anonymously twice in a row, and the second response carries no cache-hit indicator from ruleset `cache-hit-headers.json` (`[{ header, pattern }]`: header name case-insensitive, `pattern` a regex over the header value; `CF-Cache-Status` → `^HIT$`, `X-Vercel-Cache` → `^HIT$`, `X-Nf-Cache-Status` → `(?i)^hit`, `X-Cache` → `(?i)^hit`, `Age` → `^[1-9][0-9]*$`): an edge that caches the variant anonymously also caches it for sessions.
- **SEC-014** · W · html — Subresource Integrity: every cross-origin `<script src>` and `<link rel=stylesheet href>` whose host is in ruleset `sri-hosts.json` (`[{ host, versionedPathPattern }]`: cdnjs.cloudflare.com, cdn.jsdelivr.net, unpkg.com, code.jquery.com, …) and whose path matches that entry's `versionedPathPattern` carries `integrity` and `crossorigin` attributes.
- **SEC-015** · P1 · edge — `security.txt` per `securityTxt`: `/.well-known/security.txt` on `previewUrl` and, with `edge.production`, on each `production.origins` entry answers 2xx `text/plain` with RFC 9116 `Contact:` and `Expires:` fields, and `Expires` is after the edge pass's wall clock (non-deterministic, as SEC-056). `"optional"`: absence passes, but a file that is served must still be valid.
- **SEC-016** · P0 · http, edge — Shared-cacheable responses carry no `Set-Cookie`. Shared-cacheable = `Cache-Control` (or `CDN-Cache-Control`, `Surrogate-Control`, `Vercel-CDN-Cache-Control`) contains `public`, `s-maxage` > 0, or `max-age` > 0 without `private`/`no-store`. Checked on every probed response (anonymous and authenticated). (SEC-013 owns cache headers of authenticated responses; PRF-008 owns lifetimes.)
- **SEC-056** · P1 · edge — TLS on `previewUrl` and, with `edge.production`, `production.origins`: the leaf certificate is valid for ≥ `tls.minDaysValid` days at the time of the edge pass (the run records it); its SANs cover the host of each production origin and, when that host is a registrable domain (Public Suffix List) or `www.` plus one, both the registrable domain and its `www.` host; the server sends the full chain (validates against the bundled Mozilla root store without AIA fetching); TLS 1.0 and 1.1 handshakes are refused and TLS 1.2 or 1.3 succeeds.

## 4. Authentication, authorization, sessions (probe-proven)

- **SEC-017** · P1 · http — Session renewal: part `fixation` — a session cookie (each name in `auth.sessionCookies`) present before login, and one pre-set to `sg-fixation-{n}`, is not the value in force after the login flow; part `credential-change` — after each `passwordFlows` flow, the sessions of the flow's account captured before the snapshot (04 § 4.2 step 6) are refused (no `passwordFlows` → `notConfigured`). The flow's account = its `account`, else the account whose `{account.<id>.email}` generator it uses; neither → that flow is `notConfigured(flow account)`. (mutating stage, 04 § 4.2 step 8)
- **SEC-018** · P1 · browser, html — Password policy (NIST SP 800-63B-4): the minimum is `passwords.minLength`, or `passwords.minLengthWithMfa` when `passwords.mfa: true`. **Password-set inputs** = `input[type=password]` elements with `autocomplete="new-password"`, plus every `input[type=password]` that is the target of a `fill` step in a flow with `journey: "signup"` or in a `passwordFlows` flow (so omitting the attribute exempts nothing); found in the raw HTML or the rendered DOM of sampled pages and of pages visited by flows. Flows containing a `fill` into a password-set input are replayed with that value replaced by: (a) a password one character shorter than the minimum → rejected; (b) the first entry of the bundled breached-password list (ruleset `breached-passwords.txt`) with length ≥ the minimum → rejected (the build of ruleset `breached-passwords.txt` requires ≥ 100 entries of length 15–64; at run time no entry of length ≥ the minimum → variant (b) is skipped and the report states it); (c) a 64-character password → accepted; (d) a lowercase-letters-only password of exactly the minimum length → accepted (no composition rules). Generated passwords are drawn from the lock-digest PRNG (TR-103) seeded per flow and step, charset `[a-z0-9]` for (a) and (c), `[a-z]` for (d). Accepted = the flow completes with all expectations passing; rejected = it does not and logging in with the variant fails. Every password-set input has no `maxlength` below 64 (html part). No flow fills a password-set input: blocking finding `missing-element` owned by `operator` (flows are Operator-owned, 01 § 5.2; "no flow exercises the password input at <selector>") when any sampled or flow-visited page contains a password-set input, else `notApplicable`. Replays (mutating stage, 04 § 4.2 step 8).
- **SEC-019** · P1 · http — OAuth/OIDC: part `state` — each `oauth.callbacks` route requested with `code=sg{n}sg{n}sg{n}sg{n}` (32 characters) and (a) no `state`, (b) a `state` from a different initiation, sets no session cookie and isn't a protected body match against the default P; part `client-redirect` — each `oauth.initiate` route requested with `redirect_uri`, `redirect_to`, `redirectTo`, `return_to` set to `https://evil.shipgate.test/cb` answers with no `Location` whose provider-bound `redirect_uri`/`redirect_to` parameter or own target is off the service's origins (SEC-003 owns plain redirect parameters); part `authorization-server` — each `oauth.authorize` route requested with each `oauth.clients[].clientId` and `redirect_uri=https://evil.shipgate.test/cb` (not in that client's `redirectUris`) answers with an error and never redirects to that URI (no `oauth.clients` → this part is `notConfigured(security.oauth.clients)`). Without any `oauth` entries: `notApplicable`.
- **SEC-020** · P0† · cfg, http — Every `api`-surface route and endpoint (declared, or discovered during the crawl and flows) matches a `security.routes` pattern; one that matches none is a finding. (`public`/`asset` default to anonymous and `app` to `auth: required`, 01 § 2.1; routes in no surface are CFG-003's.)
- **SEC-021** · P0† · http — `auth: required` routes refuse anonymous requests: API 401/403, pages redirect to `auth.loginPath`; never 200 with protected data. API = a route on the `api` surface, or a response whose `Content-Type` is not `text/html`; everything else is a page. Every declared route and discovered endpoint is probed. Probe methods: for each route, every method it is known to accept (contract operations, flow-recorded requests, adapter `routes.discover` output where it reports methods; none known → GET). GET/HEAD probes run in the read-only stage. Part `write-methods` (P0†): the other methods run in the mutating stage (04 § 4.2 step 8) with the flow-recorded body, else the contract example, else `{}` as `application/json`; each must be refused **and** have no side effect. (Env secret values: SEC-005; the status of cross-tenant reads: SEC-023; writes: SEC-036.)

## 7. Payments, webhooks, realtime, storage

- **SEC-040** · P0 · browser, ast — Card data is entered only in the provider's hosted fields/iframe or redirect (`payments.hostedFields`). Card inputs = `input`/`textarea` elements in the top document or same-origin frames with `autocomplete` `cc-number`, `cc-csc` or `cc-exp*`, or `name`/`id` matching `(?i)card.?num|cc.?num|cvc|cvv|\bpan\b`, or `inputmode=numeric` with `maxlength` 13–19 inside a form whose submission goes to a service origin. Part `dom` (browser): any card input on a page visited by a `journey: "checkout"` flow is a finding. Part `source` (ast): the same patterns in JSX/template markup are a finding. `hostedFields: false` = the Operator declares a PCI-scoped own card form: the rule is `notApplicable` and the report lists that declaration.
- **SEC-041** · P0 · http — Prices and amounts are computed server-side: the request carrying the field marked by a flow's `markAmount` step is replayed with the amount set to 1 minor unit (or, for a price id, with the id of the `business.json` `prices[]` entry with the lowest `amount` different from the original's); the server rejects it or the provider-bound amount stays unchanged (egress proxy observes the provider request) (mutating stage, 04 § 4.2 step 8). Without a `markAmount` step: `notConfigured`.
- **SEC-042** · P0 · build — No live-mode payment key (the live-key patterns of CFG-004: `sk_live_`, `rk_live_`, `pk_live_`, plus PayPal live client ids and other provider live prefixes from the SEC-050 provider-key patterns, 04 § 13), secret or publishable, appears in any G3 output (client and server build directories); the verify build must use test keys. Part `client-secret` — a live secret key in client assets — is reported only by SEC-005 `provider-pattern` (SEC-005 `owns: ["SEC-042#client-secret"]`); the main part reports every other occurrence. (Verify-environment keys: CFG-004; production must use live keys: SEC-065.)
- **SEC-043** · P0 · http — Realtime (`realtime.protocol` adapter: supabase, socket.io, raw-ws; other protocols: `noAdapterSupport`). Protected channels = `realtime.tenantChannelPattern` instantiated with each account's `tenant` (`verifyEnv.auth.accounts`), joined over each `realtime.channels` endpoint. Part `anonymous` (P0): a subscription to each protected channel with no session is refused. Part `cross-tenant` (P0): account B's subscription to the instance for A's tenant is refused. Refused = the server answers the join with an error (supabase: `phx_reply` with `status: "error"`; socket.io: an `error`/`connect_error` event, or no ack within 5 s; raw-ws: a close frame), or the subscriber receives no message within 5 s after shipgate publishes `sg-rt-{n}` on that channel as account A. The publish counts only if account A's own subscription to that channel receives `sg-rt-{n}` within 5 s; otherwise the probe is a `flow-step-failed` finding (a dead realtime server proves nothing). No `tenantChannelPattern` → `notConfigured(security.realtime.tenantChannelPattern)`; no `channels` → `notConfigured(security.realtime.channels)`. (mutating stage, 04 § 4.2 step 8: the publish)
- **SEC-044** · P0 · http, db — Storage. Probe objects: for each bucket, the objects uploaded during account A's flows (recorded storage upload requests); none → objects listed with the service key; none → `notConfigured(storage objects for <bucket>)`. Part `anonymous-read` (P0, http): every probe object of a `private: true` bucket is refused with no session. Part `cross-tenant-read` (P0, http): account B's read of A's probe objects in a `private: true` bucket is refused. Part `policies` (P0, db): every `storage.buckets` row named in `security.storage.buckets[]` has at least one `storage.objects` policy whose `USING` expression mentions `bucket_id`. Part `signed-url-expiry` (P0): a signed URL for a probe object, issued with the lifetime set to 5 s via `auth.tokenTtlVar` (format: shared definitions *Lifetime variables*), is refused 7 s later; without `auth.tokenTtlVar` the part is `notConfigured(auth.tokenTtlVar)`. Storage providers other than the Supabase addon → `noAdapterSupport`. Reads run in the mutating stage after the uploading flow (04 § 4.2 step 8).
- **SEC-048** · P0 · http — Payment fulfilment: entitlements are granted only from a verified webhook or a server-side lookup of the provider session. Part `fabricated` — each account requests `payments.successPath` with `{id}` = a provider-shaped id from ruleset `payment-id-shapes.json` (`[{ provider, template }]`, `template` over `{n}`; Stripe `cs_test_sg{n}`; a `payments.provider` with no entry → `notConfigured(payment-id-shapes.json: <provider>)`); part `foreign-session` — when a mutating flow completed a test-mode payment and reached `successPath`, account B requests the same URL. Afterwards the `payments.entitlement` value for the requesting account still equals `unpaidValue`. Without `successPath` or `entitlement`: `notConfigured`. (mutating stage, 04 § 4.2 step 8)
- **SEC-049** · P1 · http — Webhook replay, for `auth: signature` routes with `scheme`, `secretVar` and `fixture`: shipgate signs the fixture event with the secret per the scheme (ruleset `webhook-schemes.json`: Stripe, Standard Webhooks/Svix, GitHub, Shopify, Paddle, Lemon Squeezy). Part `stale` — a correctly signed event whose signed timestamp is `toleranceSec + 60` s in the past is rejected (non-2xx) and has no side effect (schemes without a signed timestamp: `notApplicable`); part `duplicate` — the same event id delivered twice with fresh signatures: both answered 2xx, and the second delivery has no side effect, measured from the state after the first. (mutating stage, 04 § 4.2 step 8) `webhook-schemes.json` entries: `{ scheme, signatureHeader, format, signedPayload, algorithm: "hmac-sha256"|"hmac-sha1", encoding: "hex"|"base64", secretDecoding: "raw"|"base64"|"base64-after-prefix", timestamp: "header"|"format-param"|"none", timestampHeader?, idSource: { header } | { jsonPath: [path] } }`. `format` is the header value template over `{ts}` and `{sig}`; `signedPayload` a template over `{ts}`, `{id}` and `{body}` (the raw body bytes); `base64-after-prefix` = strip everything up to and including the first `_`, then base64-decode; `raw` = the secret's UTF-8 bytes; an `idSource.jsonPath` list is joined with `:`. Shipped entries: `stripe` (`Stripe-Signature`, `t={ts},v1={sig}`, `{ts}.{body}`, hmac-sha256, hex, raw, format-param, id `$.id`); `standard-webhooks` (`webhook-signature`, `v1,{sig}`, `{id}.{ts}.{body}`, hmac-sha256, base64, base64-after-prefix, header `webhook-timestamp`, id header `webhook-id`); `github` (`X-Hub-Signature-256`, `sha256={sig}`, `{body}`, hmac-sha256, hex, raw, none, id header `X-GitHub-Delivery`); `shopify` (`X-Shopify-Hmac-Sha256`, `{sig}`, `{body}`, hmac-sha256, base64, raw, none, id header `X-Shopify-Webhook-Id`); `paddle` (`Paddle-Signature`, `ts={ts};h1={sig}`, `{ts}:{body}`, hmac-sha256, hex, raw, format-param, id `$.event_id`); `lemon-squeezy` (`X-Signature`, `{sig}`, `{body}`, hmac-sha256, hex, raw, none, id `[$.meta.event_name, $.data.id]`). For the `duplicate` part the id is rewritten in the fixture body (jsonPath) or header before signing; the fresh signature of the second delivery uses a timestamp 1 s later.
- **SEC-063** · P1 · browser, http — Payment-page scripts (PCI DSS 4.0.1 req. 6.4.3). Payment pages = documents visited by `journey: "checkout"` flows that contain an input with `autocomplete` `cc-*` or an iframe from a `hosts[]` entry with purpose `payments`. On them, every script loaded by the browser (static, dynamic and in same-origin frames) comes from the service origin, from a `hosts[]` entry with purpose `payments` or `essential: true`, or matches an entry of the Operator-signed inventory `quality/data/payment-scripts.json`; part `csp` (http) — the CSP of those documents (`script-src`, else `default-src`) contains no `*`, no host source with a `*`, and no scheme-only `https:`/`http:`. No checkout flow: `notConfigured`.
- **SEC-064** · P1 · http, cfg — Session lifetime and admin MFA (ASVS V3/V2):
  - Part `lifetime` (mutating stage, 04 § 4.2 step 8): needs `security.session.idleVar` and/or `absoluteVar`, the env variables holding the service's idle and absolute session lifetimes; `idleVar`/`absoluteVar` hold integer seconds (shared definitions *Lifetime variables*). shipgate restarts the service with the variable under test set to `5` and the other left as configured, logs in afresh, then checks:
    - idle: no request for 7 s → the next request is refused;
    - absolute: requests at t = 2, 4, 6 and 8 s after login; those at t ≤ 4 s are accepted and those at t ≥ 6 s refused.

    Variable values: shared definitions *Lifetime variables*. Without the variables: `notConfigured(security.session.idleVar)`.
  - Part `maxima` (cfg; D-004): per kind ∈ {idle, absolute}, the **maximum** = the strictest non-`null` `<kind>Sec` over `project.kinds` in ruleset `session-lifetimes.json` (`{ <projectKind>: { idleSec, absoluteSec } }`, `null` = no maximum; defaults (NIST SP 800-63B-4): `ymyl` idle 3600, absolute 86400; every other kind idle `null`, absolute 2592000). The **effective value** = the value of the env variable `security.session.<kind>Var` read from `verify.env`, then the service `env` (format: shared definitions *Lifetime variables*); when the variable is unset or `<kind>Var` is `null`, the declared `security.session.<kind>Sec`, which the report marks `unverified`; neither → unknown. Fails when the effective value or the declared value exceeds the maximum (finding `value-mismatch` naming the key, the value and the maximum). A non-`null` maximum with an unknown effective value is a blocking finding `missing-element` owned by `operator`, naming `security.session.<kind>Sec` (required-facts rule, 04 § 1.2). `auth.strategy: "none"` → the part is `notApplicable`. The Operator may set stricter values in `security.session`, never looser ones.
  - Part `admin-mfa` (cfg): accounts with role `admin` in `verifyEnv.auth.accounts` either use TOTP or `security.adminMfa: "enforced-elsewhere"` is declared with a non-empty `adminMfaReason`. TOTP is used = `auth.strategy: "flow"`, `_login.json` has a `totp` step, and `SHIPGATE_ACCT_<ID>_TOTP_SECRET` is set for that account; with `command` or `header` strategies only `enforced-elsewhere` satisfies the part.
- **SEC-065** · P0 · edge — Production takes real payments: with `project.stage: "live"` and `security.payments` set, the edge pass loads the checkout routes recorded by `journey: "checkout"` flows on `production.origins` (GET only) and the same-origin scripts they reference. Neither may contain a test-mode marker from ruleset `payment-test-markers.json` (`[{ provider, kind: "literal"|"regex", pattern }]`, matched case-sensitively against the raw bodies of the checkout documents and the referenced same-origin scripts; e.g. Stripe literal `pk_test_`, Stripe regex `livemode\s*[:=]\s*(false|0)`, PayPal regex `sandbox\.paypal\.com|client-id=sb\b`, Paddle `sandbox-` hosts, Braintree sandbox), unless `security.payments.testModeInProduction: true` and `security.payments.testModeReason` is a non-empty string (pack validation, CFG-006, rejects `true` without a reason). (Live keys in the verify environment: CFG-004.)
- **SEC-066** · W · review, cfg — CI workflow hardening (CI files are Operator-owned, so this is advice to the Operator). Third-party actions are pinned to a full commit SHA. No `pull_request_target` workflow checks out the PR head (= a step using `actions/checkout` whose `with.ref` contains `github.event.pull_request.head` or `github.head_ref`). No `${{ github.event.* }}` expression is interpolated inside `run:` steps. Equivalent checks for other CI providers come from ruleset `ci-hardening.json` (`[{ provider, fileGlob, check, pattern }]`).
- **SEC-067** · P1 · browser, http — Email ownership before trust (OWASP ASVS 5.0 V6), when `project.kinds` contains `saas` (mutating stage, 04 § 4.2 step 8). `security.signup.verification: "none"` = the Operator declares that the product allows unverified use: the rule is `notApplicable` and the report lists that declaration. Otherwise, no flow with `journey: "signup"` → blocking finding `missing-element` owned by `operator` (flows are Operator-owned, 01 § 5.2; "saas project has no signup flow"). **Cut point:** the signup flow runs up to, not including, its first `openEmailLink` step (the whole flow when it has none); the new account's session = the cookies named in `auth.sessionCookies` in that browser context at the cut; the remaining steps run after the `gate` probe. Part `gate` (P1): with the session at the cut, a request to the lexicographically first sampled URL of each route group matching `security.signup.verifiedOnly` (empty = every `app` surface pattern) answers 401/403 or redirects to a page that is not a protected body match. Part `email` (P1): judged from the SMTP sink whatever the flow's steps: it receives a message to the signup address within 30 s after the last step before the cut; none → finding (the product doesn't verify email at all). Part `single-use` (P1; `verification: "link"`): after the first link in that message has been opened once in the signup flow's browser context, the same link requested again in a fresh browser context answers 401/403/410 or a page without a new cookie named in `auth.sessionCookies`; a signup flow with no `openEmailLink` step → blocking finding `missing-element` owned by `operator`, naming the flow. (SEC-029 does not judge signup links.) With `verification: "code"` the `single-use` part is `notApplicable`.

## 8. Secrets and dependencies

- **SEC-050** · P0† · diff — No secrets committed (04 § 13): part `provider-pattern` (P0†) — the provider-key patterns of 04 § 13; part `env-value` (P0†) — literal values of non-public `verify.env` variables that are secrets per SEC-005 (name and value-content conditions); part `entropy` (W) — entropy-only hits; part `env-file` (P0†) — a committed file named `.env` or `.env.*` other than `.env.example`, `.env.sample`, `.env.template` and `.env.dist`, containing a line `^[A-Z_][A-Z0-9_]*=\S` whose value is a secret per SEC-005. Part `history` (P0) — once, at `init` and `verify --adopt`, every commit reachable from `HEAD` is scanned with the same patterns; each hit becomes an Operator-owned debt entry (03 § 9) that clears only when the Operator signs a rotation attestation (`rotatedOn` date) on it; later runs re-evaluate those entries without rescanning.
- **SEC-051** · P0 · deps — No known vulnerabilities ≥ `vulnerabilities.blockAt` (OSV offline database), except waived packages. `blockAt` ∈ `low`, `medium`, `high`, `critical`. An advisory's level is the highest of its CVSS v3/v4 base score (< 4.0 low, 4.0–6.9 medium, 7.0–8.9 high, ≥ 9.0 critical) and its `database_specific.severity` (`LOW`, `MODERATE` = medium, `HIGH`, `CRITICAL`). Part `unrated` (W): an advisory with no severity data. Part `dev-only` (W): packages outside the lockfile's production install set. The main part covers packages in the production install set.
- **SEC-052** · P1 · deps — Direct dependencies added in the diff (04 § 5). Part `licence` (P1): the registry-snapshot licence, parsed as an SPDX expression, is allowed when an `OR` has at least one allowed operand and an `AND` (or `WITH`) has all of them in `licences.allow`. Part `licence-unknown` (W): the licence is missing from the snapshot or unparseable. Part `deprecated` (P1): deprecated according to the offline registry snapshot fetched by `shipgate fetch` → finding. Part `deprecated-unknown` (W): the package is absent from the snapshot, so deprecation is unknown. (Repository archival is not judged: the registry snapshot has no repository state.)
- **SEC-053** · P0 · deps, diff — Supply chain. Part `lockfile` — every dependency manifest has its committed lockfile (`package-lock.json`/`pnpm-lock.yaml`/`yarn.lock`/`bun.lock`, `poetry.lock`/`uv.lock`/hash-pinned `requirements*.txt`, `composer.lock`, `Gemfile.lock`, `go.sum`, `Cargo.lock`), and every direct dependency in the manifest has a lockfile entry whose version satisfies its declared range (frozen-install equivalence, checked offline). Ranges use the ecosystem's native grammar: npm semver, PEP 440, Composer, Bundler, Cargo semver; Go (`go.sum`) checks only that every `go.mod` requirement has a `go.sum` line. Part `registry` — every resolved URL is on a host in ruleset `registries.json` (`{ <ecosystem>: [host] }`, exact host match) for its ecosystem or in `dependencies.registries`, and every entry carries an integrity hash where the lockfile format supports one; git, file and tarball-URL sources are findings unless the package is in `dependencies.allowNames`. Part `age` — each package version added or changed in the diff was published ≥ `dependencies.minReleaseAgeDays` days before the reference time (04 § 15), per the registry snapshot fetched by `shipgate fetch`. Part `age-unknown` (W): the publish time of such a version is absent from the snapshot. Part `typosquat` — each new direct dependency name, unless in `dependencies.allowNames` or itself in the list, is not within Damerau-Levenshtein distance 2 (names ≥ 6 characters) or 1 (4–5 characters) of a name in the ecosystem's top-10,000 list (ruleset `popular-packages/<ecosystem>.txt`); names < 4 characters are exempt. Part `install-scripts` — each new package with install-time scripts (npm `hasInstallScript`, pnpm `requiresBuild`, and the per-ecosystem lockfile flags of ruleset `install-script-flags.json`: `[{ ecosystem, lockfile, jsonPath }]`) is listed in `quality/proposals/dependencies.json` with `installScripts: true`. (Declaration of dependencies: AGT-009.)
