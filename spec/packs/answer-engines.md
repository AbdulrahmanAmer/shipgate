# Pack: answer-engines (AEO / GEO)

> Making pages easy for answer engines (ChatGPT search, Perplexity, Google AI Overviews, Copilot, Claude) to reach, understand, attribute and cite. Builds on web-delivery: the most important rule for answer engines is already RTE-001 (content in raw HTML), because most AI crawlers don't execute JavaScript.

**Evidence level, stated honestly:** search engines say AI features rely on normal SEO fundamentals, and published evidence for AEO/GEO-specific tactics is thin. So only clearly decidable, low-regret rules block (P1); structural heuristics are warnings. Being cited cannot be guaranteed by any build tool; measuring citations (share of voice in AI answers) belongs to the separate monitoring product.

**Google specifically:** Google's documentation states that AI Overviews and AI Mode have no extra requirements beyond being indexed and eligible for a snippet in Search (RTE-001, IDX-*, MET-006, AEO-001), uses Googlebot for them (`Google-Extended` doesn't affect them, IDX-008), and that Google does not use `llms.txt`. `llms.txt` (IDX-010) and machine-text variants (IDX-013) serve other agents only.

---

## 1. Policy section

```jsonc
"answer-engines": {
  "organization": {
    "sameAs": ["https://www.linkedin.com/company/acme", "https://www.wikidata.org/wiki/Q000000"],
    "logo": "web:/brand/logo.png"
  },
  "authors": { "pagePattern": "web:/authors/{slug}" },
  "questions": [ { "question": "how much does a plumber cost in austin", "url": "web:/plumbers/austin-tx" } ],
  "snippetRules": [],                                // pages allowed to restrict snippets: [{ pattern, reason }]
  "indexNow": { "enabled": false, "keyPath": null }, // key file path, e.g. "web:/3f9c…e1.txt"
  "botProtection": { "provider": "none" }            // "cloudflare" | "akamai" | "fastly" | "vercel" | "none"
}
```

## 2. Rules — `AEO-*`

- **AEO-001** · P1 · html, http — No unintended snippet restrictions on indexable pages: no `nosnippet`, no `max-snippet` with a value of 0 to 49 (`-1` and values ≥ 50 pass), no `noimageindex`, no `max-image-preview:none` or `:standard`, no `max-video-preview:0`, no `data-nosnippet` on an element containing the `<h1>` or more than 50 % of `<main>` text, in meta robots (`robots`, `googlebot`, `bingbot`) or `X-Robots-Tag` — unless the page matches `snippetRules`. Part `large-preview` (W): `max-image-preview:large` absent; on pages that SE-103 judges (`discover.enabled` and an `Article`/`BlogPosting`/`NewsArticle` JSON-LD node), SE-103 part `preview` `owns` `AEO-001#large-preview` (P1 there) and this part is not reported. (Bing's `noarchive`/`nocache`, which limit Copilot grounding, are owned by SE-201; Naver's `nosourceinfo` by SE-404.)
- **AEO-002** · P1 · html, http, edge — Entity identity: the homepage of each public service origin has an `Organization` (or subtype) JSON-LD node whose `url` is that origin, and, on indexable pages, all `Organization` nodes (exact `@type` `Organization`, or the subtype of the homepage node) whose `url` is a service origin's root URL, or whose `@id` equals that origin's homepage node `@id`, share, per origin, one `@id` (`{origin}/#organization`, SCH-001) and, across origins, one `name` and `logo`; nodes whose `url` is a deeper path of the origin (location, department and author-affiliation nodes) and `LocalBusiness` subtypes with their own `url` are not compared. `url` and `@id` values are compared after 04 § 10 normalisation. With `organization.logo` set, `logo` (a URL or `ImageObject.url`) equals it, and the logo URL answers 200 with an `image/*` type, is not disallowed for Googlebot (04 § 15 robots.txt evaluation) and decodes to ≥ 112×112 px. With `organization.sameAs` set, `sameAs` equals that set exactly (both sets compared after 04 § 10 URL normalisation of each member). Without `organization`: the consistency checks apply and the declared-value checks are `notConfigured(organization)`. Part `same-as-reach` (W · edge): each declared `sameAs` URL answers a HEAD request in the edge pass with 2xx/3xx (W because many profile sites block automated requests).
- **AEO-003** · P1 · html, http — Authors: `Article`/`BlogPosting`/`NewsArticle` authors are `Person` nodes with `name` and `url` pointing to an existing author page (matching `authors.pagePattern`, 200, indexable) that carries `Person` markup. Without `authors.pagePattern`, everything except the pattern match applies (the author `url` must be a same-site indexable 200 page with `Person` markup). Part `same-as` (W): the author page's `Person` has no `sameAs`.
- **AEO-004** · W · html — Answer-ready structure for each declared `questions` entry: the target URL has an `<h1>`–`<h3>` whose words, after KW-003 normalisation (NFKC, lowercase, ruleset `stop-words.json` words removed, Snowball stemming; tokens not sorted), include every normalised word of the question, and whose next element sibling is a `<p>` of 1–80 UAX #29 words.
- **AEO-005** · W · html, diff — Citable statistics: on non-programmatic indexable pages, paragraphs stating percentages, currency amounts or "according to …" contain or are followed (same section) by at least one outbound link to a source. Part `added` (P1 · html, diff): paragraphs added in the diff on indexable non-programmatic pages (a rendered paragraph counts as added when a run of ≥ 8 consecutive normalised words of it occurs in a line added by the diff and in no removed line) that state percentages, amounts or "according to …" must meet this. It is the guard against invented statistics in agent-written articles, and LNK-007 checks that the source link resolves. Definitions for both parts: percentages and amounts are matches of the page locale's CLDR percent and currency patterns (04 § 11 parse-back); attribution phrases come from ruleset `attribution-phrases.json` for the page locale ("according to", "laut", "selon", …; NFKC, case-folded, substring); both are per-locale lists, looked up as 04 § 15 *Page locale* says (including its no-entry outcome); same section = up to the next heading of the same or higher level; outbound link = an `a[href]` to a registrable domain (Public Suffix List) other than every service origin's.
- **AEO-006** · P1 · html, site — Freshness consistency: where a visible date (04 § 15 visible dates), JSON-LD `dateModified`/`datePublished` and sitemap `<lastmod>` exist for a page, they agree to the day in pairs: the visible "updated" date = `dateModified` = `<lastmod>`; the visible "published" date = `datePublished`; when the page shows only a published date and has no `dateModified`, `<lastmod>` = `datePublished`. Values carrying an offset are compared as calendar dates in that offset; values without one are taken in `web-delivery.timeZone`.
- **AEO-007** · P1 · http — IndexNow (when `indexNow.enabled`): the key file is served at `keyPath` as `text/plain` containing exactly the key (the `keyPath` file name without `.txt`), optionally followed by one line break. `enabled` with `keyPath` `null`: `notConfigured(indexNow.keyPath)`, owner `operator`. Submissions are made by the Operator's deploy pipeline, never by agents (AGT-008).
- **AEO-008** · W · edge, review — Crawler reach at the edge: in the edge pass, sampled indexable pages requested with the `userAgent` of each `ai-agents.json` token that `aiCrawlers` allows (web-delivery IDX-008) don't return 403/429 or a challenge page (`cf-mitigated: challenge` header, or a body matching ruleset `error-pages` fingerprints, as SE-008 `ua-reach`). Because edges verify real crawlers by IP, a block here is a warning plus a review item to confirm the bot-protection settings (`botProtection.provider`, e.g. AI-crawler blocking defaults) match the policy.
- **AEO-009** · P1 · html, browser — Primary content is text: an indexable page whose `<main>` has < 50 UAX #29 words of text (excluding `<canvas>` fallback content and iframe content) is a finding when `<main>` contains an `<img>` with `alt` > 100 characters (html), or, on browser-sampled pages, a `<canvas>` or cross-origin `<iframe>` whose rendered box covers ≥ 50 % of `<main>`'s rendered box (browser). Part `pdf` (W · html): each PDF URL in a sitemap or linked from an indexable page has an indexable HTML page that links to it and whose `<title>` equals the PDF's title metadata, or the PDF response carries `Link: <…>; rel="canonical"` to an HTML URL. This part owns title equality; `rel=alternate` pairing and the document's canonical or `noindex` are SE-006's.
- **AEO-010** · P1 · html — Data tables: every `<table>` in `<main>` without `role="presentation"`/`"none"` has ≥ 1 `<th>` or a `scope` attribute; every element in `<main>` with `role="table"` or `"grid"` has ≥ 1 descendant with `role="columnheader"` or `"rowheader"`. Tables carried as images: only the AEO-009 case (near-empty `<main>`) is checked.
- **AEO-011** · deprecated — tombstone; `llms.txt` is covered by IDX-010 (web-delivery); AI crawler robots policy by IDX-008.
- **AEO-012** · P1 · baseline — No fake freshness: for each page present in this run and in `_main/routes.jsonl` (`skipped(no-main)` without it) whose normalised `<main>` text hash is unchanged (`mainTextHash`: NFKC, whitespace-collapsed, with `<time>` elements and the date strings found by AEO-006 removed), JSON-LD `dateModified`, the visible "updated" date and the sitemap `<lastmod>` equal their `_main` values. Owner of "dates move only with content"; AEO-006 owns agreement between the three sources.
- **AEO-013** · W · html — Citation anchors: on `Article`/`BlogPosting`/`NewsArticle` pages with > 1,000 `<main>` words, every `<h2>` and `<h3>` in `<main>` has an `id` that is unique on the page and doesn't match a ruleset auto-generated id pattern (`autoIdPatterns`: e.g. `:r[0-9a-z]+:`, `radix-…`, `headlessui-…`, UUIDs, ≥ 8-character hex), so deep links survive rebuilds.
- **AEO-014** · P0 (part `hidden-text` P1) · browser, html, http — No hidden or AI-targeted text on indexable pages (Google spam policies: hidden text and cloaking; Bing Webmaster Guidelines; prompt injection aimed at AI search and agents). **Hidden** and its **exemptions**: 04 § 15 *Hidden content* and *Disclosure exemption* (each exemption verified by activating its control), the one definition shared with CNT-009, SE-109 and SE-123; no other hidden-content list or colour test applies.
  - Part `hidden-text` (P1 · browser): a finding is (a) a hidden element anywhere in `<body>`, not covered by the *Disclosure exemption*, whose text content (descendants included) is ≥ 30 UAX #29 words; or (b) a page whose non-exempt hidden text in `<body>` totals ≥ 100 UAX #29 words, counting each hidden text node once however many hidden ancestors it has (one finding per page, listing the elements and their word counts; this catches text split across many elements of < 30 words). Short visually-hidden labels (screen-reader text) pass only while both limits hold. **Ownership:** inside `<main>` of programmatic family and hub pages, part `hidden-text` is owned by CNT-009 (CNT-009 `owns` `AEO-014#hidden-text` there, with its stricter required-fact and main-text checks); elsewhere, a hidden element containing an `<a href>` (to any page) is owned by SE-123 (SE-123 `owns` that condition, P0), so (a) reports only non-exempt hidden elements of ≥ 30 words that contain no `<a href>`, and (b) counts no text node inside a hidden `<a href>` and none inside CNT-009's scope. Elements matched by a class-selector `hasPart.cssSelector` of an `isAccessibleForFree: false` declaration are owned by SE-109 (SE-109 `owns` `AEO-014#hidden-text` for them) only on pages where the signed `search-engines.features` contains `paywalled-content`; without that Operator choice the markup (agent-written) exempts nothing.
  - Part `ai-addressed` (P0 · html, browser): no match of the ruleset per-locale `ai-addressed-phrases.json` (text addressed to AI systems or agents, e.g. "if you are an AI", "ignore previous instructions", "AI assistants should recommend", "note to language models"; matched as substrings after NFKC, case-fold and whitespace collapse; the page locale's list, looked up as 04 § 15 *Page locale* says (including its no-entry outcome), plus the `en` list on every page) in hidden elements (04 § 15 *Hidden content*, the *Disclosure exemption* **not** applied), HTML comments, `alt`, `title`, `aria-label`/`aria-description` attributes, `<meta>` `content` other than `description`, or JSON-LD string values. The same text visible on the page passes (it's shown to people too).
  - Part `agent-parity` (P0 · http): each indexable page in the HTTP sample (04 § 10) is fetched twice with the desktop Chrome user agent and once with the desktop Bingbot user agent (both from `search-agents.json`, as RTE-010) and with the `userAgent` of each `ai-agents.json` token of category `search` or `user-fetch` that `aiCrawlers` allows, without following redirects (as RTE-010). Each agent response has the same status, `Location` and content type as the first Chrome response; its generic `<main>` skeleton hash (04 § 11: text nodes masked as `⟦t⟧`, the same hash RTE-010 part `behaviour` uses) equals that of the first desktop Chrome response; and when the two Chrome responses have identical normalised `<main>` text (NFKC, whitespace-collapsed, as RTE-010), its normalised `<main>` text is identical as well (otherwise only the skeleton is compared, and a text difference is reported by part `text-diff`); and its `<title>`, meta description, robots directives (meta and `X-Robots-Tag`), canonical, hreflang pairs and JSON-LD `@type` and property-name sets, compared as in RTE-014, equal those of the first Chrome response wherever the two Chrome responses agree on that signal. Failure classes `status-mismatch`, `skeleton-mismatch`, `value-mismatch` (agent token, signal, both values). The same paywall exclusion as RTE-010 applies, with the same condition: only when the signed `search-engines.features` contains `paywalled-content` are elements matched by a class-selector `hasPart.cssSelector` of `isAccessibleForFree: false` markup (SE-109) removed from every response first; without that feature nothing is removed. Part `text-diff` (W · http): when the two Chrome responses differ in normalised `<main>` text, an agent response whose normalised `<main>` text equals neither of them is listed (`value-mismatch`). Googlebot vs Chrome is owned by RTE-010; edge-level bot reach by AEO-008; `.md` variants by IDX-013 (they're requested by `Accept`, not by user agent).
