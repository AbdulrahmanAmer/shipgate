# Pack: answer-engines (AEO / GEO)

> Making pages easy for answer engines (ChatGPT search, Perplexity, Google AI Overviews, Copilot, Claude) to reach, understand, attribute and cite. Builds on web-delivery: the most important rule for answer engines is already RTE-001 (content in raw HTML), because most AI crawlers don't execute JavaScript.

**Evidence level, stated honestly:** search engines say AI features rely on normal SEO fundamentals, and published evidence for AEO/GEO-specific tactics is thin. So only clearly decidable, low-regret rules block (P1); structural heuristics are warnings. Being cited cannot be guaranteed by any build tool; measuring citations (share of voice in AI answers) belongs to the separate monitoring product.

**Google specifically:** Google's documentation states that AI Overviews and AI Mode have no extra requirements beyond being indexed and eligible for a snippet in Search (RTE-001, IDX-*, MET-006, AEO-001), uses Googlebot for them (`Google-Extended` doesn't affect them, IDX-008), and that Google does not use `llms.txt`. `llms.txt` (IDX-010) and machine-text variants (IDX-013) serve other agents only.

## 1. Policy section

```jsonc
"answer-engines": {
  "organization": {
    "sameAs": ["https://www.linkedin.com/company/acme", "https://www.wikidata.org/wiki/Q000000"],
    "logo": "web:/brand/logo.png"
  },
  "authors": { "pagePattern": "web:/authors/{slug}" },
  "questions": [ { "question": "how much does a plumber cost in austin", "url": "web:/plumbers/austin-tx" } ],
  "snippetRules": [],                                // pages allowed to restrict snippets: [{ pattern, reason }]
  "indexNow": { "enabled": false, "keyPath": null }, // key file path, e.g. "web:/3f9c…e1.txt"
  "botProtection": { "provider": "none" }            // "cloudflare" | "akamai" | "fastly" | "vercel" | "none"
}
```

## 2. Rules — `AEO-*`

- **AEO-001** · P1 · html, http — No unintended snippet restrictions on indexable pages: no `nosnippet`, no `max-snippet` below 50, no `noimageindex`, no `max-image-preview:none` or `:standard`, no `max-video-preview:0`, no `data-nosnippet` on an element containing the `<h1>` or more than 50 % of `<main>` text, in meta robots (`robots`, `googlebot`, `bingbot`) or `X-Robots-Tag` — unless the page matches `snippetRules`. Part `large-preview` (W): `max-image-preview:large` absent (Discover pages: SE-103 owns it as P1). (Bing's `noarchive`/`nocache`, which limit Copilot grounding, are owned by SE-201; Naver's `nosourceinfo` by SE-404.)
- **AEO-002** · P1 · html, http, edge — Entity identity: the homepage of each public service origin has an `Organization` (or subtype) JSON-LD node whose `url` is that origin, and all `Organization` nodes on indexable pages whose `url` or `@id` is on a service origin share one `@id`, `name` and `logo`. With `organization.logo` set, `logo` (a URL or `ImageObject.url`) equals it, and the logo URL answers 200 with an `image/*` type, is not disallowed for Googlebot (04 § 15 robots.txt evaluation) and decodes to ≥ 112×112 px. With `organization.sameAs` set, `sameAs` equals that set exactly. Without `organization`: the consistency checks apply and the declared-value checks are `notConfigured(organization)`. Part `same-as-reach` (W · edge): each declared `sameAs` URL answers a HEAD request in the edge pass with 2xx/3xx (W because many profile sites block automated requests).
- **AEO-003** · P1 · html, http — Authors: `Article`/`BlogPosting` authors are `Person` nodes with `name` and `url` pointing to an existing author page (matching `authors.pagePattern`, 200, indexable) that carries `Person` markup. Without `authors.pagePattern`, everything except the pattern match applies (the author `url` must be a same-site indexable 200 page with `Person` markup). Part `same-as` (W): the author page's `Person` has no `sameAs`.
- **AEO-004** · W · html — Answer-ready structure for each declared `questions` entry: the target URL has an `<h1>`–`<h3>` whose words, after KW-003 normalisation (NFKC, lowercase, stop words removed, light stemming), include every normalised word of the question, and whose next element sibling is a `<p>` of 1–80 UAX #29 words.
- **AEO-005** · W · html, diff — Citable statistics: on non-programmatic indexable pages, paragraphs stating percentages, currency amounts or "according to …" contain or are followed (same section) by at least one outbound link to a source. Part `added` (P1 · html, diff): paragraphs added in the diff on indexable non-programmatic pages (a rendered paragraph counts as added when a run of ≥ 8 consecutive normalised words of it occurs in a line added by the diff and in no removed line) that state percentages, amounts or "according to …" must meet this. It is the guard against invented statistics in agent-written articles, and LNK-007 checks that the source link resolves. Definitions for both parts: percentages and amounts are matches of the locale's CLDR percent and currency patterns (04 § 11 parse-back); attribution phrases come from ruleset `attribution-phrases.json` per locale ("according to", "laut", "selon", …; NFKC, case-folded, substring); same section = up to the next heading of the same or higher level; outbound link = an `a[href]` to a registrable domain (Public Suffix List) other than every service origin's.
- **AEO-006** · P1 · html, site — Freshness consistency: where a visible date (04 § 15 visible dates), JSON-LD `dateModified`/`datePublished` and sitemap `<lastmod>` exist for a page, they agree to the day in pairs: the visible "updated" date = `dateModified` = `<lastmod>`; the visible "published" date = `datePublished`; when the page shows only a published date and has no `dateModified`, `<lastmod>` = `datePublished`. Values carrying an offset are compared as calendar dates in that offset; values without one are taken in `web-delivery.timeZone`.
- **AEO-007** · P1 · http — IndexNow (when `indexNow.enabled`): the key file is served at `keyPath` as `text/plain` containing exactly the key (the `keyPath` file name without `.txt`), optionally followed by one line break. Submissions are made by the Operator's deploy pipeline, never by agents (AGT-008).
- **AEO-008** · W · edge, review — Crawler reach at the edge: in the edge pass, sampled indexable pages requested with the `userAgent` of each `ai-agents.json` token that `aiCrawlers` allows (web-delivery IDX-008) don't return 403/429 or a challenge page (`cf-mitigated: challenge` header, or a body matching ruleset `error-pages` fingerprints, as SE-008 `ua-reach`). Because edges verify real crawlers by IP, a block here is a warning plus a review item to confirm the bot-protection settings (`botProtection.provider`, e.g. AI-crawler blocking defaults) match the policy.
- **AEO-009** · P1 · html, browser — Primary content is text: an indexable page whose `<main>` has < 50 UAX #29 words of text (excluding `<canvas>` fallback content and iframe content) is a finding when `<main>` contains an `<img>` with `alt` > 100 characters (html), or, on browser-sampled pages, a `<canvas>` or cross-origin `<iframe>` whose rendered box covers ≥ 50 % of `<main>`'s rendered box (browser). Part `pdf` (W · html): each PDF URL in a sitemap or linked from an indexable page has an indexable HTML page that links to it and whose `<title>` equals the PDF's title metadata, or the PDF response carries `Link: <…>; rel="canonical"` to an HTML URL.
- **AEO-010** · P1 · html — Data tables: every `<table>` in `<main>` without `role="presentation"`/`"none"` has ≥ 1 `<th>` or a `scope` attribute; every element in `<main>` with `role="table"` or `"grid"` has ≥ 1 descendant with `role="columnheader"` or `"rowheader"`. Tables carried as images: only the AEO-009 case (near-empty `<main>`) is checked.
- **AEO-011** · deprecated — tombstone; `llms.txt` is covered by IDX-010 (web-delivery); AI crawler robots policy by IDX-008.
- **AEO-012** · P1 · baseline — No fake freshness: for each page present in this run and in `_main/routes.jsonl` (`skipped(no-main)` without it) whose normalised `<main>` text hash is unchanged (`mainTextHash`: NFKC, whitespace-collapsed, with `<time>` elements and the date strings found by AEO-006 removed), JSON-LD `dateModified`, the visible "updated" date and the sitemap `<lastmod>` equal their `_main` values. Owner of "dates move only with content"; AEO-006 owns agreement between the three sources.
- **AEO-013** · W · html — Citation anchors: on `Article`/`BlogPosting`/`NewsArticle` pages with > 1,000 `<main>` words, every `<h2>` and `<h3>` in `<main>` has an `id` that is unique on the page and doesn't match a ruleset auto-generated id pattern (`autoIdPatterns`: e.g. `:r[0-9a-z]+:`, `radix-…`, `headlessui-…`, UUIDs, ≥ 8-character hex), so deep links survive rebuilds.
- **AEO-014** · P0 (part `hidden-text` P1) · browser, html, http — No hidden or AI-targeted text on indexable pages (Google spam policies: hidden text and cloaking; Bing Webmaster Guidelines; prompt injection aimed at AI search and agents). Hidden = 04 § 15 hidden content; exempt = 04 § 15 disclosure exemption.
  - Part `hidden-text` (P1 · browser): a hidden element in `<main>`, `<header>` or `<footer>`, not covered by the disclosure exemption, whose text content (descendants included) is ≥ 30 UAX #29 words, or that contains an `<a href>` to an indexable page, is a finding. Short visually-hidden labels (screen-reader text under 30 words without links) pass. Owned elsewhere: hidden required facts and main text on inventory family pages (CNT-009); hidden links (SE-123). This part reports only elements neither of those rules reports.
  - Part `ai-addressed` (P0 · html, browser): no match of the ruleset per-locale `ai-addressed-phrases.json` (text addressed to AI systems or agents, e.g. "if you are an AI", "ignore previous instructions", "AI assistants should recommend", "note to language models"; matched as substrings after NFKC, case-fold and whitespace collapse, locale fallback `ll-CC` → `ll` → `en`, plus `en` on every page) in hidden elements (04 § 15 hidden content, the disclosure exemption **not** applied), HTML comments, `alt`, `title`, `aria-label`/`aria-description` attributes, `<meta>` `content` other than `description`, or JSON-LD string values. The same text visible on the page passes (it's shown to people too).
  - Part `agent-parity` (P0 · http): each indexable page in the HTTP sample (04 § 10) is fetched twice with the desktop Chrome user agent and once with the desktop Bingbot user agent (both from `search-agents.json`, as RTE-010) and with the `userAgent` of each `ai-agents.json` token of category `search` or `user-fetch` that `aiCrawlers` allows. Each agent response has the same status and content type as the first Chrome response; its `<main>` masked skeleton hash (computed as in RTE-010 part `behaviour`) equals the Chrome one; and when the two Chrome responses have identical `<main>` normalised text, its `<main>` normalised text is identical as well (otherwise only the skeleton is compared, and the text difference is a W). The same paywall exclusion as RTE-010 applies (`isAccessibleForFree: false` + `hasPart.cssSelector`, SE-109). Googlebot vs Chrome is owned by RTE-010; edge-level bot reach by AEO-008; `.md` variants by IDX-013 (they're requested by `Accept`, not by user agent).
