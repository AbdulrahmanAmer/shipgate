# Pack: performance

> Page experience (Core Web Vitals), delivery efficiency (bytes, caching, compression), and API latency. Lab results are necessary, not sufficient; field data is recommended on top.

---

## 1. Policy section

```jsonc
"performance": {
  "defaults": { "lcpMs": 2500, "cls": 0.1, "tbtMs": 200, "inpMs": 200, "scriptBytes": 170000, "cssBytes": 60000,
                "renderBlockingMs": 300, "thirdPartyBlockingMs": 250, "seoScore": 1.0,
                "ttfbMs": 600,                                                  // warm server response, non-programmatic routes (PRF-016)
                "pageBytes": 1638400, "htmlBytes": 102400 },                   // total transfer 1,600 KiB; HTML document transfer 100 KiB (PRF-019)
  "routes": { "/dashboard/**": { "lcpMs": 3000, "scriptBytes": 300000 } },   // per-surface/route overrides
  "api": { "p95Ms": 300, "concurrency": 10, "requests": 200 },                // lab load on declared endpoints
  "lighthouse": { "preset": "mobile", "runs": 3 },                          // preset: "mobile" (Lighthouse mobile emulation of the pinned version: viewport and DPR as that version defines them) | "desktop" (1350 × 940, DPR 1); runs: integer ≥ 1
  "minBenchmarkIndex": 1000,                                                  // TR-111: below it, timing budgets are skipped(slow-host)
  "fonts": { "maxFamilies": 2 },
  "listMaxItems": 100,                                                        // PRF-012: largest unpaginated list on a page
  "htmlMaxAgeSec": 0,                                                         // HTML cacheable this long without revalidation
  "images": { "maxOversizeRatio": 1.5 }                                       // intrinsic width ≤ ratio × rendered width × DPR
}
```

Budgets apply per route group. Public pages: the browser-sampled URLs (04 § 10). `app` pages: the final URL of each flow with a non-`null` `account`, plus each `goto` target of such flows (normalised, 04 § 10, deduplicated), each loaded by Lighthouse in a context holding that flow account's stored session (a URL reached by several accounts uses the one whose id is first in byte order among `verifyEnv.auth.accounts`); route group = the adapter route pattern of the URL (04 § 10 *Route groups*). An `app` route group no flow visits has no budget run. PRF-003, PRF-004, PRF-006, PRF-015, PRF-017 and PRF-018 run on these URLs (PRF-018: public ones only); PRF-007 runs on the HTTP sample; PRF-008 and PRF-009 on the responses their text names; PRF-005 and PRF-012 on browser-sampled pages (PRF-012 also on the `app` URLs above).

**Calibration (TR-111).** The host is calibrated once per run: the median `benchmarkIndex` measured at the start of the first of G4 and G6 that runs (04 § 6.3) is the only index; every timing rule, including INP from flows in G6, compares it with `minBenchmarkIndex`, and per-run Lighthouse indices are not used for this. `minBenchmarkIndex` defaults to 1000 (also when the performance pack is off, so CRW-001 is calibrated), the floor of Lighthouse's "low-end desktop" bracket (its throttling documentation: high-end desktop 1500–2000, low-end desktop 1000–1500). Lighthouse's fixed 4× CPU slowdown is tuned for desktop-class hosts; below 1000 the throttled run falls under the mid-tier mobile device it emulates, so timing budgets would measure the host, not the page. Calibrated rules: PRF-001 parts `lcp` and `tbt`, PRF-002, PRF-006, PRF-011, PRF-016, and CRW-001's verify-environment TTFB (programmatic pack, `http` channel in G4; its edge-pass measurement is not calibrated and always runs). Byte budgets (PRF-010, PRF-019) and pass/fail audits don't depend on host speed and are never `skipped(slow-host)`.

## 2. Rules — `PRF-*`

- **PRF-001** · P2 · browser — Per route group (aggregation: 04 § 6.2): parts `lcp` (LCP ≤ `lcpMs`), `cls` (CLS ≤ `cls`), `tbt` (TBT ≤ `tbtMs`) and `seo` (indexable pages, 04 § 15 *Indexable page*: score ≥ `seoScore` over the Lighthouse SEO-category audits other than `document-title`, `meta-description`, `http-status-code`, `is-crawlable`, `robots-txt`, `canonical`, `hreflang`, `link-text`, `crawlable-anchors` and `image-alt`, which web-delivery, search-engines and accessibility rules own; the score is the category's weighted mean over the remaining audits, and with none remaining in the pinned Lighthouse part `seo` is `notApplicable`). Only `lcp` and `tbt` are `skipped(slow-host)` below `minBenchmarkIndex` (TR-111). Finding `budget-exceeded` showing the route group, metric and value. (Script bytes: PRF-010.)
- **PRF-002** · P2 · browser — Interaction responsiveness: for each declared flow's main Chromium run (not A11-019 keyboard replays), INP (`web-vitals` `onINP`, `reportAllChanges`, final value at flow end), measured from flow start to flow end without CPU or network throttling, ≤ `inpMs` (finding `budget-exceeded` showing the flow id and value; a flow with no reported interaction passes). A `measure: "inp"` step records the value at that step in the report; the judged value is the final one. The INP of a flow is the maximum, over the documents the flow loads, of that document's final `onINP` value (a soft navigation stays in its document). `skipped(slow-host)` below `minBenchmarkIndex` (TR-111). Part `probe` (W): on sampled public pages of route groups that no flow visits, clicks on up to 5 visible controls in `<main>` (first 5 in document order of the control inventory built by the flows engine, shared with UX-001/UX-006 and built even when the ux pack is off; navigation intercepted) are measured the same way.
- **PRF-003** · P2 · browser — LCP image handling, at the Lighthouse preset viewport: part `discovery` — Lighthouse audit `lcp-discovery-insight` passes (LCP image discoverable in the initial HTML, not lazy-loaded, `fetchpriority=high`); part `srcset` — the LCP `<img>` has `srcset` with `w` descriptors and a `sizes` attribute; part `format` — the LCP image is in a modern format (§ 3). LCP element not an image (`<img>`, SVG `<image>` or CSS background image): all parts `notApplicable` for that URL. LCP element a CSS background image or SVG `<image>`: `srcset` `notApplicable`. LCP image `image/svg+xml`: `srcset` and `format` `notApplicable`. Findings `missing-element` (`discovery`, `srcset`) / `forbidden-value` (`format`) showing the URL and the image URL. (Dimension attributes: PRF-007.)
- **PRF-004** · P2 · browser — Layout stability: Lighthouse `cls-culprits-insight` passes; every `<video>`, `<iframe>`, `<embed>` and `<object>` in the final DOM has numeric `width` and `height` attributes, or a computed `aspect-ratio` other than `auto`, or a declaration `width` and `height` (both, not `auto`) in the element's `style` attribute or in a matching rule of a loaded stylesheet (CSSOM; the winning declaration by specificity and order) (`missing-element` showing the selector; a failing `cls-culprits-insight` is `budget-exceeded` showing the URL and CLS). (`<img>` dimensions: PRF-007.)
- **PRF-005** · P2 · browser — Fonts, on sampled pages: every `@font-face` `src` URL in loaded stylesheets is same-origin with a service origin or on a `hosts[]` entry with purpose `assets` (part `self-hosted`); the number of distinct `@font-face` `font-family` names (case-insensitive) is ≤ `fonts.maxFamilies` (part `families`); every `@font-face` sets `font-display` `swap` or `optional` (part `display`); no `<link rel=stylesheet>` or `@import` that declares `@font-face` loads from a host other than a service origin or such an `assets` host (part `external`). Findings `forbidden-value` / `budget-exceeded` showing the stylesheet URL and family.
- **PRF-006** · P2 · browser — Render-blocking time ≤ `renderBlockingMs` (LCP savings estimated by `render-blocking-insight`) and third-party main-thread time — the sum of `mainThreadTime` (ms) over the entity rows of `third-parties-insight` other than the entity of the project's origins — ≤ `thirdPartyBlockingMs` (measured with real third-party hosts allowed by the `hosts` registry). Finding `budget-exceeded` showing the route group, measure and value.
- **PRF-007** · P2 · html — Every `<img>` in the HTML of sampled pages has numeric `width` and `height` attributes (owner of image dimension attributes; `missing-element` showing the selector; alt text is owned by A11-007).
- **PRF-008** · P1 · http, edge — Hashed static assets (adapter build manifest, or filenames matching `[.-][a-f0-9]{8,}\.`): `Cache-Control` carrying `public`, `immutable` and `max-age` ≥ 31536000 (directive order and other directives ignored). HTML: `max-age` ≤ `htmlMaxAgeSec` unless `must-revalidate`/`no-cache` is present; `max-age` is the larger of `max-age` and `s-maxage`; a missing `Cache-Control` header counts as `max-age=0`. Edge-owned caching is checked in G8. Findings `header-value` (wrong directives), `missing-header` (no header on a hashed asset), showing the URL and the header value.
- **PRF-009** · P1 · http — Every same-origin response fetched by the crawl and sampled-page loads with status 200, a `Content-Type` of `text/html`, `text/css`, `*/javascript`, `application/json`, `application/*+json` or `image/svg+xml`, and an uncompressed body ≥ 1,024 bytes, requested with `Accept-Encoding: br, gzip`, carries `Content-Encoding: br` or `gzip` (finding `missing-header` showing the URL and size).
- **PRF-010** · P2 · build, browser — Per-route first-load JavaScript ≤ `scriptBytes` and CSS ≤ `cssBytes` (the gzip level-9 compressed size of the JS and CSS files the adapter bundle manifest lists for the route's initial load, summed per route; route group value = maximum across its routes); growth > 10 % of `scriptBytes` or `cssBytes` vs the same route group in `_main/budgets.json` is a finding (`skipped(no-main)` without it). Finding `budget-exceeded` showing the route group, measure and bytes. W parts on sampled pages: `unused-js` (Lighthouse `unused-javascript` fails), `legacy-js` (`legacy-javascript-insight` fails), `duplicate-js` (`duplicated-javascript-insight` fails).
- **PRF-011** · P2 · http — API latency under lab load: each operation of the service's data-api `contracts` with method GET, sent `api.requests` times with `api.concurrency` in flight, each request built by contract request generation (04 § 15) for its 200 response and authenticated as the account whose id is first in byte order among `verifyEnv.auth.accounts`: p95 (nearest rank: the ⌈0.95 n⌉-th smallest of n samples) of the time from request start to last body byte ≤ `api.p95Ms` (finding `budget-exceeded` showing the operation and p95). Verify environment, local data volume from seeds; mutating stage (04 § 4.2 step 8, the "load" stage); `remote: write`. No `GET` operation in the service's `contracts`: `notApplicable`. No `verifyEnv.auth.accounts` entry: `notConfigured(verifyEnv.auth.accounts)`.
- **PRF-012** · P1 · html, browser — List **pages** are paginated or bounded. A *list page* is a sampled public page or an `app` page reached by a flow whose `<main>` contains an element with ≥ 20 children that have the same tag name and the same set of class tokens (order ignored). It is bounded when the number of those children is ≤ `performance.listMaxItems`, or the page has a link with `rel=next`, a link matching a web-delivery `pagination` pattern, or a link or button whose accessible name has a phrase match (accessibility § 1 *Phrase match*, page locale per 04 § 15) in ruleset `pagination-labels.json`. Otherwise `budget-exceeded` showing the selector and child count. (API list endpoints are owned by API-005.)
- **PRF-013** · W · review — Raising a cache lifetime or disabling a feature to meet a budget is recorded in the report with its impact.
- **PRF-014** · W · review — Field RUM (`web-vitals` or equivalent) reports LCP, INP and CLS per route group in production (production monitoring itself is a separate product).
- **PRF-015** · P2 · browser — Images in `<main>`, at the Lighthouse preset viewport and DPR: part `oversize` — intrinsic width ≤ `images.maxOversizeRatio` × rendered width × device pixel ratio; part `srcset` — images rendered wider than 400 CSS px have a `srcset` (on the `<img>` or a `<picture>` `<source>`) with ≥ 2 candidates; part `format` — each image is in a modern format (§ 3). `image/svg+xml` responses are exempt; parts `srcset` and `format` exclude the page's LCP image (PRF-003). Findings `budget-exceeded` (`oversize`), `missing-element` (`srcset`), `forbidden-value` (`format`), showing the image URL.
- **PRF-016** · P2 · http — Server response time: per route group of non-programmatic routes, warm TTFB (time from sending the request on an already established keep-alive connection to the first response byte; one discarded request, then the median of 5 sequential requests per URL of the browser sample (04 § 10: min(3, group size) per route group); maximum across the group's URLs) ≤ `ttfbMs`. Programmatic family and hub pages are owned by CRW-001. Finding `budget-exceeded` showing the route group, URL and TTFB.
- **PRF-017** · P2 · browser — Offscreen media deferred: at the Lighthouse preset viewport after load, every rendered `<img>` and `<iframe>` whose bounding box starts at or below the first viewport's bottom edge has `loading="lazy"`. A facade that inserts the iframe only on interaction passes (no iframe at load). The LCP element is exempt. Finding `forbidden-value` showing the selector and the media URL.
- **PRF-018** · P2 · browser — Back/forward cache: for sampled public pages, navigating to the first same-origin `<a href>` target in document order that is not the page itself and not a fragment-only link, then back, restores from bfcache (CDP `Page.backForwardCacheNotUsed` not fired; `PerformanceNavigationTiming.notRestoredReasons` null or empty), ignoring reasons in the ruleset `bfcache-harness-reasons` list; parts `unload` (an `unload` listener is registered) and `no-store` (public HTML sent with `Cache-Control: no-store`) are parts of PRF-018's own severity (P2), emitted instead of the main part when they are the only not-restored reason. Findings `forbidden-value` showing the URL and the not-restored reasons.
- **PRF-019** · P2 · browser — Page weight per route group (aggregation 04 § 6.2): total transfer bytes of the page load (Lighthouse `total-byte-weight`) ≤ `pageBytes`; HTML document transfer ≤ `htmlBytes`. Finding `budget-exceeded` showing the route group, measure and bytes.
- **PRF-020** · W · data — Field Core Web Vitals: for each `production.origins` host with `quality/data/crux/<host>.json` (§ 3), every record's p75 `largest_contentful_paint` ≤ `lcpMs`, `interaction_to_next_paint` ≤ `inpMs` and `cumulative_layout_shift` ≤ `cls` — origin records against `defaults`, URL records against the most specific budget of the URL's route group. Part `stale`: a record whose `collectionPeriod.lastDate` is more than 35 days before the reference time (04 § 15). No file: `skipped(no-field-data)` (optional input). Not host-calibrated.

## 3. Implementation notes
- Lighthouse (navigation mode) and the `web-vitals` measurement run through the managed Node and the Playwright-pinned Chromium (04 § 6). HTTP-level checks (PRF-008/009/011/016) are measured by the Verifier directly.
- Lab numbers vary: median of `runs` per URL, then the maximum across the route group.
- Audit ids are those of the pinned Lighthouse (13.x, insight audits); an audit "passes" when its score is ≥ 0.9 (Lighthouse's own pass threshold; `notApplicable` audits pass, and so does an audit with a `null` score, `scoreDisplayMode` `informative` or `manual`). When a Lighthouse upgrade renames an audit, ruleset `lighthouse-audit-renames.json` maps the old id.
- *Modern format* (PRF-003, PRF-015): the image response's `Content-Type` is `image/avif` or `image/webp`, or the `<img>` is in a `<picture>` with a `<source type="image/avif|webp">`. PRF-003 and PRF-015 run at the Lighthouse preset viewport and DPR.
- One `benchmarkIndex` per run (04 § 6.3), measured at the start of the first of G4 and G6 that runs (in G4 before load runs), is used by every timing rule in G4 and G6 (TR-111).
- PRF-020 reads `quality/data/crux/<host>.json` (Operator export, one file per production origin host): a CrUX API `queryRecord` response or an array of them (`record.key.origin` or `record.key.url`, `metrics.<metric>.percentiles.p75`, `collectionPeriod.lastDate`).
