# Pack: testing

> Operator-owned declarative flows run by the Verifier itself (agents can't weaken them), the project's own test suite, honest agent tests, optional cross-browser runs and mutation sampling. Test evasion is AGT-004 (core). Flow file format: `03-formats.md` § 10.

---

## 1. Policy section

```jsonc
"testing": {
  "flows": "quality/flows/",
  "requireTestsFor": ["route", "api-handler"],     // file roles whose changes need test changes
  "projectTests": true,                            // run services[].commands.test in G1 (BLD-003)
  "crossBrowser": { "enabled": false, "browsers": ["firefox", "webkit"], "flows": ["*"] },
  "mutation": { "enabled": false, "sample": 30 },
  "criticalRoutes": [],                            // URL patterns each visited by ≥ 1 flow (TST-010)
  "coverage": { "report": null, "changedLinesMin": 0.7 }   // report: lcov/cobertura path; null = auto-detect (TST-011)
}
```

## 2. Rules — `TST-*`

- **TST-001** · P0 · browser, cfg — Every declared flow passes in the verify environment with assertions on observable outcomes (URL, visible text, API/DB/email state), not just absence of errors. Part `asserts` (P0 · cfg): a flow must contain at least one of `expectUrl`, `expectText`, `expectApi`, `expectDb`, `expectEmail`, `expectDownload`, `expectEgress` after its last action step (`click`, `dblclick`, `check`, `uncheck`, `fill`, `select`, `press`, `upload`, `submitEmpty`; 03 § 10); `expectVisible`/`expectHidden` alone do not count. A flow with no action step needs at least one such `expect*` step anywhere. Otherwise one finding `missing-element` for the flow (groupKey: flow id), owner `operator`.
- **TST-002** · P0 · browser — Flows with `persist: true` re-check their final assertions after a reload: after the last step, the page is reloaded (Playwright `reload`, waiting for `load`) and the maximal run of consecutive `expect*` steps at the end of `steps` runs again, each with its own `timeoutMs`; a failure is a finding `flow-step-failed` (step index of the re-run step, `after-reload` in the evidence). A flow whose last step is not an `expect*` step: `notApplicable`.
- **TST-003** · P1 · diff, graph — Each changed file whose role is in `requireTestsFor` is imported, directly or transitively (test import graph, ≤ 5 hops), by a test file (role `test`, 04 § 7.1) added or modified in the diff; for a `route` file, a test file added or modified in the diff that contains a string literal equal to a path its URL pattern matches (route→file map) also counts. Otherwise a finding `missing-element` naming the file (waivable).
- **TST-004** · P1 · cmd, ast — Honest tests (pass/fail of the project's own tests is BLD-003). Part `order` (P1 · cmd): the tests run a second time, with the adapter `testShuffle` flag when declared, else in the same order. Per-test outcomes come from the JUnit XML the adapter test command writes (adapter `testReport` path; else whole-command exit codes). A test that passes in one run and fails in the other is a finding. Part `sleep` (P1 · ast): test files added or modified in the diff call no adapter `sleepApis` with a numeric-literal argument. Part `egress` (W · cmd): the egress proxy recorded a request to a host outside the verify environment during either run (G1 test commands get the proxy variables and the proxy starts before G1 when this part applies, 04 § 4.6; reduced runs without the proxy: `skipped(reduced)`).
- **TST-005** · W · review — Tests assert behaviour through public interfaces rather than private implementation details.
- **TST-006** · P1 · cmd — With `mutation.enabled` (profile `nightly`): candidates are the occurrences (tree-sitter tokens) of the listed operators and literals in lines added by the diff, ordered by (file path bytes, line, column), one mutant per occurrence (candidate key `<path>:<line>:<column>:<operator>`); the Verifier draws `mutation.sample` of them without replacement with the lock-digest PRNG (stream id `mutation`), or all when fewer, and reruns `commands.test` for each. A mutant whose test run exceeds 3 × the duration of the unmutated G1 test run is killed and counts as detected. Operators: `==`↔`!=`, `<`↔`>=`, `>`↔`<=`, `&&`↔`||`, `true`↔`false`, removal of a unary `!`, integer literal n → n+1, deletion of an expression-statement call. Mutants that fail to build are replaced by the next draw. A mutant that leaves all tests passing is a finding `missing-element` (evidence: path, line, column, operator) of part `main` (P1) when a test imports the mutated file (test import graph, as TST-003), or of part `untested-file` (W) when no test imports it.
- **TST-007** · P0 · cfg — Flows, fixtures and contracts used as oracles are Operator-owned and signed; agents propose new ones in `quality/proposals/`. `testing.flows` must be `quality/flows/`; `data-api.contracts[].path`, `data-api.examples` and `data-api.released` must lie under `quality/contracts/`; `security.ownership` and `data-api.firebase.seed` under `quality/fixtures/` (flow `upload` paths outside `quality/fixtures/` are CFG-001, 03 § 10). Otherwise `schema-violation` owned by `operator` (the oracle would sit outside the lock; what counts as Operator-owned: 03 § 8 *Operator-owned sources*).
- **TST-008** · P1 · browser — Cross-browser: with `crossBrowser.enabled`, each flow matched by `crossBrowser.flows` (flow-id globs) runs in each browser of its own `browsers` (03 § 10) ∪ `crossBrowser.browsers` and passes in each. A listed browser with no managed build for the OS: `skipped(no-browser)` for that browser, listed in the report; an installable browser that fails to launch is a finding `command-failed`.
- **TST-009** · P1 · browser — Every flow step on `app` surfaces has zero uncaught errors from origin scripts and zero failed same-origin requests: a response with status ≥ 400, or a network failure, for a request of resource type `script`, `stylesheet`, `image`, `font`, `fetch`, `xhr` or `media` (not `document`), except a request matched by an `expectApi` step of the same flow with the same method, path and status (class `runtime-error`; evidence: URL, status, step index) (flow steps on `public` surfaces are owned by RTE-013; errors from non-origin scripts are excluded, 04 § 6.1).
- **TST-010** · P1 · cfg, browser — Critical journeys have flows: each `security.authEndpoints` entry is requested during ≥ 1 flow (browser network log); with `security.payments`, ≥ 1 flow has `journey: "checkout"` and a `markAmount` step (which also feeds SEC-041); when any flow has `journey: "signup"`, ≥ 1 flow has `journey: "deletion"`; when `auth.strategy` ≠ `"none"`, ≥ 1 flow has `journey: "logout"` and a non-null `account` (03 § 10; a missing one is reported only by SEC-028, as a blocking `missing-element` owned by `operator`, since flows live in Operator-owned `quality/flows/`); each `criticalRoutes` pattern is matched by a `goto` or `expectUrl` step of ≥ 1 flow (cfg part). Part `cancel` (P1 · cfg, browser): with `security.payments.recurring: true`, ≥ 1 flow has `journey: "cancel"` (it passes under TST-001); when additionally `privacy.jurisdictions` contains `"de"` (BGB § 312k), every browser-sampled public page (04 § 10) has an `<a>` or `button` whose accessible name equals, after NFKC, case-fold and whitespace collapse, a ruleset `cancel-labels.json` entry for the page locale (lookup and no-entry outcome: 04 § 15 *Page locale*) ("Verträge hier kündigen", …), and an `<a>` of that kind answers 200. The withdrawal flow is owned by PRV-021 `flow`. Form coverage is owned by UX-001.
- **TST-011** · P2 · cmd — Changed-line coverage: when `services[].commands.coverage` is set, it runs in G1. Before it runs, shipgate deletes `coverage.report` (else every auto-detect candidate: `coverage/lcov.info`, `lcov.info`, `coverage/cobertura-coverage.xml`, `coverage.xml` under the service path); afterwards only a report that run produced is read (`coverage.report`, else the first candidate present), as lcov or Cobertura XML; of the diff's added or modified lines that the report lists as executable, in files whose role is in `requireTestsFor`, the share with a hit count > 0 is ≥ `coverage.changedLinesMin`. No `commands.coverage`: `notApplicable` (as CFG-002 states for the optional `coverage` command); no such executable changed lines: `notApplicable`; a missing report after the command ran: finding.

Flows reach the verify environment through the browser routing in 04 § 2; `submitEmpty` and `markAmount` steps (03 § 10) feed A11-003 and SEC-041.
