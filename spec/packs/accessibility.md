# Pack: accessibility

> Target: WCAG 2.2 level AA. Automated checks catch a large share of issues, not all; the report never claims compliance (TR-110).

---

## 1. Policy section

```jsonc
"accessibility": {
  "standard": "wcag22aa",
  "axeImpactsBlocking": ["critical", "serious"],   // "moderate"/"minor" become warnings
  "viewports": [320, 768, 1280],                   // CSS px widths for reflow checks; each is run at height 800 CSS px, DPR 1, no touch
  "genericAltWords": { "en": ["image", "photo", "picture", "graphic", "icon"] },
  "keyboardFlows": ["login", "signup", "register", "checkout", "contact"],   // flows with keyboard: null whose journey or id contains one of these count as keyboard flows (03 § 10; A11-019, A11-022)
  "help": [],                                      // selectors of help mechanisms (contact link, chat launcher, help page link) for A11-024
  "pdfs": { "maxFiles": 20 }                       // A11-026 cap per run (≤ 20 MB each)
}
```
Sampling follows 04 § 10 (≥ 3 pages per route group) plus every declared flow step.

**Header menu toggles** (`mobile-nav` parts of A11-001, A11-004): at the smallest `viewports` width, each visible element with an `aria-expanded` attribute inside `<header>` or the `banner` landmark.

**Pixel-difference measure** (A11-004, A11-020, A11-021): ≥ 1 % of the element's box (plus 4 px margin) differs between two screenshots, or from the box's most frequent colour when only one screenshot is taken. A pixel differs when any RGB channel differs by ≥ 16 (0–255).

**Standard:** `standard: "wcag22aa"` (only value) runs axe-core with `runOnly: { type: "tag", values: ["wcag2a", "wcag2aa", "wcag21a", "wcag21aa", "wcag22aa"] }`.

**Interactive element** (A11-004, A11-015, A11-017, A11-029): visible, not `disabled`, not inert, no negative `tabindex`, and `a[href]`, `button`, `input:not([type=hidden])`, `select`, `textarea`, `summary`, `[contenteditable]`, `[tabindex]` ≥ 0, or a control of the flows-engine control inventory. For the A11-004 Tab walk a radio group (`input[type=radio]` with the same `name` in the same form or root) counts as one element: its checked radio, else its first radio in document order; the others are reached by arrow keys and need not be focused.

**Phrase match** (A11-022, A11-030): a text has a phrase match in a phrase list (the file the rule names) when, with both NFKC-normalised, case-folded and whitespace-collapsed, a phrase of the list for the page locale (04 § 15 *Page locale*, including the per-locale lookup and the no-entry outcome) occurs in the text as a substring.

**Axe findings** (A11-001, A11-003 labels, A11-006): each violating node is a `forbidden-value` finding showing the axe rule id, impact and selector.

## 2. Rules — `A11-*`

- **A11-001** · P1 · browser — axe-core reports no violations with impact in `axeImpactsBlocking` on sampled pages and at every flow step. Part `mobile-nav` (P1) — the same check with each header menu toggle opened by the A11-004 `mobile-nav` activation. Excluded (owned elsewhere), where present in the pinned axe-core: `color-contrast` (A11-005), `target-size` (A11-006), `image-alt`, `input-image-alt`, `role-img-alt`, `svg-img-alt`, `area-alt`, `button-name`, `link-name` (A11-007), `label`, `select-name` (A11-003), `duplicate-id*`, `landmark-*` (A11-002), `html-has-lang`, `html-lang-valid` (MET-007), `heading-order`, `page-has-heading-one` (MET-003).
- **A11-002** · P1 · html — Page structure. Part `landmarks`: each sampled page has exactly one page-level `banner` and one page-level `contentinfo` (UX-016 definition) and, when it has ≥ 3 same-origin links outside `<main>`, ≥ 1 `navigation` landmark containing ≥ 1 of them. Part `ids`: no two elements share an `id` value. Part `nesting`: no `banner`, `contentinfo` or `main` landmark is a descendant of another landmark, and no landmark is a descendant of a landmark with the same role. Findings: `missing-element` (landmark absent), `duplicate-element` (second landmark, repeated `id`), `forbidden-value` (misnesting), each showing the selector. (One `<main>` and heading order: MET-003; `lang`: MET-007.)
- **A11-003** · P1 · browser — Forms: every control has a programmatic label (axe-core rules `label` and `select-name` report no violation, any impact, on sampled pages and flow steps). At each flow `submitEmpty` step, for every control of the form that is empty and has `required` or `aria-required="true"` (or on which the `invalid` event fired), within 2 s there is an *error element* — a visible element with non-whitespace text that was not visible before the submit — whose `id` is in the control's `aria-describedby` or `aria-errormessage` (the latter with `aria-invalid="true"` on the control); it is *announced* when it or an ancestor has `role=alert|status` or `aria-live` `polite|assertive`, or `document.activeElement` is the first such control. Otherwise `missing-element` showing the control selector. Controls on which the `invalid` event fired (native validation, no `novalidate`) are judged by the same test. Part `required`: each control with `required` or `aria-required="true"` has `*` or a ruleset `required-labels.json` phrase (per locale) in its accessible name or `<label>` text, or the form's text contains such a phrase explaining the marker (`missing-element` showing the selector).
- **A11-004** · P1 · browser — Keyboard: a Tab walk on each sampled page reaches every interactive element, with no trap; each focused element shows a visible focus indicator, detected as a screenshot difference of ≥ 1 % of the element's box (plus 4 px margin) between focused and unfocused states (covers `:focus-visible`, ancestor and pseudo-element styles); dialogs opened in flows trap focus and restore it on close. The Tab walk runs until focus returns to the first focused element or for max(500, 2 × interactive elements + 10) presses; an interactive element (§ 1) never focused is `missing-element`; 10 consecutive presses that leave focus on the same element, or not returning within the press limit, is a trap (`flow-step-failed` showing the selector); no visible focus indicator is `missing-element` showing the selector. Dialogs: after a flow step opens a `role=dialog|alertdialog` or `<dialog open>`, 2 × (its interactive elements + 1) Tab presses keep focus inside it, and after it closes `document.activeElement` is the element that opened it (`flow-step-failed` otherwise). Part `mobile-nav` (P1) — on sampled pages, each header menu toggle is reached by the Tab walk, and pressing Enter on it (and, in a fresh load, Space) sets `aria-expanded="true"` and makes the element it controls (`aria-controls`, else its next sibling) visible (`flow-step-failed` showing the toggle). (Task completion by keyboard: A11-019; change on focus: A11-028.)
- **A11-005** · P1 · browser — Colour contrast (1.4.3): axe-core rule `color-contrast` reports no violation with impact in `axeImpactsBlocking` on sampled pages and flow steps (`value-mismatch` showing the selector, the measured and the required ratio); each `incomplete` node of that rule is a W finding `value-mismatch` showing the selector. Non-text contrast (1.4.11) is not checked automatically; it is a review item of A11-009. (Dark scheme: A11-020.)
- **A11-006** · P2 · browser — Target size (2.5.8): axe-core rule `target-size` reports no violation on sampled pages and flow steps (its spacing exception implements 2.5.8).
- **A11-007** · P1 · html — Images and names: every `<img>`, `input[type=image]` and `area[href]` has an `alt` attribute; on `<img>`, `alt=""` (or `role=presentation|none`) marks decorative and passes; `input[type=image]` and `area[href]` are actionable and each needs a non-empty `alt`, `aria-label` or `aria-labelledby` text, which then passes the checks below; any other `alt`, trimmed, is not empty, does not match `^[^\s/]+\.(avif|bmp|gif|jpe?g|png|svg|webp)$` (case-insensitive), is not equal to the `src` or its last path segment, and, case-folded, is not one `genericAltWords` entry for the page locale (fallback `en`). Elements with `role=img` (including `<svg role=img>`) have a non-empty accessible name, and axe-core rules `button-name` and `link-name` report no violation (icon-only buttons and links). Findings `missing-element` / `forbidden-value` showing the selector and `alt`. (Owner of alt rules; PRF-007 covers dimensions.)
- **A11-008** · P1 · browser — Under emulated `prefers-reduced-motion: reduce`, 1 s after load, `document.getAnimations()` contains no running animation with infinite iterations or total duration > 5 s that was not started by a user action (`forbidden-value` showing the animation's target selector). (Hover/focus content: A11-029.)
- **A11-009** · W · review — Transcripts and audio description for media; complex widgets follow WAI-ARIA authoring practices; and non-text contrast of UI components and graphics (1.4.11). (Automated caption/autoplay/carousel parts: A11-021.)
- **A11-010** · deprecated — Moved to tool requirement TR-110 (report wording); kept as a tombstone id.
- **A11-011** · P1 · browser — Reflow (1.4.10): at 320 CSS px width, the page fails when any element's border box right edge exceeds viewport width + 1 px, unless that element is, or is inside, a `<table>`, `<pre>`, `<code>`, `<canvas>`, `<svg>`, an `<iframe>` from a `hosts[]` entry with purpose `maps`, or an ancestor with computed `overflow-x` `auto` or `scroll`, or is hidden (04 § 15 Hidden content) or has computed `position: fixed`. Finding `budget-exceeded` showing the selector and its right edge.
- **A11-012** · P1 · browser — Text spacing (1.4.12): after injecting line-height 1.5, paragraph spacing 2em, letter spacing 0.12em, word spacing 0.16em, no text container that is not hidden (04 § 15 Hidden content, judged before the injection) and that has `scrollHeight <= clientHeight + 1` and `scrollWidth <= clientWidth + 1` before the injection has `scrollHeight > clientHeight + 1` or `scrollWidth > clientWidth + 1` after it, while its computed `overflow` on that axis is `hidden`, excluding containers with intentional truncation (`text-overflow: ellipsis` or line-clamp) whose full text is available via `title`, `aria-label` or an `aria-expanded` control whose `aria-controls` names the container or an ancestor of it. Runs at each `viewports` width; the injected stylesheet applies the four values with `!important` to every element (paragraph spacing as `margin-bottom` on `p`). *Text container* = an element with a non-whitespace direct text child. Finding `forbidden-value` showing the selector and both sizes.
- **A11-013** · P1 · browser — Resize text (1.4.4): at 200 % zoom, emulated as viewport 640 × 400 CSS px with `deviceScaleFactor` 2 (a 1280 × 800 window zoomed to 200 %), same clipping test (before = the same page at 1280 × 800, DPR 1), exclusions and finding as A11-012.
- **A11-014** · P1 · browser — Orientation (1.3.4), on sampled pages. Part `lock`: during load and flows, no call to `screen.orientation.lock` (init-script hook), and at 844 × 390 and 390 × 844 the computed `transform` of `<html>`, `<body>` and the `<main>` element is `none` or a matrix whose `b` and `c` components are 0 (|x| < 0.001) (`forbidden-value` showing the element or call). Part `landscape`: at 844 × 390 no A11-011 violation, and flows with `orientation: both` pass at 844 × 390 (`budget-exceeded` as A11-011; `flow-step-failed` for a failing flow).
- **A11-015** · P1 · browser — Focus not obscured (2.4.11): during the A11-004 Tab walk, for each focused element, after the browser scrolls it into view, at least one of the 9 points of a 3 × 3 grid over its border box clipped to the viewport returns (via `elementFromPoint`) the element or a descendant; none returning it while the covering elements have computed `position: fixed|sticky` (or an ancestor does) is a `forbidden-value` finding showing both selectors.
- **A11-016** · P1 · browser — Accessible authentication (3.3.8): in flows with `journey` `login` or `signup` and in forms containing `input[type=password]` on sampled pages. Part `paste`: with clipboard text `sg-paste` (context granted `clipboard-read`/`clipboard-write`), focusing each text, email and password input and pressing `ControlOrMeta+V` leaves its value containing `sg-paste` (`forbidden-value` otherwise). Part `autocomplete`: password inputs carry `current-password` in `login` journeys, `new-password` in `signup` journeys, either elsewhere; the input located by each `totp` step carries `one-time-code`; the text or email input that precedes the first password input in the same form carries `username` or `email` — each token optionally followed by `webauthn`; inputs that ruleset `autocomplete-map.json` maps are judged by A11-022 instead (`missing-element` showing the selector).
- **A11-017** · P1 · browser — Responsive layout at each `viewports` width: no in-flow element extends beyond the viewport, and no interactive element's center point is covered (`elementFromPoint` returns an element that is not the interactive element, a descendant or ancestor of it, or its associated `<label>`), excluding open menus/dialogs and `position: fixed|sticky` bars that leave ≥ 50 % of the viewport height free. An element "extends beyond the viewport" when its border box right edge exceeds viewport width + 1 px and it is not excepted by A11-011; at 320 px horizontal overflow is owned by A11-011. Interactive elements (§ 1) are scrolled into view before the `elementFromPoint` test at their centre. Findings `budget-exceeded` (overflow, showing the selector and right edge) and `forbidden-value` (covered, showing both selectors). (Dark scheme: A11-020.)
- **A11-018** · W · browser — No accessibility overlay: no host in ruleset `a11y-overlays.json` (accessiBe, UserWay, AudioEye, EqualWeb, Max Access, …) is requested on sampled pages (`forbidden-value` showing the request URL).
- **A11-019** · P1 · browser — Keyboard-only task completion (2.1.1): each keyboard flow (flows with `keyboard: true`, or `keyboard: null` and `journey` or flow id containing an entry of `keyboardFlows`) is replayed with pointer steps converted: `click` → Tab (Shift+Tab after wrapping) until `document.activeElement` matches the Locator, then Enter (links, buttons) or Space (checkboxes, radios, `role=switch`); `check`/`uncheck` → Tab, then Space; `fill` → Tab, select-all, then typing the value; `select` → Tab, then typing the option label. `hover`, `dblclick` and `upload` steps run unchanged. Fails when a Locator isn't focused within 200 Tab presses or the converted flow's expectations fail (`flow-step-failed` showing the flow id and step index). Replays of mutating flows run in their own stage (mutating stage, 04 § 4.2 step 8).
- **A11-020** · P1 · browser — Colour-scheme variants. Part `dark` — when any loaded stylesheet contains a `prefers-color-scheme: dark` media query, A11-005 and A11-017 also run on sampled pages under emulated `colorScheme: 'dark'` (their failure classes). Part `forced-colors` — under emulated `forcedColors: 'active'`, each icon-only control (button or link with no text node content and an accessible name from `aria-label`, `aria-labelledby` or `title`) passes the pixel-difference measure against its box's most frequent colour (`missing-element` showing the selector).
- **A11-021** · P1 · html, browser — Media and motion. Part `captions` (html) — every `<video>` without the `muted` attribute contains `<track kind="captions">` or `<track kind="subtitles">` with a `src` returning 200; each `<iframe>` whose host is a `hosts[]` entry with purpose `video` produces one W review item "captions available for the embedded video" showing the `src`. Part `autoplay` (html) — no `<video>` or `<audio>` has `autoplay` without `muted` (`forbidden-value`). Part `carousel` (browser) — a region that is auto-advancing (its visible content passes the pixel-difference measure between screenshots 0 s and 10 s after load with no input, and it matches `[aria-roledescription=carousel]` or a ruleset `carousel-markers.json` class/id pattern) contains a control whose accessible name matches ruleset `carousel-controls.json` (pause/stop/play labels per locale), and after keyboard focus moves into it, screenshots 0 s and 10 s later don't differ by the measure. Missing track, control or pause: `missing-element` showing the selector.
- **A11-022** · P1 · html, browser — Input purpose (1.3.5): in forms reached by keyboard flows (flows with `keyboard: true`, or `keyboard: null` and `journey` or flow id containing an entry of `keyboardFlows`) and forms containing a password field, inputs matched by ruleset `autocomplete-map.json` carry the mapped `autocomplete` token (a section prefix, `shipping`/`billing` and a trailing `webauthn` are allowed); an `email`- or `text`-typed input that precedes the first password input of its form also accepts `username`. `autocomplete-map.json` shape: `[{ "token": "<autocomplete token>", "types": [input type], "names": [regex], "labels": { "<locale>": [phrase] } }]` (tokens at least `email`, `tel`, `name`, `given-name`, `family-name`, `street-address`, `address-level1`, `address-level2`, `postal-code`, `country`, `cc-name`, `cc-number`, `cc-exp`, `cc-csc`). An input is mapped to the first entry, in file order, whose `types` contains its `type`, or one of whose `names` regexes (unanchored, case-insensitive) matches its `name` or `id`, or one of whose `labels` phrases has a phrase match (§ 1) in its accessible name. Failure class `missing-element` showing the selector and the expected token.
- **A11-023** · P1 · browser — Client-side navigation: when a flow step changes `location.pathname` without a document load, within 2 s `document.title` differs from the title before the step, and either `document.activeElement` is `<main>`, an `<h1>` or inside `<main>` (not `<body>` and not the triggering element), or an `aria-live`/`role=status|alert` region's text changed and contains the new `<h1>` text or title. Otherwise `missing-element` showing the flow id and step index.
- **A11-024** · P2 · site — Consistent help (3.2.6): on sampled pages where two or more `help` selectors match, their relative document order is the same on every page (`inconsistent-set` showing the pages and orders).
- **A11-025** · W · ast — Dragging movements (2.5.7): changed code that imports a library in ruleset `drag-libraries.json` (`@dnd-kit/*`, `react-dnd`, `react-beautiful-dnd`, `@hello-pangea/dnd`, `sortablejs`, `vuedraggable`, `dragula`, `interactjs`, `@atlaskit/pragmatic-drag-and-drop`, …) or adds `draggable="true"`/drag event handlers produces a review item: a single-pointer alternative exists.
- **A11-026** · P2 · http — Linked PDFs: same-origin links from sampled pages to `application/pdf` responses (up to `pdfs.maxFiles`, ≤ 20 MB each) have a document catalog with `/StructTreeRoot`, `/MarkInfo << /Marked true >>`, a non-empty `/Lang`, `/ViewerPreferences << /DisplayDocTitle true >>`, and a non-empty `Title` in the Info dictionary or XMP `dc:title` (`missing-element` showing the URL and the missing entry). PDFs are taken in crawl order of first discovery, then URL. A response over 20 MB is not downloaded and is a `budget-exceeded` finding of this rule showing the URL and `Content-Length`; PDFs beyond `maxFiles` are listed as one W item with their URLs.
- **A11-027** · P2 · browser — Bypass blocks (2.4.1): on pages with more than 10 links inside `nav`/`role=navigation` elements, with consent already decided, the first Tab press focuses a link whose `href` is a same-page fragment targeting `<main>` (or an element inside it), and activating it with Enter moves `document.activeElement` to that target or inside `<main>` (`missing-element` showing the page URL).
- **A11-028** · P1 · browser — Predictable focus and input (3.2.1, 3.2.2). Part `on-focus` — during the A11-004 Tab walk, focusing an element causes no document load, no `location.pathname` change, no new page or popup, and no `dialog` event or newly visible `role=dialog|alertdialog` / `<dialog open>` element. Part `on-input` — on sampled pages, each visible `<select>` (ArrowDown to another option), radio (ArrowDown) and checkbox (Space) operated by keyboard without activating a submit control causes no document load, no `location.pathname` change and no new page or popup (query-string-only changes are allowed) (mutating stage, 04 § 4.2 step 8). Findings `forbidden-value` showing the selector and the change.
- **A11-029** · W · browser — Content on hover or focus (1.4.13): for each element whose focus during the A11-004 Tab walk, or whose hover (hovered: each interactive element of § 1 and each element with `aria-describedby`, `title` or `[data-tooltip]`, up to 50 per page in document order), makes an element outside the trigger, and not a dialog, change from hidden to not hidden (04 § 15 Hidden content, judged before and 100 ms after the interaction), pressing Escape hides that element within 500 ms without moving focus or pointer (dismissible), and after hovering the trigger, moving the pointer onto the revealed element's centre keeps it visible for 1 s (hoverable). Findings `forbidden-value` showing the trigger and the revealed element.
- **A11-030** · P1 · browser — Redundant entry (3.3.7, Level A): in flows with `journey` `signup`, `checkout` or `contact` that span more than one document or view (a view = the DOM after a step that changes `location.pathname`, loads a document, or makes a `<form>` that was hidden not hidden), a field whose `autocomplete` token — its own, else the A11-022 mapped token; section prefixes and `shipping`/`billing` ignored for the comparison — was already filled by an earlier `fill` or `select` step of the same flow is, on the later view before the flow fills it, prefilled with the earlier value, or the later view has a checkbox or button whose accessible name has a phrase match (§ 1) in ruleset per-locale `same-as-labels.json` ("Billing address same as shipping", …) that, once activated, fills it with the earlier value. Excluded tokens: `new-password`, `current-password`, `one-time-code`, `cc-number`, `cc-csc`, `cc-exp`. Finding `missing-element` showing both views (URL and step index) and the token. Single-view flows: `notApplicable`.
